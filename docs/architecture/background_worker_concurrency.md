# Background Worker Concurrency Architecture

## 1. Definition
Background workers process asynchronous tasks, including Agent memory summarization, document indexing, and mission execution. The architecture must guarantee exactly-once processing semantics without lock contention.

## 2. Lock Acquisition
* Workers claim tasks by executing a transaction combining `UPDATE` with `SELECT ... FOR UPDATE SKIP LOCKED`.
* The `assigned_worker_id` and `updated_at` timestamps are recorded to track ownership.

## 3. Timeout and Recovery
* A supervisor process continuously monitors the `updated_at` column.
* If a task remains in `RUNNING` state beyond the defined timeout (e.g., 5 minutes), the supervisor forces the task to `STUCK` or resets it to `PENDING` for retry.
* The `worker_id` is cleared upon reset.

## 4. Multi-Tenant Fairness
* The queue selector query (`SELECT id FROM queue ...`) must incorporate logic to ensure a single high-volume tenant does not starve other tenants.
* Fair-share scheduling is enforced by limiting the number of active locks a single tenant can hold concurrently.

## 5. Scaling
* Because of `SKIP LOCKED`, we can dynamically scale worker pods from 1 to 100 without query blocking, ensuring near-linear horizontal scalability.
