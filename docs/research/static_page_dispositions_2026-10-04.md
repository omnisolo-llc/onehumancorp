## This follow-up batch

Eight paths receive reviewed replacements: two trial-extension interstitials, four changelog implementations, and two hardcoded unified-feed implementations. Changelog migration requires real loading/error/empty/content handling. Unified-feed replacement records actual approval decisions and explicitly does not promise a provider send. Successful verification would leave 296 shipped HTML paths; that is not resolution of the wider 190-path implementation category.

Separately, the affiliate growth screen must display actual tenant-scoped count and commission-cents responses, mark absent referral metrics unavailable, and stop claiming that total commission was paid. Backend aggregate failures must not become successful zero totals.

Scope and completion limits: the dedicated growth screen and shared statistics endpoint are repaired here. The mounted `AffiliateMarketingWidget` and the two retained `affiliate-dashboard.html` variants still need error-state corrections; the widget also labels total commission as paid. Trial grants, active-referral accounting, payout reconciliation and provider execution after approval remain unimplemented. Replacing a false success with an unavailable state does not complete any of these capabilities. The separately approved two-alias service-creation migration also does not implement reservation deposits or RSVP delivery.

## Larger implementation work

| Scope | Evidence and preserved functionality | Required result and acceptance |
| --- | --- | --- |
| Kairos | Canonical tasks, mesh and memory endpoints return fixed empty JSON while the UI uses live-orchestration labels. | Connect to existing authoritative task/mesh/memory services, or explicitly identify unavailable capabilities until implemented. Failed reads must not become healthy empty telemetry. Verify tenant scope, error states and real state changes. |
| Booking and RSVP | Useful configuration/builders coexist with timer-based submitted/registration/email confirmation paths. | Persist the booking or RSVP and return its durable identifier before confirming registration. Delivery needs its own actual receipt; network failure and rejected submissions must preserve input and never claim delivery. |
| Subscription parsing | The current parsing handler hardcodes lesson-plan defaults; static callers also disagree on singular/plural endpoint ownership. | Define and validate the real input/output contract, reuse a supported implementation, and reject unavailable parsing. Test varied real input, invalid responses and correct route ownership; no demonstration defaults in production responses. |
| Rewards, referral and unboxing campaigns | Real campaign configuration/event tracking coexists with fixed codes, mock customer identifiers, or event-only success presented as activation/invitation delivery. | Separate recorded interaction from reward issuance, entitlement activation and message delivery. Require authorization, persistence, unique/replay-safe receipts, and verified downstream status before each consequential claim. |
| POS, assistant and calendar | Useful owner workflows remain, but some branches claim paid/running/sent or derive payment state from booking confirmation. | Map displayed state to the relevant payment/task/command receipt. Preserve unknown outcomes for reconciliation, dates/timezones and edited terms; verify rejection, timeout, restart and duplicate-event behavior. |
| Pricing, referral widget and link-in-bio | Reviewed real functions remain; canonical identity/lifecycle, settings or theme behavior differs. | Establish explicit migration contracts for existing configuration and consumers before redirecting. Preserve reviewed public capability access and historical standalone sources. |

Public documents, private-profile handling, quote/approval receipts, field-service state, and guarded post-purchase sharing must be preserved rather than removed based on names. Provider-facing work requires the applicable authority and isolated/sandbox evidence; this batch performs no production provider action.
