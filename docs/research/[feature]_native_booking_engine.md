# Feature Brief: Native Booking Engine for KAIROS

## Title
Native Booking Engine: AI-Driven Scheduling

## Problem Statement
Small business owners like Carlos (Handyman) and Leo (Music Tutor) rely heavily on scheduling. However, currently, the OHC platform lacks a native booking engine that the AI Agent can read from and write to autonomously. Existing solutions (like linking out to Calendly) create a disjointed experience and break the "autonomous teammate" paradigm.

## Design Doc

### High-Level Requirements
- **Native Data Structure:** The booking system must live inside OHC's DB, completely accessible by the KAIROS Orchestrator.
- **Deposit Support:** Must integrate seamlessly with the existing Payment system to require deposits upon booking (a top pain point for Carlos).
- **AI R/W Access:** The AI Operations/Sales agents must be able to read availability, propose slots in chat, and block off time automatically.

### Mobile UX Constraints
- The user interface for the business owner to view their schedule must be optimized for 375px.
- Approving a booking draft generated by AI must be a 1-tap operation.

### Action Items
- Design the DB schema for `bookings` and `availability`.
- Implement KAIROS event triggers for `booking.created` and `booking.canceled`.
- Train the `SalesAgent` to negotiate times using the `availability` endpoint.
