### Title
[ui] Mobile-First Agent Activity Feed for 1-Tap Approvals

### Problem Statement
Small business owners, particularly non-technical founders, suffer from "Operational Fatigue" (the #2 SMB pain point, reported by 68% of users). They are overwhelmed by the "never-ending inbox" and manual tasks across disparate systems. Existing competitors (Shopify Sidekick, Wix ADI) treat AI as a reactive tool requiring prompts, which places the cognitive burden back on the user. OHC users need an AI teammate that operates autonomously in the background and presents drafted, ready-to-execute actions that can be approved instantly from a mobile device.

### Research Report
- **Competitor Gap:** Shopify and Wix rely on reactive AI chat interfaces. Durable and 10Web focus heavily on initial site generation but lack deep, proactive operational support post-launch.
- **Pain Points Addressed:** Operational Fatigue, Technical Jargon.
- **Validation:** High perceived value is found in solutions that save daily time while maintaining owner control. "Background Draft & Approve" solves the "Communication Lag" pain point where 40% of users report losing sales due to delayed responses.

### Design Doc
- **Architecture:**
  - KAIROS Orchestrator monitors the Teammate Mesh for events (e.g., new order, customer message).
  - Relevant Autonomous Agent (e.g., Customer Success, Operations) drafts an action (e.g., reply to message, flag low stock).
  - Drafted action is queued in the OHC-SIP DB pending queue with an assigned `ActionRisk` level.
- **UI Flow (375px First):**
  - **Home Dashboard:** Features an "Action Required" / "Agent Activity Feed" prominently at the top.
  - **Card Interaction:** Each card represents a pending agent task. It displays a plain-language summary (e.g., "The Ambassador drafted a reply to the vegan cake inquiry").
  - **1-Tap Action:** Prominent "Approve & Send" (primary) and "Edit" (secondary) buttons on each card.
  - **Resolution:** Upon approval, the action is executed, and the card transitions to a "Completed" state or disappears.

### Implementation Prompt
Implement the "Agent Activity Feed" UI component for the mobile dashboard. Create a system to display pending actions generated by backend AI agents. Ensure the feed correctly pulls from the pending task queue. Implement the "Approve" flow (which triggers execution) and the "Edit" flow (which allows the user to modify the agent's draft before sending) for each action type. The UI must be perfectly optimized for a 375px mobile screen and use plain, jargon-free language throughout.
