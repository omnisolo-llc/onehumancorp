# 🛡️ OHC Agent Harness Audit & Capability Gap Analysis

## Problem Statement
The OHC Agentic OS requires absolute autonomy and secure execution for our AI agents. However, while our core orchestration (KAIROS) is scaling, our local Agent Harness—the secure execution environment where agents interact with the OS and run commands—lacks the sophisticated security boundaries and fine-grained capabilities found in leading proprietary and open-source models. Without these robust constraints, agents could unintentionally compromise host systems or interfere with one another during concurrent operations.

## Research Report

We performed a deep technical audit of the **Claude Code** agent harness architecture to understand its isolation primitives, permission models, and execution semantics. Claude Code's harness relies heavily on `@anthropic-ai/sandbox-runtime` for structural security.

### Core Discoveries: The Claude Code Harness (via `sandbox-runtime`)
1.  **Deep OS-Level Isolation (Linux `bwrap`)**:
    *   Claude Code leverages `bwrap` (Bubblewrap) on Linux to create lightweight namespaces for agent processes. This enforces strict filesystem visibility and immutability.
    *   **Finding:** We identified detailed `linux-sandbox-utils.ts` and `generate-seccomp-filter.ts`, confirming that the system generates dynamic BPF seccomp filters per command to block dangerous syscalls (`ptrace`, `unshare`, etc.) based on real-time task context.
2.  **Granular Network Interception via Proxies**:
    *   The `SandboxManager` initiates MITM HTTP (`http-proxy.ts`) and SOCKS5 proxies. Network traffic generated by the agent is intercepted, and requests are checked against an allow/deny list dynamically *during* the execution of the command.
    *   **Finding:** The configuration schema (`SandboxRuntimeConfigSchema`) enables allow-listing specific domains per task, dropping everything else at the proxy layer.
3.  **Symlink Defense & Path Scrubbing**:
    *   The sandbox meticulously guards against directory traversal and symlink replacement attacks. We found a dedicated `findSymlinkInPath` check in `linux-sandbox-utils.ts` that blocks agents from creating symlinks to sensitive locations before executing `bwrap`.
    *   **Finding:** `sandbox-runtime` manages ghost mount points (creating empty files for `--ro-bind` deny paths) and uses a registered process exit handler to automatically scrub these artifacts, ensuring no residue is left in the workspace.
4.  **Graceful Degradation (Fallback)**:
    *   The CLI layer (`sandbox-adapter.ts`) wraps `sandbox-runtime` and performs proactive dependency checking (`checkDependencies()`). If `bwrap` is missing or the platform isn't supported, it can fall back to a constrained "prompt-based" permission mode (or fail gracefully).

## Design Doc

### Proposed Architecture: OHC Dynamic Agent Harness (DAH)

To bridge this gap, OHC will implement the **Dynamic Agent Harness (DAH)**. The DAH will act as the security perimeter between the Orchestration Engine and the underlying Host OS.

1.  **DAH Execution Engine (Go-based)**:
    *   We will build a Go-based execution engine (`srcs/server/bash_sandbox/`) that wraps agent commands.
    *   On Linux, it will utilize `libcontainer` or directly wrap `bwrap` to create ephemeral, isolated mount namespaces per task.
    *   The engine will mount the specific task workspace as read-write, and the rest of the filesystem as strictly read-only or invisible.
2.  **Egress Proxy Daemon**:
    *   A lightweight forward proxy will run alongside the DAH.
    *   Agent configuration (via KAIROS) will pass a list of `AllowedDomains`. The proxy will enforce these rules at L4/L7.
3.  **Command Pre-Flight AST Checker**:
    *   Before execution, bash commands will be parsed to detect dangerous patterns (e.g., attempting to overwrite `~/.bashrc`, alias hijacking, or modifying `.git/hooks`).
4.  **UI Integration**:
    *   The Agent Audit Dashboard will display the active security policies for running tasks, showing blocked syscalls or network requests in real-time.

## Implementation Prompt

**Task:** Implement the Linux `bwrap` isolation layer for the OHC Dynamic Agent Harness in `srcs/server/bash_sandbox/`.

**Context:** The Research Agent has determined that OHC requires secure command execution similar to Claude Code's `sandbox-runtime`.

**Instructions for Implementer:**
1.  **Create the Runner:** In `srcs/server/bash_sandbox/runner.go`, create a `BwrapRunner` struct that implements a generic `CommandRunner` interface.
2.  **Implement Isolation Logic:**
    *   The `Run(ctx context.Context, cmd string, cfg SandboxConfig)` method must construct a `bwrap` command.
    *   It must automatically `--ro-bind / /` (make the root filesystem read-only).
    *   It must `--bind <cfg.WorkspaceDir> <cfg.WorkspaceDir>` (allow write access ONLY to the specific task workspace).
    *   It must use `--unshare-all` to drop namespaces.
3.  **Network Setup:** Add a `--share-net` flag capability controlled by `cfg.AllowNetwork`. If `false`, the agent has no network access.
4.  **Error Handling:** Ensure that if the `bwrap` binary is missing from the system path, the runner fails initialization gracefully with a clear error indicating the missing dependency.
5.  **Tests:** Write comprehensive Go unit tests in `runner_test.go` verifying the correct command-line arguments are constructed for `bwrap` given different `SandboxConfig` permutations.

**Acceptance Criteria:**
*   `bwrap` command construction is exact and covers filesystem and network isolation.
*   Unit tests pass with 100% coverage for the new runner.
*   An end-to-end test is implemented to verify the agent's interaction via the Dynamic Agent Harness (from login UI through task completion).
