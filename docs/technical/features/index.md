# Features

Feature documentation is grouped by capability area. Mature feature areas should include a design doc, critical user journey, test plan, and user guide when the capability is operator-facing.

## Capability Areas

<div class="grid cards" markdown>

- **Core orchestration**
  Agent delegation, meeting rooms, task routing, and interaction protocols.
  [Open core orchestration](core-orchestration/design-doc.md)

- **Agent platform**
  Advanced agentic capabilities, Tooling MCP, marketplace, and plugins.
  [Open Tooling MCP](tooling-mcp/design-doc.md)

- **KAIROS**
  Orchestration, hybrid AI OS features, state machines, and AutoDream flows.
  [Open KAIROS design](kairos/design_doc.md)

- **Business platform**
  Billing, identity, persistence, collaboration, marketplace, and SRE capabilities.
  [Open billing design](billing-finance/design-doc.md)

</div>

## Documentation Pattern

- **Design doc**: intended behavior, architecture, tradeoffs, and interfaces.
- **CUJ**: the user-visible journey and acceptance criteria.
- **Test plan**: verification strategy and regression coverage.
- **User guide**: operator-facing instructions for shipped workflows.

Cross-cutting platform design belongs in [Architecture](../architecture/index.md).
