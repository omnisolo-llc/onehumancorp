# Marketplace descriptor contract and remaining capabilities

Publish the BFF and native repairs together. The previous native JSON-RPC handler mapped `role` to `author` and replaced version/endpoint with invented values; the repaired BFF rejects such receipts, but it cannot undo an upstream write. The paired native handler deserializes the reviewed descriptor directly and rejects unsupported fields before calling the registry.

The existing configured HTTP registry supports descriptor search, fetch, and publication: `id`, `name`, `description`, `author`, `version`, and `endpoint`. A new publication may omit its ID and receive one from the registry. A fetch must return its requested ID. Publication acknowledgement must contain a nonempty ID and match the reviewed metadata (and any explicitly supplied ID). `role` and `system_prompt` are not supported by this registry contract and are rejected before provider effects. This work does not introduce agent installation, full definition storage, or private tenant-scoped registry capabilities.

Missing, invalid, or placeholder registry configuration returns unavailable. Production constructors never select the test registry. An agent-RPC connection failure returns unavailable for marketplace operations without replaying through another client; a publication may have reached the first destination and requires reconciliation before retry. The agent tool classifies an unknown publication as requiring intervention rather than automatic transient retry. The existing hosted RPC tenant-runtime denial and authenticated server authority remain unchanged.

Every client search/fetch reads the authoritative registry. Process-local entries can no longer reappear after provider deletion or conceal denial. HTTP redirects are not followed. Provider receipt validation and rereads do not establish the real provider's durability or access policy; those remain integration acceptance requirements.

Fresh bounded verification uses `scripts/marketplace-contract/run.sh`. It compiles the maintained provider, tool adapter, and types directly, and extracts the actual constructor, listing, and publication-dispatch fragments with source fingerprints. Its isolated local HTTP registry verifies transport/receipt behavior and client restart, not external registry restart or real-provider persistence. The root Node wiring checks guard against reintroducing mock fallback and automatic publication retry. Full workspace, browser and provider acceptance remain separate gates.

The existing marketplace page's installation toast is only local UI state, and its full-agent publication form is unsupported by this descriptor service. Those product capabilities must not be advertised as implemented or made equivalent to hiring an agent. A truthful unavailable state closes a false completion claim; it does not complete the missing installation feature.
