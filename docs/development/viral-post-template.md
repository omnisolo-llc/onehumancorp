# Social post template boundary

The viral-post generator composes a local text template from the owner-entered product and benefit. It does not call an AI model, publish a social post, create a storefront, or confirm a live destination.

An optional destination must be an absolute HTTP(S) URL without whitespace, control characters or backslashes. The existing web-link validator preserves accepted input exactly. An empty destination omits the link; neither a business display name nor a local tenant key is treated as a publication receipt.

Copy feedback awaits the actual browser clipboard promise. Rejection remains visible and a completion for an older generated post cannot mark a new post copied. The browser journey retains native clipboard verification under explicitly loopback-scoped permissions.

This repair does not change the pre-existing Pro-plan or trial-extension policy. The shared `useProPlan` eligibility/receipt contract and the existing trial sharing claim need separate review; this text-template checkpoint does not certify an entitlement grant. A future publication flow must consume a verified publication receipt rather than reconstruct an address.

Focused component tests cover absent/explicit/invalid links, clipboard success/failure and stale completion. Actual hosted browser execution remains a separate acceptance gate.
