## Sync Mechanics

<div style="backdrop-filter: blur(20px) saturate(200%); background: rgba(255, 255, 255, 0.03); border: 1px solid rgba(255,255,255,0.1); border-radius: 12px; padding: 1.5rem; margin-bottom: 2rem;">
  <p>Standalone clients use an internal sync daemon to synchronize local RAG contexts with the Cloud Gateway over mutually authenticated TLS. Memories are processed with a <code>sync_status</code> to ensure reliable Last-Write-Wins (LWW) conflict resolution between the local device and the K8s cloud.</p>
  <p>The <code>Sync Daemon</code> periodically queries the local SQLite DB for rows where <code>sync_status = 'pending'</code>, batches them, and sends them via an encrypted SPIFFE/SPIRE payload to the Cloud API Gateway.</p>
</div>

## Critical User Journeys (CUJ)

<div style="backdrop-filter: blur(20px) saturate(200%); background: rgba(255, 255, 255, 0.03); border: 1px solid rgba(255,255,255,0.1); border-radius: 12px; padding: 1.5rem; margin-bottom: 2rem;">
  <ol>
    <li><strong>System Startup:</strong> Operator spins up the OHC cluster with KAIROS layer in Hybrid Mode.</li>
    <li><strong>Local Memory Generation:</strong> Standalone agent generates a new episodic memory and stores it in the local SQLite DB.</li>
    <li><strong>Background Sync:</strong> The Sync Daemon detects new un-synced memories and upserts them to the Cloud Orchestration engine (PostgreSQL).</li>
    <li><strong>Cloud Retrieval:</strong> A different cloud-based agent queries the global pgvector index to retrieve the insight generated by the standalone agent.</li>
  </ol>
