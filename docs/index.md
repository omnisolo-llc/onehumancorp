# One Human Corp Docs

One Human Corp documentation is organized around the work engineers and operators do most often: understand the platform, build features, operate the system, and trace design decisions back to source material.

The documentation source lives in `docs/`, the site navigation is maintained in `mkdocs.yml`, and GitHub Pages is built from Markdown by MkDocs.

## Documentation Map

- **Get Started**: setup, developer guide, onboarding, and tutorial material.
- **Build with OHC**: product and platform feature specs grouped by capability.
- **Architecture**: system design, KAIROS, orchestration, RAG, reliability, sync, and security.
- **APIs**: API reference pages and protocol guides.
- **Guides**: walkthroughs, demos, troubleshooting, and support flows.
- **Operations**: task tracking, release notes, chaos audits, and release pipeline notes.
- **Business**: roadmap, execution plan, cost work, and public-facing product material.
- **Research**: research reports, site audits, and technical evaluations.

## Site Conventions

- Write source content in Markdown.
- Keep the primary reader path in `mkdocs.yml`.
- Put historical material under `docs/technical/archive/`.
- Prefer neutral Markdown over inline HTML styling so pages remain readable in both dark and light modes.
