# Documentation Architecture Planning

This document outlines the high-level architecture and implementation plan for the OneHumanCorp documentation features.

## Target Audience
Small Business Owners (non-technical). All writing must be at an 8th-grade level, utilizing plain language and a "Business Owner Lens".

## 1. In-App Help Center
**Architecture:**
- Hosted within the Next.js frontend as a dedicated `/help` route.
- Content managed via Markdown/MDX.
- Indexed using a client-side search library (e.g., Fuse.js) for instantaneous results without backend roundtrips.
- **Mobile First:** Responsive design using Glassmorphism styling (`backdrop-filter: blur(20px) saturate(200%)`).

## 2. Contextual Tooltips & Registry
**Architecture:**
- **Registry:** A central JSON/TypeScript configuration mapping UI component IDs to their respective tooltip content. This decouples documentation updates from UI code changes.
- **Component:** A reusable React `Tooltip` component utilizing floating-ui for positioning.
- **Trigger:** Hover events on desktop, long-press on mobile.

## 3. Interactive Walkthroughs
**Architecture:**
- **State Management:** A global context (e.g., Zustand) tracking the user's progress through active tours.
- **Renderer:** An overlay system highlighting the target element (via `getBoundingClientRect`) combined with a speech bubble component.
- **Data:** Walkthrough steps defined in a centralized configuration.

## 4. AI-Powered Help Chat
**Architecture:**
- **UI:** A floating chat widget accessible globally.
- **Backend:** A specialized Help Agent configured within the existing agent framework.
- **Context:** The agent is provided the help center Markdown content via RAG (Retrieval-Augmented Generation).
- **Responses:** Must prioritize citing source articles with deep links.

## 5. Video Tutorials
**Architecture:**
- **Metadata:** Stored in the backend (PostgreSQL) tracking video URL, title, tags, and duration.
- **Player:** A responsive HTML5 video player component optimized for portrait viewing on mobile devices.

## 6. API Documentation (Advanced)
**Architecture:**
- **Spec:** OpenAPI 3.0 specification generated from backend routes.
- **UI:** Swagger UI or Redoc embedded within an "Advanced Settings" section.

## 7. Release Notes & Changelog
**Architecture:**
- **Data Source:** Aggregated from Git commit history or a dedicated release notes CMS.
- **UI:** A "What's New" modal or dedicated page utilizing plain language and screenshots, distinct from developer changelogs.

## Glassmorphism UI Standards
All newly introduced UI components (Help Center, Walkthroughs, Tooltips, Release Notes) must implement the following styles:
- Semi-transparent backgrounds (e.g., `rgba(255, 255, 255, 0.1)` in dark mode).
- Blur effects (`backdrop-filter: blur(20px) saturate(200%)`).
- Subtle white borders (`border: 1px solid rgba(255, 255, 255, 0.2)`).
- Minimum touch target size of 44x44px.
