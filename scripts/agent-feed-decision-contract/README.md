# Agent-feed decision integrity contract

`source /workspace/shared/recovered-toolchains/env.sh` is a local recovery-environment convenience, not a repository dependency. Normal prerequisites are the documented Rust toolchain, PostgreSQL server tools and Redis. Use `with-owned-postgres.sh` to create disposable loopback services or provide an explicit `OHC_FEED_TEST_DATABASE_URL` with an `ohc_*_test` database plus `OHC_FEED_TEST_REDIS_URL`.

The harness imports actual production HTTP, repository, queue, worker, canonical authentication and migration code. For the unmodified baseline, the decision HTTP function is copied verbatim into a generated module; after extraction the complete production decisions module is imported by path. The source manifest records all inputs and is verified unchanged after tests.

The production action router is imported unchanged. The business action exercised here is the real `create_product` database handler. Provider handlers outside this contract are explicit panic boundaries, never fake successful delivery implementations. Cache invalidation and WebSocket publication are inert because they cannot establish database/dispatch correctness. No production database or live provider/work dispatch is permitted. This focused gate does not replace `make lint` and `make test`.

The minimum 103-test inventory preserves all 57 original cases: 47 explicit canonical-feed `contract::` PostgreSQL cases plus `repository::tests::test_agent_feed_repo_lifecycle` against owned PostgreSQL, five inherited SQLite cases, two worker/router cases, and two source/presentation cases. It adds 26 legacy-triage HTTP/auth/database cases, 13 each on PostgreSQL and SQLite; 18 local-effect cases, nine per engine including the existing `product_id` booking alias; one independent PostgreSQL auth/data pool case; and one pending-task source projection contract. The runner provisions a unique lifecycle schema through `OMNISOLO_DATABASE_URL` and requires the inherited test's durable APPROVED row afterward. Its optional connection-failure return therefore cannot certify this focused gate. The pure presentation case compiles the exact existing API/work-triage mobile projection closures; it does not replace persistence or authority.

Legacy cases import the production handler and table definitions, use real signed tokens with the canonical auth repository, and mount both compatibility aliases. They cover current member/demoted-owner authority, absent and foreign IDs, edited draft and receipt readback, matching/conflicting/concurrent retries, historical terminal records, dismissal without queue admission, immediate write failures and deferred COMMIT failures on both databases. SQLite uses a deferred foreign-key failure and PostgreSQL a deferred constraint trigger; neither replaces commit with a mock. Local quote/line, booking, and shift cases read back actual effects, require identical receipts on retry, reject foreign references, and require quote effects to roll back with a failed receipt commit. The independent-pool PostgreSQL case exercises actual canonical relation proof; its schema comes from maintained production migrations, including `ohc_staff_member`, rather than invented optional tables. Cache invalidation remains an inert boundary. These cases do not claim provider delivery, process-restart verification, or execution of unsupported actions. The existing canonical catalog-worker cases retain their actual local-product effect checks.

Queued catalog side-effect fixtures use the canonical restricted-role worker pool with the production products RLS policy and exact production pool-reset hooks. Fixture setup, cross-tenant assertions and generic system-scope queue polling use the owned administrative connection. This proves `process_job` and its tenant-local effect boundary, not a privilege-free global polling loop. Controlled incident effects verify that generic dispatch semantics remain unchanged, without certifying incident RLS or provider delivery.

Preparation compiles the actual post-authentication worker startup block, checks domain/worker registrations, and hashes those files along with all directly imported production sources. The local catalog transaction commits the product UUID, returned receipt and queue status together. Explicit revocation during an INSERT rolls it back; owner and token changes after the final fence serialize behind the actual deferred COMMIT. Natural bearer expiry does not revoke durably admitted work. Failed or ambiguous local attempts remain held; generic effect/acknowledgement behavior remains separate.
