# Terminal payment integrity contract

The Rust gate imports the complete production state protocol and Stripe integration, with exact production migration 142 and 1040. An injected recording provider is used instead of network or live Stripe. PostgreSQL persistence and transactions remain real; the runner requires an explicitly supplied disposable database and never treats missing prerequisites as passing/skipped tests.

Run: OHC_TERMINAL_TEST_DATABASE_URL=<owned disposable database> bash scripts/terminal-payment-integrity/run.sh

Coverage: missing/foreign/malformed IDs, changed amount/provider, provider-side amount mismatch before capture, duplicate create/capture, concurrent capture, unknown external outcomes, legacy unbound records, persistence failure after provider effect, closed database and omission of client secrets from receipts. The companion Node source check covers canonical handler/alias wiring. Next route and UI tests exercise transport normalization and durable browser attempt handling.

Known scope: amount-only payments. Catalog/cart captures are rejected before effects until every item and reservation has a durable transaction binding. Earlier unknown operations require reconciliation; no new automatic retry or replacement charge is implemented. This is not full POS or accounting certification.

Review regressions additionally cover: mounted token handler ignores a forged SPIFFE header in favor of verified AuthInfo (and rejects header-only calls); capturable amount must equal the saved amount; a recording loopback HTTP provider changes the amount between GET and POST, but the real Stripe transport still sends the saved amount_to_capture and mismatched completion cannot report success. The legacy ID-only capture helper fails closed. Native gate inventory: 23 tests after the persisted offline-authority correction. Browser tests also retain original recovery/receipt evidence when the tenant or cart view changes during capture.

Offline review correction: the worker now reads tenant-bound canonical `pos_offline_transactions.request_identity/request_status` or a preserved `sync_events` receipt. Queue markers alone are never authority. All four producers retain classification and original payload; missing, unknown, malformed, contradictory, foreign and legacy identities return an error so work remains pending. Explicit canonical cash and inventory receipts only acknowledge effects already committed by their producer. The removed legacy fallthrough no longer repeats inventory/orders, simulates payment failures, captures cards, or creates an unconditional ledger credit.

The focused native gate now contains 23 tests, including eight tests using exact production envelope builders and the complete production worker handler with the real queue Job/handler types. The only worker DB fixture is the pool field it accesses. Three additional PostgreSQL tests in the existing sync-durability gate exercise the actual canonical cash/tap producers and their persisted receipts. These are authored tests, not verified passes without running Rust/PostgreSQL. SQL-WASM supplements validate SQL and DDL only.

Remaining functional gaps: offline card collection/capture and legacy gRPC/SQLite offline records have no verified collection/fulfillment contract; they remain held for reconciliation. Unknown operations do not become cash by omission. `/api/v1/sync/offline` now requires explicit consistent cash_sale/inventory_sale classification for those mutations; existing explicit nonpayment/cash semantics stay distinct. Canonical terminal offline cash_sale still records its completed order and inventory exactly once. The worker only acknowledges that committed receipt. PosSyncWorker has no established production registration in the audited source, so these changes do not certify a running offline processing integration. No automatic replacement charge or replay of unproved historical side effects is enabled.
