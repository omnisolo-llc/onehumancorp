  **Title**: Integrate Twilio for WhatsApp Business API

  **Problem Statement**:
  Owners and operators in many regions (like LATAM, India, and parts of Europe/Africa) rely heavily on WhatsApp as their primary communication channel with customers for inquiries, orders, and support. Currently, OHC captures demand via web forms and email, but misses out on direct WhatsApp interactions. If Maya (home baker) or Fatima (food cart operator) gets an order on WhatsApp, they have to manually switch between their personal/business WhatsApp app and OHC, leading to lost context, missed messages, and duplicated effort. They need their work assistant to triage WhatsApp messages just like web forms and emails.

  **Research Report**:
  - **Tool Evaluated**: Twilio API for WhatsApp (Cloud)
  - **Market Context**: WhatsApp is the dominant messaging app globally. Competitors like Shopify, Wix, and various local CRM tools offer WhatsApp integration via Meta or Twilio to capture orders and provide customer support.
  - **Ease of Use**: Twilio abstracts the complexity of Meta's direct WhatsApp Business API, providing a simpler, more robust REST API and webhook system for sending and receiving messages. For the non-technical user, the setup involves connecting their Twilio/WhatsApp number once, after which OHC transparently handles message routing.
  - **Pricing**: Twilio offers a pay-as-you-go model per conversation (business-initiated vs user-initiated), which is standard and scales well for both small businesses and larger operations. It easily fits into a multi-tenant cloud model where API keys are securely managed per tenant.
  - **Why Twilio over direct Meta API**: Twilio provides built-in fallback to SMS if a user isn't on WhatsApp, unified messaging APIs, and historically better documentation and SDK support for Go/Node than direct Meta APIs, reducing maintenance overhead for OHC engineering.

  **Design Doc**:
  - **Integration Point**: The Twilio webhook endpoint will be exposed on the OHC API layer to receive incoming WhatsApp messages.
  - **Tenant Mapping**: Incoming webhooks will be mapped to the correct OHC tenant (owner workspace) based on the Twilio account SID or recipient phone number configured for that tenant.
  - **Workflow**:
    1. Customer sends a WhatsApp message to Maya's business number.
    2. Twilio fires a webhook to OHC.
    3. OHC routes the message to the correct tenant and enqueues an AI Job (Work Triage).
    4. The Work Triage agent analyzes the message, groups it with any existing customer context, and surfaces it in Maya's "today's priorities" feed in the OHC Flutter App.
    5. Maya reviews the drafted reply in OHC and taps "Send".
    6. OHC calls the Twilio API to dispatch the outbound WhatsApp message.
  - **User Experience**: The owner only sees a unified inbox and task feed. They do not see Twilio configurations or API keys after the initial setup.

  **Implementation Prompt**:
  - **Outcome**: A non-technical owner can receive incoming WhatsApp messages in their OHC feed, view drafted replies generated by the Customer Assistant, and send replies back to the customer's WhatsApp, all without leaving the OHC interface.
  - **Acceptance Criteria**:
    1. An incoming WhatsApp message via Twilio webhook successfully creates a unified task/message in the OHC feed for the correct tenant.
    2. The Customer Assistant automatically drafts a relevant reply based on the tenant's context.
    3. The owner can approve and send the drafted reply, which successfully routes back through Twilio to the customer's WhatsApp.
    4. The Twilio connection must be configurable per-tenant.

  **Priority**: P1 (High)
  **Estimated Scope**: Medium
