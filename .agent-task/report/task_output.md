  # Research Report: Autonomous Client Intake & Dynamic Quoting System

  ## Executive Summary
  This report details the architectural design for an AI-driven, autonomous Client Intake and Dynamic Quoting system for OneHumanCorp (OHC). This capability specifically targets service providers (e.g., Carlos the Handyman, Nora the Agency Principal) who lose time and revenue to manual lead triage, unstandardized quoting, and delayed client follow-ups. Existing solutions like HoneyBook or Jobber provide workflows but rely on the owner to act; OHC will leverage AI agents to actively draft quotes, coordinate intake forms, and prompt the owner for one-tap approvals.

  ## 1. Problem Statement
  Service-based and project-based owners suffer from the "intake bottleneck". When a lead reaches out via a contact form, email, or social DM, the owner must manually:
  1. Reply to gather more details (e.g., photos of the repair, project scope).
  2. Synthesize those details into a standard pricing model.
  3. Draft an estimate or proposal.
  4. Follow up if the lead goes cold.

  This manual process leads to lost leads and inaccurate quotes, especially when the owner is in the field (like Carlos) or managing a team (like Nora).

  ## 2. Research Report
  - **Market Context**: Tools like HoneyBook, Dubsado, and Jobber offer CRM and quoting, but they are passive tools. They provide templates, but the owner still does the work. Wix and Shopify have basic forms, but they don't natively tie into a quoting engine.
  - **The OHC Opportunity**: By integrating intake natively with a Service Catalog and the Sales/Operations AI Agents, OHC can read an incoming request, request missing context (like a photo), cross-reference the Service Catalog, and draft a complete quote for the owner to approve on their mobile device.
  - **Competitor Gaps**:
    - *Jobber*: Great for home services but requires manual quote creation.
    - *HoneyBook*: Excellent client portals but lacks proactive agentic drafting.
    - *Shopify/Wix*: Not built for dynamic service quoting.

  ## 3. Design Doc
  ### Architecture & Data Model (PostgreSQL)
  The core architecture involves moving from unstructured intake to structured quoting via the AI Sales Agent.

  - **`IntakeRequest`**: A multi-channel entity representing an incoming lead (via Web Form, Email, or DM). Contains unstructured text and attachments (e.g., photos).
  - **`ServiceItem`**: Standardized service definitions (e.g., "Hourly Rate - Plumbing", "Fixed Fee - Logo Design").
  - **`Quote`**: A draft or finalized estimate linking an `IntakeRequest` to `ServiceItem`s, containing dynamic variables (hours, materials).
  - **`QuoteLineItem`**: Specific line items within a `Quote`.

  ### AI Integration
  - **Sales Agent ("The Estimator")**: Monitors the `IntakeRequest` queue. When a new request arrives, it uses LLM intent parsing to match the request to the owner's `ServiceItem` catalog. It drafts a `Quote` in a "pending_approval" state.
  - **Customer Success Agent ("The Ambassador")**: If the intake is missing crucial details (e.g., "I need a leak fixed" but no photo or location), this agent automatically drafts a reply asking for the missing context.

  ### Mermaid Architecture Diagram
  ```mermaid
  sequenceDiagram
      participant Customer
      participant OHC_UnifiedInbox
      participant Agent_Ambassador
      participant Agent_Estimator
      participant Database
      participant Owner_MobileApp

      Customer->>OHC_UnifiedInbox: Submits Intake Form (Text + Photo)
      OHC_UnifiedInbox->>Database: Creates IntakeRequest
      OHC_UnifiedInbox->>Agent_Ambassador: Triggers Intake Analysis
      Agent_Ambassador->>Agent_Ambassador: Analyzes completeness
      alt Missing Information
          Agent_Ambassador->>Customer: Drafts/Sends "Can you provide X?"
      else Information Complete
          Agent_Ambassador->>Agent_Estimator: Passes context for Quoting
          Agent_Estimator->>Database: Queries Service Catalog
          Agent_Estimator->>Database: Drafts Quote (Status: Pending)
          Database->>Owner_MobileApp: Push Notification: "Quote Drafted"
      end
      Owner_MobileApp->>Owner_MobileApp: Owner reviews Quote on 375px UI
      Owner_MobileApp->>Database: Approves & Sends Quote
      Database->>Customer: Delivers final Quote via Email/SMS
  ```

  ### Mobile UX Flow (375px)
  1. **Notification**: Carlos receives a push: "New Intake: Sink Repair. Agent has drafted a $150 quote."
  2. **Intake Review (The Command Center)**: Tapping the notification opens a card showing the customer's original message, the attached photo, and a summary generated by the AI.
  3. **Quote Approval**: Below the summary is the drafted quote. Carlos sees line items: "Labor: 1 hr", "Parts: $50". He can tap any line to edit the amount.
  4. **One-Tap Send**: A prominent, thumb-friendly button at the bottom reads "Approve & Send Quote".
  5. **Empty State**: If no quotes are pending, a clean "Inbox Zero" state is shown with a translucent glass motif.

  ## 4. Implementation Prompt
  **Feature Name**: Autonomous Client Intake & Dynamic Quoting System

  **Target Persona**: Carlos the Handyman

  **Outcome**: Carlos receives an intake request on his phone. Instead of having to type out an estimate while on a ladder, he opens OHC, sees that his AI agent has already read the request, matched it to his standard rates, and drafted a quote. He taps "Approve & Send" and gets back to work.

  **Critical User Journey (CUJ)**:
  1. An API endpoint simulates an incoming `IntakeRequest` (e.g., "Need my kitchen faucet replaced, here is a pic").
  2. The backend Sales Agent processes this, matches it to a "Plumbing Hourly" service, and creates a Draft `Quote` in the database.
  3. Carlos logs into the mobile view (375px).
  4. He navigates to the "Quotes" tab (which must use premium Translucent Glass styling).
  5. He opens the pending quote, verifies the AI-generated line items, and taps "Approve".
  6. The `Quote` state changes to "Sent".

  **Next Actions for Engineering**:
  1. Create the `IntakeRequest`, `Quote`, and `QuoteLineItem` schemas with strict multi-tenant isolation.
  2. Implement the Sales Agent logic to convert an `IntakeRequest` into a Draft `Quote` using the LLM provider.
  3. Build the mobile-first (375px) UI for reviewing and approving quotes, ensuring all touch targets are at least 44x44px.
  4. Add an E2E Playwright test covering the full flow from Intake creation to Quote approval in the UI.
