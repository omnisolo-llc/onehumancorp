  # Research Report: OHC Centralized Agent Feed Architecture

  ## Problem Statement
  Small business owners often lack a centralized view of all actionable items generated by their business and the various AI agents operating on their behalf. Items like new orders to fulfill, customer messages requiring a response (across multiple channels like Instagram, SMS, and WhatsApp), and promotional draft approvals are scattered. A non-technical user (e.g., Maya the baker) needs a unified, mobile-friendly feed that aggregates these tasks, prioritizes them, and provides 1-tap resolution options without having to navigate a complex dashboard.

  ## Research Report
  **Findings & Competitive Analysis:**
  - **Traditional Platforms (Shopify, Wix):** Typically silo information into separate dashboards (e.g., Orders, Messages, Marketing). They require the user to hunt for tasks, leading to missed opportunities and operational inefficiency.
  - **Current OHC Implementation:** We have an `AgentFeedItem` concept in the backend (`agent_feed_repo.rs`, `agent_feed.rs`) and a `UnifiedAgentFeed` React component on the frontend. However, the system needs to be robustly designed to handle high volumes of events from various sources (webhooks, internal state changes) and present them reliably in a mobile-first (375px) UI.
  - **The Gap:** The current implementation needs to clearly differentiate between "Actionable Proposals" (items requiring user approval) and an "Activity Log" (items already processed or informational). Furthermore, the intent resolution and generation pipeline (the LLM layer) must seamlessly integrate with this feed.

  ## Design Doc
  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Event Sources: Webhooks, Internal DB] -->|Publish| B(Redis Message Bus / KAIROS)
      B --> C[Agent Workers]
      C -->|Draft Action| D[Agent Feed Repo DB]
      D --> E[Unified Agent Feed API]
      E -->|Fetch Pending| F[Mobile Frontend - 375px]
      F -->|1-Tap Approve| G[Action Execution Engine]
      G -->|Update State| D
  ```

  ### Mobile UX Flow (375px First)
  1. **Home Screen:** User opens the OHC app and sees the `UnifiedAgentFeed` as the primary view.
  2. **Tabs:** The feed is divided into "Proposals" (action needed) and "Activity" (log).
  3. **Cards:** Each proposal is a card with clear, concise text (e.g., "Drafted reply for new Instagram DM").
  4. **Actions:** The card features primary actions like "Approve & Send" or "Edit" with minimum 44x44px touch targets.
  5. **Feedback:** Upon approval, the card gracefully transitions out (or updates its state to 'APPROVED') and moves to the Activity tab.

  ### AI Agent Integration
  - **The Ambassador (Customer Success):** Drafts replies to unified inbox messages (WhatsApp, IG) and places them in the feed as 'Pending Approval'.
  - **The Manager (Operations):** Flags low inventory and proposes restock orders via the feed.
  - **The Promoter (Marketing):** Generates social media posts or email campaigns based on business milestones and requests approval via the feed.

  ## Implementation Prompt
  **Objective:** Enhance the `UnifiedAgentFeed` mobile UX and its underlying API to robustly handle diverse agent proposals (e.g., Omnichannel Inbox replies, Restock alerts) and ensure strict adherence to the 375px mobile constraint and 44x44px touch targets.

  **Critical User Journey (CUJ):**
  1. An external event (e.g., a WhatsApp message) is received and processed by an agent, creating a pending `AgentFeedItem`.
  2. The owner opens the OHC mobile app (375px viewport).
  3. The `UnifiedAgentFeed` displays the pending item as an action card under the "Proposals" tab.
  4. The owner taps the 1-Tap "Approve" button (ensuring the touch target is ≥44x44px).
  5. The UI updates optimistically, and the backend processes the approval, moving the item's state to 'APPROVED'.

  **Acceptance Criteria:**
  - Verify layout constraints: Ensure no horizontal scrolling on a 375px viewport.
  - Touch targets for all interactive elements in the feed must be at least 44x44px.
  - Implement full E2E Playwright tests covering this CUJ, specifically asserting the layout constraints and the state transition from pending to approved.
  - Do not prescribe specific database schema modifications; assume `agent_feed_items` table is sufficient but focus on the API and UI reliability.
