  # Mission Queue Protocol Brief: Unified Agent Feed & Triage System

  ## Problem Statement
  Small business owners and operators (e.g., Maya, Carlos) struggle to manage their daily operations efficiently because legacy platforms rely on complex, multi-page desktop dashboards. Key workflows like handling new inquiries, reviewing drafts, and updating stock require deep navigation on a small phone screen. This creates "Setup Paralysis" and "Mobile Limitations." OHC needs a centralized, actionable command center—a Unified Agent Feed—that presents prioritized tasks as simple cards that can be resolved with a single tap, completely replacing the traditional hamburger menu/dashboard paradigm on mobile.

  ## Research Report
  Based on competitive analysis of Shopify Sidekick, Wix Studio, and AI-native tools like Durable and Lindy:
  - **Legacy platforms (Shopify/Wix)** relegate mobile apps to simple "viewers" for metrics or require opening a web browser to configure complex workflows.
  - **Link-in-bio tools** succeed because of their extreme simplicity for mobile creators but lack robust backend capabilities.
  - **The OHC Differentiator:** By turning operations into an "Approval Interface," complex tasks (like setting up a discount, replying to inquiries) are surfaced as pre-configured cards generated by specialized AI agents. The user simply reads the summary and taps "Approve."

  ## Design Doc
  ### Architecture Diagram
  ```mermaid
  graph TD
      MobileApp[OHC Flutter Mobile App]
      Feed[Unified Agent Feed UI]
      Backend[Go + PostgreSQL Backend]
      AI_Queue[AI Job Queue]
      Agent_CS[Customer Service Agent]
      Agent_Ops[Operations Agent]
      Agent_Sales[Sales Agent]

      MobileApp --> Feed
      Feed --> Backend
      Backend --> AI_Queue
      AI_Queue --> Agent_CS
      AI_Queue --> Agent_Ops
      AI_Queue --> Agent_Sales

      Agent_CS -- Generates Draft Reply Card --> Backend
      Agent_Ops -- Generates Restock Card --> Backend
      Agent_Sales -- Generates Promo Card --> Backend

      Backend -- Pushes Prioritized Cards --> Feed
  ```

  ### Mobile UX Flow (375px First)
  1. **Home Screen / Feed View:** The user launches the app. The primary screen is a vertical feed of task cards with no horizontal scrolling.
  2. **Card Structure:**
     - **Header:** Agent Identity (e.g., "Operations Assistant") & Priority Badge.
     - **Body:** Concise summary of the event (e.g., "Maya, you have 3 unread Instagram DMs asking about vegan cake availability.").
     - **Action Area:** Primary "Approve & Send Drafts" (minimum 44x44px target) and secondary "Review/Edit".
  3. **Interaction:** Tapping "Approve" triggers the backend to execute the pre-computed state change. The card smoothly transitions to a "Done" state and disappears or collapses.

  ### AI Agent Integration Points
  - **Agent Notification Publisher:** AI agents must hook into the backend API to publish structured `AgentTaskCard` proposals instead of just logging state.
  - **Distributed Locks:** Redis Redlock (`ohc:lock:{tenant_id}:feed:{card_id}`) is used to prevent duplicate feed executions if the owner taps multiple times quickly on flaky mobile connections.

  ## Implementation Prompt
  **Objective:** Build the Mobile-First Unified Agent Feed UI and backend integration.
  **CUJ (Critical User Journey):**
  1. Log in to the application as a tenant owner on a 375px viewport.
  2. Navigate to the default home screen, which must now render the `UnifiedAgentFeed` instead of a static analytics dashboard.
  3. Verify the feed displays at least 2 mock or real agent-generated task cards.
  4. Click the primary "Approve" action on the top card.
  5. Verify the card processes the action with a clear visual loading state and is removed from the feed upon success.
  **Acceptance Criteria:**
  - The UI must be implemented in Flutter (or the canonical desktop UI `src/ui/tauri/` taking into account mobile layout) targeting a strict 375px minimum width.
  - No horizontal scrolling is permitted on the feed.
  - Touch targets for all interactive buttons must be >= 44x44px.
  - The backend must expose a new endpoint or gRPC service to fetch and mutate the state of agent feed cards.
  - The design must use OHC Premium Tokens (translucent materials, clear spacing).
