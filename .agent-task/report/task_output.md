issue_title: "Implement The Ambassador Agent Instagram DM Outbound Dispatch"
issue_description: |
  # Research Report & Design Doc: The Ambassador Agent (Instagram DM Outbound)

  ## Target Persona
  **Maya (Home Baker)**: Solopreneurs like Maya miss critical sales because they cannot continuously monitor social media DMs (like Instagram) while running their physical operations (baking, delivering). Existing solutions require complex logic builders (e.g., ManyChat) which are too technical.

  ## Problem Statement & Identified Gap
  The OHC platform currently provides a foundation for the Ambassador Agent: it ingests Meta webhooks (`meta_webhook.rs`), triggers an event (`tenant.omnichannel.message.received`), processes it via `CustomerSuccessAgent` (intent parsing, RAG for context), drafts a reply, and surfaces it to the Mobile Agent Feed.

  **The Gap:** When the user (Maya) taps "Approve & Send" on the drafted reply, the system correctly updates the `agent_feed_items` state. However, the subsequent outbound dispatch in `handle_inbox_action` (`src/server/domain/inbox.rs`) only implements delivery for `whatsapp` (via `IntegrationsRegistry::send_whatsapp`) and `sms` (via Twilio). It **entirely ignores** messages where `source == "instagram"` or `"facebook"`.
  Furthermore, the `RealMetaClient` (`src/server/integrations/meta/client.rs`) lacks the correct implementation for sending outbound Instagram Graph API messages.

  ## Architecture Design

  ### 1. Data Model & Sync Protocol
  - The `inbox_messages` and `omni_inbox_messages` schemas remain the source of truth for the message thread.
  - No database schema changes are strictly necessary; the system simply needs to invoke the correct external API via the existing `IntegrationsRegistry` when `handle_inbox_action` processes an Instagram reply.

  ### 2. AI Agent Integration Points
  - The LLM intent and RAG generation logic inside `CustomerSuccessAgent` are already functioning correctly to produce the draft reply.
  - The crucial point is the final mile: seamlessly dispatching the drafted and approved response.

  ### 3. Mobile-First UX
  - The UX remains exactly as designed in the `UnifiedAgentFeed`. The action card displays the incoming DM context, the drafted reply, and the 1-tap "Approve & Send" button optimized for a 375px viewport (minimum 44x44px touch targets).

  ### 4. Implementation Details & Dispatch Logic
  - `src/server/domain/inbox.rs`: Expand `handle_inbox_action` to support `source == "instagram"`. It should retrieve the Meta integration credentials (access token) and invoke the `IntegrationsRegistry`'s `send_message` function with `platform = "instagram"`.
  - `src/server/integrations/meta/client.rs`: Update `RealMetaClient::send_message` to correctly format requests for the Instagram Graph API (e.g., proper recipient object schema `{ "recipient": { "id": "<igsid>" }, "message": { "text": "..." } }`).

  ## Implementation Prompt (For Engineering Swarm)
  **Feature Name:** The Ambassador - Instagram DM Outbound Dispatch

  **Target Persona:** Maya the Baker

  **Outcome:** An end-to-end automated DM response system where the drafted reply generated by The Ambassador Agent for an incoming Instagram DM is successfully dispatched back to the Instagram user when Maya clicks "Approve & Send".

  **Critical User Journey (CUJ):**
  1. A customer DMs Maya on Instagram.
  2. The webhook ingests the message, and The Ambassador agent drafts a reply.
  3. The drafted reply appears in the OHC mobile web app (375px view) Agent Feed.
  4. Maya taps the "Approve & Send" button.
  5. The backend (`handle_inbox_action`) successfully identifies the message source as `instagram` and uses the `IntegrationsRegistry` and `RealMetaClient` to send the response via the Instagram Graph API.

  **Next Actions for Engineering:**
  - Update `src/server/domain/inbox.rs` (`handle_inbox_action`) to dispatch responses via the `IntegrationsRegistry` when the message source is `instagram`.
  - Update `src/server/integrations/meta/client.rs` to correctly structure the API request for outbound Instagram messages.
  - Add Playwright E2E tests verifying the end-to-end flow, using local webhook mocks to simulate the Instagram API response. No direct changes to the database schemas are needed.

  **Priority:** P0
  **Estimated Scope:** Medium
