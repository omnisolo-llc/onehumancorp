  # Research Report: Work Triage & Assistant-First Mobile Shell

  ## 1. Problem Statement
  Small business owners like Maya (Baker), Carlos (Handyman), and Fatima (Food Cart) suffer from "dashboard fatigue." Traditional SMB platforms like Shopify or Square drop users into a complex dashboard of graphs and menus. When these users open their app, they don't want to dig through menus to find out what needs doing—they want an assistant to tell them: "Here is what needs your attention today, and here is the drafted action."

  ## 2. Research & Market Gap
  - **Competitors (Shopify, Wix, Square):** Rely on static dashboards, separate inboxes, and manual navigation. Shopify's "Sidekick" is an advisory chatbot, not an integrated triage feed.
  - **The OHC Vision:** "Open OHC and immediately know what needs attention today." The home screen should not be a chart; it should be a prioritized, actionable feed of work generated by the AI agent swarm.
  - **The Gap:** We need a foundational "Assistant-First Shell" that aggregates tasks, messages, approvals, and anomalies into a single, mobile-first feed, bridging the gap between passive tools and an active AI Work Assistant.

  ## 3. Design Doc: Assistant-First Shell Architecture

  ### 3.1 Architecture Diagram

  ### 3.2 Mobile UX Flow (375px Baseline)
  - **The "Good Morning" View:** The user opens the app to a clean, UniFi-style translucent glass interface. At the top: "Good morning, Maya. You have 3 items needing attention."
  - **The Triage Feed:** Below the greeting is a vertical list of cards. Each card represents a unit of work:
    - *Card 1:* "Instagram DM from Sarah: 'Do you do vegan cakes?'" (Includes a button: "Review AI Drafted Reply").
    - *Card 2:* "Pending Delivery: 3 cakes need delivery by 2 PM." (Includes button: "View Route Map").
    - *Card 3:* "Anomaly: Vegan cake requests are up 20% this week." (Includes button: "Generate Vegan Menu Option").
  - **Action-Oriented:** Users don't navigate away. They tap "Review Reply," a bottom sheet slides up with the drafted text, they tap "Approve," and the card dismisses itself. The feed gets smaller until the day's triage is done.

  ### 3.3 Core Technical Decisions
  - **Unified Feed Data Model:** A centralized `triage_items` table (or similar NoSQL construct) that standardizes disparate events (messages, orders, alerts) into a common format (`title`, `description`, `agent_source`, `action_type`, `status`).
  - **Push vs Pull:** Agents proactively push prioritized items to the Triage Engine, rather than the client polling multiple disparate services.
  - **Zero Mock Data:** The UI must be driven entirely by the backend API. Empty states should reflect a true zero-inbox state, not placeholder graphics.

  ## 4. Implementation Prompt
  **For Implementer Agent:**
  Build the foundational "Assistant-First Shell" and "Work Triage Feed" for the frontend and its supporting backend API.

  - **User-Facing Outcome:** The home screen of the application must be a prioritized list of actionable items generated by various agents, not a standard navigation menu or chart dashboard.
  - **CUJ:** Maya opens the app and sees three cards in her feed: an unread message, a pending order, and an AI-drafted quote. She clicks "Approve" on the drafted quote card. The backend executes the approval, and the card is removed from her feed.
  - **Acceptance Criteria:**
    - Create a backend service/endpoint (e.g., `GET /api/v1/triage/feed`) that aggregates and returns prioritized work items.
    - Build the Flutter/Next.js (depending on current stack target) mobile-first UI (375px width strictly enforced) rendering this feed using the Glassmorphism design system.
    - Implement interactive elements (e.g., an "Approve" or "Dismiss" button on a feed card) that hit a corresponding mutation endpoint, updating the database and immediately reflecting the change in the UI without a full page reload.
    - Ensure zero mock data is present in the final UI code; all cards must come from the live backend stack.
    - Add comprehensive E2E tests verifying the feed loads, an item can be interacted with, and the item state changes.
