  **Mission Queue Protocol Brief:**

  **Title**: Invisible Payment Collections via Stripe Integration

  **Problem Statement**:
  Small business owners and solopreneurs (like independent service providers, handypersons, and consultants) lose countless hours chasing unpaid invoices, manually creating payment links, and reconciling bank transfers. They need to get paid quickly and reliably, but setting up merchant accounts and embedding checkout flows is often too technical and time-consuming. They need a system that can automatically generate payment requests, follow up on unpaid balances, and reconcile payments back into their operations without manual intervention.

  **Research Report**:
  - **Tool Evaluated**: Stripe
  - **Target Persona**: The Solo Service Provider (Nora).
  - **Ease of Use for Non-Technical Users**: Stripe offers a robust API and pre-built checkout pages (Stripe Checkout) and payment links (Stripe Payment Links). While setting up a Stripe account directly requires some business information, integrating it into a platform like OmniSolo allows the platform to handle the heavy lifting (e.g., via Stripe Connect) or simply use the owner's standard Stripe API keys to generate links autonomously.
  - **Pricing**: Standard pricing is typically 2.9% + 30¢ per successful card charge, which is standard for the industry. There are no setup fees or monthly fees for standard usage, making it very accessible for small businesses.
  - **Capabilities**: Stripe supports a massive array of payment methods globally, recurring billing, invoicing, and in-person payments (Terminal). Their webhooks are reliable and well-documented.
  - **Market Context**: Stripe is a market leader and widely requested by business owners who want reliable, fast payouts. Competing tools (like Square or PayPal) are also popular, but Stripe's API is often considered superior for platform integrations.

  **Design Doc**:
  - **Integration Model**: OHC should integrate with Stripe to allow the business owner to connect their existing Stripe account (or create one). This could be managed via OAuth (Stripe Connect Standard) or by allowing the user to securely input their API keys.
  - **Triggers & Actions**:
    - *Trigger*: A booking is confirmed, an invoice is generated by the Salesperson Agent, or a service is completed.
    - *Action*: The system autonomously calls the Stripe API to generate a Payment Link or Checkout Session URL.
    - *Action*: The system embeds this link in a communication (email/SMS) to the customer.
    - *Trigger*: Customer pays via the Stripe link. Stripe sends a `checkout.session.completed` webhook to OHC.
    - *Action*: OHC receives the webhook, marks the internal invoice as paid, and optionally triggers a "Thank You" message or next step in the workflow (e.g., scheduling fulfillment).
  - **User Visibility**: The owner sees a connected "Stripe" indicator on their dashboard. Invoices and quotes automatically include payment links. They see payments land in their dashboard without having to log into Stripe daily.

  **Implementation Prompt**:
  - Implement a secure connection method for Stripe in the integrations settings.
  - Create the backend logic to generate Stripe Payment Links when a quote or invoice is finalized.
  - Implement a webhook listener to receive Stripe payment confirmations and update the corresponding internal record's status to 'paid'.
  - Ensure the UI reflects the payment status in real-time or upon refresh.
  - *Acceptance Criteria*: A non-technical owner can connect Stripe, generate a quote that automatically includes a working payment link, and see the quote marked as paid when the customer completes the transaction in a test environment.

  **Priority**: P1 (High - Getting paid is critical to business operations).
  **Estimated Scope**: Medium.
