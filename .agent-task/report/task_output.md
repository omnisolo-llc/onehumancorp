# Scout: Tool Integration Research Report

## Executive Summary
This comprehensive report evaluates seven critical tool categories requested by OHC's small business community. The focus is to deeply analyze usability, pricing, data privacy, and implementation complexity across both Cloud (multi-tenant) and Standalone environments. The goal is to provide actionable research that empowers implementers to build robust, user-friendly integrations.

## Category: Unified Inbox for Social Media

### Problem Statement
Small business owners miss customer inquiries because they are scattered across Instagram, Facebook, WhatsApp, and TikTok.

### Research Report
Meta (IG/FB/WA) has strong APIs but complex OAuth. TikTok is emerging but APIs are less stable for DMs. Competitors like Hootsuite are too pricey. Standalone mode is hard due to API key management; Cloud mode is ideal.

### Design Recommendation
OAuth connection flow in settings. Unified inbox UI pulling from webhooks. Replies routed back through respective APIs.

### Implementation Prompt
Build a unified inbox view where users can connect social accounts and reply to messages from one screen.

### Deep Dive Analysis

**Platform Specifics**: Meta's Graph API is complex, requiring business verification. TikTok's API is newer and subject to frequent changes.

**Pricing Model**: Most unified inbox platforms charge per user or per connected channel. We should aim for a flat tier.

**Cloud vs Standalone**: OAuth flows in Cloud mode are straightforward. Standalone mode requires users to create Meta Developer apps, which is a non-starter for most.

**Security**: Handling DMs requires high-trust scopes. GDPR compliance is critical, as we are processing PII.

**Rate Limits**: Meta imposes strict rate limits. Our architecture needs aggressive caching and webhook processing queues to prevent dropping messages.

## Category: Automated Booking and Calendar Sync

### Problem Statement
Manual back-and-forth scheduling wastes time and leads to double bookings.

### Research Report
Google Calendar and Outlook APIs are standard. Tools like Calendly dominate but charge per user. Integrating direct calendar sync allows custom booking pages without extra subscriptions. Works well in both Cloud and Standalone (with custom API keys).

### Design Recommendation
Connect Google/Outlook account. Set availability rules. Shareable booking link that auto-creates calendar events.

### Implementation Prompt
Create a booking page feature that syncs with Google Calendar to prevent double booking and allows clients to self-schedule.

### Deep Dive Analysis

**Platform Specifics**: Google Calendar API is robust. Microsoft Graph API handles Outlook/Exchange but is notorious for complex auth.

**Pricing Model**: Calendly charges ~$10/user/month. By integrating directly with Google/Outlook APIs, OHC can offer this free, a major selling point.

**Cloud vs Standalone**: OAuth in Cloud is easy. Standalone is possible if users are willing to paste an API key, but it's friction.

**Security**: Calendar data often contains sensitive meeting details. We need strict tenant isolation.

**Rate Limits**: Google Calendar limits API calls per project. We must batch requests where possible.

## Category: Integrated Email Campaigns

### Problem Statement
Exporting customer lists to Mailchimp is tedious and disconnects sales data from marketing efforts.

### Research Report
Mailgun/Sendgrid are good for transactional, but we need campaign management. Integrating a simplified email builder directly linked to the customer CRM saves time. Must handle unsubscribe links and CAN-SPAM compliance. Cloud is better for sender reputation.

### Design Recommendation
Email template builder in UI. Select customer segments from CRM. Send via backend email provider integration.

### Implementation Prompt
Develop a simple email campaign sender that uses the existing customer list and tracks open rates.

### Deep Dive Analysis

**Platform Specifics**: Mailchimp has the brand recognition, but SendGrid or Mailgun offer better developer APIs for building native experiences.

**Pricing Model**: Email marketing is almost exclusively volume-based (per 1k emails). We need to pass this cost transparently to the user.

**Cloud vs Standalone**: Cloud mode allows OHC to manage sender reputation across IPs. Standalone mode puts the burden of domain authentication (SPF/DKIM) entirely on the small business owner, which is risky.

**Compliance**: CAN-SPAM, GDPR, and strict unsubscribe handling are non-negotiable. The integration must automatically handle bounces and spam complaints.

**Deliverability**: Managing deliverability is an ongoing challenge. We should partner with a strong transactional email provider.

## Category: Alternative Global Payment Gateways

### Problem Statement
Stripe isn't supported everywhere, or fees are too high for local transactions (e.g., LATAM, India).

### Research Report
Mercado Pago (LATAM), Paytm (India), and Alipay (China) are critical for global adoption. They offer lower local fees and preferred payment methods. APIs vary wildly. Standalone is viable if users plug in their own credentials.

### Design Recommendation
Pluggable payment gateway architecture. User selects region/provider and enters credentials. Checkout UI adapts to provider.

### Implementation Prompt
Implement support for Mercado Pago and Paytm alongside Stripe for checkout.

### Deep Dive Analysis

**Platform Specifics**: Stripe is excellent but lacks deep penetration in LATAM (Mercado Pago) and India (Paytm). We need an abstract payment gateway interface.

**Pricing Model**: Transaction fees (e.g., 2.9% + 30¢). Integrating alternative gateways can lower local processing fees for our users.

**Cloud vs Standalone**: Payment gateways are inherently standalone friendly, as the user typically connects their own account credentials directly.

**Security**: PCI-DSS compliance. We must ensure OHC never touches raw credit card data, relying instead on tokens or hosted checkout pages.

**Refunds and Disputes**: The integration must handle the full lifecycle, including webhooks for chargebacks and asynchronous settlement.

## Category: Real-time Shipping Labels and Rates

### Problem Statement
Calculating shipping costs manually and copying addresses to carrier sites leads to errors and lost money.

### Research Report
EasyPost or Shippo APIs aggregate carriers (USPS, UPS, FedEx, DHL). Essential for physical product sellers. Need to handle package dimensions and weights. Cloud mode simplifies API key management.

### Design Recommendation
Order fulfillment screen. Input package weight/dims. Fetch rates via EasyPost. Generate and print label. Auto-update tracking.

### Implementation Prompt
Add a feature to fetch shipping rates and generate printable labels for orders.

### Deep Dive Analysis

**Platform Specifics**: EasyPost and Shippo abstract away individual carriers (USPS, FedEx, DHL). This is far superior to integrating carriers one-by-one.

**Pricing Model**: Typically a few cents per label. EasyPost offers a strong free tier (120k shipments/year) which is perfect for OHC's target market.

**Cloud vs Standalone**: Cloud mode allows centralized billing. Standalone requires users to create their own Shippo/EasyPost accounts, which is acceptable friction for physical product sellers.

**Complexity**: Shipping requires accurate weights, dimensions, and customs declarations for international orders. The UI must validate these inputs before API submission.

**Tracking**: Webhooks for real-time tracking updates (pre-transit, out for delivery, delivered) are essential for triggering customer notifications.

## Category: Global SMS Notifications

### Problem Statement
Customers don't always check email. SMS is needed for urgent updates (appointments, shipping).

### Research Report
Twilio is standard but expensive globally. MessageBird or Vonage might be better. Must handle opt-outs strictly. Very useful for low-tech customer bases.

### Design Recommendation
SMS provider integration. Trigger rules (e.g., 'Order Shipped'). Twilio API for sending.

### Implementation Prompt
Integrate Twilio to allow sending automated order and appointment reminders via SMS.

### Deep Dive Analysis

**Platform Specifics**: Twilio is the industry standard but is increasingly expensive globally. MessageBird or Vonage offer competitive international rates.

**Pricing Model**: Pay-per-message. Costs vary wildly by destination country. We need to implement spending limits to prevent unexpected bills for business owners.

**Cloud vs Standalone**: In Cloud mode, OHC acts as the sender. This requires A2P 10DLC registration in the US, which is complex. Standalone mode forces the user to register their own Twilio number.

**Compliance**: TCPA in the US requires explicit opt-in for marketing SMS. We must differentiate between transactional (order updates) and promotional messages.

**Deliverability**: SMS filtering by carriers is aggressive. We need to monitor delivery rates and handle 'undelivered' webhooks gracefully.

## Category: Auto-Generated Video Conference Links

### Problem Statement
Manually creating Zoom links for online consultations is tedious.

### Research Report
Zoom and Google Meet APIs allow programmatic link generation. Essential for service businesses (tutors, consultants). Can be tied to the Calendar integration.

### Design Recommendation
When a 'virtual' appointment is booked, hit Zoom API to create meeting. Store join link in appointment details and email to client.

### Implementation Prompt
Automatically generate and attach a Zoom or Google Meet link to appointments marked as 'virtual'.

### Deep Dive Analysis

**Platform Specifics**: Zoom and Google Meet APIs. Zoom requires OAuth for user-level app creation.

**Pricing Model**: Zoom API usage is generally free for the developer, but the user needs a paid Zoom account for meetings >40 mins.

**Cloud vs Standalone**: OAuth flows work well in Cloud. For Standalone, Google Meet is easier if tied to the Calendar integration.

**Security**: Meeting links must be securely stored and only shared with the booked client to prevent 'Zoombombing'.

**Integration Synergy**: This feature is highly dependent on the Calendar integration. A standalone video generation feature has limited value without the scheduling context.
