  **Title**: Implement OHC Unified Agent Feed

  **Problem Statement**:
  Business owners like Maya (baker) or Carlos (handyman) are overwhelmed by notifications from different channels (Instagram DMs, SMS, booking forms, payment confirmations). Traditional dashboards require them to hunt for information and decide what to do next. There is a critical gap: they need a single, unified daily work feed that not only aggregates incoming demand and tasks, but also presents proactive, AI-drafted actions (e.g., "Drafted reply to Maya about vegan cakes", "Approve quote for Carlos") that they can approve with one tap on a 375px mobile screen.

  **Research Report**:
  - **Competitor Analysis**:
    - **Shopify Sidekick**: Excellent for commerce data, but focused on chat-based interactions rather than an actionable queue of drafted tasks.
    - **HubSpot Breeze**: Integrates well with CRM data, but feels like an enterprise software suite rather than a lightweight mobile work assistant.
    - **GoDaddy Airo**: Focused heavily on initial setup rather than day-to-day triage.
    - **Wix Studio AI**: Heavily website-creation-centric.
  - **The Gap**: None of these tools provide an "Invisible AI Automation" feed that acts as a prioritized inbox of *actions* (not just messages). The OHC Agent Feed must unify messages, tasks, bookings, and payments, presenting "Action Cards" that reduce the owner's cognitive load.

  **Design Doc**:

  **Architecture Diagram (Mermaid.js)**:
  ```mermaid
  graph TD
      A[Event Sources: Webhooks, DB, Stripe] --> B[Event Ingestion Pipeline]
      B --> C[AI Job Queue / Redis PubSub]
      C --> D[Intent & Context Resolution Layer]
      D --> E[RAG & Memory]
      D --> F[Draft Generation]
      F --> G[Action Card Database]
      G --> H[Mobile Frontend Feed]
      H --> I{User Action}
      I -->|Approve| J[Execute Action]
      I -->|Edit| K[Open Editor]
      I -->|Discard| L[Archive]
  ```

  **UI Wireframes & Mobile UX Flow (375px first)**:
  - **Home Screen (The Feed)**: A vertically scrolling list of "Action Cards". No horizontal scrolling.
  - **Action Card Structure**:
    - *Context header*: "Instagram DM • 5m ago"
    - *Summary*: "Customer asked about vegan cakes."
    - *AI Draft*: "Yes, we have vegan cakes! Here is a booking link."
    - *Action Row*: Large tap targets (44x44px minimum) for [Approve], [Edit], [Dismiss].
  - **Interaction Flow**: Tapping [Approve] changes the card state to "Sent/Done" with a fluid, translucent glass animation, then the card collapses, bringing the next priority item into view. Tapping [Edit] opens a native keyboard-friendly text area.

  **AI Agent Integration Points**:
  - The Event Ingestion Pipeline triggers the `Work Triage` agent to classify importance.
  - The `Customer Assistant` agent drafts the response using context from the `Knowledge & Compliance` agent.
  - State is synchronized with the Agent Feed backend to surface the card to the user.

  **Key Design Decisions**:
  - **Action-Oriented Cards**: Instead of showing messages that require reading and deciding, we show drafted actions that require only approval.
  - **Translucent Glass Material UI**: Aligns with the OHC Premium Token library, providing clear visual hierarchy while keeping the interface feeling lightweight and modern.
  - **Optimistic UI Updates**: Network actions when approving a card must feel instantaneous, with background retries if the user's connection drops (crucial for users like Fatima with slow data).

  **Implementation Prompt**:
  You are implementing the Unified Agent Feed for OneHumanCorp. Your goal is to build the end-to-end critical user journey (CUJ) where a user logs in and sees a unified list of actionable items generated by the system, and can approve or dismiss them.
  1. Build the backend foundation to store and serve "Action Cards" to a mobile-first frontend.
  2. Implement the UI using the established Premium Token library (translucent materials, clean spacing). Ensure it fits perfectly on a 375px screen with touch targets >= 44x44px.
  3. Wire the frontend [Approve] and [Dismiss] buttons to optimistic UI updates and robust backend handlers.
  4. Ensure 100% unit test coverage and write Playwright E2E tests verifying the feed interaction, including empty states and error handling. Do not use mocked data in the final UI components.
