  # [architecture] Autonomous Voice AI Receptionist Mesh

  ## Title
  Autonomous Voice AI Receptionist Mesh

  ## Problem Statement
  Small business owners like Carlos (the handyman) and Fatima (the food cart operator) frequently miss phone calls because their hands are full, they are driving, or they are actively serving customers. A missed call is often a lost lead, as customers will simply call the next business on Google Maps. Current solutions like basic voicemail are passive and don't convert leads; virtual human receptionists are too expensive; and legacy IVR systems ("press 1 for hours") frustrate customers. They need an intelligent, multi-lingual, voice-native AI agent that can answer the phone instantly, hold natural conversations, answer questions, take orders or bookings, and triage urgent issues without any manual intervention.

  ## Research Report
  *   **Shopify / Wix / Squarespace:** None of these platforms offer native voice AI receptionists. They rely exclusively on web-based forms, chatbots, or third-party app integrations (like connecting a Twilio IVR, which requires developer knowledge).
  *   **Standalone AI Receptionists (e.g., Bland AI, Synthflow):** While powerful, these require integrating distinct knowledge bases, calendars, and CRM systems, which breaks the OHC "Radical Simplicity" rule. They are not deeply aware of the merchant's unified catalog, inventory, or daily context out-of-the-box.
  *   **OHC Differentiation - "Deep Contextual Voice":** The OHC Voice Receptionist is a native node on the Hybrid Event Mesh. It isn't just reading a script; it dynamically queries the Operations Agent for real-time inventory (e.g., "Yes, we still have 5 vegan cakes left") and the Sales Agent for bookings (e.g., "Carlos is free at 3 PM tomorrow. Should I lock that in?"). It seamlessly hands off the conversation to the Unified Thread when complete.

  ### UI Wireframes & 375px Baseline
  **Core Layout: macOS-style Translucent Glass + Ubiquiti UniFi Modular Dashboard Cards**
  *   **Global Viewport:** 375px width (Mobile First).
  *   **Settings Screen:**
      *   A simple toggle: `[AI Receptionist: Active]`
      *   **Voice Selection:** A horizontal scrolling card set with play buttons to preview voices (e.g., "Friendly Female," "Professional Male").
      *   **Language Priority:** Dropdown for primary/secondary languages (e.g., English / Spanish).
  *   **Unified Thread View (Post-Call):**
      *   Instead of a text message, the thread shows an audio waveform card.
      *   Below the waveform, a summarized, actionable card generated by the AI:
          *   **Summary:** "Customer asked for a quote to fix a leaking pipe."
          *   **Action Drafted:** "Drafted quote for $150 based on standard rate."
          *   **Buttons:** `[Approve & Text Quote]` or `[Call Back]`

  ### Mobile UX Flow
  1. **The Call:** A customer calls Carlos's OHC-provisioned business number while he is under a sink.
  2. **The Intercept:** The Voice Agent answers: "Hi, this is Carlos's Handyman Service. I'm his AI assistant. How can I help?"
  3. **The Interaction:** Customer asks about a leak. Agent gathers details, checks Carlos's calendar, and books a tentative slot.
  4. **The Notification:** Carlos receives a push notification: "📞 AI Handled Call: New tentative booking for tomorrow at 2 PM. Leak repair."
  5. **The Handoff:** Carlos reviews the transcript/summary in his Unified Inbox and taps one button to confirm the appointment.

  ### AI Agent Integration Points
  *   **Real-time Streaming STT/TTS:** Fast speech-to-text and text-to-speech models running at the edge for low latency (< 500ms conversational turn).
  *   **Ambassador Agent (Voice Mode):** The LLM driving the conversation, provided with a strict system prompt containing the business's current state (inventory, pricing, calendar).
  *   **Cross-Department Handoff:** The Voice Agent triggers standard NATS events to the Sales or Operations departments to lock inventory or generate quotes based on spoken requests.

  ### Key Design Decisions (Why, not How)
  *   **Native Edge Integration:** Voice latency is critical. The SIP termination and AI inference must be geographically close. We avoid chaining multiple third-party API calls (e.g., Twilio -> OpenAI -> Custom Backend) to minimize the "awkward pause" in conversation.
  *   **Summary over Transcript:** Small business owners don't have time to read a 5-minute transcript. The UI must prioritize the AI-generated *actionable summary* while keeping the audio/transcript available for auditing.
  *   **Multi-tenant Isolation:** Strict SPIFFE identity checks at the SIP gateway ensure calls are routed to the correct tenant's isolated agent context.

  ## Implementation Prompt
  **To the Implementer Swarm:**
  Your objective is to build the core architecture for the Autonomous Voice AI Receptionist Mesh. This system must handle inbound SIP calls, stream the audio to a low-latency LLM agent configured with the merchant's business context, and log the interaction into the Unified Inbox.

  **Customer User Journey (CUJ):**
  1. The merchant toggles "AI Receptionist" on in the app.
  2. A customer dials the merchant's phone number.
  3. The AI answers, converses naturally, and fulfills a simple intent (e.g., checking business hours or booking a slot).
  4. The merchant receives an actionable summary in their Unified Inbox immediately after the call.

  **Acceptance Criteria:**
  *   **Latency Target:** Conversational turn latency (end-of-speech to start-of-response) must be under 800ms.
  *   **Context Awareness:** The voice agent must successfully answer questions based on the mocked business catalog/calendar data.
  *   **Mobile UI Parity:** The post-call summary card must render perfectly on a 375px viewport adhering to the Translucent Glass design tokens.
  *   **Unified Thread Integration:** Call summaries and transcripts must appear seamlessly in the same thread view as SMS and DMs.
