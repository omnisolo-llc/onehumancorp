  # Research Report: The Agent Approval Feed (Mobile MVP)

  ## 1. Problem Statement
  Small business owners are overwhelmed by complex, multi-tab dashboards (like Shopify or Wix) when trying to manage their business from a phone. Current mobile companion apps often redirect to unreadable web views for complex tasks. To realize the "Invisible AI Automation" vision, OHC needs a single, unified interface where owners can review, approve, or reject actions drafted by various AI agents (e.g., Marketing, Operations, Customer Success) entirely within a 375px mobile viewport.

  ## 2. Research Report
  - **The Mobile Management Gap:** Legacy platforms treat mobile apps as supplementary. Creators and micro-SMEs (like Linktree users) operate 100% from their phones and demand extreme simplicity.
  - **The "Approval" Paradigm:** Instead of a user navigating a complex form to set up a discount code, an Agent (e.g., The Manager) drafts the action. The user simply taps "Approve" on a highly visible card.
  - **Competitor Insights:** Link-in-bio tools succeed because of touch-friendly UI and zero CSS editing. Shopify's mobile app excels at basic fulfillment but fails at complex configuration.
  - **Target Persona:** Carlos (handyman) or Fatima (food cart) who need to make immediate decisions on the go without squinting at tiny forms.

  ## 3. Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Various Event Sources: Messages, low stock, abandoned carts] --> B(Event Mesh)
      B --> C[AI Agents: Operations, Ambassador, Marketing]
      C -->|Draft Action/Message| D[Action Required Queue DB]
      D --> E[Mobile App Feed API]
      E --> F[Unified Agent Feed UI 375px]
      F -->|Approve/Reject| G[Action Router]
      G --> H[Execute Action & Update State]
  ```

  ### UI Wireframes & Mobile UX Flow (375px First)
  - **Main Screen:** A vertically scrolling feed of "Action Cards". No complex hamburger menus or dense charts initially.
  - **Action Card Anatomy:**
    - **Header:** Agent Name (e.g., "Operations Agent") and timestamp.
    - **Context:** Brief explanation (e.g., "Inventory for 'Vegan Cake' is below 5.").
    - **Proposed Action:** Clear statement (e.g., "Draft a restock order for 20 units?").
    - **Controls:** Large (>= 44x44px touch target) "Approve" (Primary) and "Reject/Edit" (Secondary) buttons.
  - **Glassmorphism:** Adopt the premium OHC Translucent Glass materials.

  ### AI Agent Integration Points
  - **Action Required Queue:** Agents (like the Ambassador for DMs or the Cart Recovery agent) push structured proposed actions to a central `action_required_queue_repo`.
  - **Action Router:** A centralized handler that receives an "Approve" signal and dispatches the execution back to the relevant domain logic (e.g., sending the message, updating inventory).

  ### Key Design Decisions
  - **Aggregated View:** All agent requests funnel into one feed. The user doesn't check the "Marketing tab" then the "Operations tab".
  - **Optimistic UI:** When a user taps "Approve", the card should immediately visually indicate success or transition out, while the backend processes the action asynchronously.

  ## 4. Implementation Prompt
  **Objective:** Build the core backend API and the mobile-first frontend component for the Unified Agent Feed.
  - **User-Facing Outcome:** The owner opens the app and sees a feed of pending tasks generated by agents. They can tap "Approve" on a card to execute the agent's proposed action.
  - **CUJ:**
    1. System generates a dummy "Action Required" item (e.g., a drafted reply to a customer message).
    2. Owner views the feed on a 375px screen.
    3. Owner taps "Approve".
    4. The item is marked as approved and the action is processed.
  - Ensure the frontend uses the established OHC design tokens (glassmorphism, clear typography).
  - Integrate with the existing `action_required_queue_repo.rs` (if it exists, or create a simple abstraction) to fetch and update tasks.
