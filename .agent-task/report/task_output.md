  # Research Report: OHC Unified Autonomous Workforce & Floor Management Architecture

  ## 1. Problem Statement
  Location managers and operational owners like Jun (managing one location of a larger operation) or Carlos (managing a team of field technicians) struggle to coordinate staff, assign tasks dynamically based on real-time demand, and escalate issues without constant manual oversight. Existing platforms (e.g., Homebase, Deputy, 7shifts) are disjointed from the core commerce and customer service tools. They act as passive scheduling systems rather than active workforce managers. Consequently, when a surge in orders occurs or a critical piece of equipment breaks, the manager must manually reassign staff, often while trying to serve customers simultaneously.

  ## 2. Research Report
  - **Market Context**: Traditional workforce management tools (Homebase, Sling, Deputy) focus heavily on scheduling, time-tracking, and payroll integration. However, they lack "operational awareness"—they don't know *what* work is happening, only *who* is clocked in. Enterprise tools (like ServiceNow) offer robust task management but are far too complex and expensive for SMBs.
  - **The OHC Opportunity**: Because OHC already handles the commerce (orders, bookings) and customer service (inquiries, feedback), it is uniquely positioned to bridge the gap. By introducing an Autonomous Workforce & Floor Management Architecture, OHC can dynamically assign tasks to clocked-in staff based on real-time business context.
  - **Competitor Gaps**:
    - *Homebase/Deputy*: Excellent for scheduling and timesheets, but zero integration with real-time order volume or customer service requests.
    - *Shopify POS/Square*: They know the order volume but don't manage the workforce or assign tasks.
    - *Asana/Trello*: Good for project management, but not designed for real-time floor operations or shift-based workers.

  ## 3. Design Doc
  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Business Event Bus] -->|New Order / Issue / Surge| B{Operations Agent}
      B -->|Evaluate Real-time State| C[Workforce State Manager]
      C -->|Check Clocked-in Staff & Roles| D[(PostgreSQL Ledger)]
      B -->|Generate Task| E[Task Queue]
      E -->|Assign & Notify| F[Staff Mobile App 375px]
      F -->|Task Completed| B
      B -->|Escalate if Overdue| G[Owner/Manager Feed]
  ```

  ### Data Model (PostgreSQL & Redis)
  - **`StaffMember`**: Defines the employee, their roles, and current status (clocked-in, on-break).
  - **`Task`**: Represents a unit of work (e.g., "Prep Order #123", "Restock Cups", "Clean Spill at Table 4"). Includes priority, estimated time, and assigned `StaffMember`.
  - **`Shift`**: The scheduled and actual time worked by a staff member.
  - **Redis Task Pub/Sub**: Real-time dispatching of tasks to active staff clients to ensure sub-second UI updates without hammering the database.

  ### Mobile UX Flow (375px Mobile-First)
  - **Staff View ("The Floor")**: A highly simplified UI showing only what the staff member needs to do *right now*. Large, easy-to-tap cards representing tasks. Swipe right to complete, swipe left to request help.
  - **Manager View ("The Command Center")**: A real-time dashboard showing the status of the floor. Highlights bottlenecks (e.g., "Prep station is 15 minutes behind") and AI-suggested interventions.
  - **Zero-Friction Interactions**: If a task is marked complete, the Operations Agent automatically moves the associated order state forward and notifies the customer, eliminating double-entry.

  ### AI Agent Integration Points
  - **Operations Agent**: The core brain. It monitors incoming demand (orders, bookings) and automatically breaks them down into tasks. It assigns tasks based on staff roles and current workload. If a task is overdue, it dynamically reassigns it or escalates it to the manager.
  - **Decision Assistant**: Analyzes task completion times over days/weeks to provide managers with insights: "Your team is consistently understaffed on Tuesday mornings."

  ### Key Design Decisions & Why
  - **Event-Driven Task Generation**: Tasks are not just manually created; they are autonomously generated by the Operations Agent reacting to business events (e.g., a VIP customer arrives, inventory drops low).
  - **Swipe-Based Staff UI**: Minimizes cognitive load and screen time for staff who need to keep their eyes on the physical environment.
  - **Manager Escalation Only**: The manager is only notified when the AI cannot resolve a bottleneck itself, preserving the "Owner Clarity" value.

  ## 4. Implementation Prompt
  **Feature Name**: Autonomous Workforce & Floor Management
  **Target Persona**: Jun the Location Manager
  **User Facing Outcome**: Jun no longer has to manually shout out tasks or reassign staff when it gets busy. The OHC system knows who is clocked in and automatically routes tasks (like prepping specific orders or restocking) to the right staff member's mobile device. Jun only gets alerted if something falls significantly behind.
  **Critical User Journey (CUJ)**:
  1. Jun clocks in 3 staff members via the OHC app.
  2. A surge of 5 online orders arrives.
  3. The Operations Agent automatically breaks these orders down into prep tasks.
  4. The Agent assigns the tasks evenly across the 3 active staff members, popping up as large, tappable cards on their respective OHC mobile views.
  5. One staff member swipes to complete a task; the order status updates automatically, and the customer receives an SMS.
  6. A task is ignored for 10 minutes; the Agent automatically reassigns it to another available staff member and drops a low-priority note in Jun's feed.

  **Next Actions for Engineering**:
  1. Implement the core Data Models (`StaffMember`, `Shift`, `Task`) with strict multi-tenant isolation.
  2. Develop the Operations Agent logic to intercept business events (e.g., new order) and translate them into actionable `Task` records.
  3. Build the real-time Task Dispatch system using Redis Pub/Sub to push updates instantly to connected mobile clients.
  4. Implement the "Staff View" mobile UI with swipe-to-complete interactions and the "Manager Feed" for escalations.
