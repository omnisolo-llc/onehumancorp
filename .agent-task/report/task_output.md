  <h2 style="color: #ffffff; border-bottom: 1px solid rgba(255, 255, 255, 0.1); padding-bottom: 12px;">5. Implementation Issue Briefs</h2>

  <!-- Brief 1 -->
  <div style="background: rgba(0, 0, 0, 0.2); padding: 20px; border-radius: 8px; margin-bottom: 24px; border: 1px solid rgba(255, 255, 255, 0.05);">
    <h3 style="color: #38bdf8; margin-top: 0;">[Integrations] Unified Manychat/Instagram Social Inbox</h3>
    <p style="color: #e2e8f0;"><strong>Problem Statement:</strong> Maya (Home Baker) receives orders across Instagram, WhatsApp, and Facebook. Managing these manually causes her to miss orders while baking.</p>
    <p style="color: #e2e8f0;"><strong>Research Report:</strong> Manychat offers the most robust webhook and API ecosystem for aggregating Meta messaging platforms. Integrating Manychat allows OHC to pull all DMs into a single dashboard. 68% of SMB users cite Operational Fatigue as a primary pain point.</p>
    <p style="color: #e2e8f0;"><strong>Design Doc:</strong> Create a "Customer Inbox" view (optimized for 375px mobile). When a user authenticates via OAuth with Facebook/Instagram, register webhooks to receive new DMs. The KAIROS Orchestrator triggers the Customer Success Agent to draft contextual replies for 1-tap user approval before dispatching back via API.</p>
    <p style="color: #e2e8f0;"><strong>Implementation Prompt:</strong> Implement an OAuth flow to connect a user's Instagram/Facebook account (via Manychat or direct Meta Graph API). Create a webhook endpoint that receives incoming messages, stores them in the unified inbox, and triggers the Customer Success agent to draft a reply. Expose the conversation history in the UI.</p>
    <p style="color: #e2e8f0;"><strong>Priority:</strong> P0 | <strong>Estimated Scope:</strong> Large</p>
  </div>

  <!-- Brief 2 -->
  <div style="background: rgba(0, 0, 0, 0.2); padding: 20px; border-radius: 8px; margin-bottom: 24px; border: 1px solid rgba(255, 255, 255, 0.05);">
    <h3 style="color: #38bdf8; margin-top: 0;">[Booking] Automated Zoom Link Generation for Service Bookings</h3>
    <p style="color: #e2e8f0;"><strong>Problem Statement:</strong> Leo (Music Tutor) manually creates Zoom links for every booked lesson. This process is error-prone, annoying, and unprofessional if forgotten.</p>
    <p style="color: #e2e8f0;"><strong>Research Report:</strong> Zoom Server-to-Server OAuth or standard OAuth API allows instant meeting generation. Service providers (tutoring, consulting) consider automated video links table stakes.</p>
    <p style="color: #e2e8f0;"><strong>Design Doc:</strong> Extend the Service/Product creation flow to allow "Online Meeting" as a location type. Add a Zoom OAuth connect button in settings. When an order event (booking) is processed for an online service, the Operations Agent automatically calls the Zoom API, retrieves a join URL, and embeds it into the calendar invite and customer confirmation email.</p>
    <p style="color: #e2e8f0;"><strong>Implementation Prompt:</strong> Create an OAuth integration with Zoom. Automatically generate a unique Zoom meeting link when a customer books a virtual service. Ensure the generated link is stored with the booking entity and included in the outbound confirmation emails.</p>
    <p style="color: #e2e8f0;"><strong>Priority:</strong> P1 | <strong>Estimated Scope:</strong> Medium</p>
  </div>

  <!-- Brief 3 -->
  <div style="background: rgba(0, 0, 0, 0.2); padding: 20px; border-radius: 8px; margin-bottom: 24px; border: 1px solid rgba(255, 255, 255, 0.05);">
    <h3 style="color: #38bdf8; margin-top: 0;">[Notifications] Twilio SMS Alerts for Orders and Reminders</h3>
    <p style="color: #e2e8f0;"><strong>Problem Statement:</strong> Fatima (Food Cart Operator) relies on her phone but frequently misses app push notifications in noisy environments. She needs immediate, high-priority SMS alerts when an order is placed.</p>
    <p style="color: #e2e8f0;"><strong>Research Report:</strong> Twilio provides highly reliable global SMS infrastructure. SMS delivery guarantees reach out-perform email and push notifications, crucial for time-sensitive fulfillment and reducing customer no-shows for bookings.</p>
    <p style="color: #e2e8f0;"><strong>Design Doc:</strong> Add an "SMS Notifications" toggle in user settings. Connect the backend to the Twilio Programmable SMS API. Subscribe to KAIROS Order Paid and Appointment Upcoming events. When triggered, the agent dispatches async jobs to send an SMS string to the merchant ("New order!") or the customer ("Reminder: Lesson in 1 hour").</p>
    <p style="color: #e2e8f0;"><strong>Implementation Prompt:</strong> Integrate the Twilio SDK. Add a setting for the business owner to opt-in to SMS alerts for new orders. Implement a scheduled job that texts customers an appointment reminder X hours before their booking. Handle E.164 phone formatting globally.</p>
    <p style="color: #e2e8f0;"><strong>Priority:</strong> P2 | <strong>Estimated Scope:</strong> Medium</p>
  </div>

  <!-- Brief 4 -->
  <div style="background: rgba(0, 0, 0, 0.2); padding: 20px; border-radius: 8px; margin-bottom: 0; border: 1px solid rgba(255, 255, 255, 0.05);">
    <h3 style="color: #38bdf8; margin-top: 0;">[Payments] Mercado Pago Integration for LATAM Market Expansion</h3>
    <p style="color: #e2e8f0;"><strong>Problem Statement:</strong> Merchants in LATAM (e.g., Brazil) cannot easily use Stripe and need local payment methods (Pix, OXXO, local credit cards) to effectively sell to their customers.</p>
    <p style="color: #e2e8f0;"><strong>Research Report:</strong> Mercado Pago is the dominant payment processor in Latin America. To capture the massive unbanked and mobile-first SMB market in LATAM, OHC must support regional payment processors as first-class citizens.</p>
    <p style="color: #e2e8f0;"><strong>Design Doc:</strong> Abstract the Payment Gateway interface to support multiple providers. If a merchant's region is set to LATAM, expose Mercado Pago OAuth connection. Ensure the checkout UI dynamically routes the payment intent to Mercado Pago and properly handles incoming webhooks to fulfill orders.</p>
    <p style="color: #e2e8f0;"><strong>Implementation Prompt:</strong> Integrate Mercado Pago as an alternative payment provider alongside Stripe. Update the checkout flow to dynamically switch to the appropriate provider based on merchant settings. Normalize incoming payment webhooks from Mercado Pago into standard OHC order fulfillment events.</p>
    <p style="color: #e2e8f0;"><strong>Priority:</strong> P2 | <strong>Estimated Scope:</strong> Large</p>
  </div>
