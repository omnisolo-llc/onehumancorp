  # Research Report: Agent Feed Action Approval Flow (Unified Inbox)

  ## Overview
  The Agent Feed is designed to be the central nervous system for business owners using OHC. While the backend infrastructure for the Agent Feed exists (e.g., `ui_unified_agent_feed` caching and `load_ui_ledger_from_db`), and documents detail the "Invisible AI Automation" vision (e.g., `agent_feed_deep_dive.md`), there's a critical gap in the actual implementation of the "Action Required: Approve Reply" flow for the Unified Inbox. The Ambassador agent generates drafted responses, but the frontend lacks a cohesive, mobile-first unified action card interface for a 1-tap "Approve/Edit/Discard" workflow.

  ## Problem Statement
  Small business owners are overwhelmed with messages across multiple channels. The Ambassador agent theoretically drafts responses, but if the user cannot easily see, edit, and approve these drafts in a dedicated, mobile-optimized (375px) action feed, the AI's value is lost. The current "read-reply" process remains manual, defeating the purpose of a proactive AI assistant.

  ## Research Report
  - **Current State:** The backend has a concept of a unified agent feed (`UI_UNIFIED_AGENT_FEED_CACHE`) and an inbox cache (`UI_INBOX_CACHE`), but the crucial interactive layer connecting a drafted reply (from The Ambassador) to a user action (Approve/Send) is missing or incomplete in the frontend shell.
  - **Competitor Analysis:** Shopify and Wix offer unified inboxes, but they are reactive. OHC's differentiation is proactive drafting.
  - **Gap:** We need a dedicated frontend component for "Action Cards" within the Agent Feed, specifically tailored for message approvals. This component must support "1-Tap Approve" which dispatches the message, and "Edit" which opens a native keyboard experience.

  ## Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Agent Feed API /api/v1/feed] --> B[Frontend Agent Feed Store]
      B --> C{Action Card Component}
      C -->|Drafted Message| D[Approve Button]
      C -->|Drafted Message| E[Edit Button]
      C -->|Drafted Message| F[Discard Button]
      D --> G[Dispatch Approval API]
      E --> H[Open Edit Modal with Native Keyboard]
      F --> I[Dispatch Discard API]
      G --> J[Backend Message Bus -> External Channel]
  ```

  ### Mobile UX Flow (375px First)
  1. **Home Shell:** The primary view is the Agent Feed.
  2. **Action Card:** A card titled "Action Required: New Message from Sarah".
  3. **Content:** Shows customer context (e.g., "Sarah bought a vegan cake 2 months ago") and the drafted reply in a text area or clear text block.
  4. **Interactions:**
     - **Primary Button:** "Approve & Send" (Green/Brand color, prominent). Tapping immediately sends and removes the card.
     - **Secondary Button:** "Edit" (Ghost/Outline). Tapping expands the text area or opens a full-screen edit view with the native keyboard.
     - **Tertiary Action:** Swipe left to "Discard" or an "X" icon.
  5. **Visual Design:** Use the OHC Premium Token library (Translucent Glass materials, clean hierarchy).

  ### AI Agent Integration Points
  - The UI consumes data generated by **The Ambassador** agent. The card must display the AI's confidence level or reasoning if available, building trust with the owner.

  ## Implementation Prompt
  Implement the "Action Card" component for the Unified Agent Feed in the Flutter/PWA frontend. This component must handle drafted messages from The Ambassador agent. Ensure the layout is perfectly optimized for a 375px width. Implement the API integration to handle "Approve", "Edit", and "Discard" actions. Create a Playwright E2E test simulating an owner logging in, seeing a drafted message card, and clicking "Approve".
