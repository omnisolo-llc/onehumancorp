  # OHC Feature Mission: Unified AI Assistant Inbox for SMBs

  ## Problem Statement
  Small business owners and operators (like **Maya the baker** and **Carlos the handyman**) are currently forced to context-switch across multiple isolated communication channels (Instagram DMs, WhatsApp, SMS, Web Forms, and email) to capture demand and manage work. They manually triage these messages, parse details, check schedules, draft quotes, and update statuses. This leads to missed leads, delayed responses, and a chaotic workday. The gap in current SMB software is a centralized, AI-first Work Triage capability that unifies these streams and automatically proposes the next business action (e.g., "Draft a $50 quote for a custom cake delivery on Saturday").

  ### Track 2: Deep-Dive on Shopify Sidekick

  **Capabilities:**
  Shopify Sidekick is an AI-powered assistant built directly into the Shopify admin. It helps merchants perform tasks (e.g., "Put my summer collection on sale"), answer questions about store performance ("Why did sales drop on Tuesday?"), and draft content. It leverages Shopify's deep ecosystem knowledge but relies on the merchant explicitly interacting with it as a chat widget.

  **Success Factors:**
  - Embedded directly in the merchant's workflow.
  - Understands commerce context natively (products, orders, customers).
  - Lowers the barrier to entry for complex platform features.

  **User Sentiment Audit (Shopify Inbox & AI):**
  - *Positive:* Users love the unified view of customer chat from their store.
  - *Pain Point:* "I get Instagram DMs that Sidekick can't see, and I still have to manually link a DM to an order. It feels like an admin tool, not an assistant running my business." (r/shopify).

  ### Track 3: OHC Gap Matrix

  | Feature | Shopify / Sidekick | WeCom / DingTalk | OHC Current | OHC Target Vision |
  |---|---|---|---|---|

  **Unresolved Pain Point:**
  Competitors still treat messaging as a "CRM inbox" to be managed by the user. OHC's goal is for an AI assistant to *triage* the inbox and propose the next action (Work Intake), saving the owner from manually parsing intent.

  ## Design Doc

  ### High-Level Architecture
  - **Entity Types:** `Conversation`, `Message`, `Contact`, `TriageAction` (enum: Draft_Quote, Schedule_Booking, Share_FAQ).
  - **Key Relationships:** A `Conversation` belongs to a `Tenant` and a `Contact`. A `TriageAction` is generated by the AI Job Queue upon a new `Message`.
  - **Integration Points:** Stripe for payment links, Calendar/Booking for scheduling, external APIs (e.g., WhatsApp, IG) via webhook ingestion.

  ### Mobile UX Flow (375px First)
  1. **Home/Feed:** OHC opens to the "Today" feed. The top card shows: "3 new inquiries. 2 cake quotes drafted, 1 scheduling conflict."
  2. **Review Drafts:** Maya taps "Review Drafts." The UI shows a translucent modal card with the customer's original IG message, and the AI's proposed reply including a Stripe payment link for a $50 deposit.
  3. **Approve/Edit:** A large (44x44px minimum touch target) "Send & Request Deposit" primary button is at the bottom, with a secondary "Edit" icon.
  4. **State Transition:** Upon sending, the action moves to the "Pending Operations" section automatically.

  ## Implementation Prompt

  **User-Facing Outcome:** The owner opens the OHC mobile app and sees a prioritized feed of incoming customer requests across all channels. Instead of an empty text box, the AI has already drafted a context-aware reply and proposed a concrete business action (e.g., attaching a quote or booking link) that the owner can approve with a single tap.

  **Critical User Journey (CUJ):**
  1. A new message webhook is received by the backend.
  2. The Work Triage capability analyzes the message, identifies the customer, and determines the intent.
  3. The Customer Assistant drafts a reply, and if applicable, the Sales Assistant generates a pending quote.
  4. The owner logs into the OHC frontend, navigates to the Work Triage feed.
  5. The owner taps the drafted response, reviews the attached quote, and clicks "Approve."
  6. The system dispatches the message back to the channel.

  **Acceptance Criteria:**
  - Webhook endpoint for generic message ingestion successfully persists to the database.
  - Background job processes the message and generates a drafted reply using the LLM provider.
  - Frontend displays the "Work Triage" feed with unapproved drafts prominently at the top, respecting 375px mobile constraints.
  - "Approve" action correctly updates the conversation state and triggers the outbound message mock/integration.
  - End-to-end Playwright test covers the ingestion, UI review, and approval flow without mocking internal DB/API calls.
