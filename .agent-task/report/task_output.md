  ## Mission Queue Protocol Brief

  **Title**: Architect & Implement Zero-Trust Tap-to-Pay Mobile POS Integration

  **Problem Statement**:
  Users like Priya (boutique operator) and Fatima (food cart owner) currently experience a severe disconnect when taking in-person payments. They are forced to rely on disconnected external card readers, which breaks the unified OHC workflow. When sales occur in-person, they are not automatically reconciled with OHC's inventory and revenue tracking, leading to disjointed operations and manual entry errors. Without "Tap-to-Pay on iPhone/Android" integration directly within the OHC mobile assistant, the platform cannot serve as the sole operating system for these business owners.

  **Research Report**:
  - **Market Context**: Modern mobile POS systems (e.g., Shopify POS, Stripe Terminal, Square) have shifted from requiring dedicated external card readers to utilizing the built-in NFC hardware on smartphones (Tap-to-Pay). This drastically lowers the barrier to entry for small business owners, aligning perfectly with OHC's promise of radical simplicity.
  - **Competitor Analysis**:
    - *Shopify*: Uses the Stripe Terminal SDK integrated into the Shopify POS app, seamlessly linking in-person taps to online inventory.
    - *Square*: Native hardware and software ecosystem. Tap-to-Pay is natively supported in the app, setting the standard for mobile-first POS.
  - **OHC Requirement**: OHC must allow operators to capture payments securely using their existing smartphones. The solution involves integrating a Tap-to-Pay capability (like Stripe Terminal SDK) into our Flutter/PWA shell. Offline resilience, strict multi-tenant isolation, and immediate agent synchronization are critical requirements.

  ## Design Doc

  **Architecture Diagram**
  ```mermaid
  graph TD
      A[OHC Mobile App - 375px] -->|Initiates Payment| B(Tap-to-Pay / Stripe Terminal SDK);
      B -->|NFC Tap| C[Customer Card / Apple Pay];
      B -->|Payment Intent Confirmation| D(OHC Payment Gateway API);
      D --> E[(PostgreSQL - Tenant Isolated)];
      D --> F[Sales & Revenue AI Agent];
      F -->|Updates Daily Summary| G[Owner Work Feed];
      F -->|Reconciles Inventory| H[Operations Assistant];
  ```

  **Mobile UX Flow (375px Baseline)**
  - The operator views a pending order or booking from their feed and taps a prominent, thumb-friendly "Collect Payment" action button (44x44px minimum touch target).
  - A modal slides up using macOS-style Translucent Glass materials, prompting the operator to present the phone: "Tap to Pay".
  - The native Tap-to-Pay SDK takes over the screen securely, masking all background elements.
  - Upon successful NFC tap, a clear success checkmark appears, and the operator is returned to the OHC feed.
  - The Sales Agent immediately drafts a digital receipt and offers the operator the option to text or email it to the customer.

  **AI Agent Integration Points**
  - **Sales & Revenue Assistant**: Subscribes to the successful Payment Intent webhook/event, updates the business's daily revenue stats, and drafts the customer receipt.
  - **Operations Assistant**: Marks the corresponding task or order as `PAID` and automatically triggers the next fulfillment step (e.g., notifying Jun the location manager, or printing Fatima's food ticket).

  **Key Design Decisions**
  - **Zero Trust & Security**: The Tap-to-Pay SDK must be initialized using temporary connection tokens generated by the OHC backend. These tokens must be strictly scoped to the `tenant_id`. SPIFFE/SPIRE identity protocols will handle the secure backend-to-payment-provider token exchange.
  - **Mobile-First SDK**: Integration must occur at the native Flutter level, exposing a method channel to the PWA shell if required. All UI elements must strictly adhere to the OHC Premium Token library (Ubiquiti-style hierarchy, translucent materials).

  ## Implementation Prompt

  **For Implementer Agent**:
  Implement the Tap-to-Pay feature within the OHC Mobile application and Backend Payment Gateway.

  - **Objective**: Integrate the Tap-to-Pay SDK (e.g., Stripe Terminal) for mobile devices, bridging in-person NFC payments directly to OHC order completion and agent orchestration.
  - **CUJ**: Priya completes a dress sale in-store. She taps "Collect Payment" on her phone, which activates the Tap-to-Pay overlay. The customer taps their card. Upon success, OHC registers the order as paid, the Operations Assistant deducts the item from inventory, and the Sales Assistant updates the daily revenue summary.
  - **Acceptance Criteria**:
    1. Backend provides a secure endpoint to generate a strictly tenant-isolated connection token.
    2. Mobile UI includes a "Collect Payment" action that triggers the Tap-to-Pay SDK via method channels.
    3. The UI gracefully handles offline states or network degradation by queueing the sync if the provider supports offline authorizations, or clearly indicating the need for connection.
    4. Integration of mock/test-mode Tap-to-Pay in E2E Playwright/Flutter tests.
    5. Sales and Operations AI agents correctly process the completion event, updating the ledger and feed without human intervention.
