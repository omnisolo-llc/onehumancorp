  # Research Report: Agent Feed & Automated Actions (Mobile-First)

  ## Title
  Mobile-First Agent Feed: Unified Inbox & Automated Actions

  ## Problem Statement
  Small business owners (like Maya the baker or Carlos the handyman) are overwhelmed by managing communications, tasks, and operational metrics across disparate systems. Existing platforms like Shopify or Wix provide fragmented interfaces that force users to act as system administrators rather than business operators. Without a centralized, actionable feed, owners miss critical leads, delay customer responses, and lose revenue opportunities.

  ## Research Report
  - **Market Context**: Platforms like Shopify and Wix require extensive configuration and relying on third-party apps for unified communication. AI tools in these ecosystems are mostly reactive chatbots (e.g., Shopify Sidekick) rather than proactive executors.
  - **OHC Differentiation**: OHC's unique value proposition is the "Invisible AI Automation." The Agent Feed operationalizes this by transforming a traditional dashboard into a prioritized, actionable queue of AI-drafted responses, operational alerts, and business insights.
  - **Persona Fit**:
    - *Maya*: Needs a feed to approve AI-drafted Instagram DM replies regarding cake availability.
    - *Carlos*: Needs to see pending quotes and booking requests pushed by the Operations agent.

  ## Design Doc
  - **Architecture Diagram**:
    ```mermaid
    sequenceDiagram
      participant External as Webhooks (Instagram/Stripe)
      participant EventBus as Redis Pub/Sub
      participant Worker as AI Job Queue
      participant LLM as Gemini/OpenAI
      participant DB as PostgreSQL (Tenant Isolated)
      participant UI as Mobile App (Flutter/PWA)

      External->>EventBus: Event Received (e.g., DM)
      EventBus->>Worker: Process Event
      Worker->>LLM: Classify Intent & Draft Response
      LLM-->>Worker: Draft Ready
      Worker->>DB: Store Action Card
      DB->>UI: Push Notification / Feed Update
    ```
  - **Mobile UX Flow (375px)**:
    1. **Home Screen**: Replaces complex charts with a scrollable list of "Action Cards."
    2. **Action Card**: Displays the context (e.g., "Customer asked about vegan cakes"), the AI's drafted response, and primary actions ("Approve & Send", "Edit", "Discard").
    3. **Handoff**: Tapping "Approve" triggers the backend to execute the action via the appropriate integration, moving the card to an "Archive" state.
  - **AI Agent Integration Points**: The feed aggregates outputs from the "Customer Success Agent" (drafting replies), "Operations Agent" (inventory alerts), and "Finance Agent" (revenue summaries).
  - **Key Design Decisions**:
    - **Proactive over Reactive**: The system pushes actionable items to the owner, minimizing navigation.
    - **Single Tap Execution**: High-confidence AI actions require only a single tap to approve.
    - **Clear Status Tokens**: Visual indicators (e.g., Urgent, Action Needed, FYI) guide the owner's attention.

  ## Implementation Prompt
  - **Objective**: Implement the primary "Agent Feed" view in the mobile web app, displaying actionable cards generated by backend AI processes.
  - **CUJ**:
    1. Owner logs into the OHC app.
    2. The Home screen displays a prioritized list of Action Cards.
    3. The owner reviews a card (e.g., a drafted reply to a customer inquiry).
    4. The owner taps "Approve" on the card.
    5. The card visually transitions to a completed state, and the action is dispatched to the backend.
  - **Acceptance Criteria**:
    - The layout must perfectly fit a 375px viewport without horizontal scrolling.
    - Action cards must use clear typography, strong spacing, and translucent material design tokens.
    - Touch targets for actions ("Approve", "Edit") must be at least 44x44px.
    - Optimistic UI updates must handle network latency gracefully.
    - Implement Playwright E2E tests verifying the feed rendering and the approval flow interaction.
