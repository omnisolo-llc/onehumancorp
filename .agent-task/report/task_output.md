issue_title: "Implement the Unified Agent Feed (Mobile MVP)"
issue_description: |
  ## Mission Queue Protocol
  This task aims to implement the "Unified Agent Feed" for OneHumanCorp, an essential mobile-first capability bridging the gap between traditional complex admin dashboards and proactive AI automation for non-technical owners.

  ### Problem Statement
  Legacy commerce apps require non-technical business owners to navigate complex multi-level menus to manage their operations, handle marketing, or process customer queries. This is nearly impossible to do efficiently on a small 375px mobile screen. They lack an intuitive, centralized "Action Feed" that proactively pushes drafts, suggestions, and alerts from various AI agents to the user for quick, one-tap approval.

  ### Research Report
  - **Shopify/Wix:** Rely on complex web-based dashboards or companion apps that act merely as stats viewers, not operational execution environments. Actions require digging through menus.
  - **Link-in-Bio Tools:** Good mobile UX but lack real operational depth.
  - **OHC Opportunity:** Utilize the "Unified Agent Feed" paradigm. Agents (Customer Success, Operations, Sales) analyze context and push proactive Action Cards to a centralized, mobile-first feed. The owner just reviews and taps "Approve."

  ### Design Doc
  **Architecture Diagram**
  ```mermaid
  graph TD
      A[Event Bus/Message Queue] --> B[Agent Task Queue]
      B --> C{The Manager}
      B --> D{The Ambassador}
      B --> E{The Promoter}
      C --> F[Draft Action Card]
      D --> F
      E --> F
      F --> G[Database: Tenant Action Items]
      G --> H[Mobile App Unified Feed]
      H --> I[User Approves]
      I --> J[Action Execution Pipeline]
  ```

  **UI Wireframes & Mobile UX Flow (375px First)**
  - **Home Screen:** The primary view is the Agent Feed. A vertical list of Glassmorphism "Action Cards".
  - **Card Structure:** Title (e.g., "Drafted Reply", "Restock Needed"), Context snippet, and large action buttons (e.g., "Approve & Send", "Edit", "Dismiss").
  - **Interaction:** Tapping an action button triggers the backend execution pipeline, resolving the card and removing it from the feed.

  **AI Agent Integration Points**
  - Agents (Operations, Customer Success) write `ActionItem` records to the database.
  - The UI polls or subscribes to real-time updates for these `ActionItems`.

  **Key Design Decisions**
  - **Approval Interface Paradigm:** Shift from forms to proactive cards.
  - **Strict Mobile-First:** Minimum 44x44px touch targets. No horizontal scrolling on 375px width.

  ### Implementation Prompt
  **User-Facing Outcome:** When a business owner opens the OHC mobile app, they see a prioritized feed of action cards generated by AI agents (e.g., a drafted reply to a customer, a suggestion to reorder inventory). They can tap "Approve" to instantly execute the action or "Dismiss" to ignore it.

  **CUJ & Acceptance Criteria:**
  1. Define a backend data model (`ActionItem`) for tenant-scoped agent suggestions with statuses (Pending, Approved, Dismissed).
  2. Implement an API endpoint to fetch pending Action Items for the current tenant.
  3. Create a mobile-first (375px) Flutter view displaying a vertical list of these Action Items as cards.
  4. Ensure each card has prominent "Approve" and "Dismiss" buttons (>= 44x44px).
  5. Implement API endpoints and UI state management to handle the "Approve" and "Dismiss" actions, updating the `ActionItem` status and removing the card from the feed.
  6. Provide Playwright/Flutter E2E tests validating the feed display and interaction flows.

  **Priority:** P0
  **Estimated Scope:** Large
