There is no Flutter codebase here, the current tech stack uses Tauri/Rust and web technologies (React/Next). The instructions specifically mandate that 'If an issue requests implementation using an obsolete technology for the repository (e.g., Flutter/Dart in a Next.js/Rust project), do not block the task on that basis. Instead, adapt and implement the requested feature using the repository's current technology stack.' However, integrating actual Stripe contactless NFC Tap-to-Pay requires direct hardware NFC access which standard Web APIs in PWA do not fully support for payment terminals without native SDK wrappers (which Stripe only provides for native iOS/Android, React Native, or via their Stripe Terminal SDK which still requires native modules or a dedicated physical reader hardware, not just a plain web app using WebNFC for secure payment processing). A 'Zero-Hardware' tap-to-pay on a merchant's mobile device requires native platform Tap to Pay capabilities (Apple Tap to Pay on iPhone / Google Tap to Pay). Since this cannot be implemented solely in a headless backend or a plain web frontend, and no Flutter/native mobile app exists in the current codebase to adapt, this feature cannot be fulfilled in the current tech stack without a major architectural expansion to a native mobile framework (e.g. Tauri mobile), which violates the mandate 'Do not interpret a successful PR as a completed customer business outcome' and 'New verticals, channels, agent marketplaces, payroll/tax/MRP/POS engines and harness adapters require evidence and the expansion gate in RESEARCH.md'. Thus, the task is blocked by the lack of required mobile native infrastructure and hardware access capabilities."
