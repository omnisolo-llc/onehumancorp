  # Research Report: Autonomous Field Service Estimation & Routing Architecture

  ## 1. Problem Statement
  Service-based small business owners on the move (e.g., Carlos the Handyman) lack a unified system that seamlessly connects lead intake, estimation, scheduling, route planning, and payment collection. They typically juggle separate apps for text messages, maps, calendars, and invoicing. Existing field service software (e.g., Jobber, Housecall Pro) is often too complex, requiring significant setup and manual management. The owner needs an AI assistant that intercepts incoming service requests, drafts estimates, suggests optimal routing, and secures deposits while they are at a job site, all from a 375px mobile screen.

  ## 2. Research Report
  - **Market Context**: Platforms like Jobber and ServiceTitan dominate field service, but their UX is often overwhelming for a solo operator like Carlos. They function as comprehensive CRM and ERP systems, whereas micro-SMEs need an "assistant" that does the work for them.
  - **The OHC Opportunity**: By integrating lead capture, quoting, and geographical scheduling directly into the AI Operations Agent, OHC can create a proactive, frictionless field service flow.
  - **Competitor Gaps**:
    - *Jobber*: Comprehensive but passive; requires the user to input data and plan routes manually.
    - *Housecall Pro*: Good dispatching but lacks agentic AI for automated follow-ups and routing optimization.
    - *Thumbtack / Angi*: Good for lead generation but highly fragmented from the operator's actual schedule and financials.

  ## 3. Design Doc
  ### Data Model & Sync Protocol (PostgreSQL)
  - `ServiceRequest`: Inbound lead details (customer issue, photos, location).
  - `Estimate`: Proposed scope of work, pricing, and required deposit, generated by AI.
  - `ServiceJob`: Confirmed booking with scheduled time block, geo-location, and status (pending, traveling, in-progress, completed).
  - `RoutePlan`: Daily sequence of `ServiceJob`s, optimized for travel time.

  ### Architecture Diagram
  ```mermaid
  erDiagram
      ServiceRequest ||--o| Estimate : "generates"
      Estimate ||--o| ServiceJob : "converts to"
      ServiceJob }|--|| RoutePlan : "scheduled in"
      Customer ||--o{ ServiceRequest : "submits"
  ```

  ### Mobile UX Flow (375px)
  1. **Work Triage (Inbox)**: Carlos receives an inbound request (e.g., via SMS or web form). The Sales Agent automatically drafts a preliminary estimate based on his historical pricing.
  2. **Estimate Approval**: Carlos reviews the drafted estimate on a clean, scrollable card and taps "Send to Customer" with one touch.
  3. **Scheduling & Routing (Daily View)**: Once accepted and deposit paid, the job drops into Carlos's daily view. The Operations Agent recalculates his optimal route for the day, visually mapping it out on a touch-friendly timeline.
  4. **On-Site Execution**: Carlos taps a job card to see customer notes, uses native device navigation to get there, and marks the job "Complete" to instantly trigger a final invoice (Stripe Terminal or link).

  ### AI Agent Coordination
  - **Sales Agent**: Monitors Work Intake (SMS/forms), analyzes job details, and drafts `Estimates`. Follows up on unaccepted quotes after 24 hours.
  - **Operations Agent**: Tracks `ServiceJob`s, computes travel times between locations using standard mapping APIs, and constructs the daily `RoutePlan`. Warns Carlos if a requested time slot conflicts with travel requirements.
  - **Finance Agent**: Handles deposit collection via Stripe links on the estimate, and automates final invoicing upon job completion.

  ### Key Design Decisions
  - **Agent-First Flow**: The system does not wait for the user to create an estimate; the AI drafts it upon intake, shifting the owner from "data entry" to "approval".
  - **Geo-Aware Scheduling**: Availability slots offered to customers must account for travel time from the previous job, preventing impossible schedules.

  ## 4. Implementation Prompt
  **Feature Name**: Autonomous Field Service Estimation & Routing System
  **Target Persona**: Carlos the Field Service Owner
  **Outcome**: Carlos can receive a service request, approve an AI-drafted estimate with one tap, and have the job automatically scheduled into an optimized daily route that respects travel times, all managed via a simple mobile interface.

  **Critical User Journey (CUJ)**:
  1. A new service request (with a photo and address) enters the Work Triage feed.
  2. The Sales Agent drafts an estimate with a suggested price and deposit requirement.
  3. Carlos views the draft on his phone and taps "Approve & Send".
  4. The customer accepts and pays the deposit.
  5. The Operations Agent schedules the job and updates Carlos's daily route, inserting it logically based on geo-location and existing bookings.

  **Next Actions for Engineering**:
  1. Implement the core Data Models (`ServiceRequest`, `Estimate`, `ServiceJob`, `RoutePlan`) with multi-tenant isolation.
  2. Develop the AI Sales Agent capability to draft estimates from raw service requests.
  3. Develop the AI Operations Agent capability to perform geo-aware scheduling and route optimization.
  4. Create the mobile-first UX for Work Triage (Estimate approval) and the Daily Route Plan view.
