  # Agentic Intake-to-Proposal Pipeline for Agency Workflows

  ## Problem Statement
  Service professionals, independent contractors, and agency principals (like Nora) experience significant friction turning casual client inquiries into formalized, approved projects. Currently, the process requires context switching across multiple tools: a form builder for intake, a word processor for proposals, a project management tool for tasks, and an invoicing platform for billing. This fragmentation causes delays, dropped leads, and high administrative overhead, preventing the owner from focusing on actual client work. Non-technical operators need an invisible, AI-driven pipeline that seamlessly converts an initial request into a drafted proposal, pending only their approval.

  ## Research Report
  - **Market Context**: Traditional platforms like HoneyBook and Dubsado offer comprehensive client management, but their setup is notoriously complex, requiring extensive template creation and workflow mapping. General website builders (Wix, Squarespace) provide basic intake forms but lack any automated progression to quoting or task generation. Enterprise tools (Salesforce, HubSpot) are overly engineered and cost-prohibitive for micro-agencies.
  - **The OHC Opportunity**: By integrating project intake directly with OHC's Operations and Knowledge AI Agents, OHC can eliminate the administrative gap. An inquiry should trigger an agent to instantly review past similar projects, draft a contextual proposal, and present a mobile-optimized approval card to the owner.
  - **Competitor Gaps**:
    - *HoneyBook/Dubsado*: Steeper learning curve; reactive workflow building.
    - *Shopify/Wix*: Not natively designed for complex, high-touch service pipelines.
    - *Notion AI*: Good for drafting, but disconnected from billing and client communication loops.

  ## Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Client Intake Form/Email] -->|Webhook/Event| B(OHC Event Gateway)
      B --> C[The Analyst Agent: Scope Extraction]
      C -->|Query| D[(Tenant Memory & Knowledge Base)]
      C -->|Query| E[(Past Projects & Proposals)]
      C --> F[The Drafter Agent: Proposal Generation]
      F --> G[The Planner Agent: Task & Milestone Breakdown]
      F --> H[Action Required Queue]
      G --> H
      H --> I[Mobile Feed: Proposal Approval Card]
      I -->|Approve| J[Client Delivery & Invoicing Schedule]
  ```

  ### Mobile UX Flow (375px First)
  1. **Notification & Feed**: Nora receives a push notification: "New Inquiry from Acme Corp. Draft proposal ready for review."
  2. **Approval Card**: The OHC mobile feed displays a rich card detailing the client request, a summarized scope of work, and an estimated budget generated by the AI. Touch targets are large (≥ 44x44px).
  3. **Detail View**: Tapping the card reveals a translucent glassmorphic overlay containing the full text of the proposal and auto-generated internal task milestones.
  4. **Action**: Nora can tap "Approve & Send" or use natural language to request an edit (e.g., "Add a 10% rush fee to this").
  5. **Client Handoff**: Upon approval, the proposal is emailed to the client via a secure link, and initial project tasks are populated in Nora's daily operations view.

  ### AI Agent Integration Points
  - **The Analyst Agent**: Parses raw text from emails or forms to extract budget, timeline, and core deliverables.
  - **The Drafter (Sales/Knowledge) Agent**: Uses RAG against the tenant's past successful proposals and pricing models to formulate a highly contextual, professional quote.
  - **The Planner (Operations) Agent**: Deconstructs the approved scope into actionable, scheduled tasks for the agency team, assigning them to the relevant staff or contractors.

  ### Key Design Decisions
  - **Proactive Proposal Generation**: Instead of just logging a lead, OHC proactively does the work of drafting the proposal. The owner operates in an "editor" rather than "creator" mindset.
  - **Unified Project State**: Proposals, tasks, and eventually invoices are all intrinsically linked to a single `Project` entity within the database, eliminating duplicate data entry.
  - **Mobile-First Editing**: Editing a proposal on a 375px screen is hard. OHC solves this by relying on chat-based, natural language adjustments rather than a complex rich-text editor on mobile.

  ## Implementation Prompt
  **Feature Name**: Agentic Intake-to-Proposal Pipeline
  **Target Persona**: Nora the Agency Principal

  **Outcome**: When a potential client submits an inquiry, OHC's AI agents automatically parse the request, query past successful projects for pricing/scope context, and draft a complete proposal. The owner simply reviews, adjusts via chat if necessary, and approves the proposal from their mobile feed.

  **Critical User Journey (CUJ)**:
  1. A webhook simulates a new client inquiry (e.g., a form submission detailing a web design project).
  2. The intake event triggers the AI workflow, which generates a structured proposal and corresponding project tasks.
  3. Nora logs into the OHC mobile view and sees a "Proposal Ready for Approval" card in her feed.
  4. Nora taps the card, reviews the generated text and pricing, and taps "Approve & Send".
  5. The system transitions the lead to an active project state and logs the proposal as sent.

  **Acceptance Criteria**:
  - The UI must be fully functional on a 375px viewport, utilizing translucent glass styling and UniFi-style modular cards.
  - The AI generation must use the existing LLM provider abstraction and RAG capabilities.
  - E2E Playwright tests must cover the full flow: webhook ingestion, mobile feed display, and proposal approval.
  - Data models for `Inquiry`, `Proposal`, and `Project` must enforce row-level tenant isolation.
