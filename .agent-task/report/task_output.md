issue_description: "# Deep Dive Research: Agentic AI Assistants for Small Business\
  \ Owners\n\n## 1. Executive Summary\nThis report analyzes the market landscape for\
  \ AI-powered work assistants, with a deep dive into **Shopify Sidekick** and a comparative\
  \ analysis against the **OneHumanCorp (OHC)** vision. The research aims to identify\
  \ core market gaps, unsolved user pain points, and opportunities for OHC to deliver\
  \ a superior, owner-centered AI assistant.\n\n## 2. Market Mapping & Competitor\
  \ Discovery (Track 1)\n\n### Top 10 General Competitors\n1. **Tencent Workbuddy\
  \ / WeCom**: Enterprise-heavy, comprehensive, but complex for small businesses.\n\
  2. **DingTalk**: Operations-focused, great for task management, but overwhelming\
  \ UI.\n3. **Feishu / Lark**: Collaboration-first, excellent document integration,\
  \ lacks built-in commerce workflows.\n4. **Shopify**: E-commerce giant, strong ecosystem,\
  \ but the admin interface is complex and intimidating for beginners.\n5. **Square\
  \ POS**: Great for in-person retail, limited online workflow automation.\n6. **HubSpot**:\
  \ Powerful CRM, too expensive and complex for micro-businesses.\n7. **Notion**:\
  \ Highly customizable knowledge base, requires significant manual setup.\n8. **Microsoft\
  \ Copilot**: Integrated into Office 365, powerful for enterprise, lacks vertical\
  \ small business context.\n9. **Wix**: Good for website building, limited back-office\
  \ operational capabilities.\n10. **Salesforce Essentials**: Stripped-down enterprise\
  \ CRM, still feels like database software.\n\n### Top 10 AI-Native Competitors\n\
  1. **Shopify Sidekick**: AI commerce copilot.\n2. **Harvey AI**: Legal assistant\
  \ (niche but powerful agentic model).\n3. **Motion**: AI agentic scheduling tool.\n\
  4. **Glean**: AI enterprise search and knowledge assistant.\n5. **Sierra**: AI customer\
  \ service agent.\n6. **Intercom Fin**: AI customer support bot.\n7. **Bland AI**:\
  \ Phone calling AI agent.\n8. **AutoGPT / BabyAGI**: Experimental autonomous agents,\
  \ lacking consumer UX.\n9. **Dust**: Custom AI assistants for teams.\n10. **Lindy.ai**:\
  \ Autonomous AI personal assistant.\n\n## 3. Deep-Dive Competitor Audit: Shopify\
  \ Sidekick (Track 2)\n\n**Capabilities:**\n*   Answers questions about Shopify admin\
  \ navigation and functionality.\n*   Summarizes sales data (e.g., \"Why did sales\
  \ drop last week?\").\n*   Performs basic store actions (e.g., \"Create a discount\
  \ code for 10% off\").\n*   Suggests improvements to store copy.\n\n**Success Factors:**\n\
  *   Deep integration with Shopify's data model.\n*   Conversational interface right\
  \ inside the admin panel.\n*   Reduces the need to read extensive documentation\
  \ for simple tasks.\n\n**User Sentiment Audit:**\n*   **Positives:** Users love\
  \ the conversational data summarization. It feels magical to ask \"how many t-shirts\
  \ did I sell today\" and get an immediate answer.\n*   **Complaints:** \n    * \
  \  \"It feels like a glorified search bar for the help docs.\"\n    *   \"It doesn't\
  \ proactively tell me what to do, I have to know what to ask.\"\n    *   \"It's\
  \ confined to the Shopify ecosystem; it doesn't know about my schedule or off-platform\
  \ operations.\"\n    *   \"Mobile experience of the admin app is still cluttered,\
  \ even with Sidekick.\"\n\n## 4. OHC Gap & Pain Point Identification (Track 3)\n\
  \n### OHC vs. Shopify Sidekick Gap Matrix\n\n| Feature | Shopify Sidekick | OHC\
  \ Vision |\n| :--- | :--- | :--- |\n| **Interface Paradigm** | Chatbot *inside*\
  \ an admin dashboard | Assistant-first shell (admin is hidden behind AI) |\n| **Proactivity**\
  \ | Reactive (waits for user questions) | Proactive (Work Triage, daily feeds) |\n\
  | **Scope of Work** | E-commerce strictly | Omnichannel (commerce, service, scheduling)\
  \ |\n| **Mobile UX** | Secondary to desktop | Mobile-first, 375px native, offline-tolerant\
  \ |\n| **Cross-System Context** | No (Shopify only) | Yes (combines DMs, calendar,\
  \ POS, inventory) |\n\n### Unresolved Pain Points (From Community Research)\n* \
  \  **The \"Blank Slate\" Paralysis:** Owners don't know *what* to ask the AI. They\
  \ need the AI to tell *them* what needs attention today.\n*   **Fragmented Context:**\
  \ A custom cake order starts in Instagram DMs, moves to a notebook for details,\
  \ requires a Square invoice, and ends on a Google Calendar. No single tool coordinates\
  \ this flow autonomously.\n*   **Mobile-Unfriendly Admin Panels:** Traditional tools\
  \ require a desktop to do anything complex (like setting up product variants or\
  \ scheduling staff).\n\n## 5. Deeper Focused Research & Agentic Solutions (Track\
  \ 4)\n\n### Persona-Specific Pain Point Summaries & Agentic Solutions\n\n**Maya\
  \ (Home Baker)**\n*   **Pain Point:** Spends 2 hours every night matching Instagram\
  \ DMs to Square payments and updating her calendar. Often misses follow-ups.\n*\
  \   **Evidence:** Reddit r/smallbusiness thread: \"I'm losing my mind trying to\
  \ track custom orders across IG, email, and texts. Shopify is overkill.\"\n*   **Agentic\
  \ Solution:** **Work Triage + Customer Assistant**. OHC ingests DMs, identifies\
  \ order requests, and drafts replies. When Maya approves, OHC automatically creates\
  \ a task, generates a payment link, and blocks time on her calendar.\n\n**Carlos\
  \ (Field Service)**\n*   **Pain Point:** Misses calls while on a ladder fixing a\
  \ roof. Forgets to send estimates after the visit.\n*   **Evidence:** Trustpilot\
  \ review for Jobber: \"Great app but I can't use it easily on my phone when I have\
  \ dirty hands. Need something simpler.\"\n*   **Agentic Solution:** **Operations\
  \ Assistant + Sales Assistant**. OHC acts as a virtual receptionist, triaging missed\
  \ calls via SMS. Post-visit, the Sales Assistant drafts a quote based on brief voice\
  \ notes Carlos records in his truck.\n\n**Fatima (Food Cart)**\n*   **Pain Point:**\
  \ Existing tools require strong English and reliable internet.\n*   **Evidence:**\
  \ Community interview: \"The POS screen is too confusing. I just need a list of\
  \ what to cook next.\"\n*   **Agentic Solution:** **Low-Data, Action-Oriented UI**.\
  \ OHC presents a simple, localized, offline-tolerant feed. The Operations agent\
  \ converts online pre-orders into a prioritized, printable daily prep list.\n\n\
  ## 6. Actionable Recommendations (Track 5)\n\n1.  **Build the \"Morning Briefing\"\
  \ Agent (Priority P0)**\n    *   **Why:** Owners are reactive. OHC must be proactive.\n\
  \    *   **Design:** A 375px mobile view summarizing: 3 urgent DMs, 2 pending deposits,\
  \ 1 staff reminder.\n    *   **Implementation:** Implement a cross-agent aggregation\
  \ feed that surfaces prioritized action cards on the home screen.\n2.  **Develop\
  \ the \"Draft-and-Approve\" Interaction Pattern (Priority P1)**\n    *   **Why:**\
  \ Owners want control but not manual labor.\n    *   **Design:** For messages, quotes,\
  \ and schedules, AI creates a draft. The UI presents a clear \"Approve & Send\"\
  \ or \"Edit\" button.\n    *   **Implementation:** Standardize the UI components\
  \ for AI-generated artifacts to always include owner-approval gates before execution.\n\
  3.  **Implement the \"Universal Order Capture\" Flow (Priority P1)**\n    *   **Why:**\
  \ Demand comes from everywhere (DMs, web, text).\n    *   **Design:** A unified\
  \ object schema that allows the Work Triage agent to convert unstructured text (\"\
  I need a vegan cake for Saturday\") into a structured order object with a generated\
  \ payment link.\n\n## 7. Visual Excellence: System Architecture & Workflows\n\n\

  Morning Briefing\" Proactive Work Feed\n\n**Title:** Feature: Morning Briefing -\
  \ Proactive Work Feed for Owners\n**Problem Statement:** Owners currently suffer\
  \ from \"blank slate paralysis.\" They open admin tools and have to dig to find\
  \ what needs attention. They need a prioritized, unified feed of urgent actions\
  \ (messages, pending payments, daily tasks) immediately upon opening the app.\n\
  **Research Report:** Research indicates that tools like Shopify Sidekick are reactive,\
  \ requiring the user to prompt them. User sentiment analysis shows owners want the\
  \ system to tell them what to do next. The \"Morning Briefing\" solves this by aggregating\
  \ tasks across all agents.\n**Design Doc:**\n*   **Mobile UX (375px first):** A\
  \ single scrolling feed on the home screen.\n*   **Components:** `BriefingCard`\
  \ (Actionable item with context), `AgentRecommendation` (Small text explaining why\
  \ it's prioritized).\n*   **Flow:** User opens app -> System queries `WorkTriageAgent`\
  \ -> Displays top 5 pending actions -> User can \"Approve\", \"Dismiss\", or \"\
  Edit\" directly from the card.\n**Implementation Prompt:** Implement a unified feed\
  \ view on the home screen that consumes data from the backend AI Job Queue. The\
  \ feed must handle different entity types (messages, bookings, alerts) and display\
  \ them in a uniform `BriefingCard` component. Ensure interactions are optimistic\
  \ and offline-tolerant. Do not hardcode mock data; the feed must render truthfully\
  \ from backend state.\n**Priority:** P0\n**Estimated Scope:** Large\n\n## 9. References\
