issue_title: "Agentic Client Intake & Automated Proposal Workflow"
issue_description: |
  ## 1. Problem Statement
  Service-based and agency owners (e.g., Nora the Agency Principal) spend hours each week manually collecting project requirements from potential clients, following up with missing information, drafting customized proposals, and sending invoice reminders. This manual intake and proposal process creates a bottleneck, delaying revenue generation and introducing human error into pricing and scope definition. Existing tools (like Dubsado or HoneyBook) offer templates and forms but lack active, agentic execution to autonomously manage the back-and-forth negotiation and drafting.

  ## 2. Research Report
  - **Market Context**: Platforms like Dubsado, HoneyBook, and HubSpot provide CRM and proposal capabilities but require heavy manual configuration (workflows, form building, email templates). They wait for the client to fill out a static form.
  - **The OHC Opportunity**: By introducing an "Agentic Client Intake" process, OHC can replace static forms with an interactive, AI-driven conversation (via web widget, SMS, or email) that dynamically asks follow-up questions based on the client's initial request.
  - **Competitor Gaps**:
    - *HoneyBook/Dubsado*: Excellent client portals but rely on the owner to review intake forms and manually construct the proposal using templates.
    - *HubSpot*: Enterprise-focused, high cost, and high complexity for small agencies.
    - *Lindy.ai / 11x.ai*: Autonomous but often disconnected from the core billing and project management infrastructure.

  ## 3. Design Doc
  ### Data Model (PostgreSQL)
  - `ClientIntake`: Tracks the conversational state and collected requirements for a new lead.
  - `ProjectScope`: Structured data generated by the AI from the intake conversation (deliverables, timeline, budget).
  - `Proposal`: The generated proposal document linked to the `ProjectScope` and `Customer`, with states (`draft`, `sent`, `approved`, `rejected`).
  - `Invoice`: Linked directly to the approved `Proposal` with automated payment schedules.

  ### AI Integration
  - **Sales/Customer Success Agent**: Interacts with the lead to gather requirements interactively. Identifies missing information (e.g., "You mentioned a website redesign, do you also need branding?") and updates the `ClientIntake` state.
  - **Operations Agent**: Uses the finalized `ClientIntake` to generate the `ProjectScope` and draft a `Proposal`.
  - **Finance Agent**: Automatically schedules invoice reminders once the proposal is approved.

  ### Mobile UX Flow (375px)
  1. **Owner View (Agent Feed)**: The owner receives an Action Card: "New Lead: Website Redesign for Acme Corp. All requirements gathered. Proposal drafted."
  2. **Proposal Review**: The owner taps the card to review the AI-drafted proposal in a mobile-optimized view. They can make quick edits or approve it.
  3. **One-Tap Send**: Tapping "Approve & Send" dispatches the proposal to the client via email/SMS with a Stripe payment link for the deposit.

  ## 4. Implementation Prompt
  **Feature Name**: OHC Agentic Client Intake & Proposal Generator
  **Target Persona**: Nora the Agency Principal
  **Outcome**: A prospective client submits a brief inquiry. The AI agent asks clarifying questions, gathers the full scope, and drafts a complete proposal. Nora reviews and approves the proposal from her phone with one tap.

  **Next Actions**:
  1. Implement the data models (`ClientIntake`, `ProjectScope`, `Proposal`) with strict row-level multi-tenant isolation.
  2. Build the Sales Agent capability to handle interactive intake conversations and structured data extraction.
  3. Develop the Operations Agent workflow to generate proposals from structured `ProjectScope` data.
  4. Create the mobile-first Owner UI (Action Cards) for reviewing, editing, and approving proposals.
