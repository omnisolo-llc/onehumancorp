  # [Architecture] Autonomous AI Voice Receptionist Engine

  ## Problem Statement
  For service-based and mobile businesses like **Carlos (The Freelance Handyman)** and **Fatima (The Food Cart Operator)**, incoming phone calls are the primary source of revenue. However, because they are actively working (fixing pipes, cooking food), they frequently miss calls. Missed calls mean lost revenue. While OHC handles online storefronts and web bookings beautifully, it currently lacks a solution for customers who prefer to call. These business owners need an invisible, multi-lingual AI receptionist that can answer the phone, speak naturally to customers, answer questions, provide quotes, and book appointments—all completely autonomously, 24/7.

  ## Research Report
  ### Competitor Analysis
  - **Shopify / Wix / Squarespace:** None of the major website builders offer integrated, autonomous voice agents. They rely exclusively on web-based forms, live chat, or directing users to call the owner's personal phone number.
  - **Standalone Voice AI Startups (e.g., Bland AI, Vapi):** Powerful, but require technical knowledge to set up webhooks, craft system prompts, and handle state management. Far too complex for a non-technical persona.
  - **GoDaddy:** Offers basic VoIP call forwarding, but no AI conversational capability.

  ### Opportunity for OHC
  OHC has the opportunity to introduce a true category-killer feature. By leveraging WebRTC, Twilio's SIP/PSTN infrastructure, and the OpenAI Realtime API (or Gemini Multimodal Live API), OHC can automatically provision a dedicated business phone number. The OHC "Customer Success" and "Sales" agents will interface via streaming audio to converse with customers, query the OHC PostgreSQL database for availability/inventory, and execute transactions using tool calls. This transforms OHC from a "website builder" into a "complete virtual business operations team".

  ## Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD;
      Customer[Customer on Phone] -->|PSTN / SIP| Twilio[Twilio Voice Gateway];
      Twilio -->|Media Stream (WebSockets)| VoiceGateway[OHC Voice Gateway Service];
      VoiceGateway <-->|Bi-directional Audio Stream| LLM[OpenAI Realtime API / Gemini Live API];
      LLM -->|Tool Calls (JSON)| Orchestrator[KAIROS Orchestrator];
      Orchestrator -->|Query Availability| OpsAgent[AI Operations Agent];
      Orchestrator -->|Quote Generation| SalesAgent[AI Sales Agent];
      OpsAgent <--> DB[(PostgreSQL + pgvector)];
      SalesAgent <--> DB;
      Orchestrator -->|Push Notification| MobileApp[OHC Mobile App (Carlos/Fatima)];
  ```

  ### Mobile UX Flow (375px First)
  1. **Activation (Zero Friction):** Under the "Sales & Acquisition" tab, the user taps a glassmorphic card labeled "Voice Receptionist".
  2. **Configuration:** A single screen with:
     - A dropdown for "Agent Voice" (e.g., Friendly, Professional).
     - A toggle for "Multi-lingual Support" (auto-detects Spanish/Arabic/English).
     - A big "Activate Business Number" button.
  3. **Provisioning:** OHC securely provisions a Twilio phone number in the background. A success screen shows the new number: "Your AI Receptionist is now live at (555) 123-4567."
  4. **Call Logs & Transcripts:** A clean list view where each missed/handled call appears as an interactive card. Tapping a card shows a summary generated by the AI (e.g., "Booked plumbing repair for Tuesday 2 PM") and an option to play the audio recording or view the text transcript.

  ### AI Agent Integration Points
  - **Customer Success ("The Ambassador"):** Acts as the primary persona over the phone. Uses RAG against the business's policy and FAQ memory.
  - **Sales & Acquisition ("The Salesperson"):** Called upon mid-conversation via tool calls to generate price quotes based on the customer's verbal description of the problem.
  - **Operations ("The Manager"):** Invoked via tool calls to check the booking calendar, find an open slot, and commit the appointment to the database.

  ### Key Design Decisions
  - **Streaming over REST:** Must use WebSocket-based media streams directly to the LLM (OpenAI Realtime API) to achieve latency under 500ms. Conversational latency higher than 1 second breaks the illusion of a human-like assistant.
  - **Tool Calling as State:** The voice model must have access to specific OHC tool calls (e.g., `check_calendar`, `book_appointment`, `get_pricing`) to bridge the audio domain to the OHC core database.
  - **Multi-Tenant Isolation:** Twilio WebSockets must authenticate to the OHC Voice Gateway using a generated JWT tied strictly to the `tenant_id` associated with the provisioned phone number.

  ## Implementation Prompt
  **For the Implementer Agent:**
  Implement the Voice Gateway architecture for the Autonomous AI Voice Receptionist.
  1. Create a new service in the Go backend that accepts inbound WebSocket connections from Twilio Media Streams.
  2. Implement a duplex bridge that forwards audio payloads from Twilio to the OpenAI Realtime API (or configured LLM provider) via WebSockets.
  3. Add tool-call handlers within the Voice Gateway that interface with the KAIROS Orchestrator (e.g., responding to `check_availability` by querying the PostgreSQL database for the `tenant_id`).
  4. Update the mobile API to allow a tenant to provision a Twilio number and select voice preferences.
  5. Provide comprehensive unit tests for the audio bridging logic and E2E Playwright tests that simulate an inbound WebSocket connection and verify the database booking state.
