  # Research Report: Expanding the Agent Feed Ecosystem for Operations

  ## Executive Summary
  This report identifies a significant gap in the OHC platform's Agent Feed component. Currently, the Agent Feed primarily focuses on low-stock alerts from the Operations Agent and general message drafting from the Customer Success Agent. However, the true vision of "Invisible AI Automation" requires a more comprehensive and proactive Operations Agent that coordinates a broader spectrum of daily work tasks directly through the feed.

  ## 1. Market Mapping & Competitor Discovery (Track 1)
  Competitors like Monday.com and Asana provide robust task management but rely entirely on manual user input or static rule-based automations. Shopify Sidekick (in preview) attempts to assist with commerce tasks, but lacks deep integration into daily, offline operational workflows. OHC's unique value proposition is shifting from "dashboards and task lists" to "proactive agent suggestions" via the Agent Feed.

  ## 2. OHC Gap & Pain Point Identification (Track 3)
  - **Persona Focus:** Jun (Location Manager) and Carlos (Field Service Owner).
  - **The Gap:** Jun spends significant time manually coordinating daily location prep (e.g., "Check patio seating," "Restock receipt paper"). Carlos struggles to manage ad-hoc tasks between service calls. Currently, they must manually enter and track these tasks. The Operations Agent should proactively generate and push these routine and context-aware tasks into their Agent Feed based on schedules, recent events, or anomalies, requiring only a simple "Approve" or "Complete" tap.

  ## 3. Deep Dive Architecture Design (Track 2 & Track 3)

  ### Data Model & Intent
  - We will leverage the existing `agent_feed_items` and `department_tasks` tables.
  - Introduce new event sources and context payloads for the Operations Agent specifically aimed at "Routine Operations" and "Anomaly Resolution."

  ### AI Agent Coordination
  - **Operations Agent ("The Manager"):** Will be expanded to include a chron-based task generator (simulated via background jobs or triggered by start-of-day events). It will analyze the tenant's business type (e.g., Food & Beverage vs. Service) and generate relevant daily operational tasks, pushing them as `agent_feed_items`.

  ### Mobile-First Implementation
  - Ensure the new task-oriented Action Cards in the Agent Feed are perfectly formatted for a 375px viewport.
  - Buttons for "Mark Complete", "Assign to Staff", or "Dismiss" must be prominent and easily tappable (≥ 44x44px).

  ## 4. Proposed Implementation Steps & Issue Prompt

  **Feature Name:** OHC Proactive Operations Task Feed

  **Target Persona:** Jun the Location Manager

  **Outcome:** Jun opens his OHC app at 7:00 AM and sees a prioritized feed of daily prep tasks generated by the Operations Agent, tailored to his specific location's needs, without having to configure them manually.

  **Critical User Journey (CUJ):**
  1. Jun logs into the OHC mobile app in the morning.
  2. His Agent Feed displays 3 new Action Cards generated by the Operations Agent: "Review Daily Prep Checklist", "Follow up on delayed supplier delivery from yesterday", and "Staffing alert: Only 1 person scheduled for closing shift."
  3. Jun taps "Review Checklist" and quickly marks items complete.
  4. He taps "Assign to Sarah" on the supplier follow-up card.
  5. He taps "Draft Schedule Request" on the staffing alert card, utilizing the Assistant's drafting capability.

  **Next Actions for Engineering:**
  - **Step 1:** Enhance the Operations Agent logic (in `src/server/services/ops` or similar) to generate scheduled and context-aware operational tasks.
  - **Step 2:** Ensure these tasks are correctly mapped to `agent_feed_items` with appropriate UI payloads for rendering task-specific Action Cards.
  - **Step 3:** Implement the necessary frontend components in Tauri to render these new Action Card types and handle the associated actions (Complete, Assign, Dismiss).

  **Priority:** P2
  **Estimated Scope:** Medium
