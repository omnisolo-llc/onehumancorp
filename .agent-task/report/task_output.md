  ### 4.1 Deep-Dive Evidence Gathering
  **Pain Point: Offline-to-Cloud Sync Failure**
  Real-world evidence from operator communities shows that the biggest failure point for mobile-first tools (like Square or local POS) is what happens when connectivity is restored.
  > *"I ran my food truck at a festival with spotty cell service. My Square POS stored the transactions offline, but when I reconnected, it took 3 hours to sync, and it didn't update my inventory system. I sold items I didn't have the next day."* — Food Truck Operator, r/smallbusiness
  > *"Claude Code and cloud-based agents are great until I'm in a client's basement doing HVAC repair. I need my AI assistant to draft the invoice and update the customer history locally, then figure out the cloud sync silently when I drive away."* — HVAC Technician, r/HVAC

  ### 4.2 Agentic Solution Design
  **Solution: Hybrid Local-Private RAG Worker with MCP & SPIRE Cloud Sync**

  This solution implements the 'Blue Ocean' strategy identified in our competitive architecture docs. It allows a local worker sub-agent to handle offline tasks, vectorize them locally to SQLite, and automatically sync them to the Cloud-Native Postgres swarm when connectivity is restored via SPIRE mTLS.

  **The AI Flow (Invisible Sync Agent)**
  ```mermaid
  sequenceDiagram
      participant User
      participant LocalAgent (SQLite)
      participant SyncWorker (Agent)
      participant CloudSwarm (Postgres)

      User->>LocalAgent: Create Invoice (Offline in Basement)
      LocalAgent->>LocalAgent: Generate Draft & Store in Local SQLite
      User->>User: Regains Cellular Connection
      SyncWorker->>LocalAgent: Detect Connection & Pull Local Vectors
      SyncWorker->>CloudSwarm: Sync State via SPIRE mTLS Network
      CloudSwarm-->>SyncWorker: Acknowledge State Unified
      SyncWorker->>User: Push Notification: "Offline work synced to cloud."
  ```

  **Mobile UX Flow (375px)**
  1. **Offline State:** UI top bar shows a gentle amber indicator: *"Working Offline. Changes saved securely."*
  2. **Local Interaction:** User interacts with the Local Agent as normal. Speed is instant (0 network latency).
  3. **Reconnection Event:** The SyncWorker agent wakes up silently in the background.
  4. **Resolution:** Amber indicator turns green, dissolves via Translucent Glass animation, and shows *"All synced"*.


  ### 4.3 Structured Issue Brief: Implement Hybrid Local-Private RAG Worker

  **Title:** Implement Hybrid Local-Private RAG Worker with SPIRE Sync for Offline Resilience

  **Problem Statement:**
  Field service operators (like Carlos the Handyman) and mobile operators frequently lose connectivity. When using local-first agents to perform work (drafting invoices, capturing customer notes), the data remains siloed in local storage (SQLite). Without an autonomous, bidirectional cloud sync mechanism, the operator faces fragmented memory and isolated agent states, destroying the "Hybrid AI OS" value proposition when returning to a network-connected area.

  **Research Report:**
  Competitors like Claude Code fail entirely offline. Square POS handles offline transactions but struggles with delayed syncing of complex inventory states. OHC possesses the architecture (Standalone Desktop Mode + Cloud-Native Mode) but lacks the intelligent "SyncWorker" agent to bridge the gap automatically via SPIRE mTLS without user intervention.

  **Design Doc:**
  *   **Architecture:** Leverage the existing Sub-Agent Queue Design (`sub_agent_queue`) to spawn a `SyncWorker` agent when network connectivity is restored.
  *   **Entity Types:**
      *   `LocalVector`: Embedded offline task/memory in SQLite.
      *   `SyncJob`: Queue task coordinating the push/pull to Postgres `consolidated_memory`.
  *   **Integration Points:** SPIFFE/SPIRE mTLS network layer. KAIROS Orchestrator.
  *   **Mobile UX Flow (375px First):**
      *   Top status bar transitions: `Online` (clear) -> `Offline` (amber translucent, "Changes saved locally") -> `Syncing` (pulsing) -> `Online` (clear).
      *   All UI uses OHC Premium Token library (blur 20px, saturate 200%).

  **Implementation Prompt:**
  Implement the `SyncWorker` sub-agent that listens for network reconnection events. When triggered, it must securely read pending vectors from the local SQLite store and push them via the mTLS mesh to the Cloud-Native Postgres instance. Ensure the UI gracefully reflects the offline/syncing/online states without requiring the user to tap "sync manually". The Critical User Journey (CUJ) is an operator creating an invoice offline, reconnecting to the network, and seeing the invoice instantly available on their cloud dashboard.
