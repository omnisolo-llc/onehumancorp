issue_title: "Implement Mobile-First Unified Agent Feed for OHC Operators"
issue_description: |
  ## Problem Statement
  Legacy platform architectures treat mobile apps as supplementary "dashboards" while requiring a desktop view for store building, complex management, and executing critical actions. For small business owners (like Maya the baker, Fatima the food cart owner, or Carlos the handyman), who operate primarily or entirely from their 375px mobile screens, this causes setup paralysis, missed opportunities, and operational friction. They need to handle multi-faceted operations—fulfilling orders, drafting marketing emails, managing discounts, or replying to DMs—from a single, intuitive interface on their phone without navigating a complex labyrinth of toggles or needing a desktop computer.

  ## Research Report
  Based on the global SMB market research and mobile-first design documents, the current pain points in legacy systems (Shopify, Wix, Squarespace) include setup paralysis, desktop-only management tools, omnichannel chaos, and lack of true mobile operability.
  In contrast to Link-in-Bio tools which are simple but lack robust backend commerce support, the proposed solution shifts from a static dashboard paradigm to an **"Approval" Interface Paradigm**. Rather than relying on traditional multi-step forms, OHC utilizes invisible AI agents (Operations, Marketing, Advisory) to draft logic, workflows, and messages. These are presented to the user as actionable "cards" within a unified feed, turning complex multi-step processes into single "Approve" touch actions.

  ### UI Wireframes & Mobile UX Flow (375px)
  1. **Home Screen**: A vertically scrolling feed containing context-aware Agent Proposals.
  2. **Card Design**:
      - **Context**: Icon/Color coding based on Agent (Operations: Blue, Advisory: Purple, Marketing: Green).
      - **Content**: Concise text (e.g., "3 new orders to fulfill", "Drafted an Instagram post for your new cake").
      - **Interaction**: Minimum 44x44px touch target buttons (e.g., [Fulfill Now], [Review & Post], [Approve]).
  3. **Interaction Flow**:
      - User taps a primary action button on a card.
      - The card expands inline with a macOS Translucent Glass styling effect.
      - The user reviews the details, makes minor edits if necessary (using native mobile keyboards), and confirms the action.
      - The card shows a succinct "Task Completed" state before fading out of the primary feed.

  ### AI Agent Integration
  - **Triggers**: Agents run asynchronously (via the existing `SKIP LOCKED` PostgreSQL job queue) based on events (new order, stale inventory, DM received) or temporal checks (e.g., 30 days since the last promo).
  - **Proposals**: Agents create structured proposal objects. The feed API aggregates these into unified notification cards.
  - **Execution**: Upon user approval, the feed API triggers the execution payload tied to the proposal, invoking the respective service (payment capture, email dispatch, social post).

  ## Implementation Prompt
  **User-Facing Outcome**: Launch a "Unified Agent Feed" on the mobile app home screen that replaces standard dashboards. It should render AI-generated task proposals as actionable cards, allowing the user to approve complex operations in one tap.
  **Critical User Journey (CUJ)**:
  1. User opens the OHC mobile application on a 375px screen.
  2. User views the primary dashboard showing a vertical feed of three distinct Agent Proposal cards (e.g., fulfilling orders, a drafted marketing email, and an auto-generated social post).
  3. User taps the primary action button (e.g., "Yes, draft it") on an advisory card.
  4. The card smoothly expands to display the AI-drafted content with translucent glass styling.
  5. User taps "Approve & Send", triggering the underlying execution logic, and the card updates to a completed state before disappearing.
  **Acceptance Criteria**:
  - The UI must be fully functional and optimized for a 375px viewport with no horizontal scrolling.
  - All actionable buttons must have a minimum touch target size of 44x44px.
  - The visual style must use OHC Premium Tokens (clean typography, translucent glass materials).
  - The feed correctly segregates and prioritizes cards generated by the Operations, Marketing, and Customer Service agents.
  - E2E tests (Playwright) must verify that interacting with the cards completes the simulated workflow end-to-end without mocking internal API or database requests.
