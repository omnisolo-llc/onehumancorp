  # Mission Queue Protocol: OHC AI Operations & Analytics Copilot

  ## Title
  OHC AI Operations & Analytics Copilot - Unifying Fragmented Business Visibility

  ## Problem Statement
  Small business owners (Maya, Carlos, Priya) suffer from "dashboard fatigue." They use multiple disjointed tools (Shopify for sales, Jobber/Square for bookings, Quickbooks for finance) to understand their business state. This requires technical context switching and manual correlation. They don't want to "read dashboards"; they want plain-language answers like "Why are cake sales down this week?" or "Which service routes are most profitable?" OHC currently lacks a unified, agent-driven insight layer that answers these questions proactively and naturally.

  ### Track 2: Deep-Dive Competitor Audit (Shopify Magic / Sidekick)
  **Capabilities:** Sidekick acts as a deeply integrated commerce assistant. It can query store data ("How many sales today?"), execute actions ("Put all summer shirts on sale"), and draft content.
  **Success Factors:** Zero configuration required. It understands the underlying data schema natively. High delight comes from natural language actions replacing complex UI navigation (e.g., bulk discount application).
  **User Sentiment Audit:** Users love the time saved on mundane tasks (writing product descriptions). Complaints focus on its inability to handle complex cross-system logic (e.g., tying a Shopify sale to an external booking or specific customer service interaction). It is strictly e-commerce bound.

  ### Track 3: OHC Gap & Pain Point Identification
  **OHC Gap:** OHC has basic dashboards, but lacks conversational analytics and cross-domain action correlation. An owner cannot ask "How many cake deliveries do I have tomorrow, and what is the total expected revenue from them?"

  **Persona-Specific Pain Points:**
  - **Maya (Baker):** Spends an hour every evening matching Instagram DM deposits against Square transactions. Wants to ask, "Which custom orders are fully paid for tomorrow?"
  - **Carlos (Handyman):** Switches between Jobber (schedule) and QuickBooks (invoices). Needs to know, "Did my 2 PM job pay the invoice yet?" without opening a laptop.
  - **Priya (Boutique):** Needs to know which variants are running low before launching an Instagram sale. "What’s my lowest stock item right now?"

  ### Track 4: Deeper Focused Research & Agentic Solutions
  **Evidence:** Salon owners on GlossGenius and field service workers on Jobber frequently request "daily summary" features to avoid parsing reports.
  **Agentic Solution:** Implement a "Finance & Decision Assistant" capability. An AI agent that has real-time read access (via internal tools/APIs) to the unified OHC Postgres database (across bookings, orders, and messages) and can present plain-language daily summaries and answer natural language data queries.

  ## Design Doc

  **High-Level Architecture:**
  - **Entity:** `AnalyticsQuery`, `DailySummary`
  - **Agent Tooling:** Expose internal read-only API endpoints (e.g., `GetDailyRevenue`, `GetPendingBookings`, `GetUnansweredMessages`) to the primary Gemini LLM agent via the existing tool-calling framework.
  - **Memory:** The agent stores recent summaries in the `tenant` scoped memory to maintain context (e.g., "Yesterday was slow, but today is busy").

  **UI/UX (Mobile-First 375px):**
  - **Home Screen "Command Center":** Replace static metric cards with a dynamic, conversational "Morning Briefing" card generated by the agent.
  - **Insight Chat:** A dedicated tab or sticky floating action button to chat with the Decision Assistant.
  - **Visuals:** Use the OHC Premium Token library (translucent materials, clear typography). Instead of tables, use narrative text with inline, tappable "Action Pills" (e.g., "[Review 3 Unread DMs]", "[Send Invoice for $150]").

  **Competitive Landscape Matrix**
  | Competitor | Natural Language Query | Cross-Domain (Comm+Ops) | Zero-Config Setup | Mobile First UX |
  | --- | --- | --- | --- | --- |
  | **Shopify Sidekick** | Yes | No (Comm only) | Yes | Good |
  | **Jobber AI** | No | No (Ops only) | No | Good |
  | **HubSpot Breeze** | Yes | Partial | No | Poor |
  | **Notion AI** | Yes | No (Docs only) | Yes | Average |
  | **OHC (Proposed)** | Yes | Yes (Unified) | Yes | Excellent |

  **Architecture Flow (Mermaid)**
  ```mermaid
  graph TD
    A[Owner Query] --> B(Command Center UI)
    B --> C{Work Triage Agent}
    C --> D[Decision Assistant]
    D --> E[(Tenant Postgres DB)]
    E --> D
    D --> F[Draft Summary]
    F --> G[Present Action Pills to Owner]
  ```

  **Agent Integration:**
  - Introduce a new System Prompt for the `DecisionAssistant` role.
  - Route user analytics queries ("How are we doing this week?") to this specific capability.

  ## Implementation Prompt
  Implement the "Morning Briefing" and conversational analytics feature.
  1. **Backend:** Create internal, read-only tools for the AI agent to fetch aggregated daily/weekly stats for the current `tenant_id` (revenue, bookings, pending tasks).
  2. **Agent:** Update the agent routing to recognize analytics intents and utilize the new tools to generate a "Morning Briefing" summary.
  3. **Frontend (Tauri/Flutter):** On the main dashboard, display the AI-generated "Morning Briefing." Allow the user to ask follow-up questions in the unified chat interface. Ensure the UI looks excellent on a 375px width screen using standard OHC design tokens.
  4. **CUJ:** User logs in at 8 AM. They see: "Good morning Maya. You have 3 custom cake deliveries today totaling $450, and 2 unanswered DMs." User types "Who are the DMs from?" and the agent responds with context.
