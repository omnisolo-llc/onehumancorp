  # Deep-Dive Competitor Audit (Track 2): Shopify Sidekick

  ## Capabilities ("What they can do")
  - Context-aware answers about the merchant's store data (sales, orders, inventory).
  - Ability to execute tasks (e.g., "Put all my summer t-shirts on sale at a 20% discount").
  - Content generation (email drafts, product descriptions, blog posts).
  - Store setup assistance and configuration guidance.

  ## Success Factors
  - **Data Gravity**: Sidekick has direct, zero-setup access to the merchant's entire catalog, customer list, and sales history.
  - **Action-Oriented**: It doesn't just answer; it executes (e.g., changing prices, creating segments).
  - **Embedded UI**: Resides directly in the admin panel, always accessible as a slide-out drawer.

  ## User Sentiment Audit
  - **Positives**: Time savings for routine tasks (like writing descriptions), quick answers to "how to do X in Shopify".
  - **Negatives**: Struggles with complex, multi-step operational logic (e.g., "coordinate with my supplier and delay these 5 shipments"). Feels more like a command-line interface for Shopify than a true proactive *assistant*. It waits for commands rather than highlighting what needs attention today. Many users on r/ecommerce mention it's "cool but I still have to know what to ask it."

  # OHC Gap & Pain Point Identification (Track 3)

  ## OHC Gap Matrix vs Shopify Sidekick

  | Feature | Shopify Sidekick | OHC (Current State) | OHC Target |
  |---------|------------------|---------------------|------------|
  | Context-Aware Q&A | Yes (Inventory/Sales) | Partial | Full (Cross-Domain) |
  | Task Execution | Yes (Price drops, segments) | No | Yes (Proactive & Reactive) |
  | Multi-Channel Comms | No (Mostly internal) | No | Yes (DMs, SMS, Email) |
  | Proactive Triage | No (Reactive) | No | Yes ("What needs attention today") |
  | Mobile-First | No (Desktop heavy) | Yes | Yes (Native 375px feel) |

  ## Unresolved Pain Points (Market-wide)
  - **The "Blank Slate" Assistant**: Most AI tools require the owner to figure out *what* to ask. Owners don't have time to prompt an AI; they want the AI to tell them what needs doing.
  - **Siloed Execution**: You can draft an email in ChatGPT, but you have to copy it to Gmail, check inventory in Square, and update a spreadsheet.
  - **Mobile Unfriendly**: Deeply complex admin dashboards are impossible to use on a 375px screen while running a food cart or managing a boutique floor. Carlos (handyman) and Fatima (food cart) cannot use a complex sidebar menu on their phones.

  # Focused Research & Agentic Solutions (Track 4)

  ## Agentic Solution: The "Proactive Morning Briefing" & "Action Feed"
  Instead of a chat box waiting for input, OHC should present a unified "Action Feed" when the owner opens the app.
  - **Work Triage Agent**: Ingests DMs, low stock alerts, and new bookings overnight.
  - **Customer Assistant Agent**: Drafts suggested replies.
  - **UI Presentation**: The owner sees: "3 urgent messages drafted, 2 orders need fulfillment, 1 anomaly in recent payments." One tap to review and approve.

  ## Design Doc
  - **Architecture**:
    - **Entity Types**: `ActionItem`, `TriageEvent`, `AgentDraft`.
    - **Key Relationships**: `ActionItem` linked to `Tenant`, generated by `TriageEvent` queue.
    - **Integration Points**: AI Job Queue evaluates incoming webhooks (e.g., Stripe, Instagram DMs) and triggers `Work Triage` agent.
  - **UI Wireframes**:
    - **Mobile First (375px)**: Main screen is not a dashboard of charts, but a vertical scroll of Action Cards. Each card has a one-sentence summary (e.g., "Maya asked about a custom cake for Saturday") and a primary action button (e.g., "Review drafted reply").
    - **Translucent Materials**: Use OHC Premium Tokens for glass-morphic, depth-layered cards indicating urgency (red/orange accents for urgent, clear for normal).
  - **AI Agent Integration**: Gemini Pro processes the context and emits structured JSON for the Action Card draft.

  ## Implementation Prompt
  **Outcome**: When Carlos or Maya opens the OHC app, they are immediately presented with a prioritized "Action Feed" of what needs their attention today. The system must process incoming simulated events (messages, bookings) and display them as actionable cards with AI-drafted responses or next steps.
  **Critical User Journey (CUJ)**:
  1. Owner logs into the app (375px mobile view).
  2. Owner sees the "Morning Briefing" with 3 pending items.
  3. Owner taps "Review drafted reply" on an Instagram DM inquiry.
  4. Owner sees the AI-drafted message, makes a quick edit, and taps "Send & Book".
  **Acceptance Criteria**:
  - The UI must be fully functional on a 375px width screen without horizontal scrolling.
  - Action cards must clearly explain *why* the item needs attention.
  - The AI must proactively draft the response, so the user only has to approve/edit.
