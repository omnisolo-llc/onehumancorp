  # OHC Universal Assistant Workstation (Jarvis-Parity)

  ## Title
  OHC Universal Assistant Workstation & Native Tools

  ## Problem Statement
  Small business owners and operators (Maya, Carlos, Leo, Nora) need a central "Jarvis" to orchestrate their work—from modifying inventory and generating social posts to drafting reports and approving payments. Currently, they must navigate a fragmented dashboard or manage separate standalone chat interfaces. The lack of a native, permissions-gated, integrated assistant means the AI cannot perform meaningful side-effects (like modifying local files, sending external messages, or creating invoices) safely without a dedicated execution workspace.

  ## Research Report
  - **The "Jarvis" Gap**: As defined in `2026-06-07-jarvis-workbuddy-parity-design.md`, OHC lacks a primary `assistant` surface that matches Tencent WorkBuddy's capabilities.
  - **Permission & Safety**: AI systems in SMB contexts require a "Guarded Default" mode. File writes, system changes, or outbound communications must route through an explicit user-approval interface rather than failing silently or acting recklessly.
  - **Artifact Generation**: The output of an agent's work shouldn't just be chat text; it needs to be durable artifacts (CSV, PDF, HTML preview) that the owner can verify and download.

  ## Design Doc
  ### Architecture Diagram
  ```mermaid
  graph TD
      A[User Input / Remote Chat] --> B(Assistant Route: /assistant)
      B --> C[Task Execution Engine]
      C --> D{Permission Gateway}
      D -->|Safe/Read-only| E[Tool Execution]
      D -->|High Risk / Write| F[Approval Queue]
      F -->|User Approves| E
      E --> G[Artifact Generation]
      G --> H[Artifact Store]
      H --> I[Result Panel / Chat Thread]
  ```

  ### UI Wireframes & Mobile UX Flow (375px First)
  - **Layout**:
    - **Main Area**: Conversational thread displaying agent reasoning, tool invocation markers (e.g., "Agent is reading local files..."), and standard chat interactions.
    - **Results Panel (Right Drawer on Desktop, Bottom Sheet on Mobile)**: Displays generated artifacts (e.g., a preview of a drafted email or a generated spreadsheet of inventory).
    - **Approval Card**: Inline within the chat stream. When a high-risk tool (e.g., `hybrid_fs_write`) is called, an actionable card appears: "Agent wants to overwrite `menu.md`. [View Diff] [Approve] [Deny]".
  - **Mobile Constraints**: The results panel and chat stream must be perfectly legible on a 375px width, utilizing vertical stacking. Touch targets for approvals must be 44x44px minimum.

  ### AI Agent Integration Points
  - **Planner & Execution Loop**: Integrate the existing tool frameworks (MCP, `HybridFSMcpServer`) into a unified Task loop that understands the concept of a `Workspace`.
  - **File Operations**: Utilize the `hybridfsmcp` server for local sandbox/file operations, ensuring that mutations trigger the `Permission Gateway`.

  ### Key Design Decisions
  - **Explicit Workspaces**: Tasks are bound to a Workspace, which defines default directories and memory scope.
  - **First-Class Artifacts**: Any output file generated by the agent is tracked as an `Artifact` record, not just a stray file on disk, enabling versioning and easy retrieval.

  ## Implementation Prompt
  **Feature Name**: Jarvis Workstation Core

  **Target Persona**: Nora (Agency Principal needing to draft and approve proposals)

  **Next Actions for Engineering**:
  1.  **Data Schema**: Define the PostgreSQL schema for `AssistantWorkspace`, `AssistantTask`, `AssistantMessage`, and `AssistantArtifact` with strict multi-tenant isolation.
  2.  **API Layer**: Implement the basic REST/gRPC endpoints for creating a workspace, starting a task, streaming messages, and handling approval callbacks.
  3.  **UI Foundation**: Create the `/assistant` route in the Tauri frontend. Implement the basic chat interface and the results panel (Artifacts tab).

  **Acceptance Criteria**:
  - A user can navigate to `/assistant` and start a new task.
  - The task executes a basic agent loop and returns a text response.
  - The data model successfully persists the task, messages, and any generated artifacts to PostgreSQL.
