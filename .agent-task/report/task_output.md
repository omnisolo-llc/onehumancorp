  # Mission Queue Protocol: Stripe Integration Research

  ## Problem Statement
  Owners need a reliable, trusted way to collect money for their services (deposits, invoices, and final payments) without constantly checking their bank accounts or manually matching payments to jobs. Currently, OmniSolo has fragmented Stripe implementations and placeholders (e.g., generating checkout-looking UUIDs without creating real provider sessions), preventing owners from having a verified, end-to-end cash collection and reconciliation process.

  ## Research Report: Stripe & Stripe Connect
  **Value Proposition & Usability:**
  Stripe is the industry standard for payment processing, offering immediate trust for end-customers and comprehensive tools for owners. For a non-technical owner, Stripe Connect allows seamless onboarding where they can link their existing bank account or create a new Stripe account in minutes.

  **Capabilities & Limits:**
  - **OAuth / Onboarding:** Stripe Connect (Express or Standard) provides a hosted onboarding flow, handling KYC and identity verification. OAuth scopes can be tightly restricted to only create payments and read balances for the specific tenant.
  - **Webhooks:** Stripe provides robust webhook delivery with built-in retry logic (up to 3 days) and signature verification (`Stripe-Signature` header) to ensure authenticity. Webhooks can handle events like `checkout.session.completed`, `invoice.paid`, and `payment_intent.succeeded`. Deduplication is handled via event IDs.
  - **Quotas & Limits:** Stripe API allows 100 read/write operations per second in live mode, which is well above the required threshold for our current scale.
  - **Commercial Terms:** Standard pricing is 2.9% + 30¢ per successful card charge, directly absorbed by the owner's customer or the owner. No direct SaaS fees for the basic Connect infrastructure.
  - **Deployment & Security:** API keys and restricted keys must be securely stored in the Connection Vault. PCI compliance is offloaded to Stripe by using Stripe Checkout and Payment Links, meaning OmniSolo never touches raw credit card data.

  ## Design Doc
  **Integration Strategy:**
  - **Authentication & Onboarding:** Use Stripe Connect OAuth to securely onboard owners. Store the `stripe_account_id` and restricted refresh/access tokens in the `ConnectionVault`.
  - **Checkout Flow:** When a proposal is approved or an invoice is generated, the agent will call the Stripe API to create a `checkout.session`. The system will persist the Stripe session ID with a "pending" state in the database, rather than fabricating a fake UUID URL.
  - **Reconciliation:** A dedicated webhook listener will securely verify the Stripe signature. Upon receiving `checkout.session.completed` or `invoice.paid`, the system will idempotently update the invoice state to "paid" and trigger the corresponding department event to continue the fulfillment workflow.
  - **Revocation:** If an owner disconnects their Stripe account, the agent will gracefully fail payment requests and direct the user to reconnect.

  ## Implementation Prompt
  **User-Facing Outcome:**
  When an owner finishes setting up their business, they will click "Connect Payments" and be routed through Stripe's secure onboarding. Once connected, any proposal or invoice generated by the AI team will include a real Stripe Checkout link. When their customer pays, the system will automatically mark the job as paid, notify the owner, and advance the workflow, completely eliminating manual reconciliation.

  **Acceptance Criteria:**
  1. Remove placeholder UUID checkout URL generation and replace it with real Stripe Checkout Session creation.
  2. Ensure Stripe credentials (Account ID / OAuth tokens) are securely read from the existing `ConnectionVault`.
  3. Implement a webhook endpoint that verifies the `Stripe-Signature` header and idempotently updates payment states.
  4. Ensure any failure to connect to Stripe or missing credentials fails cleanly and informs the user/agent.
