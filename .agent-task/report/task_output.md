issue_title: Implement Universal Triage Inbox to Close Omnichannel Fragmentation Gap
issue_description: "# Autonomous Work Assistant Market & Shopify Sidekick Deep-Dive\n\n## 1. Problem Statement\nNon-technical owners and operators (bakers, repair businesses, boutiques) are overwhelmed by complex multi-tool platforms. They lack the time to operate complex admin interfaces and need actionable AI that acts as a proactive co-worker rather than a passive chatbot. Current tools (e.g., Shopify, Notion) require high-friction setup, lack cross-domain operational intelligence, and force the owner into technical maintenance.\n\n## 2. Research Report: Market Mapping\n\n### Top 10 General Competitors\n1. Shopify - Leading e-commerce platform transitioning to AI assistance.\n2. Square - POS and small business suite.\n3. Wix - Website builder with basic CRM/Scheduling.\n4. HubSpot - Complex CRM and marketing automation.\n5. Notion - General productivity and wiki with AI.\n6. Microsoft Copilot - Enterprise-heavy integrated AI.\n7. Tencent Workbuddy - Dominant ecosystem orchestration.\n\
  8. WeCom - WeChat ecosystem B2B gateway.\n9. DingTalk - Alibaba's SMB operation backbone.\n10. Feishu / Lark - ByteDance's all-in-one productivity suite.\n\n### Top 10 AI-Native Competitors\n1. Replit Agent - Code-first assistant for builders.\n2. Claude Code - High-context terminal agent.\n3. Devin - Autonomous software engineer.\n4. Sierra - Customer support agentic workflows.\n5. AutoGPT - Open-source autonomous agent framework.\n6. MultiOn - Web automation agent.\n7. Lindy.ai - Personal AI executive assistant.\n8. Synthflow - AI voice assistant for SMBs.\n9. Bland AI - High-volume conversational AI phone agent.\n10. ChatGPT Plugins/GPTs - Custom task-specific bots.\n\n---\n\n## 3. Deep-Dive: Shopify Sidekick\n\n### Capabilities\n- Commerce-aware conversational AI inside Shopify Admin.\n- Generates store analytics, modifies theme settings, and answers support queries.\n- Drafts product descriptions and email campaigns.\n\n### Success Factors\n- **Frictionless Integration:** Native access\
  \ to all store data (inventory, sales).\n- **Domain Specificity:** Deeply understands e-commerce taxonomy.\n\n### User Sentiment Audit (App Store / Forums)\n- *Pros:* \"Finally I don't have to search menus to find discount settings.\"\n- *Cons (The Gap):* \"Sidekick only helps with the store. It doesn't know my schedule, my suppliers, or my offline tasks.\" \"It's still an admin tool, not an operator tool.\"\n\n---\n\n## 4. OHC Gap & Pain Point Identification\n\n### OHC Feature Audit\n- Strong foundation in Kairos state orchestration and distributed sub-agents.\n- Multi-tenant architecture and mobile-first approach.\n\n### Gap Matrix\n\n| Feature | OHC Current | Shopify Sidekick | Target State |\n| :--- | :--- | :--- | :--- |\n| **Cross-Domain Operation** | Low | Low (Commerce only) | High |\n| **Proactive Action Feed** | Medium | Low | High |\n| **Offline-First Resilience** | Low | Low | High |\n\n### Unresolved Pain Point\n**The Omnichannel Fragmentation Gap:** Owners like Maya (Baker)\
  \ manage DMs on Instagram, orders in a notebook, and payments via Venmo. No single system unifies these streams seamlessly without demanding IT setup.\n\n---\n\n## 5. Design Doc: The OHC Universal Triage Inbox\n\n### High-Level Architecture\n- **Entities:** `UnifiedMessage`, `IntentClassification`, `SuggestedAction`.\n- **Integrations:** Social Webhook Gateway, OHC Task Queue.\n- **AI Agent Integration:** `CustomerAssistantAgent` monitors the incoming event bus, drafting responses and proposing structured state transitions (e.g., \"Draft Invoice for Custom Cake\").\n\n### Mobile UX Flow (375px)\n1. **Home Screen:** \"Triage Feed\" displaying consolidated urgent messages and agent-drafted proposals.\n2. **Action Card:** User taps a message. The screen shows the original text, the inferred customer context, and 1-3 highly visible action buttons (e.g., \"Approve Reply & Send Quote\", \"Modify Terms\").\n3. **Completion:** Minimal translucent success state, automatically advancing to the next\
  \ priority.\n\n### Mermaid Chart: Architecture & Flow\n\n```mermaid\ngraph TD\n    A[Incoming Social DM / Webhook] --> B(Webhook Gateway)\n    B --> C{Triage Orchestrator}\n    C -->|Intent: Inquiry| D[CustomerAssistantAgent]\n    C -->|Intent: Booking| E[OperationsAssistantAgent]\n    D --> F[Draft Reply & Quote]\n    E --> G[Draft Calendar Slot]\n    F --> H((Owner Action Feed))\n    G --> H\n    H -->|Owner Approves| I[Execute State Change]\n```\n\n---\n\n## 6. Implementation Prompt\n\n**Goal:** Implement the \"Unified Triage Feed\" on the Flutter/PWA mobile client and its supporting backend endpoints.\n\n**Critical User Journey (CUJ):**\n1. User (Maya) opens the app on her phone.\n2. The default screen is the Triage Feed, listing pending unapproved agent actions (e.g., drafted Instagram reply).\n3. Maya taps \"Approve\" on a drafted quote.\n4. The system executes the quote transmission and removes the item from the Triage Feed.\n\n**Acceptance Criteria:**\n- Backend API must provide\
  \ an endpoint to fetch agent-proposed actions.\n- Frontend must implement a 375px-optimized card layout for pending actions.\n- Action execution must update the local state optimistically and sync gracefully with the server.\n- The UI must NOT use mock data; it must consume real backend states.\n\n---\n\n## Priority: P0\n## Estimated Scope: Large\n\n---\n\n## 7.
