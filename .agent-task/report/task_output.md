  # Mission Queue Protocol Brief: Offline-First Unified Agent Action Feed

  ## Title
  [Mobile] Implement Offline-First Unified Agent Action Feed (375px)

  ## Problem Statement
  Business owners like Fatima (food cart operator in limited connectivity) and Carlos (handyman on the road) rely heavily on OHC for managing work. The current Agent Feed architecture requires an active, stable internet connection to load intent classifications, generated drafts, and push actions. When the connection drops, owners cannot see their immediate tasks, pending drafts, or upcoming schedules, causing friction, operational paralysis, and potential loss of revenue. They need to seamlessly view, approve, and queue tasks and communications while offline, with actions synchronizing back transparently when connectivity is restored.

  ## Research Report
  - **Context**: The existing Agent Feed (as detailed in `agent_feed_deep_dive.md`) is designed to classify intents and generate drafts proactively. However, based on mobile-first operational research (`ohc_smb_mobile_first_design_research.md`), operators in low-bandwidth environments need resilient edge persistence.
  - **Competitor Analysis**: Tools like Linear, Shopify POS, and modern link-in-bio suites buffer local state to prevent UI blocking. Shopify’s app handles offline POS elegantly but struggles with complex backend workflow configuration offline.
  - **Opportunity**: By implementing local SQLite-based caching (or IndexedDB for PWA) and a background sync queue, OHC can distinguish itself as a truly reliable "on-the-go" operator platform. The Agent Feed must support offline reading of generated cards and local queuing of "Approve/Discard" events.

  ## Design Doc
  ### High-Level Architecture
  - **Local State & Sync Manager**: A background worker that intercepts incoming Push/Websocket events and stores them locally.
  - **Offline Queue**: A persistent local table (`local_agent_action_queue`) that captures user decisions (e.g., "Approve Card 123").
  - **Conflict Resolution**: Last-write-wins with server validation on connection restore.

  ### Architecture Diagram
  ```mermaid
  sequenceDiagram
      participant Owner Mobile App
      participant Local Sync Engine (SQLite/PWA Cache)
      participant OHC Backend API
      participant Agent Orchestrator

      Owner Mobile App->>Local Sync Engine: App Load (Offline)
      Local Sync Engine-->>Owner Mobile App: Return Cached Action Cards
      Owner Mobile App->>Local Sync Engine: "Approve" Card #123
      Local Sync Engine->>Local Sync Engine: Save to Offline Queue
      Note over Local Sync Engine, OHC Backend API: Connection Restored
      Local Sync Engine->>OHC Backend API: Flush Offline Queue (Batch Sync)
      OHC Backend API->>Agent Orchestrator: Execute Approved Actions
      OHC Backend API-->>Local Sync Engine: Sync Ack & New Cards
  ```

  ### Mobile UX Flow (375px)
  1. **Launch**: User opens the app. Even if offline, the app loads instantly, showing the latest cached Agent Feed.
  2. **Offline Indicator**: A subtle UI banner (translucent glass styling) at the top reads "Working Offline. Changes will save automatically."
  3. **Interaction**: User taps "Approve" on a drafted email response. The card immediately transitions to a "Queued" state (e.g., subtle yellow status token) without waiting for a network request.
  4. **Restoration**: Upon reconnecting, the "Queued" state smoothly transitions to "Done" (green token) and disappears from the priority feed.

  ### AI Agent Integration
  - Drafts generated by the LLM on the server must include strict expiration TTLs to ensure that actions taken while offline don't approve horribly stale (e.g., >24h) contexts.
  - The local app will hide or explicitly label expired agent action cards.

  ## Implementation Prompt
  **Target Implementer**: Frontend/Mobile E2E Agent

  **User-Facing Outcome**: Fatima can open the OHC app in a dead zone, see the list of drafted pre-order replies generated by the Agent Feed 10 minutes ago, tap "Approve" on all three, and close the app. When she reaches a signal zone, the app syncs the approvals silently in the background.

  **CUJ**:
  1. Start app with active network, fetch 3 Agent Action cards.
  2. Simulate network offline (via Playwright or local config).
  3. User clicks "Approve" on the first card. UI immediately reflects success ("Saved for sync").
  4. User clicks "Discard" on the second card. UI reflects the removal.
  5. Simulate network online.
  6. Ensure background sync flushes the 2 actions to the backend successfully.
  7. Verify backend reflects the new state.

  **Acceptance Criteria**:
  - ZERO mock data; fetch real (or seeded) feed items.
  - Local persistence mechanism must survive an app restart while offline.
  - No blocking loading spinners on "Approve/Discard" when offline.
  - 100% test coverage for the sync queue logic.
