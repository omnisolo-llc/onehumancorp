  # Research Report: Universal Context-Aware Subagent Hand-Off Protocol

  <div markdown="1" style="backdrop-filter: blur(20px) saturate(200%); font-family: 'Outfit', 'Inter', sans-serif; border: 1px solid rgba(255, 255, 255, 0.1); padding: 20px; border-radius: 12px; background: rgba(255, 255, 255, 0.05); color: #fff;">

  ## 1. Problem Statement
  OneHumanCorp (OHC) is pioneering the "Hybrid Agentic OS" with components like the Shared Task List, Teammate Mesh, and AutoDream pipeline. However, a significant gap exists during inter-departmental agent collaboration.

  When the Operations Agent routes a complex multi-step request to the Finance Agent (e.g., "A customer requested a refund for this partially fulfilled order due to damage"), the Finance Agent often lacks the ephemeral, transient context that the Operations Agent holds in memory. Without a formalized, payload-agnostic Hand-Off Protocol, agents fall back to querying the entire `pgvector` memory store (AutoDream) or starting from scratch, leading to high latency, token waste, and potential hallucinations.

  Small business owners like Maya and Nora need these autonomous "departments" to act like a cohesive team passing a fully annotated folder to one another, rather than isolated silos.

  ## 2. Research Report
  Our competitive analysis indicates that monolithic agents (e.g., standard ChatGPT plugins) struggle with complex SMB tasks because they mix domains. OHC rightly isolated agents into domains (Operations, Finance, Marketing). However, reviewing the current KAIROS orchestration docs (`docs/technical/orchestration/orchestrator-design.md`), while there is a `MeshTransport` for sub-millisecond Pub/Sub and a `Shared Task List` for DAG dependencies, there is no standardized protocol for serializing the "Working Memory Context" during a task handoff.

  **Industry Benchmarks:**
  - **Shopify Flow**: Uses strict JSON schema typing for passing event data between apps, but lacks semantic reasoning context.
  - **Multi-Agent Frameworks (AutoGen, LangGraph)**: Utilize a shared "State" object passed between nodes.

  **OHC Needs:** A Universal Hand-Off Protocol over the Teammate Mesh that securely bundles the Task ID, the specific customer/entity context, and a semantic summary of the "Work Done So Far".

  ## 3. Design Doc: The Hand-Off Architecture

  ```mermaid
  sequenceDiagram
      participant Ops as Operations Agent
      participant Mesh as Teammate Mesh (Redis/Mem)
      participant State as Shared Task List (PG/SQLite)
      participant Finance as Finance Agent

      Ops->>Ops: Encounters Finance Domain Task
      Ops->>State: Creates Child Task in DAG
      Ops->>Mesh: Emits HandOffEvent(ContextBundle)
      Mesh->>Finance: Routes Event via Sub/Pub
      Finance->>State: Claims Child Task
      Finance->>Finance: Hydrates LLM Prompt with ContextBundle
      Finance->>Ops: Emits HandOffCompleteEvent(Result)
  ```

  ### Architecture Components:
  1.  **ContextBundle Protocol Buffer:** A new gRPC message definition (`context_bundle.proto`) that standardizes the payload sent over the `Teammate Mesh`.
  2.  **State Machine Extension:** Extending the `state_machine_transitions` table to include a `context_hash` or `handoff_payload` column (JSONB) to ensure durability if the Mesh fails.
  3.  **Hydration Engine:** A middleware layer in the Agent runtime that automatically injects the `ContextBundle` into the system prompt of the receiving agent before execution.

  ## 4. Implementation Prompt
  **For the Implementer Agent:**
  Your task is to implement the "Universal Context-Aware Subagent Hand-Off Protocol".

  **Critical User Journey (CUJ):**
  1. A multi-step task requiring two departments is initiated.
  2. Agent A creates a `ContextBundle` (containing the relevant tenant ID, entity ID, and a short text summary of the current context).
  3. Agent A routes this via the Teammate Mesh to Agent B.
  4. Agent B receives the task, and its initial LLM prompt is automatically enriched with the `ContextBundle` data, allowing it to complete the task without needing to redundantly query the database for the same context.

  **Acceptance Criteria:**
  - Do NOT prescribe specific DB schema changes or exact function names; design the interface and data flow.
  - Must define a generic payload structure (e.g., Protobuf or strict JSON schema) for the `ContextBundle`.
  - Must ensure the handoff is observable via OpenTelemetry tracing.
  - Must provide at least one end-to-end test (via Playwright or internal Rust tests) verifying that Agent B successfully utilizes context generated by Agent A.
