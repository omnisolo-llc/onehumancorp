issue_title: "Implement Unified Agent Feed (Mobile-First 375px)"
issue_description: |
  ## Problem Statement
  Legacy business management platforms (like Shopify and Wix) rely heavily on desktop-centric "dashboards" that overwhelm mobile users. A real small-business owner (e.g., Maya, who manages her bakery mostly on her iPhone) needs a clear, unified view of immediate actions directly on her mobile screen. Currently, OHC lacks a truly mobile-first (375px) mechanism for surfacing actionable, AI-drafted recommendations. The existing "dashboard" relies on standard metrics views rather than proactive agent-driven operations.

  ## Research Report
  - **Competitive Analysis**: Link-in-bio tools (Linktree, Stan Store) succeed with mobile creators because of their absolute simplicity, but lack robust business workflows. Legacy platforms (Shopify, Wix) fail on mobile-first business management because they require desktop for anything beyond basic order fulfillment.
  - **The OHC Differentiator**: Instead of a complex form with 20 toggles to set up a discount code or reply to an inquiry, OHC will use a "Unified Agent Feed". The LLM (via an event ingestion pipeline and intention resolution) drafts the response or action and presents it as a single "Card" on a mobile dashboard with a massive "Approve" button.
  - **Observations**: OHC currently has fragmented traces of this (like `TriageFeed.tsx` and `UnifiedAgentFeed.tsx`), but the implementation is either incomplete, clunky, or failing E2E tests (e.g., `src/e2e/unified_agent_feed.spec.ts` where UI elements are missing). The current dashboard relies on standard HTML/React structures that are not fully optimized for the 375px constraint or the "Agent Feed" paradigm.

  ## Design Doc
  **Architecture Overview**
  - **Backend**: The Agent Feed relies on the existing `agent_feed_items` and `agent_approvals` tables. The API (`/api/agents/feed` or similar) streams or serves these actionable items to the frontend.
  - **Frontend (Mobile-First 375px)**: A unified, vertically scrolling feed replacing the traditional dashboard on mobile. Each item is an "Action Card".
  - **Card Anatomy**:
    - **Context Head**: Identifies the source (e.g., "Instagram DM", "Operations", "Marketing"). Use subtle color coding and icons.
    - **Body**: The core message or customer inquiry (e.g., "Do you make custom vegan cakes?").
    - **Drafted Action**: The AI's proposed response or action (e.g., "Yes we do! Here is a booking link: https://ohc.page/book"). Presented distinctly (e.g., italicized or in a slightly offset background).
    - **Action Footer**: A large (min 44x44px touch target) "Approve" button, alongside optional "Edit" or "Discard" actions.
  - **Styling**: Must use OHC Premium Tokens (Glassmorphism, clean Apple/Ubiquiti-style hierarchy, restrained translucent materials). Strict adherence to max-width 375px on mobile breakpoints. No horizontal scrolling.

  **Mobile UX Flow**
  1. User opens the OHC app/PWA on a mobile device (375px viewport).
  2. The initial view is the "Unified Agent Feed".
  3. The feed displays actionable cards (e.g., a pending Instagram DM reply).
  4. The user taps the primary "Approve" button on a card.
  5. The card visually confirms the action (optimistic UI update) and disappears from the feed or marks as complete.

  **AI Agent Integration Points**
  - The feed consumes data generated by various agents (Marketing, Operations, Customer Success). The agents listen to webhooks or internal events, classify intent, use RAG for context, and insert records into `agent_feed_items` or `agent_approvals` with a `PENDING_APPROVAL` or `DRAFT` state.

  ## Implementation Prompt
  Implement the user-facing "Unified Agent Feed" for the OHC mobile dashboard. The feed must strictly adhere to a 375px mobile-first layout. When the user loads the dashboard, they should see a vertical list of Action Cards representing tasks drafted by various AI agents (e.g., Operations, Marketing, Customer Service).

  Specifically, implement the UI to support the Instagram DM custom cake scenario (Persona: Maya):
  - A card showing the source as "Instagram DM".
  - Display the customer's message.
  - Display the AI-drafted reply.
  - Provide a large "Approve" button (`data-testid="approve-instagram-dm"`) with a minimum 44x44px touch target.
  - Ensure tapping "Approve" optimistically removes the card from the feed.

  The implementation must ensure that `src/e2e/unified_agent_feed.spec.ts` passes. The layout must use Glassmorphism styling and avoid any horizontal scrolling on a 375px viewport.
