  # F04 / OHC-10: Accurate Usage Metering & Billing Remediation

  ## Problem Statement
  For an owner like Nora the solo web professional, her business is operating with invisible costs. When her AI assistant prepares a website quote or chats with a customer, she doesn't see what she's actually spending on AI "brainpower" (model usage). Currently, the system silently ignores these costs or pretends they are free. This means Nora could be losing money on small jobs without realizing it, and we cannot offer her a sustainable "bring your own key" (BYOK) or metered billing plan.

  ## Research Report
  **Findings & Data:**
  According to the current `docs/research/business_capability_and_usage_economics_audit.md`, there is a concrete gap: the proposal LLM adapter returns zero usage (`Usage::default()`), local models return unmetered text, and proxy streams bypass settlement entirely.

  **Competitive Comparison:**
  *   **Claude Code for SMBs:** Provides transparent, itemized token usage on every CLI interaction.
  *   **ChatGPT Enterprise/Business:** Clearly segregates workspace queries from API usage, providing admins with precise token consumption graphs.
  *   **OHC Current State:** Omits model usage metrics from critical paths, risking silent margin erosion.

  **Sources:**
  *   `docs/research/business_capability_and_usage_economics_audit.md` (2026-09-18)
  *   `docs/research/native_migration_and_remediation.md` (Finding F04)
  *   `src/server/api/proposals.rs`

  ## Design Doc

  **High-Level Architecture:**
  ```mermaid
  graph TD
      A[AI Agent / Proposal Engine] -->|Generates Quote| B{Provider Facade}
      B -->|Stream Response| C[Client UI]
      B -->|Intercept Tokens| D[Usage Metering Service]
      D -->|Record| E[(Tenant Usage Ledger)]
      E -->|Sync| F[Cost Reporting Dashboard]
  ```

  **UI Wireframes & Screen Flow (Mobile First - 375px):**
  1.  **Dashboard Screen:** Top banner showing "Current Month AI Spend: $4.50" with a progress bar against the preset budget.
  2.  **Quote Generation Screen:** A subtle tag below the generated text: "AI prep cost: $0.02".
  3.  **Billing Settings:** Toggle to switch between "OHC Managed AI Plan" and "Connect My Own Provider Key".

  **AI Agent Integration Points:**
  *   The AI agent must wrap every completion and embedding request with an observability context that guarantees token counting.
  *   Streaming endpoints must accumulate usage chunks and settle them asynchronously with the ledger upon stream completion.

  ## Persona-Specific User Journey
  **Nora (Solo Web Professional):**
  1.  Nora logs in and creates a proposal for a new website redesign.
  2.  The AI assistant drafts the entire document.
  3.  Nora reviews the draft on her phone. Below the draft, a small receipt shows the exact tokens used and its estimated cost.
  4.  Nora feels confident because the platform is transparent; she knows she won't be hit with a surprise bill at the end of the month.

  ## Rationale
  OHC should implement comprehensive usage metering because the current codebase (F04) leaks cost data. Without capturing true usage (input/output/cache tokens) across all streams and local models, OHC cannot sustainably price its service, and owners cannot trust the platform's cost projections.

  ## Implementation Prompt
  **Outcome:** Owners will see precise, itemized AI costs for every business action generated by the platform.
  **Critical User Journey:**
  1. User requests an AI action (e.g., generate proposal).
  2. System processes the request.
  3. UI displays the result along with the exact cost of the operation.
  **Acceptance Criteria:**
  *   All AI interactions (proposals, streams, local models) capture actual input, output, and cache token counts.
  *   No paths return `Usage::default()` or fabricated free usage.
  *   Usage is attributed correctly to the tenant and displayed on the cost dashboard.
  *   Happy path: Quote generates and usage increments. Failure path: Stream drops mid-generation, but accumulated usage is still settled to the ledger.

  ## Strategy Admission
  *   **OHC Target ID:** OHC-10 (Cash, cost and business portability)
  *   **Launch/Run stage:** Launch
  *   **Observed/inferred gap:** Observed (F04 Audit Finding)
  *   **Evidence level:** Documented / Source-verified
  *   **Baseline and measurable result:** Currently 0% of streamed proposal tokens are metered. Goal: 100% metering accuracy for all model paths.
  *   **Dependencies/reuse:** Relies on existing `Tracker` infrastructure.
  *   **Non-goals:** Do not build a completely new billing provider; use the existing ledger. Do not change pricing tiers.
  *   **Authority class:** System-level (Read/Write Usage Data)
  *   **Cost/measurement plan:** Tracked as OHC-funded model usage if on managed plan.
