  # Research Report: Edge-Cached Dynamic Storefront & SEO Optimization

  ## Executive Summary
  This report details an architectural strategy to improve the public-facing storefront performance and SEO discoverability for OHC merchants. Currently, many AI-generated or dynamic pages suffer from high Time to First Byte (TTFB) and poor Core Web Vitals, penalizing our merchants in search rankings. We propose an Edge-Cached dynamic storefront architecture, combining the flexibility of server-rendered personalized content with the speed of static CDNs.

  ## 1. Market Mapping & Competitor Discovery
  Leading e-commerce platforms (Shopify, BigCommerce) heavily leverage Edge Computing (e.g., Cloudflare Workers, Vercel Edge Network) to cache storefront pages close to the end-user. Simple website builders (Wix, Squarespace) often generate static HTML but struggle with dynamic inventory or personalized pricing.
  - **Shopify Oxygen**: A dedicated edge hosting platform for custom storefronts, ensuring sub-50ms global TTFB.
  - **Vercel/Next.js (App Router)**: Uses advanced caching (Data Cache, Full Route Cache) to make dynamic pages load instantly.

  ## 2. OHC Gap & Pain Point Identification
  - **Persona Focus**: Priya (boutique owner) and Leo (music tutor) rely on organic search traffic.
  - **The Gap**: OHC's current Rust/Axum and Flutter/Next.js hybrid architecture dynamically renders storefronts on every request. This is too slow for global SEO standards. When Leo's portfolio goes viral on TikTok, the backend struggles to serve thousands of concurrent requests efficiently.

  ## 3. Deep Dive Architecture Design

  ### Caching Strategy & Invalidation Protocol
  - **Edge CDN (Cloudflare/Fastly)**: Public storefront URLs (`/store/:tenant_id/product/:id`) are cached at the edge.
  - **Stale-While-Revalidate (SWR)**: The edge serves the cached version while asynchronously fetching the updated version from the OHC origin server.
  - **Targeted Cache Invalidation**: When the Operations Agent or the central ledger registers a meaningful state change (e.g., price update, stock reaching zero), a webhook is fired to the CDN to aggressively invalidate the specific `/product/:id` route, ensuring customers never see stale pricing or "in stock" for sold-out items.

  ### AI Agent Coordination
  - **Marketing Agent ("The Promoter")**: Analyzes Google Search Console metrics, identifies poor-performing pages (due to speed or content), and automatically triggers a rebuild/cache invalidation with optimized metadata.
  - **Operations Agent ("The Manager")**: Responsible for emitting the precise events that trigger targeted cache invalidations when inventory changes.

  ### SEO Metadata Management
  - The storefront generation must automatically inject precise Schema.org JSON-LD (Product, LocalBusiness, Offer) and OpenGraph tags.
  - The AI Assistant generates optimized meta titles and descriptions based on product details.

  ## 4. Implementation Prompt
  **Feature Name:** Edge-Cached Dynamic Storefront Architecture
  **Target Persona:** Leo the Music Tutor (needs high-performance portfolio)
  **Outcome:** A public-facing storefront that loads in under 100ms globally, automatically invalidates its cache when Leo updates his availability or pricing, and features perfect SEO metadata generated by AI.

  **Critical User Journey (CUJ):**
  1. Leo updates the price of his "Masterclass Video" from $50 to $40 via the OHC mobile app.
  2. The OHC Rust backend updates the PostgreSQL ledger.
  3. The Operations Agent intercepts the state change and fires a targeted cache invalidation request to the Edge CDN for `/store/leo-music/product/masterclass`.
  4. A customer in Japan clicks Leo's TikTok link 5 seconds later. They receive the updated $40 pricing instantly via the Tokyo edge node (sub-50ms TTFB).

  **Next Actions for Engineering:**
  - **Step 1**: Implement the HTTP caching headers (Cache-Control, SWR) in the Rust Axum public storefront routes.
  - **Step 2**: Build the Cache Invalidation Service to listen to database/ledger changes and trigger CDN purges.
  - **Step 3**: Integrate Schema.org JSON-LD injection into the storefront rendering pipeline, populated by the Marketing Agent.
