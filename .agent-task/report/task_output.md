  ## Title
  Implement Multi-Tenant Real-Time Unified Omnichannel Inbox UI

  ## Problem Statement
  Small business owners (like Carlos the handyman or Maya the baker) receive customer inquiries across multiple unlinked channels: Instagram DMs, WhatsApp, SMS, and email. Managing these manually leads to missed messages, slow response times, and lost sales. Traditional platform "unified inboxes" (e.g., Shopify Inbox, Wix Inbox) simply aggregate messages without context. They require the owner to manually type responses, often lacking the customer's purchase history or past interactions across other channels. This creates a reactive, labor-intensive process that doesn't scale for a solopreneur.

  OHC is missing a unified frontend interface to aggregate these messages. While there are research documents highlighting this gap (`[research]_ai_unified_inbox_differentiation.md`), there is no implemented frontend component that provides a unified, mobile-first view of customer messages across channels (WhatsApp, Instagram, Email, SMS) combined with AI-drafted responses (The Ambassador agent).

  ## Research Report
  **Findings & Competitive Analysis:**
  - **Shopify Inbox:** Aggregates chat and email but relies heavily on manual responses or basic, rigid auto-replies. It does not proactively draft contextual responses based on full customer history across all channels.
  - **Wix Inbox:** Good aggregation, but AI features are mostly limited to "improving tone" or generating generic replies, not acting as an autonomous customer success agent.
  - **Zendesk/Intercom:** Enterprise-grade and far too complex/expensive for a single-person SMB.
  - **OHC Opportunity:** Leverage our "Teammate" AI philosophy. The Customer Success Agent (The Ambassador) doesn't just aggregate messages; it reads them, queries the customer's omnichannel identity graph (purchase history, past bookings, previous DMs), and proactively drafts a complete, accurate response. The owner just sees an "Action Required: Approve Reply" card in their mobile feed.

  We need to build a new UI module in the Flutter frontend to serve as the unified inbox, integrating directly with the Go backend over REST/gRPC and providing real-time updates for new incoming messages.

  ## Design Doc
  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Mobile App Feed 375px - Flutter] --> B{Omnichannel Inbox Component}
      B --> C[Message List View]
      B --> D[Message Thread View]
      D --> E[Customer Context Card]
      D --> F[AI Draft Approval Card]
      B -->|REST/gRPC| G[Go Backend / Omnichannel Gateway]
      G -->|Webhooks| H[External Channels: IG, WhatsApp, Email]
  ```

  ### UI Wireframes & Mobile UX Flow (375px First)
  - **Inbox List View:** A clean list of active conversations. Each row shows the customer name, channel icon (IG, WhatsApp, etc.), unread status, and a badge if there is a pending AI draft awaiting approval.
  - **Message Thread View (Interaction):** Tapping a conversation opens a unified view.
    - Top half shows the customer context (e.g., "Sarah bought a vegan cake 2 months ago").
    - Middle section shows the message history.
    - Bottom half shows the AI-drafted reply (e.g., "Hi Sarah! Yes, we still make the vegan chocolate. Would you like to reorder for this weekend?").
  - **Action:** A prominent primary button "Approve & Send" and a secondary "Edit".
  - **Visual Design:** Glassmorphism cards, blurred background to maintain focus, native keyboard integration if editing. Uses the OHC Premium Token library (clean Apple/Ubiquiti-style hierarchy, restrained translucent materials, strong spacing, readable typography).

  ### AI Agent Integration Points
  - **The Ambassador (Customer Success Agent):** The UI will render the pre-drafted responses generated by The Ambassador agent. When the user taps "Approve & Send", the UI sends a confirmation to the Go backend, which dispatches the message and clears the draft state.

  ### Key Design Decisions
  - **Mobile-First (375px):** The entire UI must be fully functional and beautifully designed for a 375px viewport without horizontal scrolling.
  - **Proactive Drafting (Read-Approve vs. Read-Reply):** The UI emphasizes the AI draft, moving the user flow from manual typing to a quick review and approval process.
  - **Zero Trust:** All API calls from the UI must use the existing authentication tokens to ensure row-level tenant isolation.

  ## Implementation Prompt
  **User-Facing Outcome:** As a business owner, when a customer DMs me on Instagram asking about their past order, I open the OHC app to find a pre-written, perfectly accurate response already drafted. I tap one button to send it, taking 2 seconds instead of 2 minutes.

  **CUJ & Acceptance Criteria:**
  1. Implement a new `Omnichannel Inbox` view in the Flutter frontend, accessible from the main navigation.
  2. Implement a real integration with the Go backend to fetch a list of conversations and display them in a mobile-first list view. Do not use mock data.
  3. Implement the `Message Thread View` showing customer context, message history, and the AI-drafted response card.
  4. Implement the "Approve & Send" and "Edit" interaction flows. This must interact with real backend API endpoints.
  5. The UI must be fully responsive, prioritizing the 375px mobile viewport, using the defined OHC premium design tokens (translucent glass materials, clean typography).
  6. Provide Playwright E2E tests: A user logs in, navigates to the Inbox, sees a conversation with a pending draft, taps the conversation, and clicks "Approve & Send". All data must flow through the real application stack without network request mocking.

  **Note to Implementer:** Do not prescribe specific backend database schemas or internal backend routing here. Focus entirely on the frontend UI components, state management, and the contract with the API (REST/gRPC) to fetch and mutate message state in a real end-to-end flow.
