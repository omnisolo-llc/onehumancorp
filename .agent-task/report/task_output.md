issue_title: "[Mobile-First UX] Fix Unified Agent Feed approval and sync states for 375px UX"
issue_description: |
  **Problem Statement**:
  A non-technical owner or operator requires OHC's operations and marketing capabilities to be accessible entirely on a 375px mobile screen. Currently, the "Agent Feed" mechanism fails to properly resolve and dismiss action cards across different underlying systems. When an owner clicks "Approve" on a draft generated by a sub-agent (e.g., Marketing or Operations), the feed does not successfully clear the ghost task out of all sub-tables (like `daily_work_items`, `agent_approvals`, and `agent_action_requests`), leading to a cluttered, broken feed that undermines the "Unified Inbox / Assistant" value proposition.

  **Research Report**:
  - The legacy desktop workflow forces users to check different tabs for `daily_work`, `approvals`, and `triage_items`.
  - The `triage.html` UI relies on a single endpoint `/api/ui/triage` which fetches combined states from `triage_items`, `unified_triage_actions`, `agent_feed_items`, `agent_approvals`, and `daily_work_items`.
  - The approval endpoint `/api/ui/triage/action` only sets state updates for `agent_feed_items`, `omni_inbox_messages`, `unified_triage_actions`, and `triage_items`. It completely misses `daily_work_items`, `agent_approvals`, and `agent_action_requests`, causing those cards to be fetched again on the next refresh as "PENDING".
  - This fundamentally breaks the 375px "Approval" Interface Paradigm where users need one-tap clear feeds.

  **Design Doc**:
  - *Architecture:*
    - The `update_ui_triage_action_handler` must expand its transaction block to comprehensively cover all tables queried by `load_ui_triage_from_db`.
    - SQLite and Postgres stores must both be updated identically.
    - Caches must be invalidated.
  - *Mobile UX Flow:*
    - 375px viewport target.
    - User views feed (`/api/ui/triage.html`).
    - Tap "Approve & Send" on any task (Marketing, Operations, Intake).
    - Status updates universally, card disappears cleanly, cache invalidated.
  - *AI Agent Integration:* LLMs draft the `action_payload`. Handled cards feed context back into memory indicating the user accepted the action.

  **Implementation Prompt**:
  Implement the backend state consistency for the `/api/ui/triage/action` endpoint in `src/server/lib.rs`. Ensure that when a user approves or dismisses a triage item, the respective `status` or `lifecycle_state` is also updated across the `agent_approvals`, `agent_action_requests`, and `daily_work_items` tables using the `triage_item_id`. Create E2E playwright tests under `src/e2e/ui/triage_action_feed.spec.ts` that seed draft items into these specific tables, click approve, and verify the backend removes them from the subsequent feed fetch.
