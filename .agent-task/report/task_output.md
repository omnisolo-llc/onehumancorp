issue_title: "Mobile-First UX: Implement Unified Agent Feed for OHC"
issue_description: |
  ## Problem Statement
  Currently, the OneHumanCorp (OHC) platform assumes a desktop-first management experience for complex business operations. However, our core personas (like Maya the Baker and Fatima the Food Cart Owner) operate their businesses primarily from mobile devices (375px screens). The legacy dashboard paradigm fails to serve these users when complex actions (e.g., launching a marketing campaign, updating inventory, managing subscriptions) are required.

  The core pain point is the lack of a centralized, mobile-optimized interface for reviewing and approving actions generated by the autonomous AI agents. The current UI scatters these interactions or requires desktop access, causing friction and delaying critical business decisions.

  ## Research Report
  - **Competitive Landscape**: Legacy platforms (Shopify, Wix) treat mobile apps as supplementary, requiring a desktop for setup and complex workflows. Link-in-bio tools (Linktree, Stan Store) excel on mobile due to simplicity but lack robust business operations.
  - **OHC Differentiator**: OHC's unique value proposition is **Invisible AI Automation**. Instead of forcing users to navigate complex menus, the platform should proactively push actionable items via agents.
  - **Proposed Solution**: A "Unified Agent Feed" — a centralized, mobile-first feed where users receive "Action Cards" containing agent-drafted messages, proposals, and urgent alerts. This shifts the interaction model from "Dashboard Navigation" to "Chat & Approval UI".

  ## Design Doc
  ### Architectural Overview
  The Agent Feed will aggregate events from the Event Ingestion Pipeline (e.g., Stripe, Instagram Graph API) and internal state changes. The Intent & Context Resolution (LLM Layer) will process these events and generate "Action Cards" pushed to the Unified Agent Feed UI.

  ### Mobile UX Flow (375px First)
  1. **Home Screen**: The primary landing screen after login is the Unified Agent Feed, prioritized by urgency and agent type.
  2. **Action Cards**: Each card displays a clear, concise summary of the agent's proposal or the critical alert.
  3. **Interaction**: Cards feature prominent "Approve", "Edit", or "Discard" actions with large touch targets (minimum 44x44px).
  4. **Expansion**: Tapping "Edit" or interacting with a card expands it to reveal more context (e.g., the full text of an AI-drafted email or the specific inventory items to be updated) without leaving the feed context.

  ### AI Agent Integration
  - **The Operations Agent**: Pushes alerts for low inventory, unfulfilled orders, and staff scheduling conflicts.
  - **The Customer Success Agent**: Drafts responses to customer inquiries (e.g., DMs, emails) for user review.
  - **The Marketing (Promoter) Agent**: Suggests promotional campaigns, discount codes, and social media posts based on business trends.

  ### Key Design Decisions
  - **Mobile-First Constraint**: The feed must be entirely usable and visually coherent on a 375px viewport with no horizontal scrolling.
  - **Translucent Glass UI**: Adopt the OHC Premium Token library (macOS-style translucent glass, 16px border radius) for the Action Cards.
  - **Action-Oriented**: Prioritize immediate action over data visualization on the primary feed.

  ## Implementation Prompt
  Implement the "Unified Agent Feed" on the frontend. The target is a mobile-first (375px) feed that replaces the traditional complex admin dashboard.

  **Critical User Journey (CUJ)**:
  1.  User opens the app on a simulated 375px screen.
  2.  The feed displays 3 distinct "Action Cards" (e.g., an Operations alert, a Customer Success draft, a Marketing proposal).
  3.  User taps an action button (e.g., "Approve" or "Edit") on a card.
  4.  The card transitions smoothly to reflect the action taken or expand for further input.

  **Acceptance Criteria**:
  - Layout strictly adheres to 375px width constraints (no horizontal scrolling).
  - All interactive elements (buttons, cards) have minimum 44x44px touch targets.
  - The UI uses OHC Premium Tokens (Glassmorphism, specific typography, rounded corners).
  - The feed clearly distinguishes between different agent types (e.g., using icons or subtle color coding).
  - Include robust E2E tests verifying the feed interaction flow and layout constraints.
