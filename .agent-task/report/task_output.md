issue_title: "Implement Mobile-First Unified Agent Feed"
issue_description: |
  ## Problem Statement
  Small business owners and operators like Maya (Home Baker) and Fatima (Food Cart Operator) run their businesses entirely from their smartphones. Current commerce platforms (like Shopify or Wix) rely heavily on complex desktop dashboards for configuration, marketing, and triage. Owners are overwhelmed by traditional "admin panels" with dozens of graphs, menus, and toggles that are nearly impossible to use on a 375px screen. They need an assistant that doesn't just show them raw data but instead tells them exactly what needs their attention today and proposes the next action (e.g., "Drafted a reply to a vegan cake inquiry. Approve?"). The lack of a unified, mobile-first, actionable feed prevents owners from managing operations and capitalizing on opportunities efficiently.

  ## Research Report
  Based on the competitive audit and persona analysis:
  - **Shopify / Wix / Squarespace**: Focus heavily on desktop-centric onboarding and configuration. Shopify's companion app is good for fulfilling orders, but making design or promotional changes requires a desktop.
  - **Link-in-Bio (Linktree, Beacons)**: Excel at mobile-first simplicity, but lack robust business logic, inventory, or agentic automation.
  - **AI-Native Rivals (Lindy.ai, 11x)**: Provide autonomous agentic flows but lack native e-commerce, pos, or deep service integration.

  **OHC Gap**: OHC has powerful background capabilities (KAIROS, Booking, Qouting) but currently lacks the "Zero-to-One" frontend interface that turns these capabilities into proactive, 1-click approvals for the owner. We need a "Unified Agent Feed" that serves as the command center for the owner, surfacing Action Cards generated by our AI agents.

  ## Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD;
      EventBus[Central Message Bus/Event Pipeline]
      KAIROS[KAIROS Orchestrator]
      AgentDept[AI Agent Departments: Ops, Sales, CS]
      DB[(Tenant PostgreSQL)]
      FeedService[Feed/Inbox Service]
      MobileUI[Flutter/PWA Mobile Client 375px]

      Webhook[Stripe/IG/SMS Webhooks] --> EventBus
      Internal[Inventory/Order Events] --> EventBus

      EventBus --> KAIROS
      KAIROS --> AgentDept
      AgentDept --> DB
      AgentDept --> FeedService: Generate Action Card
      FeedService --> MobileUI: Push Notification & Feed Update

      MobileUI -->|User Taps Approve| FeedService
      FeedService --> KAIROS: Execute Action
  ```

  ### Mobile UX flow (375px first)
  1. **Home Screen**: The owner opens the app. No complex sidebars. The main view is the **Agent Feed**, resembling a social feed but consisting of "Action Cards."
  2. **Triage**:
     - *Card 1 (High Priority)*: "You have 3 new orders for pickup today." -> [View Orders]
     - *Card 2 (Actionable)*: "Customer asked if we have vegan options. I drafted a reply." -> [Review & Send]
     - *Card 3 (Insight)*: "Weekly summary: Sales are up 15%. Want to run a weekend promo?" -> [Draft Promo]
  3. **Interaction**: User taps "Review & Send" on Card 2. The card flips or expands to show the pre-drafted message. The user hits a large touch-friendly "Approve" button (> 44x44px).
  4. **Completion**: The card shows a green checkmark, gracefully collapses, and the underlying capability executes the send via KAIROS.

  ### AI agent integration points
  - Agents are subscribed to KAIROS orchestration events and generate action cards inside the Feed Service.
  - When the user approves an action, a webhook or direct gRPC call is made from the FeedService to the KAIROS engine to execute the capability.
  - Generative models are invoked automatically in the background to provide a drafted output so the user does not wait.

  ### Key Design Decisions and Why
  - **Approval UI Paradigm**: Move away from form-filling. The AI does the form-filling and logic; the owner simply approves, modifies, or discards. This simplifies the mobile UX and saves time.
  - **Strict Mobile Breakpoint**: Layouts are fixed to 375px width design constraints. No horizontal scrolling to ensure perfect usability on older devices.
  - **Glassmorphism & Clear Hierarchy**: Use OHC Premium Tokens (translucent glass) to visually separate Action Cards and emphasize the primary Call-To-Action (CTA).
  - **Tenant Isolation**: All feed items are strictly scoped to the `tenant_id` ensuring complete data privacy via row-level security.

  ## Implementation Prompt
  **Implementer Agent Prompt**:
  Build the "Unified Agent Feed" UI and its supporting backend delivery mechanism.
  - **User-Facing Outcome**: The user logs into OHC on a mobile device and is immediately presented with a vertical feed of Action Cards. Each card represents an insight or a drafted action from an AI agent (e.g., drafted email, order fulfillment reminder).
  - **CUJ**:
    1. User logs in.
    2. Navigates to the Home/Feed view.
    3. Sees a list of pending Action Cards.
    4. Clicks "Approve" on an action card.
    5. The card marks as complete and triggers the backend to execute the confirmed intent.
  - **Acceptance Criteria**:
    - The UI must perfectly fit a 375px mobile screen without horizontal scrolling.
    - Touch targets must be at least 44x44px.
    - The interface must use OHC Premium Tokens (Glassmorphism, clear Apple/Ubiquiti-style hierarchy).
    - The feature must include full Playwright E2E tests validating the end-to-end CUJ from the Feed UI to backend approval state.
    - Must pass all existing `bazel test //...` and `bazel test //src/e2e:playwright` jobs.
    - Ensure zero mock data is present in the UI components (data must flow from the API/Database).
