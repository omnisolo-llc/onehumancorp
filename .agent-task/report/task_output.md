  # Mission: Implement Unified Agent Feed (Mobile MVP)

  ## Problem Statement
  Current complex operations in traditional business platforms (Shopify, Wix) require a desktop environment. Small business owners and operators operating primarily from mobile devices (like Fatima) need an assistant-first feed where agents propose actions (operations, advisory, marketing) and the owner simply reviews and taps "Approve".

  ## Research Report & Competitive Analysis
  - **Shopify & Wix**: Rely heavily on a "Companion App" model where basic order fulfillment is possible on mobile, but complex setup (discounts, workflows, theme design) requires desktop.
  - **Durable & Link-in-Bio**: Excel at fast mobile setup but lack deep business operational capabilities.
  - **OHC Differentiator**: Instead of a complex responsive dashboard full of 20 toggles, OHC uses an Agentic "Approval" paradigm. The system presents complex workflows (e.g., "Run a 20% off weekend sale") as a single feed card generated by an AI agent. The owner just taps "Approve" (with a > 44px touch target) on their 375px mobile screen.

  ## Design Doc

  ### Architecture Diagram
  ```mermaid
  graph TD
      A[Mobile UI 375px] --> B{Agent Feed Repo}
      B --> C[PostgreSQL]
      B --> D[Redis Cache]
      D --> A
      E[AI Marketing Agent] --> B
      F[AI Operations Agent] --> B
      G[AI Advisory Agent] --> B
      B --> H[Action Router]
      A -- "User Approves Action" --> B
  ```

  ### Mobile UX Flow
  1. Owner opens OHC app on a 375px screen.
  2. The default view is the **Unified Agent Feed** instead of a traditional dashboard.
  3. The feed shows vertically stacked actionable cards (e.g., Marketing Agent proposes an Instagram post, Operations Agent flags 3 pending orders).
  4. Each card contains brief context and a massive primary "Approve & Execute" button.
  5. Tapping "Approve" transitions the card to a completed state and fires off the background action via the Action Router.

  ### AI Agent Integration Points
  - **Event Triggers**: Background agents (Marketing, Ops) monitor the tenant's data (inventory, time since last promo) and insert new proposed actions into the `AgentFeedRepository`.
  - **Context Payload**: Agents attach `proposed_action` JSON payloads containing the logic (e.g., discount amount, email copy) required for the Action Router to execute the task upon user approval.

  ### Key Design Decisions
  - **Assistant-First**: The feed *is* the UI. We are moving away from traditional nested settings menus.
  - **Offline Tolerance**: Feed reads and approval actions must be tolerant to flaky mobile networks, utilizing local caching where appropriate.
  - **Mobile Constraints**: Strict adherence to 375px width, no horizontal scrolling, and touch targets ≥ 44px.

  ## Implementation Prompt
  - Build the Mobile-First Unified Agent Feed UI to consume the existing backend `AgentFeedRepository`.
  - Implement a mobile-optimized view for `src/ui/tauri/src/ui/dashboard.html` (or equivalent Tauri/Flutter entry point) that displays the feed items as large, touch-friendly cards.
  - Ensure the "Approve" action correctly calls the backend endpoint to update the feed item state and trigger the `ActionRouter`.
  - Follow the OHC Premium Token design system for styling the cards (glassmorphism, clear status indicators).
