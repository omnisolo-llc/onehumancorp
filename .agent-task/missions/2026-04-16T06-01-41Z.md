# Title: Token Burn Rate Forecasting Engine

## Problem Statement
There is no dedicated metric tracking **Token Burn Rate Forecasting**. While raw token usage is logged (`ohc_token_usage_total`), per-tenant predictive extrapolation for budget alerts is not instrumented or visualized.

## Research Report
The `docs/reports/OBSERVABILITY_AUDIT_REPORT.md` identifies that while basic metrics exist, there is a systemic gap for token burn rate forecasting. Specifically, the "Hybrid Telemetry Review" dashboard lacks specific panels for token forecasting and fine-grained agent API error rate breakdowns.

## Design Doc
1.  **Token Burn Rate Forecasting Engine:** Implement a backend background worker in the Orchestration Hub that calculates the moving average burn rate using `ohc_token_usage_total` and emits predictive cost alerts, combined with a new Grafana dashboard panel.
2. The background worker should periodically calculate a forecast metric (e.g. `ohc_token_burn_rate_forecast`) based on recent token usage trends.

## Implementation Prompt
1. Add a new background worker in the Orchestration Hub (e.g., in `srcs/server/orchestration/hub.go` or a new file `srcs/server/orchestration/telemetry_worker.go`).
2. The worker should periodically calculate the token burn rate forecast based on the `ohc_token_usage_total` metric.
3. Emit a new metric `ohc_token_burn_rate_forecast` with the calculated forecast.
4. Update the Grafana dashboard provisioning (e.g., `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` and `deploy/helm/ohc/dashboards/hybrid-telemetry.json`) to include a new panel visualizing the `ohc_token_burn_rate_forecast` metric.
