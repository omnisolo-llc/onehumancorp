# Title: OHC Master Architecture Design: Shared Task List, Teammate Mesh & AutoDream
# Problem Statement
The OHC (One Human Corp) Swarm requires a robust, scalable, and highly available orchestration layer to enable absolute autonomy. Currently, agents need a formalized Shared Task List, a Realtime Teammate Mesh for coordination, and an AutoDream pipeline for long-term vector memory consolidation.

# Research Report
**Market Analysis & Architecture Needs:**
- **Cloud-Native Scale:** Needs PostgreSQL, Redis, and PgVector to support horizontal scale and multi-tenant isolation.
- **Standalone Degradation:** Must fall back gracefully to SQLite and in-memory Pub/Sub for local setups.
- **Teammate Mesh:** Demands low-latency WebSockets/gRPC or Redis Pub/Sub for agent communication.
- **AutoDream Memory:** Demands background jobs to consolidate experiences into pgvector-based Pinecone embeddings for omni-context recall.

# Design Doc
**1. Shared Task List (Phase 1):**
- Schema: PostgreSQL `shared_tasks` table.
- Columns: `id`, `organization_id`, `title`, `payload`, `status`, `agent_id`, `updated_at`.
- Architecture: Leverage PostgreSQL `FOR UPDATE SKIP LOCKED` for reliable queueing and state machine tracking without duplicate execution.

**2. Teammate Mesh APIs (Phase 2):**
- Realtime pub/sub via Redis. Channels: `mesh:tasks`, `mesh:coordination`.
- Endpoints: WebSocket interface for Thin Client and external proxy agents. gRPC for internal mesh microservices.
- Authentication: SPIFFE/SPIRE context. Zero secrets.

**3. AutoDream Vector Pipelines (Phase 3):**
- Schema: `consolidated_memory` table with `embedding vector(1536)` (pgvector).
- Architecture: A background worker (e.g., BullMQ/Celery or Go goroutine queue) fetches COMPLETED tasks from `shared_tasks`, generates LLM embeddings, and upserts into `consolidated_memory`.
