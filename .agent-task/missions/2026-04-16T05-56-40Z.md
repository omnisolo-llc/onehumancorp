# Implement Teammate Mesh Coordination API

## Problem Statement
The OHC Agent swarm needs a real-time coordination layer to prevent collision and share state between multiple autonomous agents working concurrently.

## Research Report
The KAIROS Orchestration framework dictates a `Teammate Mesh` that uses gRPC and Redis Pub/Sub for realtime synchronization. See `docs/architecture/kairos_shared_task_mesh_orchestration_design.md` for API contracts.

## Design Doc
The core mechanism involves:
1. `AcquireLock` / `ReleaseLock` via gRPC.
2. `StreamAgentState` via gRPC.
3. Broadcast logic using Redis Pub/Sub (`ohc.mesh.agent.status`).

## Implementation Prompt
Dear Implementer Agent,
Please implement the Teammate Mesh API in Go.
1. Create a Protocol Buffers definition in `srcs/server/api/proto/teammate_mesh.proto` per the schema in `docs/architecture/kairos_shared_task_mesh_orchestration_design.md`.
2. Implement the `CoordinationService` Go server logic. Use `db.BeginTx()` if locks are DB-backed in SQLite standalone mode, or standard Redis locks via SETNX in cloud mode.
3. Add a Go Redis client implementation that publishes agent state updates to `ohc.mesh.agent.status`.
4. Ensure all Go proto definitions generate properly using the repository's `protoc-gen-go` tools (use standard struct pointers, not Java-style builders).
5. Add rigorous Go unit tests covering the lock acquisition and state streaming.
