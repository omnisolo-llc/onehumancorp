**Title:** KAIROS Orchestration: AutoDream Pipeline & Teammate Mesh Integration

**Problem Statement:**
The OHC Hybrid OS requires robust orchestration logic to route decomposed tasks. Currently, `SharedTaskOrchestrator` manages `shared_tasks_v4` transitions but lacks a Sub-Agent spawning queue and the hooks to push completed tasks and their `deliberation_log`s into the AutoDream memory consolidation pipeline (`autodream_memories`).

**Research Report:**
- The `SharedTaskOrchestrator` in `srcs/server/orchestration/tasks_db.go` handles state transitions.
- `srcs/server/orchestration/queue/queue.go` has a `JobQueue` interface that needs a concrete Sub-Agent worker queue implementation for the orchestration master loop.
- `srcs/server/orchestration/autodream/repository.go` handles PgVector insertions but `tasks_db.go` needs to trigger this on `COMPLETED` transitions via the `MemoryConsolidator` interface.
- The master plan mandates a `Sub-Agent Queue` that integrates directly with `shared_tasks_v4`.

**Design Doc:**
1. **Sub-Agent Job Queue:** Implement `SubAgentJobQueue` in `srcs/server/orchestration/queue/queue.go` that satisfies the `JobQueue` interface, using a `sub_agent_jobs` DB table.
2. **Master Loop Delegation:** Add a `DelegateToSubAgent` method to `SharedTaskOrchestrator` to spawn jobs into the queue.
3. **AutoDream & Mesh Hooks:** In `SharedTaskOrchestrator.TransitionTask`, when transitioning to `COMPLETED`, publish a Mesh event and call `autodream.Consolidate(ctx, taskID, logs)` (passing `payload` and `deliberation_log`).
4. **Visual Guidelines:** All dashboard elements reflecting these tasks must use the standard OHC glassmorphism tokens.

**Implementation Prompt:**
Dear Implementer (✨ Implementer):
