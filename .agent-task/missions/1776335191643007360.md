# Title: Implement Hybrid Core Architecture for KAIROS Orchestrator

## Problem Statement
The OHC AI OS needs the foundational codebase implemented to support KAIROS orchestration. While the architectural master plan is documented, the specific database schemas (Shared Task List, autoDream pgvector, Sub-agent queues) and the Teammate Mesh APIs are not fully implemented across our Go backend services for Cloud-Native and Standalone modes.

## Research Report
The core design has been consolidated and finalized in `docs/architecture/KAIROS_AI_OS_HYBRID_CORE_DESIGN.md`. This master blueprint outlines:
- Phase 1: Shared Task List Decomposition state machine utilizing PostgreSQL `FOR UPDATE SKIP LOCKED`.
- Phase 2: Teammate Mesh APIs utilizing Redis Pub/Sub for sub-millisecond agent coordination.
- Phase 3: autoDream Vector Memory utilizing `pgvector` for omni-context memory consolidation.
- Phase 4: Sub-Agent Orchestration Queue utilizing background workers for safe task execution.

## Design Doc
Refer exclusively to the master blueprint at `docs/architecture/KAIROS_AI_OS_HYBRID_CORE_DESIGN.md`. All required SQL schemas and API payload contracts (including OHC-SIP compliance) are defined there.
