# Problem Statement
The OHC swarm requires a unified architecture combining the Shared Task List, Teammate Mesh, and AutoDream pipelines. Without this integration, agents operate in silos and fail to consolidate long-term memory or coordinate real-time state changes seamlessly across hybrid modes (Cloud and Standalone).

# Research Report
Based on the defined KAIROS Triad:
1. **Shared Task List**: `shared_tasks` uses PostgreSQL row-level locks for Cloud mode and SQLite transactions for Standalone.
2. **Teammate Mesh**: Real-time communication utilizes `CentrifugeNode` and Redis Pub/Sub (`rueidis`).
3. **AutoDream**: Long-term memory consolidation compresses session logs via existing `srcs/server/agents/local/llm.go` and embeds them into `pgvector` indexes `swarm_memory` and `swarm_memory_embeddings`.

# Design Doc
- **Schema Validation**: Ensure `shared_tasks`, `swarm_memory`, and `swarm_memory_embeddings` are accurately synchronized between `srcs/server/db/migrations/` and the application logic in `srcs/server/orchestration/`.
- **Mesh Implementation**: Connect `CentrifugeNode` event emissions to `shared_tasks` state transitions (e.g., broadcasting when a task transitions to `ASSIGNED` or `COMPLETED`).
- **AutoDream Sweep**: Implement a background worker in `srcs/server/orchestration/autodream_worker.go` that queries `COMPLETED` tasks and session data, passing them through `llm.go` for embedding generation before upserting into the `pgvector` memory tables.
