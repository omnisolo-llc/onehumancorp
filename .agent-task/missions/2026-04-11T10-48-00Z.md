## Title
Shared Task List - DB Schema and State Machine

## Problem Statement
The KAIROS orchestrator requires a robust Shared Task List to decompose high-level features for the OHC Swarm. This entails a solid foundational database schema to represent tasks, dependencies (DAG), and a distributed state machine to track transitions without race conditions, supporting both Cloud (PostgreSQL) and Standalone (SQLite) modes.

## Research Report
Based on the OHC-HA architecture, KAIROS Orchestration relies on the Shared Task List to map high-level features into granular jobs for the swarm. The Shared Task List needs strong consistency for state transitions. In multi-tenant cloud-native mode, tasks must be isolated per `organization_id`. The distributed state machine needs to rely on DB locks and Redis (where available) to orchestrate tasks effectively.

## Design Doc
1.  **Database Schema Changes**:
    -   Create a `shared_tasks` table. Columns: `id` (UUID), `organization_id` (String), `title` (String), `description` (Text), `status` (Enum: PENDING, IN_PROGRESS, BLOCKED, COMPLETED, FAILED), `assigned_agent` (String, nullable), `created_at`, `updated_at`.
    -   Create a `shared_task_dependencies` table to track DAG relationships. Columns: `task_id` (UUID), `depends_on_task_id` (UUID).
2.  **State Machine Logic**:
    -   Implement the distributed state machine logic in Go (`srcs/server/orchestration/state_machine.go`).
    -   State transitions must be validated (e.g., cannot transition from PENDING directly to COMPLETED).
    -   Use `SELECT ... FOR UPDATE` (or SQLite equivalent logic) for atomic status updates.

## Implementation Prompt
1. Implement the database migrations for `shared_tasks` and `shared_task_dependencies` in `srcs/server/db/migrations/`.
2. Ensure queries to these tables use standard cross-compatible syntax for Hybrid Consistency (PostgreSQL and SQLite) via the `database/sql` package.
3. Write Go methods in `srcs/server/orchestration/` to manage the lifecycle of shared tasks (Create, Claim, Complete, Block) validating state transitions.
4. Add OpenTelemetry metric counters for task state transitions (`telemetry.TasksCompletedTotal`, etc.) checking for nil metrics before adding.
5. Create comprehensive unit tests verifying the DAG constraints and state transitions. Run `bazelisk test //srcs/server/...`.
