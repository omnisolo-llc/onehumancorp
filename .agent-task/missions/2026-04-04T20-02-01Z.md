# OHC Hybrid Sync Integration (PowerSync)

## Title
Implement Local-to-Cloud Sync using PowerSync

## Problem Statement
One Human Corp (OHC) operates in a Hybrid Architecture: Cloud-Native Mode (PostgreSQL) and Standalone Desktop Mode (SQLite). The core challenge is keeping local single-user SQLite databases synchronized with the multi-tenant Cloud PostgreSQL instances seamlessly, while degrading gracefully when offline and resolving conflicts upon reconnection. We need a reliable synchronization layer that handles bidirectional data flow without compromising multi-tenant data isolation or local standalone efficiency.

## Research Report
- **Tool Evaluated**: PowerSync (https://www.powersync.com/)
- **Suitability**: PowerSync is specifically designed for offline-first applications and synchronizing local SQLite databases with central PostgreSQL databases.
- **Competitors**: ElectricSQL (shifting focus, not ideal for OHC currently), WatermelonDB (requires significant backend custom sync logic).
- **Security Check**: PowerSync handles tenant isolation securely via custom sync rules on the backend and supports JWT-based authentication. In Standalone Mode, OHC can bypass external sync if offline, or sync directly to the cloud instance using an OHC-SIP auth token.
- **Integration**: Provides a robust client SDK (Flutter, Web) and a backend service/Docker container for Postgres connections.

## Design Doc
1. **Architecture**:
   - Cloud: Deploy a PowerSync Service connected to the existing multi-tenant PostgreSQL database.
   - Client (Desktop/Mobile): Integrate PowerSync SDK with the local SQLite instance.
   - Sync Rules: Define declarative sync rules in the PowerSync Service, keyed by `organization_id` to enforce strict tenant isolation.
2. **API Contracts**:
   - `GET /api/v1/auth/powersync`: Returns a short-lived JWT scoped to the current user's `organization_id` for PowerSync authentication.
3. **DB Schema Changes**:
   - Ensure all synchronized tables have a `uuid` primary key and an `updated_at` timestamp.
   - Soft deletes should be implemented using a `deleted_at` timestamp for accurate sync.
4. **Offline Capability**:
   - Read/write locally to SQLite via PowerSync SDK.
   - Operations queue locally and sync automatically when network is restored.

## Implementation Prompt
Hello Implementer, your mission is to integrate PowerSync into the OHC Hybrid Architecture to solve the local SQLite to Cloud Postgres sync challenge.

**Requirements**:
1. Add PowerSync service configuration to our Docker compose or Kubernetes manifests (Cloud mode).
2. Create an endpoint `GET /api/v1/auth/powersync` in `srcs/server/dashboard/server.go`. Use `auth.RequireRole` if applicable, but critically, include the user's `organization_id` in the returned JWT. Do NOT rely solely on roles; strict multi-tenant isolation via `organization_id` is mandatory.
3. Integrate the PowerSync Flutter SDK in `srcs/app/lib/db/`. Replace direct local SQLite writes for synchronized tables with PowerSync SDK calls.
4. Define sync rules (e.g., `sync_rules.yaml` or equivalent) that restrict row access based on `auth.claims.organization_id == row.organization_id`.
5. Ensure all synced tables in both Postgres (`db/migrations/`) and SQLite fallbacks use `updated_at` and `deleted_at`.
6. Write integration tests validating offline write queuing and online syncing.
7. Use Playwright (`browser` tool) to verify UI stability after replacing the data layer.

**Exit Conditions**: 100% passing tests, no WIP left, and the Standalone Desktop mode must still work gracefully even if the PowerSync endpoint is unreachable.
