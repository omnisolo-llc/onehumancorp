# Hybrid Agentic Identity Federation via SPIFFE/SPIRE

## Problem Statement
Competitors in the Agentic OS space rely on static API keys or platform-locked tokens for agent identity. OHC needs to enforce a "Zero Secrets" policy by introducing Zero-Trust Agentic Identity using SPIFFE/SPIRE, providing cryptographic, short-lived identities for agents whether they run in the local Standalone SQLite mode or the multi-tenant K8s Cloud.

## Research Report
A deep dive into the Agentic OS market reveals a massive security and identity management gap. Claude Code, OpenClaw, and Replit Agent rely on static API keys. OHC’s Hybrid Architecture (OHC-HA) is perfectly positioned to disrupt this by federating identity.
- Standalone Mode: The local agent receives a local SPIFFE ID, cryptographically proving its identity without relying on `OHC_CLOUD_API_KEY`.
- Cloud Federation: When escalating tasks to the multi-tenant cloud (`agent_missions` Bursting), the agent uses mTLS with its SPIFFE Verifiable Identity Document (SVID) to authenticate securely.

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC Vision (OHC-HA)** |
| :--- | :--- | :--- | :--- | :--- |
| **Agent Authentication** | Static local API Keys | Platform OAuth/Tokens | Internal Replit Auth | **SPIFFE/SPIRE SVIDs** (Zero Secrets) |
| **Secret Exfiltration Risk** | High (plaintext keys) | Medium | Medium | **Zero** (Short-lived, rotated SVIDs) |

## Design Doc

### Architecture
1. **Local Agent SVID**: The local Go sync daemon will obtain a SPIFFE ID from the local SPIRE agent.
2. **mTLS Authentication**: When sending bursting tasks via `BurstMission`, the HTTP client will be configured to use the SVID for mTLS.
3. **Cloud Endpoint Validation**: The cloud `auth.Middleware` will validate the incoming SVID.

**File Paths:**

- `srcs/server/auth/middleware.go`

**Function Signatures:**
- `func (s *SIPDB) BurstMission(ctx context.Context, missionID string, remoteEndpoint string) error`
- `func SPIFFEMiddleware(next http.Handler) http.Handler`

**Acceptance Criteria:**
1. In `sip.go`, modify the HTTP client in `BurstMission` and `SyncMissions` to retrieve the SVID from the environment or local SPIRE agent and include it in the headers (e.g. `Authorization: Bearer <svid>` or via mTLS).
2. Create `SPIFFEMiddleware` to validate the SVID and inject the authenticated identity into the request context.
3. Ensure no static API keys are used for this federation.
4. Record OpenTelemetry metrics for identity validation success/failures.
