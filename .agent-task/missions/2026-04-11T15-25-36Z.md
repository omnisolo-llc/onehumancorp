# Title: KAIROS Phase 1: Shared Task List & Distributed State Machine

## Problem Statement
The OHC Hybrid Agentic OS requires an autonomous, resilient backbone to seamlessly decompose complex, massive human goals into isolated, parallel agentic workflows. To prevent agents from stepping on each other and to properly sequence DAG (Directed Acyclic Graph) workflows, we need a robust, database-backed "Shared Task List" and "Distributed State Machine" functionality. Currently, the multi-agent execution pipeline lacks deterministic coordination and strict state transitions.

## Research Report
- **Market Context**: Orchestrating AI agents at a conglomerate scale requires state management comparable to Kubernetes controllers or temporal workflows. Simple array iterations of agents fail when concurrent steps are involved.
- **OHC Requirement**: Phase 1 of the "KAIROS Orchestrator" mandates a strict, distributed state machine where sub-agent tasks follow deterministic states (`PENDING` -> `EXECUTING` -> `REVIEW` -> `COMPLETED`).
- **Hybrid Architecture Considerations**:
  - In **Cloud-Native Mode**, this must leverage PostgreSQL (`FOR UPDATE SKIP LOCKED`) and Redis Distributed Locks.
  - In **Standalone Desktop Mode**, it must gracefully degrade to SQLite transactions and application-level `sync.Mutex` avoiding PostgreSQL-specific syntax errors.

## Design Doc
- **Module Path**: `srcs/server/orchestration/state` and `srcs/server/db/migrations`
- **Database Schema**:
  - `swarm_tasks` table: tracks `mission_id`, `parent_plan_id`, `dependencies` (JSONB), `title`, `status`, `assigned_agent_id`, `payload`, `locked_until`, `created_at`.
  - `state_machine_transitions` table: tracks state changes (`entity_id`, `entity_type`, `from_state`, `to_state`, `agent_id`, `reason`). Index on `entity_id` and `entity_type`.
- **Architecture**:
  - Create `StateManager` interface wrapping state transition logic and DB locking.
  - Implement `CloudStateManager` utilizing `RedisClient` and `PostgreSQL` semantics (`FOR UPDATE SKIP LOCKED`).
  - Implement `StandaloneStateManager` utilizing `sync.Mutex` and `SQLite` compatible queries.
  - Expose API or gRPC contracts to transition state and pull available tasks based on DAG dependencies.
