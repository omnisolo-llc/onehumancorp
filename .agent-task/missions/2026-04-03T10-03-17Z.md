# 🗺️ Guide: Onboarding System Doctor & API Key Wizard

## Problem Statement
The current Day One onboarding experience generates a `.env` file via `ohc-setup.sh` but leaves it up to the developer to figure out which environment variables (like `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) need to be configured for the agents to function. Furthermore, developers may not realize their local ports (e.g., 8080, 5432, 6379) are occupied, leading to confusing startup failures in Standalone and Cloud modes.

## Research Report
- The OHC "Hybrid Agentic OS" requires a frictionless setup.
- Existing tools in `ohc_hybrid_cli.sh` only execute setup and launch scripts.
- We need an interactive "Doctor" command that validates dependencies, port availability, and safely provisions API keys into the `.env` file.

## Design Doc
1. **CLI Enhancement**: Add a new menu option in `ohc_hybrid_cli.sh` labeled "Doctor & API Key Wizard".
2. **Dependency Check**: Validate `docker`, `bazelisk`, `go`, and `flutter` (optional but recommended).
3. **Port Check**: Use `nc` or `lsof` to check if ports 8080, 5432, and 6379 are available.
4. **API Key Provisioning**: Interactively ask the user for their LLM API keys and append/update them in the `.env` file using safe shell practices.
5. **Aesthetics**: Ensure the output matches the Premium Terminal Aesthetics mandate using the predefined color variables.

## Implementation Prompt
Update `ohc_hybrid_cli.sh` to include the "Doctor & API Key Wizard" function. Verify its functionality.
