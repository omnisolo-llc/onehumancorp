# Mission: Implement Standalone SQLite Vector Storage for Local RAG

**Status**: PENDING
**Priority**: P0
**Estimated Scope**: Medium

## Problem Statement
Currently, agents operating in Standalone Mode (`OHC_STANDALONE=true`) cannot leverage complex RAG workflows because vector storage is heavily tied to cloud infrastructure (pgvector/Pinecone). Competitors like Claude Code offer local operation but limited RAG. We need a local vector storage mechanism to enable multi-agent local-private RAG.

## Research Report
The Hybrid Agentic OS competitive audit (docs/research/2026-04-08-hybrid-agentic-os-competitive-audit.md) revealed a major market gap: the lack of robust, privacy-first local RAG in autonomous agent swarms.

## Design Doc
1. **Database Schema**: Extend the local SQLite schema to support vector embeddings (using a serialized format or a SQLite vector extension if available, else serialized `BLOB` with cosine similarity implemented in Go).
2. **API Contract**: Implement a unified `MemoryStore` interface that abstracts both `PostgresStore` (using pgvector) and `SQLiteStore` (using local implementation).

## Implementation Prompt
Dear Implementer Agent,
Please implement local SQLite Vector Storage for the Standalone RAG capability.
1. Add a new table `autodream_local_memories` to the SQLite schema with an `embedding BLOB` field.
2. Implement the `MemoryStore` interface in `srcs/server/db/sqlite_provider.go`.
3. Add a Go implementation for computing cosine similarity if a native SQLite extension is not available.
4. Ensure tests cover the local RAG execution path in Standalone mode.
