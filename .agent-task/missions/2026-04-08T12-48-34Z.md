# Shared Task List Database Schema and Orchestration APIs

## Problem Statement
The OHC swarm relies on a "Shared Task List" to decompose complex feature requests and coordinate agent workflows. Currently, there is a gap in the core data models and orchestration APIs needed to support a resilient, multi-tenant Shared Task List that seamlessly operates across both Cloud-Native (PostgreSQL/Redis) and Standalone (SQLite/Local Mutex) modes. The KAIROS orchestration layer requires this foundational schema and corresponding service layer to effectively track dependencies, assign sub-tasks, and integrate with the existing Distributed State Machine and Sub-Agent Queue.

## Research Report
The KAIROS Orchestrator acts as the master loop (Think -> Act -> Observe -> Decide).
Our existing orchestration primitives include:
- **Sub-Agent Queue (`srcs/server/orchestration/queue/queue.go`):** Handles background execution and retries.
- **Distributed State Machine (`srcs/server/orchestration/statemachine/machine.go`):** Ensures safe state transitions.
- **Teammate Mesh:** Uses Centrifuge and Redis Pub/Sub for real-time coordination.
- **AutoDream:** Handles long-term memory.

However, a persistent "Task" entity and its hierarchical relationships (Task -> Sub-Tasks) are missing. To achieve KAIROS Mode task decomposition, agents need a robust PostgreSQL/SQLite schema and Go microservice layer to create, query, and manage these shared task lists.
Competitive analysis of AI agent platforms (e.g., AutoGen, LangGraph) shows that explicit task tracking with robust state management is crucial for preventing deadlocks in multi-agent workflows.

## Design Doc

### 1. Database Schema (`srcs/server/db/migrations/..._create_shared_tasks.sql`)
We need a new table to store tasks. It must support multi-tenancy and hierarchical structures.

```sql
-- +goose Up
CREATE TABLE IF NOT EXISTS shared_tasks (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL,
    parent_task_id TEXT REFERENCES shared_tasks(id) ON DELETE CASCADE,
    title TEXT NOT NULL,
    description TEXT,
    priority TEXT NOT NULL, -- P0, P1, P2, P3
    status TEXT NOT NULL, -- PENDING, ASSIGNED, IN_PROGRESS, REVIEW, COMPLETED, FAILED
    assigned_agent_id TEXT,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_shared_tasks_org ON shared_tasks(organization_id);
CREATE INDEX idx_shared_tasks_parent ON shared_tasks(parent_task_id);
CREATE INDEX idx_shared_tasks_status ON shared_tasks(status);

-- +goose Down
DROP TABLE IF EXISTS shared_tasks;
```

### 2. Go Service Interfaces (`srcs/server/orchestration/tasks/service.go`)
Define the core service interface for managing tasks.

```go
package tasks

import (
    "context"
    "time"
)

type Task struct {
    ID              string
    OrganizationID  string
    ParentTaskID    *string
    Title           string
    Description     string
    Priority        string
    Status          string
    AssignedAgentID *string
    CreatedAt       time.Time
    UpdatedAt       time.Time
}

type Service interface {
    CreateTask(ctx context.Context, task *Task) error
    GetTask(ctx context.Context, id string, orgID string) (*Task, error)
    ListTasks(ctx context.Context, orgID string, parentID *string, status *string) ([]*Task, error)
    UpdateTaskStatus(ctx context.Context, id string, orgID string, newStatus string, agentID string) error
}
```

### 3. Implementation Plan
- Implement the `Service` interface in `srcs/server/orchestration/tasks/postgres_service.go` using `pgx` (for Cloud) and standard `database/sql` (for SQLite Standalone).
- Integrate the `UpdateTaskStatus` method with the existing `statemachine` package to ensure safe transitions.
- Integrate with `queue` package to dispatch sub-agents when a parent task is decomposed into sub-tasks.
- Ensure the API is wrapped with `auth.RequireRole("system", ...)` to enforce Zero-Trust compliance.
