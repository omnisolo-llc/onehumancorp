# Omni-Context Sub-agent Routing

**Problem Statement:**
Context latency and grounding drift during sub-agent delegation. Current models read files (`AGENTS.md` / `CLAUDE.md`) at spawn time, increasing time-to-first-token and risk of hallucination.

**Research Report:**
Following a surgical audit of the global Agentic OS landscape, we have identified a recurring structural bottleneck: context latency and grounding drift during sub-agent delegation. Current models rely on explicitly fetching project rules (`CLAUDE.md`, `AGENTS.md`) at spawn time, increasing time-to-first-token and the risk of hallucination.

### Competitive Market Audit

This analysis evaluates OHC against current market leaders across core agent orchestration parameters.

| **Context Retrieval** | Explicit file read (Adds Latency) | Persistent event history | On-demand indexing | **Instant Ingestion** via Omni-Context Routing |

**Design Doc:**
OHC will bridge this gap by directly embedding project grounding context into the swarm database at the exact moment of task delegation.
When an orchestrating agent creates a new mission for a sub-agent, the `SIPDB` system automatically reads standard grounding files (like `AGENTS.md` or `CLAUDE.md`) from the context root and injects their contents directly into the `agent_missions` payload under the `[SYSTEM GROUNDING]` namespace.

**Implementation Prompt:**
Modify the `DelegateMission` method in `srcs/server/orchestration/sip.go` to append file contents.
1. When a mission is delegated, check for the existence of `AGENTS.md` and `CLAUDE.md` in the current working directory or a configurable project root.
2. If found, read their contents.
3. Inject the combined contents into the `payload` field of the `agent_missions` schema, prefixed with `[SYSTEM GROUNDING]\n`.
4. Ensure the updated payload is saved to the database.
5. Add relevant unit tests in `srcs/server/orchestration/sip_test.go` to verify this behavior.
