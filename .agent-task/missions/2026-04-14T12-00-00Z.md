# KAIROS Orchestration Implementation

**Problem Statement:**
The OHC Swarm core functionalities (Shared Task List, Teammate Mesh APIs, and AutoDream Data Pipelines) need to be implemented to allow One Human Corp to operate seamlessly as a Hybrid Agentic OS, balancing cloud-native scalability with standalone desktop privacy. We need to create the missing structural definitions and database schemas for these core orchestration concepts.

**Research Report:**
- Evaluated codebase and architectural blueprints for the KAIROS engine.
- Shared Task List requires a distributed state machine (PostgreSQL/SQLite schemas) using `shared_tasks`.
- Teammate Mesh APIs require low-latency communication representations.
- AutoDream requires pipelines to convert ephemeral memories into long-term embeddings (pgvector) in `consolidated_memory`.
- Sub-Agent Queue requires a database representation in `sub_agent_jobs` or `sub_agent_queue` mimicking BullMQ/Celery logic for Go workers.

**Design Doc:**
See `design/kairos_orchestration.md` for complete design specifications.

**Implementation Prompt:**
Implement the Database Schema and core structures as defined in the Design Doc.
Specifically:
1. Ensure the PostgreSQL schemas for `shared_tasks`, `consolidated_memory`, and `sub_agent_queue` (and `sub_agent_jobs`) are correctly modeled in `srcs/server/db/BUILD.bazel` by adding any missing migrations to the `embedsrcs` of the `db` go_library target.
2. Define the corresponding Go structs in `srcs/server/orchestration/models.go` to match the schema.
3. Ensure that hybrid fallbacks (PostgreSQL -> SQLite) are handled correctly per the architectural mandates.
