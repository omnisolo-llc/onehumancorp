## Title
AutoDream Pipeline - PgVector Embeddings Pipeline

## Problem Statement
OHC requires an AutoDream data pipeline to consolidate episodic memory into long-term vector embeddings. This allows agents to recall past coordination and system context autonomously. The pipeline needs to handle text content alongside `VECTOR(1536)` embeddings in the database.

## Research Report
Memory indicates the `autodream_memories` table serves as the primary context table for OHC RAG, storing text alongside embeddings. The AutoDream pipeline needs to automatically process completed tasks and coordination sessions into these vectors.

## Design Doc
1.  **Database Setup**:
    -   Implement migration for the `autodream_memories` table with `VECTOR(1536)` for pgvector in PostgreSQL. Include fallback schema without vectors for SQLite if pgvector extension is absent locally.
2.  **Pipeline Logic**:
    -   Implement `srcs/server/orchestration/autodream.go`.
    -   Provide methods to accept text context, generate embeddings (mocked or real depending on LLM config), and upsert into the DB.
    -   Implement background worker to periodically scan completed Shared Tasks and Mesh logs to populate memory.

## Implementation Prompt
1. Create DB migrations for `autodream_memories`.
2. Implement the AutoDream pipeline service to ingest text and store vectors.
3. If writing Hybrid queries, handle standard arguments appropriately.
4. Add telemetry for AutoDream consolidation cycles (`telemetry.AutoDreamConsolidationTotal`).
5. Ensure robust testing: `bazelisk test //srcs/server/...`.
