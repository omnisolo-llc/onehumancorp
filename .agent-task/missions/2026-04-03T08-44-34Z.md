# Title: Implement Hybrid MCP RAG Protocol (Offline-to-Cloud Sync)

## Problem Statement
Competitors force users into a binary choice: trade privacy for cloud-scale execution, or trade scalability for local privacy. Replit and OpenClaw index only what is in the cloud, and Claude Code indexes only local directories. OHC needs to bridge this gap to synchronize a local SQLite RAG state to the cloud Postgres orchestration engine via OHC-SIP, allowing private execution locally with cloud escalation when massive parallel computation is needed.

## Research Report
A comprehensive audit of the global Agentic OS market benchmarks OHC against Claude Code, OpenClaw, and Replit Agent, revealing a structural vulnerability across competitors (over-reliance on cloud dependency or strictly siloed local states). OHC’s Hybrid Architecture provides an unmatchable "Unfair Advantage" via Offline-to-Cloud State Sync for Swarm Memories. See `RESEARCH_REPORT_HYBRID_RAG.md` for full details, Mermaid charts, and competitive tables.

## Design Doc
- **Architecture**: A daemon/synchronizer component that runs in Standalone mode.
- **Data flow**: When a local MCP agent detects a task requiring scalable compute, it orchestrates a synchronization. It sanitizes and packages the minimal required local context payload (from SQLite `agent_missions` / RAG DB) and injects it into the Cloud Postgres `agent_missions` table.
- **API Contracts**:
  - `POST /api/sync/missions`: Endpoint on the cloud API to accept synced payloads.
- **DB Schema Changes**: None required if `agent_missions.payload` JSONB can accommodate the synchronization schema.
- **UI Wireframes**: A "Syncing to Cloud Swarm" glassmorphism indicator in the Desktop Standalone shell.

## Implementation Prompt
You are an Implementer agent. Your task is to build the "Hybrid MCP RAG Protocol" synchronizer.
1. In `srcs/server/orchestration/`, create a new file `sync_daemon.go`.
2. Implement a background loop that queries the local SQLite `agent_missions` for items marked for cloud escalation. Always include a `LIMIT 100` clause in your background sync loop `SELECT` query to prevent memory explosion.
3. The sync function should securely format the local payload and make an authenticated HTTP POST request to the remote OHC Cloud API (using `OHC_CORE_URL` or a configured remote endpoint).
4. In `srcs/server/api/`, add a route and handler for `POST /api/sync/missions` to receive this payload and insert it into the Postgres `agent_missions` table.
5. Provide high-coverage unit tests for the daemon, utilizing `db.NewSqliteProvider(sqlDB)` for the local mock and ensuring cloud payload format validation.
6. Verify your changes do not break standalone/cloud abstractions.
