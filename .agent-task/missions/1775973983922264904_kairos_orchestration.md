# Mission: Architect and Implement KAIROS Orchestration
**Title**: Architect and Implement KAIROS Orchestration (Shared Task List, Teammate Mesh APIs, and AutoDream Vector Consolidation)
**Priority**: P0
**Estimated Scope**: Large

## Problem Statement
The OHC swarm currently lacks a complete implementation of the centralized, distributed KAIROS Orchestration layer. Agents cannot effectively coordinate, decompose, and track task execution across the hybrid architecture. Without a robust Shared Task List, real-time Teammate Mesh, and persistent AutoDream memory consolidation, swarm autonomy is bottlenecked.

## Research Report
Competitive analysis reveals that systems without robust distributed lock management and real-time state synchronization fail at scale.
- Replit and Claude lack native Swarm Intelligence built on durable PostgreSQL vector backends.
- OHC's unique value proposition is the Hybrid Architecture, allowing Cloud-Native PostgreSQL (FOR UPDATE SKIP LOCKED) to gracefully degrade to local SQLite mutex operations.
- The KAIROS system must decompose tasks, synchronize agent mesh communications over WebSockets (Redis Pub/Sub), and durably embed context artifacts into pgvector.

## Design Doc
1. **Shared Task List Schema (PostgreSQL/SQLite)**:
```sql
CREATE TABLE IF NOT EXISTS shared_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id VARCHAR NOT NULL,
    title VARCHAR NOT NULL,
    description TEXT,
    status VARCHAR NOT NULL DEFAULT 'PENDING',
    agent_id VARCHAR,
    priority VARCHAR NOT NULL DEFAULT 'P2',
    payload JSONB,
    parent_plan_id TEXT,
    dependencies JSONB NOT NULL DEFAULT '[]',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

2. **Teammate Mesh**:
- Cloud-Native Mode utilizes Redis Pub/Sub connected to Centrifuge hubs for WebSocket propagation to thin clients and sub-agents.
- Messages flow via channels like `mesh:tasks`, `mesh:coordination`.

3. **AutoDream Data Pipeline**:
- Intermediate worker outputs and session logs are compressed by a background pipeline.
- The pipeline utilizes embeddings, storing them directly in a `pgvector` enabled table (`autodream_memories`) for exact semantic match recall.

4. **Visual Guidelines**:
- UI wrappers for dashboards MUST utilize OHC CSS glassmorphism tokens (`backdrop-filter: blur(20px)`, `Outfit/Inter`).
