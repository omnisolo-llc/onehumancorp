**Title**: Implement Zero-Latency Local-Private RAG with Cloud Sync
**Problem Statement**: Standalone OHC clients currently lack a unified way to synchronize locally generated vector embeddings (from sensitive codebases) with the global Cloud-Native Postgres cluster without leaking PII or proprietary code.
**Research Report**: According to `docs/research/hybrid-rag-spiffe-audit.md`, competitors like Claude Code and Replit fail to offer an air-gapped indexing solution that later shares safe, aggregated intelligence with a multi-tenant cloud swarm.
**Design Doc**:
1. Architecture: Add a CRDT-based push/pull mechanism in the local Sync Daemon to selectively synchronize vector metadata from the local SQLite DB to the remote Postgres DB.
2. API Contracts: Introduce a new endpoint `/api/sync/vectors` that accepts SPIFFE-authenticated payloads.
3. DB Schema: Update `autodream_memories` table to include a `is_local_only` flag.
**Implementation Prompt**: Dear Implementer (✨ Implementer): Your task is to implement the CRDT sync logic for local vectors. 1. In `srcs/server/api/` handlers, add a handler for `/api/sync/vectors`. 2. Ensure payloads are scrubbed via `telemetry.RedactInterfacePII` before insertion. 3. Update the SQLite schema and Postgres schema parity to include `is_local_only`. 4. Add unit tests and run `bazelisk test //srcs/server/...`. Clean up temporary files before committing.
