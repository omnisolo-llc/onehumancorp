# Title: Implement KAIROS Orchestration: Shared Task List, Teammate Mesh, & AutoDream

## Problem Statement
The OHC Swarm requires a central orchestrator ("KAIROS") to decompose high-level feature requests into actionable sub-tasks and manage their lifecycle. Currently, the multi-agent coordination lacks a robust distributed state machine to handle concurrent task claiming across cloud-native and standalone environments. Furthermore, inter-agent communication (Teammate Mesh) needs formalized API contracts, and temporary agent scratchpads must be consolidated into a long-term Vector DB (AutoDream) to ensure durable, cross-session agent memory.

## Research Report
- **Competitive Analysis:** Frameworks like LangGraph provide stateful checkpoints, but OHC requires a truly decoupled Swarm Intelligence Protocol (OHC-SIP) that operates seamlessly across multi-tenant K8s pods and single-process SQLite instances.
- **Concurrency Bottlenecks:** In a cloud-native shared PostgreSQL database, multiple agents polling for the same pending task can cause Time-Of-Check to Time-Of-Use (TOCTOU) race conditions. Utilizing `FOR UPDATE SKIP LOCKED` handles this effectively on PostgreSQL. Conversely, SQLite Standalone Mode requires atomic `UPDATE ... RETURNING` queries and potentially `sync.Mutex` for queue acquisition.
- **Memory Consolidation:** Temporary `.agent-task/memory/*.yml` files accumulate rapidly. Translating these YAML states into ADA-1536 embeddings allows context retrieval via `pgvector` during future planning phases.

## Design Doc

### 1. Architecture: Shared Task List
- **State Machine Schema:**
  - Enhance `shared_tasks` (id, organization_id, title, description, status, agent_id, priority, payload, locked_until, created_at, updated_at).
  - Add or refine `task_dependencies` (task_id, depends_on_task_id) for task sequencing.
- **Queue Acquisition Flow:**
  - Implement a `DequeueTask` method in the `Provider` interface.
  - **PostgreSQL Path:** `SELECT id FROM shared_tasks WHERE status = 'PENDING' FOR UPDATE SKIP LOCKED LIMIT 1`.
  - **SQLite Path:** Use a Go `sync.Mutex` and `UPDATE shared_tasks SET status = 'IN_PROGRESS', agent_id = ? WHERE id = (SELECT id FROM shared_tasks WHERE status = 'PENDING' LIMIT 1) RETURNING id`.

### 2. Architecture: Teammate Mesh APIs
- **Realtime Mesh Channels:** Build the backend WebSocket handler mapped to Centrifuge channels (e.g., `mesh:tasks`, `mesh:coordination`).
- **Payload Strictness:** JSON payloads broadcasted MUST enforce OHC-SIP shape: `agent_id`, `action`, and `status` at the root level.
- **Transport Mechanisms:**
  - **Cloud:** Leverage Redis Pub/Sub for Centrifuge scaling.
  - **Local/Standalone:** Fallback to Go channels (In-Memory Broadcast).

### 3. Architecture: AutoDream Vector Pipeline
- **Pipeline Daemon:** A background worker routine inside the `autodream` agent or `task_orchestrator`.
- **Sync Logic:** Poll `.agent-task/memory/*.yml`. For each file, pass the `context` to the LLM for summarization, convert to an embedding, and upsert into `swarm_long_term_memory` (with `VECTOR(1536)`).
- **Standalone Behavior:** Conditionally start this engine using `if dbWrapper.IsSQLite()` check if designed to run exclusively locally, otherwise ensure cloud-native PostgreSQL vector storage.

### 4. Visual Excellence Mandate
UI components visualizing the task list or Teammate Mesh coordination must use the following CSS properties for the OHC "Premium Feel":
- `backdrop-filter: blur(20px) saturate(200%)`
- `background: rgba(255, 255, 255, 0.03)`
- `font-family: 'Outfit', 'Inter', sans-serif`
If using Flutter, these translate to `BackdropFilter`, `ImageFilter.matrix` for saturation, and explicit `Outfit` or `Inter` text styles.
