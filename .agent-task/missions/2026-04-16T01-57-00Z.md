# [research] Implement Dynamic Cloud Escalation for Hybrid MCP RAG

**Priority:** P0
**Estimated Scope:** Large

## Problem Statement
Competitors force a binary choice: local-only execution (Claude Code) causing CPU bottlenecks or mandatory cloud sync (Replit Agent) violating privacy. OHC needs a seamless bridge: execute private MCP RAG locally via SQLite by default, but dynamically escalate to cloud PostgreSQL orchestration when massive parallel computation or swarm consensus is required, preserving privacy while unlocking infinite scale.

## Research Report
Based on the competitive audit (OHC vs Claude Code/Replit Agent/OpenClaw), OHC's unique "Hybrid Architecture" positions it as the only viable "Agentic OS" for privacy-conscious power users. A critical feature gap is the lack of a built-in telemetry-driven threshold to auto-escalate local SQLite RAG workloads to the cloud Swarm via PostgreSQL.

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC (Proposed)** |
| :--- | :--- | :--- | :--- | :--- |
| **Privacy** | Local Only | Cloud Exfiltration | Cloud Exfiltration | **Hybrid (Local Default)** |
| **Scalability** | CPU Bound | Infinite | Infinite | **Dynamic Escalation via Thresholds** |
| **Offline Support** | Yes | No | No | **Yes (SQLite fallback)** |

## Design Doc
**Architecture:** A new `Sync Escalator` daemon running locally, governed by SPIFFE/SPIRE for auth.
**DB Schema:** A new table `local_mcp_rag_tasks` in the SQLite DB with an `escalation_status` column.
**API Contracts:** `POST /api/v1/orchestration/escalate` to hand off local task IDs to the cloud swarm.
**UI Wireframes:** A Glassmorphism dashboard widget indicating local vs cloud execution state with 20px blur styling.
