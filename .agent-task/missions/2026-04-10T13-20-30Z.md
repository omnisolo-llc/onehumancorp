# Title: Implement Hybrid Secrets Management MCP Proxy

## Problem Statement
Competitors build tools that are acutely aware of their environment. Over-reliance on environment-locked integrations limits agent portability in the hybrid architecture.

## Research Report
As One Human Corp (OHC) continues its trajectory toward absolute market dominance in the Agentic OS ecosystem, our "Unfair Advantage"—the **Hybrid Architecture (OHC-HA)**—must be extended to every tool and capability the agents possess. A surgical audit of Claude Code, OpenClaw, and Replit Agent reveals a common weakness: rigid, environment-locked integrations.

Based on `docs/features/advanced-agentic-capabilities/zero-trust-secret-injection/design-doc.md`, the MCP Gateway fetches the required secret just-in-time during tool execution, injecting it as an environment variable in the isolated worker pod. The secret is completely obfuscated from the agent's LLM context window.

This report outlines a strategic imperative: **Hybrid Secrets Management MCP Proxy**. Specifically, abstracting secret management behind a proxy that seamlessly switches between local environments (for Standalone Desktop mode) and Cloud environments (K8s Secrets / HashiCorp Vault for Multi-tenant Cloud mode), allowing agents to execute identical reasoning logic across entirely different infrastructure paradigms.

## Design Doc
Implement Mode-Aware Hybrid MCP Proxies for Secrets. When an OHC Agent uses a tool requiring a secret, it interacts with an `mcp.SecretProvider` interface. In `OHC_STANDALONE=true` mode, this proxy routes to a local secret store. In `OHC_MULTITENANT=true` mode, the exact same agent logic seamlessly fetches the secret from a K8s Secret or HashiCorp Vault.

This requires introducing an interface (`mcp.SecretProvider`) in the Go backend (`srcs/server/agents/mcp`) and implementing concrete providers (e.g., `LocalSecretProvider` and `CloudSecretProvider`). A factory pattern will evaluate the environment variables at boot time and inject the appropriate provider into the MCP server registry.

## Implementation Prompt
1. Create `mcp.SecretProvider` interface (`GetSecret(ctx context.Context, key string) (string, error)`) in `srcs/server/agents/mcp/secret_provider.go`.
2. Implement `LocalSecretProvider` in `srcs/server/agents/mcp/local_secret_provider.go` using a mock local store.
3. Implement `CloudSecretProvider` in `srcs/server/agents/mcp/cloud_secret_provider.go` using mock K8s/Vault logic.
4. Create a factory `NewSecretProvider()` in `srcs/server/agents/mcp/secret_provider.go` that checks `OHC_MULTITENANT` and `OHC_STANDALONE` environment variables and returns the appropriate provider.
