# Title: Shared Task List & Teammate Mesh Integration

## Problem Statement
The Swarm lacks a coordinated mechanism for task claiming and agent-to-agent realtime updates. Without this, sub-agents may experience race conditions when attempting to pick up shared tasks, leading to duplicated efforts or missed operations.

## Research Report
- Current synchronization relies on file-system locks which are not viable in Cloud-Native Mode.
- Teammate Mesh communication needs a hybrid approach that supports both Redis Pub/Sub (Cloud) and LocalMeshBroker (Standalone).
- Consolidating agent ephemeral memory into a PGVector based solution (`AutoDreamWorker`) provides long-term persistence that scales effectively.
- Reference architectures are defined in `docs/architecture/kairos_orchestration_shared_mesh_v2.md`.

## Design Doc
See `docs/architecture/kairos_orchestration_shared_mesh_v2.md` for full DB schemas and sequence diagrams.

## Implementation Prompt
Implement the Shared Task List and Teammate Mesh integration. Ensure that `FOR UPDATE SKIP LOCKED` is used for Postgres-backed shared_tasks queries and `LocalMeshBroker` is used when Redis is unavailable. Update the appropriate service endpoints to incorporate these changes. See `docs/architecture/kairos_orchestration_shared_mesh_v2.md` for architectural context.
