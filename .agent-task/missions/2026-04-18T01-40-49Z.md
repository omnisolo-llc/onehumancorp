# Mission: Implement Hybrid RAG Synchronization Engine (SQLite to pgvector)

**Title**: Implement Hybrid RAG Synchronization Engine (SQLite to pgvector)

**Problem Statement**:
OHC's competitors force a binary choice between local privacy (Claude Code) and cloud scaling (Replit). Currently, our agents lack a mechanism to sync local SQLite episodic memories up to the KAIROS Cloud PostgreSQL (pgvector) cluster. We need a background synchronization engine to bridge this gap, enabling true Hybrid Swarm Intelligence.

**Research Report**:
See `docs/reports/RESEARCH_REPORT_HYBRID_RAG_SYNC.md` for a complete competitive audit and Mermaid architecture diagram.

**Design Doc**:
1. **Local State**: Agents operating in Standalone Mode write to a local SQLite `autodream_memories` table.
2. **Synchronization Trigger**: The local `AutoDreamSyncEngine` daemon triggers synchronization in the background loop.
3. **Replication**: The `AutoDreamSyncEngine` reads un-synced rows from SQLite and pushes them over HTTP to the Cloud API Server.
4. **Cloud Aggregation**: The KAIROS API Server writes these incoming memories into the Cloud PostgreSQL database and autoDream processes them into `pgvector` embeddings.

**Implementation Prompt**:
You are an Implementer agent assigned to update the `AutoDreamSyncEngine`.
1. Update `srcs/server/sync/autodream_sync.go` to synchronize records from the `autodream_memories` table to the Cloud.
2. Define a method `syncAutoDreamMemories(ctx context.Context)` inside `AutoDreamSyncEngine`.
3. Implement the SQLite -> PostgreSQL record translation logic. Query `autodream_memories` from SQLite where records have not been synced yet (e.g., add a `synced_to_cloud` column if missing).
4. Send the batch to the Cloud API.
5. Write unit tests achieving >90% coverage using mocked local and remote database providers. Ensure fallback safety if the cloud is unreachable.
6. Adhere to the KAIROS fail-closed security mandate.

**Priority**: P0
