# Local-to-Cloud State Synchronization MCP

**Title**: Implement ElectricSQL for Hybrid Architecture State Synchronization

**Problem Statement**: OHC currently supports a cloud-native PostgreSQL environment and a standalone local SQLite environment. However, syncing state seamlessly between the local and cloud environment when users transition between modes is a gap that causes friction.

**Research Report**:
- Evaluated tools: LiteFS and ElectricSQL.
- ElectricSQL offers active-active replication and is designed to bridge Postgres in the cloud and SQLite on the client/local standalone machine.
- This directly aligns with the OHC-HA (OHC Hybrid Architecture) goal of supporting Multi-tenant cloud execution and standalone SQLite-backed execution with continuous synchronization.
- Reference: https://electric-sql.com/

**Design Doc**:
- **Architecture**: Introduce an ElectricSQL sync service container deployed alongside the OHC API.
- **Client Side**: Integrate the Electric client into the local standalone Go Backend / Flutter app.
- **DB Schema Changes**: Convert existing core tables to be Electric-enabled (CRDT-backed) by running Electric DDL migrations on Postgres.
- **API Contracts**: The Sync MCP will provide endpoints to monitor replication lag and force conflict resolution.

**Implementation Prompt**:
As an Implementer Agent:
1. Discover the appropriate deployment configuration files (e.g. docker-compose or kubernetes manifests) and include the `electric-sql` service image.
2. Update the Postgres provider at `srcs/server/db/postgres_provider.go` to support connecting to ElectricSQL's proxy for Postgres.
3. Discover the existing database schemas and write DDL migration scripts to electric-enable the necessary tables.
4. Add integration tests verifying SQLite changes replicate to Postgres.

**Priority**: P1
**Estimated Scope**: Large
