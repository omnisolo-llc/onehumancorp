# Implement KAIROS Orchestrator: Shared Task List & Sub-Agent Queue

**Problem Statement:**
The OHC Hybrid Agentic OS requires an autonomous, resilient backbone to seamlessly decompose massive human goals into isolated, parallel agentic workflows. We need to implement the actual database schemas and Go code for the "Shared Task List" (Phase 1), "Sub-Agent Orchestration Queue" (Phase 2), "Teammate Mesh APIs" (Phase 2), and "autoDream data pipelines" (Phase 3) supporting both Cloud-Native (PostgreSQL/Redis) and Standalone (SQLite) modes.

**Research Report:**
- **Shared Task List**: Acts as the "Brain", breaking down large tasks into a Directed Acyclic Graph (DAG).
  - PostgreSQL uses `SELECT FOR UPDATE SKIP LOCKED` for Cloud-Native concurrency.
  - SQLite uses explicit transactions/mutexes (`sync.Mutex` / `datetime('now')`) for Standalone execution.
- **Sub-Agent Orchestration Queue**: Distributes tasks to worker agents.
  - Cloud-Native uses Redis (via `rueidis`) Lists/Sorted Sets.
  - Standalone uses an internal SQLite table (`sub_agent_jobs`) with locking.
- **Teammate Mesh APIs**:
  - Exposes `POST /api/mesh/broadcast` and `GET /api/mesh/subscribe`.
  - Payloads are OHC-SIP compliant (JSON with `agent_id`, `action`, `status`).
- **AutoDream Pipelines**:
  - Sync local SQLite vector embeddings to Cloud pgvector instances.
  - Consolidates episodic agent memory into a durable vector store (`autodream_memories`) using `VECTOR(1536)` embeddings.

**Design Doc:**
See `docs/architecture/kairos_premium_master_design.md` for the complete architectural diagram, structural vision, and premium aesthetic tokens.

**Implementation Prompt:**
1. **Schema Definition**: Create PostgreSQL (`.sql`) and SQLite (`.sql`) schemas for `shared_tasks`, `sub_agent_jobs`, and `autodream_memories`.
   - *Requirement*: Use `id TEXT PRIMARY KEY` and map `JSONB` to SQLite `TEXT`. Utilize `pgvector` extension for `autodream_memories`.
2. **Go Interfaces**: Define repository interfaces for the Task List, Queue, and AutoDream pipeline in `srcs/server/orchestration/`.
3. **Queue & Pipeline Implementations**: Write `RedisTaskQueue` and `SQLiteTaskQueue`. Implement background worker to compress and vectorize memories into `autodream_memories`.
4. **API Implementation**: Implement the Teammate Mesh REST APIs (`/api/mesh/broadcast`, `/api/mesh/subscribe`) and payload validation.
5. **Observability**: Instrument critical paths with OpenTelemetry metrics (`metric.Float64Histogram`) placed at the root level of initialization functions.
6. **Testing**: Write unit and integration tests using `t.Fatalf`/`t.Errorf`. Set `DATABASE_URL` to `sqlite://:memory:` for SQLite tests.
