# Title: Implement Advanced Token Burn Rate Forecasting Engine

## Problem Statement
While `ohc_token_usage_total` provides a high-level overview of token consumption, it is insufficient for proactive budget management and capacity planning across multiple tenants in Cloud-Native mode. We lack a predictive model that can extrapolate future usage based on historical trends, leading to reactive responses rather than proactive alerting when a tenant is approaching their token budget.

## Research Report
Current implementation in `srcs/server/telemetry/telemetry.go` tracks token usage via a simple counter (`ohc_token_usage_total`). A new metric, `ohc_token_burn_rate_forecast`, has been partially defined but lacks a robust underlying calculation engine. To address this, we need to implement a dedicated background worker in the Orchestration Hub that calculates a moving average (e.g., EMA - Exponential Moving Average) of token usage and emits predictive cost alerts grouped by `organization_id`. This aligns with the "Token Burn Rate Forecasting Engine" proposed in previous audits.

## Design Doc
1. **Engine Component:** Create a new `TokenForecastWorker` in `srcs/server/orchestration/hub.go` or a dedicated package.
2. **Logic:** Periodically (e.g., every minute) sample the current token usage per tenant. Calculate the moving average and update the `ohc_token_burn_rate_forecast` metric.
3. **Grafana Dashboards:** Ensure `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` accurately reflects this new predictive metric with clear visualizations and alerts.
