# Problem Statement
KAIROS requires a distributed, deadlock-free database state machine to map high-level features into atomic sub-tasks that can be processed concurrently by Swarm workers.

# Research Report
PostgreSQL's `SKIP LOCKED` pattern provides robust job-queue capabilities without needing external components like Celery, ensuring simpler operations for Cloud deployments, while SQLite transactions protect Standalone deployments from TOCTOU bugs. See `docs/architecture/kairos_task_decomposition_design.md`.

# Design Doc
Refer to `docs/architecture/kairos_task_decomposition_design.md` for exact schema definitions and sequence diagrams.

# Implementation Prompt
Create the database migration to add the `shared_tasks_decomposition` table as outlined in the design doc. Update `srcs/server/db/BUILD.bazel` to include the new migration file. Implement the repository logic in `srcs/server/orchestration/` to allow fetching tasks with hybrid locking strategies. Add unit tests for task claiming.
