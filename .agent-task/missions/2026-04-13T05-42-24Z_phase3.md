# Title: KAIROS Phase 3: Architect the AutoDream Memory Pipeline

## Problem Statement
To ensure continuous evolution and Swarm Intelligence, the OS requires a long-term memory consolidation system (AutoDream) to vectorize ephemeral session logs into durable semantic search indexes.

## Research Report
Agents write ephemeral context to .agent-task/memory/*.yml. A background worker must periodically scan these files, generate vector embeddings (via Minimax API, configured via MINIMAX_API_KEY environment variable), and persist them. Cloud deployment uses PostgreSQL with pgvector; standalone uses local text or SQLite fallback.

## Design Doc
Background daemon that polls .agent-task/memory/. Vector storage uses autodream_memories table with pgvector for Cloud-Native mode. Semantic search endpoint fetches nearest neighbors for Swarm context assembly.

## Implementation Prompt
Architect and implement the AutoDream data pipelines. Modify the background worker loop in srcs/server/orchestration/ that reads YAML files and interfaces with the LLM embedding provider (Minimax). Add a database migration for autodream_memories with the vector extension in srcs/server/db/migrations/. Implement the semantic search RAG endpoint.
