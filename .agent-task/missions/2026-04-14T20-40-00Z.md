# Design Doc
Refer to the architectural guidelines found in `docs/features/kairos/master_design.md` and `docs/features/kairos/KAIROS_HYBRID_ORCHESTRATION.md`.
The implementation requires:
- `TaskStore` interface and `SharedTaskOrchestrator` in `srcs/server/orchestration/tasks_store.go` and `srcs/server/orchestration/tasks_db.go`.
- `MeshBroker` interface and `LocalMeshBroker`, `RedisMeshBroker`, and `HTTPHandler` implementations in `srcs/server/orchestration/mesh/`.
- Integrating `HTTPHandler` for `POST /api/mesh/v2/broadcast` endpoint in `srcs/server/dashboard/server.go`.
- `AutoDream` data pipelines for OHC's long-term memory consolidation system, using `pgvector` and LLM embeddings.

# Implementation Prompt
Hello Implementer! Follow these instructions to execute the KAIROS Orchestration backend features:

1. **Implement Teammate Mesh APIs:**
   - Create `srcs/server/orchestration/mesh/broker.go` with a `MeshBroker` interface possessing `Broadcast(ctx context.Context, channel string, payload []byte) error`.
   - Implement `RedisMeshBroker` using `github.com/redis/go-redis/v9` in `srcs/server/orchestration/mesh/redis_broker.go`.
   - Implement `LocalMeshBroker` using Go channels and a `sync.RWMutex` in `srcs/server/orchestration/mesh/local_broker.go`.
   - Implement an HTTP handler in `srcs/server/orchestration/mesh/http_handler.go` that decodes `channel`, `event_type`, and `data` from JSON and limits payloads to 1MB. Use `Broadcast` on the configured `MeshBroker`.
   - Register this new handler in `srcs/server/dashboard/server.go` for the path `POST /api/mesh/v2/broadcast`.

2. **Implement Task Store:**
   - Define the `TaskStore` interface in `srcs/server/orchestration/tasks_store.go` containing `ClaimTask` and `TransitionTask`.
   - Implement `ClaimTask` and `TransitionTask` in `srcs/server/orchestration/tasks_db.go` under `SharedTaskOrchestrator`.
   - Ensure the logic gracefully degrades to SQLite from PostgreSQL using `dbProvider.IsSQLite()`, correctly utilizing `FOR UPDATE SKIP LOCKED` for PG. Ensure `dependencies` array parsing works across DB types.

3. **Database Migration:**
   - Create a database migration for the `shared_tasks_decomposition` schema using `[NEXT_AVAILABLE]_shared_tasks.sql`.
   - Create a database migration for `autodream_memories` using `[NEXT_AVAILABLE]_autodream.sql` ensuring `pgvector` is used for `vector_embedding` in Cloud Mode.

4. **Implement AutoDream Pipeline:**
   - Implement `srcs/server/orchestration/autodream_pipeline.go` to connect `pgvector` to LLM embeddings and save consolidated truth into the memory tables.

5. **Verify:**
