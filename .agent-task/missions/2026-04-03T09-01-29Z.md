## Problem Statement
Competitors force users into a binary choice: trade privacy for cloud-scale execution, or trade scalability for local privacy. OHC’s Hybrid Architecture (OHC-HA) bridges this divide, allowing seamless operation switching. ### Feature Disruption: Local-Private RAG with Cloud-Scale Routing
The immediate opportunity is a unified **"Hybrid MCP RAG Protocol"**.
While Replit and OpenClaw index only what is in the cloud, and Claude Code indexes only local directories, OHC can synchronize a local SQLite RAG state to the cloud Postgres orchestration engine via OHC-SIP.

- **Private Execution**: Highly sensitive datasets are processed purely via local standalone Desktop mode.
- **Cloud Escalation**: When massive parallel computation is needed, the local client securely delegates generalized tasks to the K8s multi-tenant cloud without exposing the raw private dataset, syncing only required context payloads into the cloud's `agent_missions` table.

## Design Doc
### Architecture
- **Local Daemon**: A background process running in Standalone Desktop Mode (SQLite) that monitors local vector RAG states and mission payloads.
- **Cloud Gateway**: A secure K8s ingress endpoint that receives sanitized payloads via OHC-SIP, placing them into the `agent_missions` Postgres table.
- **Synchronization Logic**: Ensure vector embeddings are safely stringified using `%g` prior to transfer and re-ingested into `pgvector`. Background syncs must utilize `LIMIT` clauses to avoid unbounded memory queries.

### Database Schema Additions
- Modify local `sqlite` and cloud `postgres` schema to include standard `sync_status` and `last_synced_at` columns on Swarm Memory tables.

## Implementation Prompt
1. Implement a Go background worker in `orchestration/sync/worker.go` that queries the SQLite `agent_missions` table for records where `sync_status = 'pending'`.
2. Ensure the query incorporates `LIMIT 100` to constrain memory footprint.
3. Use `github.com/google/uuid` to ensure universally unique IDs on creation before inserting into SQLite since RETURNING is not recommended.
4. Format vector states for transit, explicitly using `%g` stringification.
5. Create an endpoint in the K8s cloud ingress to accept this synchronized state and insert it via Postgres, updating the local state upon success.
6. Guard any row-level locking (e.g., `FOR UPDATE SKIP LOCKED`) with an `!db.IsSQLite()` check.
7. Provide tests with initialized `db.NewSqliteProvider(sqlDB)` proving successful local extraction, formatting, and update.
