# Title: Integrate PowerSync for Hybrid Local-to-Cloud Synchronization

## Problem Statement
One Human Corp (OHC) operates under a Hybrid Architecture (OHC-HA), which requires seamless transitions between a multi-tenant Cloud environment (PostgreSQL) and a Standalone Desktop environment (SQLite). Currently, there is a gap in offline-to-cloud state sync for swarm memories and agent missions. OHC requires a robust, bi-directional synchronization mechanism that allows secure, private local execution (SQLite) to seamlessly escalate generalized computation to the cloud (PostgreSQL) without compromising data sovereignty or causing state conflicts.

## Research Report
Based on an evaluation of available synchronization technologies for the Flutter/Go/Postgres/SQLite stack, **PowerSync** emerges as the designated architectural solution.
*   **Capability**: PowerSync provides a robust Postgres-to-SQLite replication layer. It is specifically designed to keep local SQLite databases in sync with a centralized PostgreSQL backend.
*   **Ecosystem Fit**: PowerSync offers robust Flutter SDK support, making it an ideal fit for OHC's Flutter-based mobile, desktop, and web clients.
*   **Security & Multi-tenancy**: PowerSync uses a dynamic sync rules engine based on JWTs, which aligns perfectly with OHC's `organization_id` multi-tenant architecture and SPIFFE/SPIRE identity models.
*   **Offline Resilience**: It natively supports offline mode and optimistic local updates, ensuring the Standalone Desktop mode degrades gracefully and remains fully functional without an active network connection.
*   **Competitor Delta**: Unlike Replit (cloud-only) or Claude (local-only), this enables OHC's "Offline-to-Cloud State Sync for Swarm Memories", solidifying our "Blue Ocean" advantage.

## Design Doc

### Architecture
1.  **PowerSync Service**: A new backend component (run alongside the Go API in Cloud mode) connected directly to the multi-tenant PostgreSQL database via logical replication (pgoutput).
2.  **Authentication**: The Go API server will expose a new endpoint (`/api/auth/powersync/token`) that generates a short-lived JWT for PowerSync clients, embedding the user's `organization_id` and role claims.
3.  **Sync Rules (sync_rules.yaml)**: Define partitioning logic within PowerSync to ensure clients only receive data scoped to their `organization_id` (for Cloud mode) or user ID.
4.  **Flutter Integration**: Replace or augment the existing local SQLite adapters in the Flutter app with the PowerSync Flutter SDK.
5.  **Conflict Resolution**: Implement "force-local" conflict resolution for specific tables (like RAG context) to prioritize local state changes made in Standalone mode, stripping raw `rag_context` before syncing to the cloud.

### Deployment Updates
*   **Docker Compose**: Add the `powersync-service` container to `deploy/docker-compose.yml`.
*   **Bazel**: Ensure any new Go dependencies for JWT generation or PowerSync management are added to `BUILD.bazel`.

### Data Flow
`Flutter Client (SQLite + PowerSync SDK) <---> PowerSync Service <---> PostgreSQL (Logical Replication)`

## Implementation Prompt

**Role**: Implementer Agent
**Task**: Integrate PowerSync into the OHC Hybrid Architecture.

**Execution Steps**:

1.  **Database Configuration**:
    *   Ensure PostgreSQL in `deploy/docker-compose.yml` has logical replication enabled (`wal_level=logical`).
    *   Create a PowerSync user and granting necessary replication roles.

2.  **PowerSync Service Setup**:
    *   Add a `powersync` service definition to `deploy/docker-compose.yml` referencing the official PowerSync Docker image.
    *   Configure it to connect to the PostgreSQL instance.
    *   Create a `sync_rules.yaml` file to filter data (e.g., `agent_missions`, `tenant_registry`) by `organization_id` derived from the JWT token.

3.  **Go Backend - Auth Endpoint**:
    *   File: `srcs/server/auth/powersync.go` (create new file).
    *   Implement an HTTP handler that validates the current user session/SPIFFE identity.
    *   Generate a JWT signed with an RSA/Ed25519 key (that PowerSync is configured to trust). The JWT payload MUST include the user's `organization_id`.
    *   Ensure the route is protected by `auth.RequireRole` middleware.
    *   Update `srcs/server/BUILD.bazel` to include any new cryptographic libraries and the new auth package files.

4.  **Go Backend - RAG Context Sync Redaction**:
    *   File: `srcs/server/orchestration/sip.go` or the relevant sync handler.
    *   Implement a pre-sync hook or database trigger that ensures `rag_context` is explicitly stripped from payloads before transmission to the cloud when originating from a local Standalone instance. *Memory Directive: Use the `X-OHC-Conflict-Resolution: force-local` header concept or equivalent logic to govern local state overwrite precedence.*

5.  **Flutter Client SDK**:
    *   Update `srcs/app/pubspec.yaml` to include the `powersync` Flutter package.
    *   Modify the local SQLite initialization sequence in `srcs/app/lib/` to initialize PowerSync.
    *   Implement the PowerSync connector class that fetches the JWT from the new Go backend endpoint.

6.  **Testing & Verification**:
    *   Write Go unit tests for the new JWT generation endpoint, explicitly injecting mock claims using `auth.ContextWithClaims(ctx, &auth.Claims{OrganizationID: "org-1"})`. Ensure tests pass.
    *   Verify the PostgreSQL replication connection succeeds in the Docker environment.
    *   **Coverage Mandate**: Maintain >90% test coverage for all modified Go packages.
    *   **Execution Command**: Run `bazelisk test //srcs/server/...` to verify backend changes.

**Constraints & Notes**:
*   Adhere strictly to the Aesthetic Excellence standard if adding any debugging UI (Glassmorphism, 20px blur).
*   Follow standard Go error handling and avoid driver-specific inconsistencies (e.g., use `RETURNING id` instead of `.RowsAffected()` if updating DB directly).
