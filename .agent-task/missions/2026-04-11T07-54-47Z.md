# Title: Implement AutoDream Vector Consolidation (KAIROS Orchestration)

## Problem Statement
The Swarm lacks long-term semantic memory. As agents complete tasks, their episodic context is lost, preventing intelligence accumulation over time.

## Research Report
The KAIROS Orchestration Design Doc (`docs/kairos_orchestration_design.md`) dictates:
- **AutoDream Worker**: A background daemon that sweeps `COMPLETED` tasks.
- **Minimax Embedding**: Uses LLMs to summarize and embed task execution context.
- **Storage**: Vectors stored in `pgvector` indexed columns (`autodream_memories`) for Cloud Native mode, or degraded formats for SQLite.

## Design Doc
1. **Schema Updates**: Validate `agent_memories` and `autodream_memories` exist with `vector(1536)` columns.
2. **Worker Logic**: Implement an `AutoDreamWorker` in Go that reads from `shared_tasks` and `swarm_tasks`.
3. **Embedding Call**: Integrate with the Minimax client to generate dense vector representations.
4. **Storage Handlers**: Save generated vectors, gracefully mapping to text/blobs if `pool.IsSQLite()` is true.

## Implementation Prompt
1. Read `docs/kairos_orchestration_design.md` for context.
2. Implement `AutoDreamWorker` daemon in `srcs/server/orchestration/autodream_worker.go`.
3. Ensure it runs on a background goroutine and queries `COMPLETED` tasks that haven't been embedded.
4. Call the cached Minimax API client to generate context embeddings.
5. Store the embeddings using Postgres `pgvector` logic or SQLite fallback logic.
6. Create `/api/v1/autodream/sync` and `/api/v1/autodream/query` endpoints to trigger syncs and retrieve memories.
7. Achieve >90% test coverage.
