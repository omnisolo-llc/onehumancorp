<h1>Title: Implement KAIROS Setup Check/Validation Onboarding Experience</h1>

<b>Problem Statement:</b><br>
The onboarding experience currently provisions and cleans up environments but lacks an interactive, user-facing verification step that runs health checks to ensure the `db`, `blob`, and `config` directories are correctly instantiated and have the proper permissions. We need a setup validation method to complete the "Day One" experience for the Developer Advocate.

<b>Research Report:</b><br>
<p>
The `ProvisionEnvironment` and `CleanupEnvironment` are already present in `srcs/server/services/onboarding/provisioner.go`. A `CheckEnvironment` exists but only does basic existence checks. We need to implement a more robust `ValidateEnvironment` function that:
1. Ensures the base directory (`.ohc-local-data` or `.ohc-cloud-data`) exists.
2. Ensures all subdirectories (`db`, `blob`, `config`) exist and are writable.
3. Exposes a `validationsCounter metric.Int64Counter` for OpenTelemetry.
</p>

<b>Design Doc:</b><br>
*   <b>Function:</b> `ValidateEnvironment(ctx context.Context, isCloud bool) error`
*   <b>Logic:</b> Iterate through directories, attempt a test file creation (e.g., `test.tmp`) to ensure write permissions, and delete the file. Returns an error if any step fails.
*   <b>Metrics:</b> Update `init()` to register `validationsCounter`.

<b>Implementation Prompt:</b><br>
"Implement the `ValidateEnvironment` function in `srcs/server/services/onboarding/provisioner.go`. Ensure it correctly checks writability of the required directories and increments a new OpenTelemetry `validationsCounter`. Also, write corresponding tests `TestValidateEnvironment_Local_Success` and `TestValidateEnvironment_Cloud_Success` in `provisioner_test.go`."
