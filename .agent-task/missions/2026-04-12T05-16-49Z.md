# Mission: Realtime Teammate Mesh APIs (KAIROS Phase 2)

## Problem Statement
The Swarm agents need to coordinate without delays, requiring a highly available realtime communication layer. Currently, there is no standardized Teammate Mesh API implemented for other feature agents to hook into.

## Research Report
The architectural mandate (`docs/architecture/kairos/shared_task_list_design.md`) dictates using `CentrifugeNode` and Redis Pub/Sub (`rueidis`) for Cloud-Native mode, and an In-Memory channel broadcast for Standalone Mode. We need to implement the base API structure for this mesh.

## Design Doc
**Architecture Component:** `Teammate Mesh API`
**Target Path:** `srcs/server/orchestration/mesh.go` (and related files)

**Design Requirements:**
1. An interface `MeshHub` defining `Publish(ctx, channel, data)` and `Subscribe(ctx, channel, handler)`.
2. A struct `CentrifugeMesh` implementing `MeshHub` using `rueidis` and Centrifugo primitives.
3. A struct `LocalTeammateMesh` implementing `MeshHub` using simple Go channels/sync for standalone operation.

## Implementation Prompt
1. Create `srcs/server/orchestration/mesh.go`.
2. Define the `MeshHub` interface.
3. Implement `LocalTeammateMesh` with thread-safe Go channels for standalone mode.
4. (Optional/Stub) Provide the basic scaffolding for `CentrifugeMesh` assuming external Redis/Centrifugo configurations.
5. Write unit tests ensuring `LocalTeammateMesh` successfully publishes and receives messages concurrently.
