# 🚀 Shared Task List & Mesh Orchestration

## Title
Implement Shared Task List and Teammate Mesh Orchestration

## Problem Statement
The One Human Corp (OHC) Swarm currently lacks a centralized, scalable, and robust mechanism for agentic feature requests to be decomposed, enqueued, tracked, and synchronized across a hybrid multi-tenant architecture. Agents need a way to track the state of their long-running tasks, coordinate with other agents via a shared Teammate Mesh, and ensure that the backend provides horizontal scale in Cloud-Native mode and local robustness in Standalone mode.

## Research Report
- **Current State**: The system has basic queuing (`TaskOrchestrator`), but complex task dependencies and sub-agent background orchestration lack an end-to-end framework.
- **Competitors**: Platforms like AutoGPT and LangChain rely on external queuing systems (Celery, BullMQ). Our Hybrid Architecture needs to support both Postgres `SKIP LOCKED` queues in the cloud and SQLite concurrency in local mode.
- **Mesh Connectivity**: Teammate Mesh is partially implemented but needs a standardized, highly-available real-time communication layer, utilizing Redis Pub/Sub in Cloud mode and in-memory WebSockets for the Standalone variant.
- **State Tracking**: `TaskOrchestrator` needs state machine improvements to reliably coordinate dependent sub-tasks across multiple agents and sync this status with the frontend via the Centrifuge hub.

## Design Doc
1. **Architecture & Database Schema**:
   - Enhance the `swarm_tasks` and `task_dependencies` schema in both PostgreSQL and SQLite.
   - Utilize a distributed state machine logic to transition tasks (`PENDING` -> `IN_PROGRESS` -> `COMPLETED` / `FAILED`).
   - Use Postgres `FOR UPDATE SKIP LOCKED` for Cloud queueing; use global mutexes for SQLite Standalone mode.
2. **Sub-Agent Orchestration**:
   - Implement background queuing using Go routines for standalone and a unified Redis-based consumer queue (resembling BullMQ semantics) for Cloud.
3. **Teammate Mesh Architecture**:
   - Real-time events layer using Centrifuge.
   - Tasks must broadcast status to the Mesh with root-level keys (`action`, `agent_id`, `status`).
4. **AutoDream Integration**:
   - Task completions must be summarized via LLM and vectorized into `swarm_long_term_memory` or `autodream_memories` depending on the environment.
