# Mission: OHC Swarm Shared Task List & Teammate Mesh Orchestration

**Title**: Implement OHC Swarm Shared Task List & Realtime Teammate Mesh (KAIROS)
**Priority**: P0
**Estimated Scope**: Large

## Problem Statement
The OHC Hybrid Architecture currently supports basic local-to-cloud mission synchronization via `agent_missions`, but lacks a resilient, globally synchronized **Shared Task List** and a realtime **Teammate Mesh** for sub-agent coordination. Competitors limit themselves to local files (`CLAUDE.md`) or ad-hoc cloud nodes. OHC agents must autonomously coordinate, claim shared tasks via Git-like distributed locks, and consolidate memories long-term (autoDream) without human intervention, maintaining zero drift across the hybrid K8s/SQLite boundary.

## Research Report
Based on an audit of the current agentic market (OpenClaw, Claude Code, Replit Agent) and the OHC platform:
1. **Coordination Gap**: Agents currently execute missions in isolation. Complex workflows requiring deep deliberation (UltraPlan) fail because agents cannot dynamically decompose tasks and place them in a globally observable state machine.
2. **Realtime Mesh Needs**: The Swarm requires a persistent Teammate Mesh. Since OHC operates in a multi-tenant K8s environment (with Redis available), leveraging Redis Pub/Sub for realtime WebSockets/gRPC agent chatter is the optimal path for cloud, gracefully degrading to SQLite-backed channels in Standalone mode.
3. **Memory Consolidation**: A durable state mechanism (pgvector/Pinecone) is needed for "autoDream" nightly architectural consolidation, where agents synthesize learned context into permanent memory embeddings.

## Design Doc

### 1. Database Schema Changes (Postgres / SQLite)
Add a new schema for the Shared Task List and State Machine Tracking.
```sql
CREATE TABLE IF NOT EXISTS swarm_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    mission_id TEXT REFERENCES agent_missions(id),
    title TEXT NOT NULL,
    status TEXT NOT NULL CHECK (status IN ('PENDING', 'IN_PROGRESS', 'COMPLETED', 'FAILED')),
    assigned_agent_id TEXT,
    locked_until TIMESTAMPTZ,
    payload JSONB NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- For autoDream Memory Embeddings
CREATE TABLE IF NOT EXISTS swarm_long_term_memory (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    topic TEXT NOT NULL,
    summary TEXT NOT NULL,
    embedding VECTOR(1536), -- pgvector
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. Teammate Mesh API Contracts
Realtime communication over WebSockets/gRPC, bridged via Redis Pub/Sub in multi-tenant mode.

**Endpoint**: `WSS /api/v1/swarm/mesh/connect`
**Payload (Publish Task)**:
```json
{
  "type": "TASK_BROADCAST",
  "task_id": "uuid",
  "priority": "P1",
  "description": "Architect DB schema for new feature"
}
```

**Distributed Lock Mechanism**:
To prevent race conditions when agents claim tasks:
```go
// Redis-backed distributed lock with 30s TTL
acquired, err := redisClient.SetNX(ctx, "lock:task:"+taskID, agentID, 30*time.Second).Result()
```

Integrate a scalable queue (e.g., integrating an internal BullMQ-like Go worker pool in Orchestration Hub) to poll `swarm_tasks` where `status = 'PENDING'` and spawn localized agent routines.
