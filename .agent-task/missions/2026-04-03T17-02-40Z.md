# Title: Implement Hybrid Graceful Degradation (Local LLM Fallback)

## Problem Statement
Competitors fail completely when offline. OpenClaw and Replit Agent rely on purely cloud-based orchestration. Claude Code requires continuous internet connectivity. OHC needs to capitalize on its Hybrid Architecture by seamlessly transitioning from Cloud LLM APIs to a local embedded LLM model (e.g., Llama via Ollama or a quantized ONNX model) when network connectivity drops or Cloud APIs become unavailable/rate-limited, utilizing local SQLite for continuous state persistence.

## Research Report
A comprehensive audit of the global Agentic OS market benchmarks OHC against Claude Code, OpenClaw, and Replit Agent, revealing a critical structural vulnerability across competitors (over-reliance on pure cloud dependency). OHC’s Hybrid Architecture provides an unmatchable "Unfair Advantage" via Graceful Degradation.

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC Vision (OHC-HA)** |
| :--- | :--- | :--- | :--- | :--- |
| **Execution Mode** | CLI / Local-First | Pure Cloud Orchestration | Cloud IDE / Ephemeral | **True Hybrid** (K8s Cloud & Standalone Local) |
| **Data Sovereignty** | Local files (`CLAUDE.md`) | Provider-locked cloud | Replit Cloud Storage | **Postgres & SQLite SIPDB** Local/Cloud Sync |
| **Resilience / Offline**| Requires API | Fails Offline | Fails Offline | **Graceful Degradation** (Local LLM/SQLite fallback) |

## Design Doc
- **Architecture**: Introduce a LocalLLMProvider wrapper that conforms to the existing Agent LLM provider interface. Update the task orchestrator to catch network errors/timeouts from standard providers (e.g., Minimax, Gemini) and automatically failover to LocalLLMProvider.
- **Data flow**: When `http.Client` returns a timeout or DNS resolution failure, the provider router redirects the prompt sequence to the local embedded model endpoint (e.g., `http://127.0.0.1:11434/api/generate` for Ollama).
- **Configuration**: Expose `OHC_LOCAL_LLM_ENDPOINT` and `OHC_LOCAL_MODEL_NAME` in standalone mode setup.
- **UI Wireframes**: A glassmorphism toast in the bottom right corner: "Cloud Unreachable. Switched to Local Intelligence."

## Implementation Prompt
You are an Implementer agent. Your task is to build the "Hybrid Graceful Degradation (Local LLM Fallback)".
1. In `srcs/server/agents/`, create a new file `local_provider.go` implementing the standard LLM provider interface.
2. In the provider initialization logic (e.g., where Minimax or Gemini clients are instantiated), implement a wrapper/router `ResilientProvider` that attempts the primary cloud provider and catches connection/timeout errors.
3. Upon failure, it should seamlessly route the generation request to the `LocalLLMProvider`.
4. Create test coverage in `resilient_provider_test.go` simulating network failure using `httptest.Server` responding with HTTP 503 or simulated timeout.
5. Provide high-coverage unit tests utilizing the existing `db.NewSqliteProvider(sqlDB)` for local mocking.
6. Verify your changes do not break standalone/cloud abstractions. Do NOT modify the core cloud-native Postgres deployments; this is strictly an enhancement for Standalone mode (`OHC_STANDALONE=true`).
