# KAIROS Orchestration: Shared Task List, Teammate Mesh, & AutoDream

## Problem Statement
The OHC Hybrid Agentic OS requires a robust distributed system to coordinate autonomous AI agents. Currently, there is a lack of a unified backend architecture for decomposing tasks, broadcasting state changes via sub-millisecond Pub/Sub, and continuously consolidating episodic logs into long-term vector memory.

## Research Report
- **Competitors**: Agent orchestration frameworks often rely solely on single-node deployments or heavyweight cloud infrastructure. OHC needs a Hybrid architecture.
- **Cloud-Native**: PostgreSQL `FOR UPDATE SKIP LOCKED` combined with Redis Pub/Sub offers scalable concurrency.
- **Standalone**: SQLite mutexes and in-memory Go channels provide a lightweight alternative.
- **AutoDream**: Converting episodic logs into vector embeddings (pgvector) into the `consolidated_memory` table ensures Swarm agents have access to critical long-term memory.

### DB Schemas
```sql
CREATE TABLE IF NOT EXISTS shared_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id VARCHAR NOT NULL,
    title VARCHAR NOT NULL,
    description TEXT,
    status VARCHAR NOT NULL DEFAULT 'PENDING',
    agent_id VARCHAR,
    priority VARCHAR NOT NULL DEFAULT 'P2',
    payload JSONB,
    parent_plan_id TEXT,
    dependencies JSONB NOT NULL DEFAULT '[]',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS consolidated_memory (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID REFERENCES shared_tasks(id),
    content TEXT NOT NULL,
    embedding vector(1536),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### APIs
- `POST /api/v1/mesh/publish`
- `GET /api/v1/mesh/subscribe?topic=task.update`
