# Title: Implement KAIROS Hybrid Agentic OS Master Blueprint

## Problem Statement
The OHC swarm currently lacks the backend primitives required for true autonomous orchestration. We must implement the Shared Task List, Realtime Teammate Mesh APIs, and pgvector-backed autoDream data pipelines to enable stable, distributed state transitions and memory consolidation.

## Research Report
Based on architectural deliberations in `docs/architecture/kairos_hybrid_os_implementation_blueprint.md`, we identified the need for PostgreSQL tables (`kairos_shared_tasks`, `state_machine_transitions`, `autodream_vector_memories`) and a new REST endpoint (`POST /api/mesh/broadcast`) to interface with Redis Pub/Sub for Teammate Mesh events.

## Design Doc
Reference: `docs/architecture/kairos_hybrid_os_implementation_blueprint.md`
- **Database Migrations:** Create the schemas for `kairos_shared_tasks`, `state_machine_transitions`, and `autodream_vector_memories` using the definitions in the blueprint.
- **Teammate Mesh API:** Implement `POST /api/mesh/broadcast` in the Go backend.
- **State Machine:** Enforce deterministic state transitions using distributed locking (Redis `SET NX EX` in cloud mode, standard SQL `FOR UPDATE` in standalone mode).
