# Title: KAIROS Orchestration: Shared Task List, Teammate Mesh, and AutoDream Architectural Consolidation

## Problem Statement
The OHC swarm currently lacks a centralized, distributed system for agents to securely coordinate, decompose, and track task execution across the hybrid architecture. Without a "Shared Task List" leveraging our Postgres backend and Redis Pub/Sub (Teammate Mesh), agents cannot effectively orchestrate complex, multi-step workflows.

## Research Report
- Current agents operate sequentially and synchronously without cross-node DAG locking.
- Database architectures (`013_shared_tasks.sql` and `007_autodream.sql`) exist but are not seamlessly exposed to the autonomous workflow logic.
- KAIROS Orchestration is required to unify `swarm_tasks` (PostgreSQL `FOR UPDATE SKIP LOCKED` / SQLite fallback), the realtime Teammate Mesh, and the AutoDream vector pipeline.

Refer to `docs/kairos_orchestration_design.md` for full sequence diagrams and schema overviews.

## Implementation Prompt
1. Implement the `TaskManager` loop in `srcs/server/orchestration/tasks.go` to properly handle DAG dependency checks across `swarm_tasks`.
2. Connect the `TaskManager` to the Teammate Mesh API via `CentrifugeHub.PublishTaskBroadcast`.
3. Implement `AutoDreamWorker` logic to periodically compress context from `agent_session_data` into `autodream_memories` (fallback to SQLite Recency if pgvector is missing).
4. Ensure `FOR UPDATE SKIP LOCKED` is properly guarded by `dbWrapper.IsSQLite()` checks.
