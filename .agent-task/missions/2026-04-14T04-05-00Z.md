# Title: Implement KAIROS Orchestration Backend APIs

## Problem Statement
The OHC Swarm demands a highly scalable backbone to coordinate long-running distributed workloads. Currently, the system lacks a robust distributed state machine to track tasks across the swarm with exact sequence and DAG dependencies.

## Research Report
- Based on `CLAUDE_OHC.md` and OHC Hybrid Architecture (OHC-HA), the backend relies on custom interfaces. PostgreSQL provides horizontal scaling (via row-level locks `FOR UPDATE SKIP LOCKED`), while SQLite handles standalone gracefully.
- State Machine Tracking requires distributed locking.
- autoDream memory vector architecture ensures long-term agent context.

## Design Doc
Please refer to `docs/architecture/kairos_shared_task_mesh.md` for full DB schema and Teammate Mesh definitions.

## Implementation Prompt
1. Create DB migrations for `shared_tasks` and `consolidated_memory` in the database migrations directory using exact SQL defined in the design doc. You should explore the codebase to find the correct directory.
2. Implement task claiming logic in an appropriate orchestration package. Explore the codebase and create a new task queue or orchestration file. Make sure to use `SELECT ... FOR UPDATE SKIP LOCKED`.
3. Implement `POST /api/mesh/v2/broadcast` in an appropriate server or API package. Again, please explore the codebase and create new files if needed.
4. Add relevant unit tests and execute the test runner. Ensure there is high code coverage (>90%).
