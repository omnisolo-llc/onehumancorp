# Title: KAIROS Sub-Agent Observability and Mesh Resiliency Enhancements
**Priority:** P1
**Estimated Scope:** Medium

# Problem Statement
As the KAIROS Orchestrator decomposes complex feature requests and routes them to sub-agents via the Teammate Mesh, we need to ensure the system gracefully handles long-running sub-agent operations and provides necessary observability into task states. The current architecture lacks detailed tracing for sub-agent queuing delays and memory utilization metrics during concurrent task execution, which is critical for both Cloud-Native elasticity and Standalone stability.

# Research Report
- Based on `CLAUDE_OHC.md` and the existing Hybrid Architecture, we need robust orchestration components.
- Existing metrics like `ohc_token_usage_total` cover API costs, but not sub-agent execution latency or queue depths.
- In Cloud-Native mode (`OHC_MULTITENANT=true`), we need metrics to autoscale agent pods.
- In Standalone Desktop mode (`OHC_STANDALONE=true`), we need to throttle based on local resource limits to avoid overwhelming the single SQLite database and host I/O.
- The Teammate Mesh must handle agent discovery and synchronization reliably.

# Design Doc
**Architecture:**
- **Observability Layer (`srcs/server/orchestration/telemetry.go`):** Implement metrics for:
  - `sub_agent_queue_depth`: Gauge of pending tasks in the KAIROS queue.
  - `sub_agent_execution_latency`: Histogram of task completion times.
- **Teammate Mesh Enhancements (`srcs/server/orchestration/hub.go`):** Add retry and fallback mechanisms when standard mesh channels become overloaded.
- **Concurrency Controls:** Enhance the existing Standalone mode throttle with an exponential backoff retry mechanism.
- **Grafana Dashboard:** Create `deploy/docker/grafana/provisioning/dashboards/kairos-orchestration.json` to visualize these new KAIROS-specific metrics.
