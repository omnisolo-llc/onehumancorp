# Problem Statement
The OHC swarm requires a "Teammate Mesh" for realtime communication. Agents must be able to coordinate, broadcast status changes, and manage distributed locking without race conditions. Without this, the swarm cannot operate effectively in parallel.

# Research Report
- Based on `CLAUDE_OHC.md` and `README.md`, OHC operates in a "Hybrid Architecture" (`OHC-HA`).
- Realtime coordination must rely on Redis Pub/Sub in Cloud-Native mode and local WebSockets or gRPC streams in Standalone mode.
- We need a `CentrifugeNode` hub that manages these connections and acts as the message broker.

# Design Doc
**Architecture:**
- **Cloud-Native Mode:** The Teammate Mesh will utilize `Centrifuge` backed by `Redis` for horizontal scalability and pub/sub routing. Redis distributed locks (`rueidis` `SET NX EX`) will be used for locking.
- **Standalone Mode:** The Teammate Mesh will degrade to in-memory `Centrifuge` and SQLite table locks for distributed locking to avoid requiring Redis.

**API Contracts:**
```go
type MeshEvent struct {
    Topic   string          `json:"topic"`
    Payload json.RawMessage `json:"payload"`
    AgentID string          `json:"agent_id"`
}

type TeammateMesh interface {
    Publish(ctx context.Context, event MeshEvent) error
    Subscribe(ctx context.Context, topic string) (<-chan MeshEvent, error)
    AcquireLock(ctx context.Context, lockKey string, ttl time.Duration) (bool, error)
    ReleaseLock(ctx context.Context, lockKey string) error
}
```
