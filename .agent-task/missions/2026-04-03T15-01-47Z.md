# Local-Private RAG with Cloud-Scale Routing (Hybrid MCP RAG Protocol)

## Problem Statement
Competitors in the Agentic OS space force users into a binary choice: trade privacy for cloud-scale execution, or trade scalability for local privacy. There is a critical structural vulnerability across competitors (Claude Code, OpenClaw, Replit Agent) due to their over-reliance on pure cloud dependency or strictly siloed local states. OHC lacks a unified system that bridges this divide, preventing users from safely combining highly sensitive local data with cloud-scale parallel compute.

## Research Report

A comprehensive audit of the global Agentic OS market—specifically benchmarking **One Human Corp (OHC)** against **Claude Code**, **OpenClaw**, and **Replit Agent**—has revealed this gap. OHC’s **Hybrid Architecture (OHC-HA)**, leveraging multi-tenant PostgreSQL orchestration combined with local SQLite single-user degradation, provides an unmatchable "Unfair Advantage".

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC Vision (OHC-HA)** |
| :--- | :--- | :--- | :--- | :--- |
| **Execution Mode** | CLI / Local-First | Pure Cloud Orchestration | Cloud IDE / Ephemeral | **True Hybrid** (K8s Cloud & Standalone Local) |
| **Data Sovereignty** | Local files (`CLAUDE.md`) | Provider-locked cloud | Replit Cloud Storage | **Postgres & SQLite SIPDB** Local/Cloud Sync |
| **Tool Execution** | Standard MCP | Custom Plugins | Platform-native | **Universal MCP Mesh** native to K8s/Bazel |
| **Resilience / Offline**| Requires API | Fails Offline | Fails Offline | **Graceful Degradation** (Local LLM/SQLite fallback) |

The standout disruption is **Offline-to-Cloud State Sync for Swarm Memories**. By implementing a unified **"Hybrid MCP RAG Protocol"**, OHC can synchronize a local SQLite RAG state to the cloud Postgres orchestration engine via OHC-SIP.
- **Private Execution**: Highly sensitive datasets are processed purely via local standalone Desktop mode.
- **Cloud Escalation**: When massive parallel computation is needed, the local client securely delegates generalized tasks to the K8s multi-tenant cloud without exposing the raw private dataset, syncing only required context payloads into the cloud's `agent_missions` table.

## Design Doc

### Architecture
The Hybrid MCP RAG Protocol relies on a bidirectional synchronizer daemon within the OHC Orchestration Hub.

1.  **Local State (Standalone Desktop):** Data is stored in the local SQLite SIPDB (`~/.agent-task/swarm.db`). Private embeddings are generated and stored locally.
2.  **Sync Mechanism:** A background Go routine (`SyncDaemon`) monitors the local SQLite for missions marked for `cloud_escalation`.
3.  **Payload Sanitization:** Before syncing, the payload is sanitized to remove PII and raw private data, creating a generalized task context.
4.  **Cloud State (Multi-Tenant Postgres):** The sanitized mission is injected into the cloud's `agent_missions` table.
5.  **Execution & Return:** The multi-tenant cloud swarm computes the result and updates the cloud database. The `SyncDaemon` polls for completion and syncs the result back to the local SQLite database.
