# Title: Standalone Metric Buffering & Cloud Sync Fixes

## Problem Statement
While investigating the Hybrid Observability gap for local agent execution telemetry (Standalone Mode vs Cloud-Native Mode), an audit revealed key implementation discrepancies in the existing local Standalone Metric Buffer and Cloud Sync mechanism. Specifically:
1. The database initialization and buffer queries in `srcs/server/orchestration/sip.go` use the incorrect table name `local_metrics_buffer` instead of `telemetry_buffer`, causing the local metric buffer to fail silently or crash on queries, as the actual SQL migrations (`026_telemetry_buffer.sql`) create the table as `telemetry_buffer`.
2. The `POST /api/telemetry/sync` endpoint in the cloud API (`handleTelemetrySync` in `srcs/server/dashboard/server.go`) blindly calls `telemetry.BufferMetricFunc`. However, in Cloud-native deployments, `BufferMetricFunc` is strictly `nil` (it is only set in Standalone mode), which results in synced metrics being completely dropped and never ingested into the cloud's Prometheus metrics.

## Research Report
- A deep dive into OHC Hybrid Architecture (OHC-HA) metrics confirmed that Replit and OpenClaw ignore local offline metrics, presenting a unique "Unfair Advantage" for OHC.
- OHC currently emits OpenTelemetry metrics locally during execution, which are optionally buffered if `OHC_STANDALONE=true` and `OHC_TELEMETRY_ENABLED=true`.
- The SQLite migration `srcs/server/db/migrations/026_telemetry_buffer.sql` provisions a `telemetry_buffer` table to intercept these metrics.
- `srcs/server/orchestration/sip.go` attempts to write to and read from `local_metrics_buffer`, a table that does not align with the migration.
- `srcs/server/dashboard/server.go` correctly defines the `POST /api/telemetry/sync` endpoint but assumes `BufferMetricFunc` is non-nil, which violates the environment boundaries.

## Design Doc
1. **Schema Alignment:** All references to `local_metrics_buffer` in `srcs/server/orchestration/sip.go` must be updated to `telemetry_buffer`.
2. **Cloud Metrics Ingestion:** The `handleTelemetrySync` method must dynamically unmarshal the incoming synced payload arrays. Because `BufferMetricFunc` is `nil` on the cloud backend, the endpoint must iterate through the `metric_type` (e.g., `token_usage`, `agent_api_call`, `swarm_task_completed`) and manually invoke the corresponding strongly-typed OTel recording functions (e.g., `telemetry.RecordTokenUsage`, `telemetry.RecordAgentApiCall`) to ensure Prometheus correctly scrapes the historical batched agent telemetry.
3. **Fail-safe:** A default fallback should check if `telemetry.BufferMetricFunc != nil` just in case a hybrid deployment explicitly binds it.
