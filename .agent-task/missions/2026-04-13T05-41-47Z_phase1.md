# Title: KAIROS Phase 1: Architect the Shared Task List Schema

## Problem Statement
The OHC Swarm requires a durable database schema and state machine tracking to decompose complex feature requests into a shared task list for the agent team, supporting both Cloud-Native (PostgreSQL) and Standalone Desktop (SQLite) modes.

## Research Report
KAIROS tasks must track status, dependencies, priority, and agent assignments. To prevent worker collisions in Cloud-Native mode, we need FOR UPDATE SKIP LOCKED semantics in PostgreSQL. Standalone mode requires graceful degradation to SQLite transactions.

## Design Doc
Create a shared_tasks table with columns for id, status, agent_id, priority, and payload. Create a task_dependencies table to model the task DAG. Track state machine transitions.

## Implementation Prompt
Implement the backend database designs and sequence diagrams for the Shared Task List feature in srcs/server/orchestration. Create the necessary SQL migration scripts for PostgreSQL and SQLite in srcs/server/db/migrations/. Ensure the data access layer supports FOR UPDATE SKIP LOCKED for Postgres and standard transactions for SQLite. Modify the base Go structs in srcs/server/orchestration/tasks.go for the Shared Task List and ensure unit tests pass. Provide a Mermaid.js sequence diagram in the PR.
