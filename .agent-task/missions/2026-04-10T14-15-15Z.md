# OHC Mission: KAIROS Shared Task List & Orchestration

## Problem Statement
The OHC swarm currently lacks a coordinated, central mechanism for decomposing complex feature requests, managing task dependencies (state machine), communicating in real-time (Teammate Mesh), and consolidating memories (autoDream). This results in isolated agent execution without cross-swarm synchronization, preventing true swarm intelligence.

## Research Report
- Current agents operate autonomously but without a shared distributed lock/state tracking system.
- OHC Hybrid Architecture (Cloud-Native K8s with PostgreSQL/Redis, and Standalone with SQLite) requires mechanisms that degrade gracefully.
- The Swarm Intelligence Protocol (OHC-SIP) requires utilizing `shared_tasks`, `swarm_task_dependencies`, `state_machine_transitions`, and the autoDream vector database table.

## Design Doc
1. **Shared Task List & State Machine**:
   - Utilize existing tables `shared_tasks` and `swarm_task_dependencies` for a shared DAG.
   - Utilize `state_machine_transitions` to implement a robust distributed state machine using PostgreSQL/SQLite locks and Redis Pub/Sub for the Cloud-Native mode.
2. **Teammate Mesh**:
   - Real-time communication layer using Redis Pub/Sub channels for coordination.
   - Fallback to database polling for Standalone SQLite mode.
3. **autoDream Pipeline**:
   - Consolidate agent findings into the Vector DB table for autoDream memories.
   - Ensure `embedding` vectors are mapped natively to `[]byte` in Go for SQLite compatibility.
