# Mission: Dynamic Local-to-Cloud MCP RAG Escalation

## Title
Dynamic Local-to-Cloud MCP RAG Escalation

## Problem Statement
Current Agentic OS competitors force a binary choice: execute RAG (Retrieval-Augmented Generation) locally for absolute privacy but suffer CPU-bound performance (e.g., Claude Code), or execute in the cloud for infinite scalability but compromise enterprise IP privacy (e.g., Replit Agent, OpenClaw). OHC's Hybrid Architecture (OHC-HA) lacks a dynamic, latency-aware escalation policy to seamlessly transition heavy local vector queries to the Cloud PostgreSQL swarm, specifically extending the Hybrid MCP capabilities.

## Design Doc
**Architecture Overview**:
1. **Complexity Analyzer (Go)**: A new heuristic engine in `srcs/server/lib/integrations/hybridfsmcp/` (alongside `mcp.go`) that evaluates inbound MCP queries. If query complexity implies significant token processing, it triggers an escalation.
2. **Zero-Trust Sync (SPIFFE/SPIRE)**: When escalating, the local agent securely synchronizes only non-sensitive query embeddings to the Cloud instance.
3. **Graceful Degradation**: If Cloud mode is unreachable (offline), it falls back to Local processing.

## Implementation Prompt
**Context**: Implement the Dynamic Escalation Protocol for OHC Hybrid RAG.
**Instructions**:

6. **Testing**: Write comprehensive unit tests in `escalator_test.go` with >90% coverage for both cloud routing and local fallback scenarios.
