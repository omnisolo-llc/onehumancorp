# Problem Statement
Currently, agents in the One Human Corp (OHC) Swarm are forced to explicitly discover and read grounding files (like `AGENTS.md` and `CLAUDE_OHC.md`) after being spawned. This introduces latency (time-to-first-token), token bloat, and potential alignment drift if the files are not read correctly or efficiently. It acts as a bottleneck, forcing every newly spawned sub-agent to incur an I/O and processing cost before starting its actual mission.

# Research Report
Based on the Market Audit & OHC Unfair Advantage report, other agentic OSs (Claude Code, OpenCode) depend on explicit file reads, whereas OHC has a decisive opportunity to leapfrog these systems via **Omni-Context Sub-agent Routing**. The goal is to enforce Swarm-as-Code deterministic routing by natively injecting grounding contexts at the exact moment of task delegation.

The finding is clear: Instead of forcing sub-agents to invoke `read_file` tools, the `SIPDB` system will automatically read standard grounding files (`AGENTS.md`, `CLAUDE_OHC.md`) from the context root and inject their contents directly into the payload of new tasks in the `agent_missions` DB table under the `[SYSTEM GROUNDING]` namespace. This gives any newly spawned sub-agent zero-latency access to the truth while keeping architectural alignment perfect.

# Design Doc
**Architecture:**
- **Context Injector:** When `DelegateMission` is called in `srcs/server/orchestration/sip.go`, the OHC-SIP orchestrator will first read the context files.
- **Injection:** These file contents will be appended directly into the `Content` of the incoming `task` parameter.
- **Storage:** The `task.Content` is saved securely into the `agent_missions` table payload, routing it automatically.

# Implementation Prompt
You are an Implementer agent. Your task is to implement the Omni-Context Sub-agent Routing by modifying `srcs/server/orchestration/sip.go`.
1. Navigate to the `DelegateMission` method in `srcs/server/orchestration/sip.go`.
2. Locate the logic where the new task payload is constructed and saved. The existing `SIPDB` system may already have logic to read "AGENTS.md" and "CLAUDE_OHC.md" and append it as `[SYSTEM GROUNDING]`—if so, ensure it is functioning correctly and verify it via tests. If not, implement a cache-efficient way (e.g. `sync.Once`) to read `AGENTS.md` and `CLAUDE_OHC.md` from `s.ContextRoot`.
3. Concatenate the contents of the read files and append them to the end of the incoming `task.Content` under the exact header `\n\n[SYSTEM GROUNDING]\n`.
4. Ensure the system adheres to the "Fail-Closed" security mandate: If `os.ReadFile` encounters a permissions error or an error other than `os.ErrNotExist` for these files, the function must return an error and fail the mission delegation rather than continuing with incomplete context.
5. Add unit tests in `srcs/server/orchestration/sip_test.go` ensuring that when valid files exist in a temp test directory, they are successfully appended, and when they are missing, it proceeds correctly, but when a read error occurs, it fails closed.
6. Verify your changes pass by running `bazelisk test //srcs/server/orchestration/... --test_output=errors`.
