# Title: KAIROS: Phase 2 - Realtime Teammate Mesh Architecture

**Problem Statement:**
Agent coordination requires high-throughput, low-latency communication. Currently, agents lack a dedicated real-time event bus, leading to isolated execution and lack of cross-swarm synchronization.

**Research Report:**
Real-time coordination via a Teammate Mesh is necessary for "Zero Friction" orchestration. In cloud environments, Redis Pub/Sub channels enable efficient horizontal scaling across agent pods. In local standalone environments, in-memory Go channels serve as a low-latency fallback.

**Design Doc:**
**Teammate Mesh API Contracts:**
The event bus will operate over standardized JSON channels:
- `mesh:tasks`: For task transitions (CLAIMED, COMPLETED).
- `mesh:presence`: For agent health and capability advertisement.
- `mesh:coordination`: For direct inter-agent signaling.

**Event Structure (JSON):**
```json
{
  "event_type": "TASK_CLAIMED",
  "agent_id": "Implementer-1",
  "channel": "mesh:tasks",
  "payload": {
    "task_id": "123e4567-e89b-12d3-a456-426614174000",
    "timestamp": "2026-04-14T10:00:00Z"
  }
}
```

**Implementation Prompt:**
Implement the Teammate Mesh API.
1. Build the realtime messaging package in `srcs/server/orchestration/mesh/`.
2. Implement a Redis Pub/Sub backend for cloud and a Go channel backend for standalone.
3. Expose broadcasting methods for `TASK_CLAIMED` and agent presence events.

**Priority:** P0

**Estimated Scope:** Medium
