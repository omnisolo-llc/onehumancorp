# Hybrid MCP RAG Protocol (Offline-to-Cloud State Sync)

## Problem Statement

Competitors in the Agentic OS market force users into a binary choice: trade privacy for cloud-scale execution, or trade scalability for local privacy. Claude Code limits RAG to local directories, OpenClaw and Replit Agent lock users into cloud dependencies. There is currently no robust mechanism to bridge this divide safely. OHC requires a seamless **Offline-to-Cloud State Sync** allowing RAG state to be maintained securely in the local SQLite engine while delegating large compute bursts to the K8s multi-tenant cloud PostgreSQL orchestration engine without exposing raw private datasets.

## Research Report

Based on the latest comprehensive audit of the Agentic OS market, **One Human Corp (OHC)** has a significant architectural advantage through its **Hybrid Architecture (OHC-HA)**, leveraging multi-tenant PostgreSQL orchestration alongside local SQLite single-user degradation.

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC Vision (OHC-HA)** |
| :--- | :--- | :--- | :--- | :--- |
| **Execution Mode** | CLI / Local-First | Pure Cloud Orchestration | Cloud IDE / Ephemeral | **True Hybrid** (K8s Cloud & Standalone Local) |
| **Data Sovereignty** | Local files (`CLAUDE.md`) | Provider-locked cloud | Replit Cloud Storage | **Postgres & SQLite SIPDB** Local/Cloud Sync |
| **Tool Execution** | Standard MCP | Custom Plugins | Platform-native | **Universal MCP Mesh** native to K8s/Bazel |
| **Resilience / Offline**| Requires API | Fails Offline | Fails Offline | **Graceful Degradation** (Local LLM/SQLite fallback) |

The standout "Blue Ocean" disruption is the **Hybrid MCP RAG Protocol**, providing unmatchable utility that competitor's strictly cloud or purely local setups cannot provide.

*   **Private Execution**: Highly sensitive datasets are processed purely via local standalone Desktop mode.
*   **Cloud Escalation**: When massive parallel computation is needed, the local client securely delegates generalized tasks to the K8s multi-tenant cloud without exposing the raw private dataset, syncing only required context payloads into the cloud's `agent_missions` table.

### Implementation Details

1.  **SQLite/Postgres Abstraction Enhancement**: Expand the DB layer to allow an active SQLite session (Local) to authenticate via `OHC_CORE_URL` to push task manifests.
2.  **Payload Sanitizer Pipeline**: Introduce a sanitization pipeline that runs before the `agent_missions` sync. This strips highly sensitive tokens and replaces them with references that only the local client can re-hydrate.
3.  **Synchronizer Daemon (`sync_daemon.go`)**: A background routine running within the OHC Desktop wrapper that polls the cloud for completed mission states and pulls results back down into the local SQLite `swarm_memory` tables.
4.  **UI Updates**: A status indicator using the `.ohc-hybrid-panel` styling that shows when tasks have escalated to the cloud swarm.
