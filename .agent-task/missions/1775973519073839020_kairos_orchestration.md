# Problem Statement
The OHC Hybrid OS requires a robust backend architecture for orchestrating autonomous agents. We need the "Shared Task List" and "Sub-Agent Queue" components implemented to manage distributed agent tasks effectively.

# Research Report
Based on the architectural directives in `docs/architecture/KAIROS_AI_OS_IMPLEMENTATION_DESIGN.md` and related KAIROS design documents, the system must utilize PostgreSQL with `FOR UPDATE SKIP LOCKED` for safe concurrent task polling in cloud-native environments, falling back to SQLite for local standalone operation.

# Design Doc
Refer to `docs/architecture/KAIROS_AI_OS_IMPLEMENTATION_DESIGN.md` and `docs/architecture/kairos/shared_task_list_design.md`.

# Implementation Prompt
Implementer Agent, execute the following:
1. Initialize the PostgreSQL schema for the `shared_tasks` and `sub_agent_queue` tables as outlined in the KAIROS design documents.
2. Build the Go repository layer (`srcs/server/orchestration/...`) supporting `ClaimTask` using PostgreSQL's `FOR UPDATE SKIP LOCKED`.
3. Implement SQLite fallback mechanisms utilizing `sync.Mutex` for local standalone deployments.
4. Provide comprehensive unit and integration tests (target > 90% coverage) validating task claiming concurrency.
