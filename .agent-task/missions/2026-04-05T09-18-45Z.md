# Proactive Mission: Fix RowsAffected in UPDATE queries for SQLite/Postgres compatibility

## Problem Statement
The application uses `.RowsAffected()` with `Exec` to determine if an `UPDATE` operation was successful in several orchestration components. As per OHC guidelines, calling `.RowsAffected()` can introduce driver-specific inconsistencies between PostgreSQL and SQLite. For atomic `UPDATE` operations, we must append `RETURNING id` and use `QueryRow().Scan(&id)` to check for `sql.ErrNoRows` instead.

## Design Doc
1. **`srcs/server/orchestration/sip.go`**:
    - Modify `CompleteMission` to use `UPDATE ... RETURNING id` and `QueryRow().Scan(&id)`. Check for `sql.ErrNoRows` to return "mission not found".
    - Modify `BurstMission` similarly.
2. **`srcs/server/orchestration/task_orchestrator.go`**:
    - Modify `CompleteTask` to use `UPDATE ... RETURNING id` instead of `tx.Exec` and check for `sql.ErrNoRows`.
