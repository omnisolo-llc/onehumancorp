# Mission: Sub-Agent Orchestration Queue (KAIROS Phase 4)

## Problem Statement
The OHC Agentic OS requires the ability to spawn isolated sub-agents to handle decomposed tasks in the background. Currently, there is no abstraction for enqueuing and executing these background jobs in a distributed environment.

## Research Report
The KAIROS Orchestrator role defines building scalable background queuing logic (e.g., BullMQ, Celery concepts). In the Go backend, this should be an interface that can map to Redis streams/lists for Cloud-Native mode or simple goroutine workers for Standalone Mode.

## Design Doc
**Architecture Component:** `Sub-Agent Queue`
**Target Path:** `srcs/server/orchestration/queue.go`

**Design Requirements:**
1. A generic `JobQueue` interface with `Enqueue(ctx, jobType, payload)` and `RegisterWorker(jobType, handler)`.
2. A `LocalJobQueue` implementation utilizing Go channels and a fixed worker pool for standalone mode.
3. Structs defining `JobPayload` to pass necessary context (like `shared_tasks.id`) to the sub-agent.

## Implementation Prompt
1. Create `srcs/server/orchestration/queue.go`.
2. Define the `JobQueue` interface and `JobPayload` structs.
3. Implement `LocalJobQueue` with proper context cancellation and worker panics recovery.
4. Provide unit tests ensuring jobs are processed successfully and errors are handled correctly.
