# Hybrid CRDT Sync MCP Tool Integration

**Problem Statement:**
Bridging Standalone (local SQLite) with Cloud-Native (multi-tenant PostgreSQL) environments requires sophisticated state resolution. Agents modifying shared tasks offline must seamlessly synchronize with the cloud once network connectivity is restored. Currently, we have an MCP client framework (`srcs/server/agents/mcp/client.go`), but we lack the specific `crdt_pull` and `crdt_push` MCP tools required to execute the synchronization strategy detailed in `docs/architecture/hybrid_crdt_sync_blueprint.md`.

**Research Report:**
- **Current State**: The OHC Hybrid Architecture supports local (SQLite) and cloud (Postgres) modes. Agents use the Model Context Protocol (MCP).
- **Gap**: There are no explicit tools for agents to push or pull state with CRDT (Conflict-free Replicated Data Type) semantics between these environments.
- **Blueprint Alignment**: The `docs/architecture/hybrid_crdt_sync_blueprint.md` explicitly calls for `crdt_pull` and `crdt_push` tools via MCP.
- **Integration Point**: The new tools should be integrated into the `srcs/server/agents/mcp/` directory.

**Design Doc:**
1. **Tool Definitions**:
   - Create a new file: `srcs/server/agents/mcp/crdt_provider.go`.
   - Implement `CRDTPushTool` and `CRDTPullTool` structs that adhere to an MCP tool interface.
   - `CRDTPushTool`: Takes local state changes and pushes them to the remote sync endpoint.
   - `CRDTPullTool`: Fetches the latest remote state and resolves it locally using CRDT logic.
2. **Execution Flow**:
   - Utilize the existing `FormatExecutionResult` in `client.go` to standardize the output of these tools.
   - Set `HybridEscalation` to true during these operations, as they inherently cross the local-cloud boundary.
3. **Telemetry & Privacy**:
   - Ensure all payloads pushed via `CRDTPushTool` are passed through `telemetry.RedactInterfacePII` before transmission, in accordance with the PII scrubbing mandate.

**Implementation Prompt:**
1. Create a new Go file `srcs/server/agents/mcp/crdt_provider.go`.
2. Define a generic `CRDTProvider` struct that implements the MCP tool provider interface (you may need to adapt to the existing provider interface in `provider.go`).
3. Implement a `crdt_push` tool logic within this provider. It should accept a payload, pass it through `telemetry.RedactInterfacePII()`, and return a formatted execution result using `FormatExecutionResult("crdt_push", "success", redactedData, true)`.
4. Implement a `crdt_pull` tool logic that fetches remote state (mock this for now) and returns a formatted result using `FormatExecutionResult("crdt_pull", "success", mockData, true)`.
5. Create a corresponding test file `srcs/server/agents/mcp/crdt_provider_test.go`.
6. Write tests verifying that `crdt_push` correctly redacts PII (e.g., emails) and returns the expected `ExecutionResult` structure with `HybridEscalation` set to `true`.
7. Write tests verifying that `crdt_pull` returns the expected structure.
8. Ensure all new files are added to the Bazel build file (`srcs/server/agents/mcp/BUILD.bazel`) if necessary, or verify they are picked up by the existing build configuration.
9. Format the code using `gofmt -w srcs/server/agents/mcp/crdt_provider.go srcs/server/agents/mcp/crdt_provider_test.go`.
