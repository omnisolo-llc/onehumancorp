# Title: autoDream Pipeline - KAIROS Orchestrator Architecture

## Problem Statement
OHC's Swarm Intelligence Protocol (OHC-SIP) relies on long-term memory consolidation to improve the entire system daily. The "autoDream" architecture (Phase 3) needs robust data pipelines to convert unstructured memories into vector embeddings and store them efficiently for retrieval, bridging Standalone Mode (SQLite with native `[]byte` mappings) and Cloud-Native Mode (pgvector/Pinecone).

## Research Report
- `autodream_pipeline.go` exists but needs to handle KAIROS-level task consolidation.
- `srcs/server/db/migrations/024_autodream_memories.sql` defines memory tables but must integrate with pgvector/Pinecone correctly for production.
- For SQLite, vectors must be mapped to `[]byte`.

## Design Doc
1. **Data Pipeline Architecture**:
    - **Extractor**: Pulls completed KAIROS shared tasks and associated agent telemetry/logs.
    - **Transformer**: Uses LLM (e.g., Anthropic/Minimax) to summarize the task context.
    - **Embedder**: Generates embeddings for the summary.
    - **Loader**: Stores the embeddings into `swarm_memory_embeddings` (handling byte mapping for SQLite and vector for pgvector).
2. **Architecture Diagram**:
    ```mermaid
    sequenceDiagram
        participant KAIROS
        participant AutoDreamWorker
        participant LLMProvider
        participant VectorDB

        KAIROS->>AutoDreamWorker: TaskCompletedEvent
        AutoDreamWorker->>LLMProvider: Summarize & Embed(TaskContext)
        LLMProvider-->>AutoDreamWorker: Embedding Vector
        AutoDreamWorker->>VectorDB: Insert/Update(Embedding)
    ```
