# Title: Implement KAIROS Master Orchestration DB Schema & Models

## Problem Statement
The OHC Swarm requires a unified distributed state machine ("Shared Task List"), real-time coordination ("Teammate Mesh"), and vector-based consolidation ("AutoDream") to operate. While partial implementations exist in local standalone versions, we need a cohesive, K8s-ready Postgres configuration that safely orchestrates DAGs across pods without collisions.

## Research Report
Extensive study of the `.agent-task/memory/` and `docs/KAIROS_ORCHESTRATOR_DESIGN.md` indicates the immediate requirement is to standardize our `AcquireTask` logic safely handling `FOR UPDATE SKIP LOCKED` for `tasks`, `shared_tasks`, and `swarm_tasks` interchangeably.

## Design Doc
See `docs/KAIROS_HYBRID_OS_IMPLEMENTATION.md`. The design leverages a Hybrid DB Provider.

## Implementation Prompt
1. Connect all Database schemas defined in `docs/KAIROS_AI_OS_ARCHITECTURE.md`
2. Ensure `FOR UPDATE SKIP LOCKED` logic dynamically strips out or falls back to Mutex locks when `provider.IsSQLite()` evaluates to true.
3. Write robust unit tests verifying SQLite degrades gracefully and Postgres uses proper locking.
