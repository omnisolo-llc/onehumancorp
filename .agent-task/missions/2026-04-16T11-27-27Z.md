# 🚀 Implement the "Hybrid Local-Private RAG Worker"

**Problem Statement**: Current competitors like Claude Code, OpenClaw, and Replit Agent either rely on massive cloud infrastructures or pure local CLI wrappers. They lack a zero-friction, bidirectional sync capability powered by a single cohesive identity layer (SPIFFE/SPIRE). OHC can capitalize on this Blue Ocean opportunity by providing a seamless, secure transition between air-gapped local execution and highly scalable cloud coordination.

**Research Report**: According to `docs/architecture/ohc_hybrid_competitive_analysis.md`, OHC possesses unmatched flexibility with its Triple-Mode architecture (Cloud-Native, Standalone Desktop, Thin Client) that degrades gracefully to SQLite and utilizes local compute. The core disruption vector identified is "Hybrid Local-Private RAG with MCP & SPIRE Cloud Sync".

**Design Doc**:
1.  **Local Ingestion & Indexing**: Sensitive documents are vectorized locally on the user's host machine using SQLite and local embedding models.
2.  **Cloud Vector Sync (Opt-in)**: Authorized vectors are synchronized via mTLS to the Cloud-Native Postgres/pgvector instance for swarm-wide intelligence.
3.  **Model Context Protocol (MCP)**: Universal context sharing between local Desktop Mode agents and Cloud-Native agents.

**Implementation Prompt**:
Implement the "Hybrid Local-Private RAG Worker" exactly as described in `docs/architecture/ohc_hybrid_competitive_analysis.md`.
- Modify the necessary Go modules in `srcs/server/` to handle local SQLite vector ingestion and indexing.
- Implement the `SyncWorker` component that synchronizes authorized vectors via mTLS to the Cloud-Native Postgres/pgvector instance.
- Integrate MCP for universal context sharing between Desktop and Cloud-Native agents.
- Ensure the worker adheres strictly to the `SPIFFE/SPIRE` identity mesh.
- Add comprehensive test coverage to ensure the hybrid local-private RAG feature functions flawlessly in both Standalone and Cloud-Native modes.
