# Title: Integrate NATS JetStream for Hybrid Pub/Sub and Event Streaming

## Problem Statement
The OHC Hybrid Architecture currently relies on Redis Pub/Sub for the Teammate Mesh and task distribution in Cloud-Native mode. However, Redis Pub/Sub lacks robust message persistence, at-least-once delivery guarantees, and native consumer groups for distributed processing. In Standalone Desktop mode, falling back to SQLite or in-memory queues creates a significant feature disparity. We need a unified event streaming platform that can scale in Kubernetes while also embedding lightly in standalone Go binaries.

## Research Report
*   **Current State**: Redis Pub/Sub is ephemeral. If an agent crashes or loses connection during task broadcast, the message is lost. Standalone mode relies on degraded fallback mechanisms.
*   **Competitors/Alternatives**:
    *   **Apache Kafka**: Too heavy for Standalone mode; requires JVM.
    *   **RabbitMQ**: Erlang dependency makes it unsuitable for embedding.
    *   **NATS JetStream**: Written in Go. Exceptionally lightweight. Can be clustered in Kubernetes (Cloud-Native) and seamlessly embedded directly into the OHC Go binary for Standalone mode. Offers persistent streams, consumer groups, and exactly-once semantics.
*   **Conclusion**: NATS JetStream is the ideal hybrid solution, bridging the gap between massive cloud scale and embedded local performance.

## Design Doc
1.  **Architecture**:
    *   **Cloud-Native Mode**: Deploy NATS JetStream via Helm/Operator in the K8s cluster.
    *   **Standalone Mode**: Instantiate an embedded NATS server within `srcs/server/standalone_ohc.sh` or directly via Go `github.com/nats-io/nats-server/v2/server`.
2.  **Go Client Integration**: Use `github.com/nats-io/nats.go` for publishing and subscribing.
3.  **Data Serialization**: Continue using the standardized JSON payloads (with `agent_id`, `action`, and `status` at the root) over NATS subjects instead of Centrifuge/Redis channels.

## Implementation Prompt
Implement NATS JetStream integration for the OHC Teammate Mesh.
1. Add `github.com/nats-io/nats.go` and `github.com/nats-io/nats-server/v2` to `go.mod` (using Bazel `go_repository` and `gazelle`).
2. Create a new `pubsub.Provider` interface implementation in `srcs/server/pubsub/nats.go`.
3. For Standalone mode, implement an embedded NATS server startup routine. Use `dbWrapper.IsSQLite()` to conditionally start the embedded server if true, otherwise connect to the remote NATS URL (Cloud mode).
4. Refactor the existing Redis Pub/Sub code to use the new NATS provider.
5. Write unit tests in `srcs/server/pubsub/nats_test.go` ensuring message delivery and consumer group functionality. Ensure tests run correctly in both standalone and cloud mock environments.
