# Shared Task List & Realtime Teammate Mesh APIs

## Problem Statement
The OHC Swarm requires a mechanism for complex architectural changes, sub-agent orchestration, and real-time coordination. Currently, there is a gap in defining a robust distributed state machine and real-time mesh to manage these tasks and deep-deliberation cycles effectively. Without this, multi-agent workflows may fail to synchronize state and orchestrate isolated sub-agents in a reliable, distributed manner.

## Research Report
- **Task Decomposition (KAIROS Mode):** We need to architect the database schema (e.g., PostgreSQL) and microservices mapping to decompose high-level feature requests for the OHC Swarm.
- **Teammate Mesh Architecture:** A highly available realtime communication layer (e.g., WebSockets, gRPC, Redis Pub/Sub) is essential for agent coordination and broadcasting UI updates via the `mesh:tasks` Centrifuge channel.
- **Distributed Coordination:** The system must utilize database locks (like `FOR UPDATE SKIP LOCKED`) and Redis Pub/Sub channels to coordinate state reliably across the agent workforce while avoiding livelocking the system and respecting multi-tenant consistency.
- **AutoDream Consolidation:** We must establish data pipelines (using pgvector/Pinecone) to embed and consolidate architectural findings for the OHC's long-term memory.

## Design Doc

### 1. Database Schema (PostgreSQL & SQLite)
We need tables to track shared tasks and sub-agent queues:

```sql
-- Track shared tasks and their distributed state
CREATE TABLE IF NOT EXISTS ohc_shared_tasks (
    task_id UUID PRIMARY KEY,
    tenant_id TEXT NOT NULL,
    parent_task_id UUID,
    title TEXT NOT NULL,
    description TEXT,
    status TEXT NOT NULL, -- PENDING, IN_PROGRESS, COMPLETED, FAILED
    agent_id TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```
Ensure migrations are split properly if altering tables and `IF NOT EXISTS` is avoided for `ADD COLUMN` for SQLite compatibility.

### 2. State Machine & Queuing Logic
- **Interface:** `TaskOrchestrator` in `srcs/server/orchestration/`.
- **Concurrency:** Use `FOR UPDATE SKIP LOCKED` for Postgres to claim tasks. Implement an SQLite fallback using the `db.Provider` interface's `IsSQLite()` method.
- **Queuing:** Implement background synchronization loops with a `LIMIT` clause to query un-synced/pending items, preventing unbounded memory consumption.

### 3. Teammate Mesh APIs
- **Realtime Transport:** Extend the `Hub` struct in `srcs/server/orchestration/service.go`.
- **Centrifuge Broadcasting:** Provide APIs to broadcast JSON payloads. Crucially, when formatting payloads for `PublishTaskBroadcast`, preserve or explicitly set the `type` discriminator field (e.g., `payload["type"] = "TASK_BROADCAST"`) before marshalling, and omit missing keys rather than sending empty strings. Furthermore, ensure `agent_id`, `action`, and `status` are at the root of the JSON message.

### 4. AutoDream Embeddings
- **Data Pipeline:** Define structs and serialization functions for `pgvector` insertion, using `%g` for vector formatting to preserve full floating-point precision.
