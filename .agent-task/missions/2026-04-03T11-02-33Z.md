# Token Burn Rate Forecasting & SQLite Concurrency Throttling

**Priority:** P1
**Estimated Scope:** Medium

## Problem Statement
The OHC Hybrid Architecture (OHC-HA) currently suffers from specific bottlenecks depending on the deployment mode.
1. In Cloud-Native mode, while horizontal scaling manages throughput efficiently, there is a significant observability gap: we lack a Token Burn Rate Forecasting Engine to predict and alert on per-tenant LLM token budgets.
2. In Standalone Desktop mode (SQLite), the host I/O limits are rapidly reached due to Database Lock Contention (`database is locked` errors) during high-concurrency swarm operations, leading to task delegation failures.

## Research Report
A comparative analysis of Prometheus metrics, Kubernetes logs, and local SQLite status files reveals:
- **Cloud-Native:** Network latency and PostgreSQL lock contention are manageable, but predictive token forecasting is completely missing from `ohc_token_usage_total` telemetry. Grafana dashboards (`deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`) lack these panels.
- **Standalone:** Local SQLite (`swarm.db`) experiences severe `database is locked` errors during burst workloads. Exponential backoff is insufficient and often exhausted.

Reference: `OBSERVABILITY_AUDIT_REPORT.md`, `TELEMETRY_REPORT.md`

## Design Doc
1. **Token Burn Rate Forecasting Engine:**
   - **Component:** Background worker in the Orchestration Hub (`srcs/server/orchestration/service.go` or new worker package).
   - **Logic:** Calculate moving average burn rate using existing `ohc_token_usage_total` data. Emit predictive cost alerts.
   - **Observability:** Introduce a new Grafana dashboard panel in `hybrid-telemetry.json` for "Token Forecasting".
2. **Standalone SQLite Concurrency Throttling:**
   - **Component:** `DelegateMission` logic in `srcs/server/orchestration/hub.go` or relevant location.
   - **Logic:** Check for `OHC_STANDALONE` mode. If active, introduce a dynamic concurrency limiter (e.g., using a buffered channel or semaphore) to strictly throttle parallel agent writes to SQLite, ensuring zero-error stability over raw throughput.
