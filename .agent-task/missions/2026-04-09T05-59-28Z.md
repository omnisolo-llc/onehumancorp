# Feature: Shared Task List and Agent Coordination

## Problem Statement
The OHC platform currently lacks a centralized, scalable, and realtime task decomposition and coordination mechanism. High-level feature requests are not broken down effectively for the swarm, and agents lack a durable state machine and realtime communication layer to coordinate dependencies during complex architectural changes.

## Research Report
- Current microservices and database schemas are insufficient to support a robust state machine for tracking Teammate Mesh dependencies.
- A background queuing system (e.g., BullMQ, Celery) is required to spawn isolated sub-agents effectively.
- A realtime communication layer (e.g., WebSockets, gRPC, Redis Pub/Sub) is essential for agent coordination.
- Long-term memory consolidation requires robust data pipelines, such as pgvector and LLM embeddings, to implement "autoDream".

## Design Doc
1. **Task Decomposition (KAIROS Mode)**:
   - Database schemas (PostgreSQL) and microservices mapping to decompose feature requests.
2. **UltraPlan Deliberation**:
   - Deep-deliberation cycles for complex changes, managed by an orchestrated state machine.
3. **State Machine Tracking**:
   - Distributed state machine backed by database locks and Redis.
4. **Sub-Agent Orchestration**:
   - Scalable background queuing logic for task isolation and parallel processing.
5. **Teammate Mesh Architecture**:
   - Realtime communication via Redis Pub/Sub and gRPC to synchronize efforts across the swarm.
6. **AutoDream Data Pipelines**:
   - pgvector and LLM embeddings integration for architectural memory consolidation.

## Implementation Prompt
Implement the backend components for the Shared Task List and Teammate Mesh features.
1. **Schema Modifications**: Create necessary database migrations in `srcs/server/db/migrations/` to support the new state machine, sub-agent queues, and task lists.
2. **Orchestration Logic**: Develop the background queuing and state machine tracking logic in `srcs/server/orchestration/`. Ensure proper locking mechanisms are used.
3. **Teammate Mesh**: Implement the Realtime Teammate Mesh APIs (gRPC/Redis Pub/Sub) in `srcs/server/api/` and `srcs/server/interop/`.
4. **Memory Pipelines**: Integrate pgvector embeddings in `srcs/server/db/` and create the consolidation pipelines in `srcs/server/pipeline/`.
5. **Verification**: Write extensive unit and integration tests (in corresponding `*_test.go` files) ensuring >90% coverage for the newly added components, mocking Redis and K8s components where necessary using the hybrid-aware architecture.
6. **Aesthetics**: Ensure any internal dashboards for task monitoring adhere to the OHC Visual Excellence Mandate.
