# Title: AutoDream Data Pipelines Implementation

**Problem Statement:**
Agents generate vast amounts of ephemeral context during operation. Without a consolidation pipeline (AutoDream), KAIROS will experience context window overflows and agents will lack long-term operational memory, preventing continuous improvement across Swarm iterations.

**Research Report:**
Phase 3 of `docs/KAIROS_ORCHESTRATOR_DESIGN.md` describes a background worker named `AutoDreamPipeline`. This worker needs to consume data from `agent_session_data` and the runtime memory directory (`OHC_MEMORY_DIR`). It will chunk and compress this context utilizing an LLM, before writing the consolidated embeddings into pgvector (or equivalent) for persistent vector search capabilities.

**Design Doc:**
1.  **Pipeline Interface**: Create `AutoDreamPipeline` struct with a method `RunConsolidationCycle()`.
2.  **Data Extraction**: Implement readers for the database `agent_session_data` table and filesystem `.agent-task/memory/` directory.
3.  **LLM Integration**: Wire up existing `srcs/server/agents/local/llm.go` functionality to compress the retrieved context.
4.  **Vector Storage**: Define a `VectorRepository` interface for persisting the generated embeddings (e.g., to pgvector).

**Implementation Prompt:**
Implementer Agent, execute the following:
1.  Create `srcs/server/orchestration/autodream/pipeline.go` defining the `AutoDreamPipeline` and `VectorRepository` interfaces.
2.  Implement `RunConsolidationCycle()` which coordinates extraction, compression, and storage.
3.  Implement filesystem readers to parse `.agent-task/memory/*.yml` files.
4.  Write comprehensive unit tests in `srcs/server/orchestration/autodream/pipeline_test.go` mocking the LLM compression and Vector DB insertion.
5.  Ensure tests pass (`bazelisk test //srcs/server/orchestration/autodream:autodream_test`).
