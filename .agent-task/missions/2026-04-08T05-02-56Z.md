# Implement Hybrid Mode Metric Tagging for Teammate Mesh Broadcasts

## Problem Statement
Telemetry metrics for Teammate Mesh broadcasts (`RecordTeammateMeshBroadcast` in `srcs/server/telemetry/telemetry.go`) are essential for debugging orchestration issues, but `RecordTeammateMeshBroadcast` lacks a `deployment_mode` tag. This creates an observability gap, preventing effective comparison between Cloud-native and Standalone contexts in Grafana.

## Research Report
Based on the `telemetry` module (`srcs/server/telemetry/telemetry.go`), `RecordTeammateMeshBroadcast` only adds a `channel` attribute. The `handleHybridHealthCheck` provides health diagnostic data about the mesh to the UI, but Grafana visualization of the specific Teammate Mesh telemetry requires `deployment_mode` tagging for Hybrid OS operation.

## Design Doc
Update the `RecordTeammateMeshBroadcast` metric recording function in `srcs/server/telemetry/telemetry.go` to accept and record a `deployment_mode` attribute (e.g., `cloud` or `standalone`).

## Implementation Prompt
Modify `RecordTeammateMeshBroadcast` in `srcs/server/telemetry/telemetry.go` to accept a `mode string` parameter and include `attribute.String("deployment_mode", mode)`. Update any calling sites to pass the current mode (`os.Getenv("OHC_STANDALONE")`).
