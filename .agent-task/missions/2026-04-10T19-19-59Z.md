# Mission: Implement KAIROS AI OS Orchestration (Phase 1-3)

## Problem Statement
The One Human Corp (OHC) Swarm requires the KAIROS Orchestrator to define the structural and aesthetic vision for the OHC "Hybrid Agentic OS". Currently, the Swarm lacks a unified architecture to decompose massive human goals into isolated, parallel agentic workflows safely across hybrid environments (Cloud/Standalone). KAIROS must orchestrate the agent team by decomposing high-level feature requests into actionable tasks within a distributed Shared Task List, coordinating via a Teammate Mesh, and consolidating episodic memory through an AutoDream pipeline.

## Research Report
Based on an extensive architectural audit (referencing `docs/features/kairos_orchestration.md`, `docs/features/kairos/state_machine.md`, `docs/features/kairos/sub_agent_queue.md`, and `docs/features/kairos/autodream_pipeline.md`), the implementation demands three robust pillars:
1.  **Shared Task List (Decomposition):** Requires a durable, distributed state machine in PostgreSQL (using `FOR UPDATE SKIP LOCKED`) for horizontal pod concurrency, degrading to SQLite single-process Mutex locks for standalone use.
2.  **Teammate Mesh (Coordination):** A realtime communication layer using Centrifuge WebSockets and Redis Pub/Sub (`mesh:tasks`, `mesh:coordination`) in the cloud, falling back to in-memory channel broadcast for local environments.
3.  **AutoDream Pipeline (Memory):** An episodic memory consolidation system that sweeps `.agent-task/memory/*.yml` and uses LLMs to extract core truth, storing it in `pgvector` indexes (`autodream_memories`) for exact semantic search.

## Design Doc

### 1. Phase 1: Shared Task List & Distributed State Machine
**Goal:** Track task DAGs safely.
**Implementation details:**
- Table: `swarm_tasks` (`id`, `mission_id`, `dependencies` (JSONB), `title`, `status`, `assigned_agent_id`)
- Table: `state_machine_transitions` (`id`, `entity_id`, `entity_type`, `from_state`, `to_state`, `agent_id`, `reason`)
- Enforce the transition flow (`PENDING` -> `ASSIGNED` -> `EXECUTING` -> `REVIEW` -> `COMPLETED`).

### 2. Phase 2: Realtime Teammate Mesh APIs & Queue
**Goal:** Coordinate agents actively working on the Shared Task List.
**Implementation details:**
- `MeshTransport` interface (`RedisMeshTransport`, `MemoryMeshTransport`).
- Sub-Agent Queue backed by `RedisTaskQueue` or `SQLiteTaskQueue`.
- The Pub/Sub updates must enforce the OHC-SIP JSON structure, guaranteeing that `agent_id`, `action`, and `status` reside at the root level.

### 3. Phase 3: AutoDream Vector Data Pipeline
**Goal:** Long-term memory consolidation.
**Implementation details:**
- Table: `autodream_memories` (`id`, `organization_id`, `agent_id`, `content`, `embedding vector(1536)`, `source_type`).
- Worker daemon to poll `.agent-task/memory/*.yml` and generate embeddings via `srcs/server/agents/local/llm.go`.
