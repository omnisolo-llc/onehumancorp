# Title: Missing Metric Coverage: SQLite Sync Daemon Batch Size & Standalone Agent Tracing

## Problem Statement
The KAIROS telemetry infrastructure currently lacks visibility into the standalone synchronization daemon's batch processing efficiency and detailed agent execution tracing when operating in local mode. While we track `ohc_sqlite_lock_contention_total`, we don't have visibility into how effectively the `SyncDaemon` is pushing batches or a comprehensive metric for raw agent execution traces.

## Research Report
Reviewing `TELEMETRY_REPORT.md` and `OBSERVABILITY_AUDIT_REPORT.md`, there's a missing metric coverage for local daemon syncing. The `SyncDaemon` is responsible for pushing buffered metrics from Standalone mode to the Cloud-Native backend. However, the batch size it processes (`ohc_sync_daemon_batch_size`) is not instrumented or visualized.

Additionally, while `RecordAgentExecutionTrace` uses structured logging (`slog.InfoContext`), it lacks an OpenTelemetry metric counter to track the volume of these traces over time (`ohc_agent_execution_traces_total`).

## Design Doc
1. **Instrument `ohc_sync_daemon_batch_size`**: Add an OpenTelemetry `Int64Histogram` (or `Float64Histogram`) to `srcs/server/telemetry/telemetry.go`. Update `RecordSyncDaemonBatchSize` to use this new metric instead of being a no-op or uninitialized variable.
2. **Instrument `ohc_agent_execution_traces_total`**: Add an OpenTelemetry `Int64Counter` to track the total number of agent execution traces. Update `RecordAgentExecutionTrace` to increment this counter.
3. **Grafana Dashboards Update**: Add these new panels to `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`.
