# Title: Integrate Hybrid Metrics and Telemetry MCP Server

## Problem Statement
The OHC Hybrid Architecture currently delegates telemetry metrics directly to OpenTelemetry and Prometheus in cloud mode, or buffered local files in standalone mode. Agents need an MCP interface to dynamically query telemetry or insert bounded metrics related to Swarm Operations (OHC-SIP). Without an MCP interface, agents lack the autonomous ability to read their own health metrics, making autonomous performance tuning impossible.

## Research Report
- **Market Context**: Observability platforms typically rely on static dashboards. Next-generation Agentic platforms like Claude Code can read logs, but standard MCPs do not provide native access to aggregated metrics (Prometheus PromQL or OpenTelemetry traces).
- **OHC Requirement**: A "Hybrid Metrics MCP Proxy" that provides tools for agents to query telemetry data.
- **Tooling Discovery**: A dedicated MCP adapter wrapping the internal `telemetry` module.
- **Security & Multi-Tenancy**: The MCP must validate that agents only query metrics for their authenticated tenant in `OHC_MULTITENANT` mode. In Standalone, it queries the local metrics buffer.

## Design Doc
- **Module Path**: `srcs/server/tools/metricsmcp`
- **Architecture**: A new Go module within `srcs/server/tools/metricsmcp`. Tools should include `query_metrics` and `get_health_status`.
