# Enhance Observability: Token Forecasting and Agent Error Rate Metrics

## Problem Statement
While raw token usage metrics are captured by `ohc_token_usage_total`, there is no detailed fine-grained metric tracking and visualization for **Token Burn Rate Forecasting** and **Agent API Error Rates** in the Grafana dashboard for our Hybrid Architecture. This limits per-tenant proactive budget alerts and masks critical agent invocation bottlenecks in cloud-native deployments. Additionally, while we have standalone mode concurrency throttling introduced in `DelegateMission`, its impact is not clearly observable without these panels.

## Research Report
An observability audit comparing Cloud-Native and Standalone modes highlights:
- **Missing Visualization Gap**: `ohc_token_burn_rate_forecast` and `ohc_agent_api_errors_total` are recorded by the backend but missing appropriate detailed breakdown panels in `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`.
- Cloud mode relies heavily on understanding high-concurrency pod scaling efficiency, whereas standalone relies on local SQLite telemetry. Visualizing error rates grouped by `(role, api)` and forecasting token burn per tenant is essential to maintaining absolute autonomy in cost monitoring.

## Design Doc
1. **Grafana Dashboards Update**:
   - Update `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`.
   - Add a "Token Burn Rate Forecast" panel utilizing the expression `ohc_token_burn_rate_forecast` grouped by `organization_id`.
   - Add an "Agent API Errors" panel utilizing the expression `sum(rate(ohc_agent_api_errors_total[5m])) by (role, api)`.
2. **Dashboard Verification**:
   - Verify that the panels correctly use the `$datasource` variables.
