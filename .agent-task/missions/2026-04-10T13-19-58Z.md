# Title: Implement Hybrid SPIFFE/SPIRE Identity Mesh for Agents

## Problem Statement
Agentic architectures typically rely on hardcoded API keys or traditional JWTs for agent-to-agent communication. In a Hybrid architecture, where agents might migrate from a local SQLite/Standalone environment to a Cloud K8s/Postgres environment, static keys represent a massive security vulnerability and a friction point for autonomy.

## Research Report
A deep analysis of the OHC Hybrid architecture vs. Cloud-only alternatives:
- **Claude Code**: Single-user CLI; implicitly trusts the local user environment.
- **OpenClaw**: Cloud-orchestrated; relies on provider-locked IAM.
- **Replit Agent**: Ephemeral environment; uses short-lived tokens but lacks standalone hybridity.
- **OHC Vision**: We need a zero-trust "Identity Mesh" powered by SPIFFE/SPIRE. When an agent transitions from Standalone to Cloud, it should present a dynamically minted short-lived x509 SVID (SPIFFE Verifiable Identity Document) to authenticate its actions across the KAIROS Orchestration layer and Teammate Mesh without human intervention.

## Design Doc
We will implement a SPIFFE/SPIRE Identity Provider for OHC.
1. **Local Mode**: A lightweight SPIRE Agent runs alongside the Standalone daemon to issue local SVIDs.
2. **Cloud Mode**: SPIRE Server in K8s issues node/workload attestations.
3. **Integration**: The Go KAIROS Orchestrator will implement an mTLS interceptor using the `go-spiffe/v2/spiffetls` library.
