# Title: [research] Hybrid Tool Integrations for Telemetry Visualization

## Problem Statement
We have rich Prometheus metrics generated by `srcs/server/telemetry/telemetry.go` for AutoDream (RAG performance), LLM Cache hits/misses, and Standalone Sync Daemon health. However, these metrics currently lack deep hybrid analysis tools that can seamlessly shift between Cloud multi-tenant and local Standalone environments to correlate anomalies (like latency vs local SQLite locks vs remote Postgres contentions). There is an opportunity to discover and propose modern MCP or standalone integrations that expand Grafana's baseline capabilities.

## Research Report
Recent market research indicates that several emerging Model Context Protocol (MCP) servers and telemetry bridge tools now support dynamic local-to-cloud graph visualization. Tools like the generic Prometheus MCP servers or custom embedded tools could allow our agents (and humans) to directly query complex correlation queries inside the `AutoDream Memory Pipeline` and `LLM Cache Efficiency` domains without writing raw PromQL each time.

## Design Doc
1. Identify a suitable Telemetry-MCP bridge or lightweight visual correlation tool capable of reading Prometheus backends (both the standalone embedded instance and the cloud cluster).
2. Write a configuration standard that injects API keys safely (Zero Secrets constraint using SPIFFE/SPIRE where applicable).
3. Propose changes to `deploy/docker-compose.yml` and `deploy/docker/grafana/provisioning/` to expose this new tooling.
4. Design wireframes for any new UI surfaces, ensuring strict adherence to the OHC-SIP (Glassmorphism, 20px blur, `rgba(255, 255, 255, 0.03)` background, Outfit/Inter typography).

## Implementation Prompt
Hello Implementer. Your mission is to implement the Telemetry-MCP Bridge integration:
1. Open `deploy/docker-compose.yml` and add the `telemetry-mcp-bridge` service configured to connect to Prometheus.
2. Ensure the service degrades gracefully if Cloud dependencies are absent (Standalone Desktop Mode fallback).
3. Provide the Go backend wire-up in `srcs/server/agents/mcp/client.go` to register this tool with the KAIROS Orchestrator.
4. Ensure >90% test coverage for the tool registration logic. Run `bazelisk test //srcs/server/agents/mcp/...` to verify.
