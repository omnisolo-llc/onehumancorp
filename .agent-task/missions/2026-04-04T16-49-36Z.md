# OHC-HA: Local-to-Cloud MCP RAG Synchronization Daemon

**Problem Statement**
Competitors in the agentic OS market force users into a binary compromise: either execute workloads securely offline with limited compute (like local-first CLI tools) or sacrifice data sovereignty for scalable multi-tenant execution (like Replit Agent or OpenClaw). The One Human Corp Hybrid Architecture (OHC-HA) currently supports local SQLite fallback and cloud PostgreSQL orchestration, but lacks a mechanism to seamlessly and securely synchronize private, locally processed RAG (Retrieval-Augmented Generation) context vectors from the Standalone Desktop environment into the Multi-Tenant Cloud Swarm for high-compute delegation.

**Research Report**
### Competitive Market Audit

This analysis evaluates OHC's current and future capabilities against market alternatives, revealing a "Blue Ocean" opportunity in hybrid state synchronization. All findings have been verified.

**The Delta**: The integration of a Local-to-Cloud Sync Daemon. OHC will allow users to securely process highly sensitive datasets entirely on their local machine via Standalone mode (using local MCPs and SQLite). When parallel swarm computation is required, the Sync Daemon securely transfers *only* the generalized, sanitized RAG context payloads to the Cloud PostgreSQL engine (`agent_missions`), enabling cloud-scale agent execution without exposing raw private data.

**Design Doc**
### Local-to-Cloud Context Sync Daemon Architecture

**Overview**: A background synchronizer embedded in the `srcs/server/orchestration` package that manages the lifecycle of cross-environment task payloads.

**Core Components**:
1.  **SyncDaemon (`srcs/server/orchestration/sync.go`)**: A background worker instantiated during standalone boot.
2.  **State Tracking**: Utilizes `shared_tasks` to track what has been synced.
3.  **Database Compatibility**: The implementation must strictly use `pool.IsSQLite()` to diverge execution paths:
    *   *SQLite (Standalone)*: The daemon acts as an active poller, extracting local payloads to push to the remote API. (Requires explicit transaction with select-then-update due to missing `UPDATE ... RETURNING LIMIT` support).
    *   *Postgres (Cloud)*: The daemon listens for incoming payloads via the internal API and injects them into the tenant's `agent_missions` execution queue.
4.  **Security**: Internal sync API endpoints must be wrapped with `auth.RequireRole("system", ...)` to enforce SPIFFE/SPIRE Zero-Trust authentication.
5.  **Observability**: Expose sync latencies and batch sizes via OpenTelemetry metrics (e.g., `sync_daemon_batch_size`, `sync_daemon_latency_ms`).

**Implementation Prompt**
You are an Implementer agent. Your task is to build the Local-to-Cloud Sync Daemon for OHC-HA.

1.  **Create `srcs/server/orchestration/sync.go`**:
    *   Implement the `SyncDaemon` struct.
    *   Write a `Start(ctx context.Context, db pool.DB)` method that runs a background polling loop.
    *   Explicitly check `pool.IsSQLite()` to configure the daemon as the local "pusher".
    *   Implement the SQLite extraction query. Remember that SQLite does not support `UPDATE ... RETURNING` with `LIMIT`. You must use a two-step select-then-update inside an explicit transaction (`tx.Begin`).
2.  **API Endpoints (`srcs/server/api/sync_handlers.go`)**:
    *   Create endpoints to receive context payloads.
    *   Strictly wrap these handlers with `auth.RequireRole("system", ...)` for SPIFFE/SPIRE compliance.
3.  **Observability**:
    *   Add OpenTelemetry metrics in `srcs/server/telemetry` for `sync_daemon_batch_size` and record them during each sync loop.
    *   When adding new metrics, make sure `"//srcs/server/telemetry"` is added to the `deps` array in `srcs/server/orchestration/BUILD.bazel`.
4.  **Testing**:
    *   Write comprehensive tests in `srcs/server/orchestration/sync_test.go`.
    *   When testing SQLite locally, use `sql.Open("sqlite", ":memory:")` and import `_ "modernc.org/sqlite"`.
    *   Ensure all tests pass using `bazelisk test //srcs/server/...`. Do not use native `go test`.
