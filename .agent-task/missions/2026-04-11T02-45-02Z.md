# Title: Refactor Architecture to remove OHC_STANDALONE Assumption

## Problem Statement
Recent feature implementations such as Standalone Metric Buffering and SQLite Concurrency Throttling incorrectly check for an `OHC_STANDALONE` environment variable.
According to the OHC Core Architecture and memory protocol, there is no `OHC_STANDALONE` environment variable in the platform design. The platform relies strictly on evaluating `OHC_MULTITENANT` to distinguish between Multi-tenant (Cloud) and Standalone modes. Code relying on `OHC_STANDALONE` will fail to correctly identify Standalone mode when deployed naturally, breaking observability and throttling mechanisms.

## Research Report
The system audit confirmed the presence of `OHC_STANDALONE` references in `srcs/server/telemetry/telemetry.go` and `srcs/server/orchestration/hub.go`, as well as associated test files. The `InitTelemetry` function and `DelegateMission` method depend on this non-existent variable. As stated in OHC system guidelines: "Do not assume or check for the existence of an `OHC_STANDALONE` environment variable; rely strictly on evaluating `OHC_MULTITENANT` to distinguish between Multi-tenant and Standalone modes."

## Design Doc
1.  **Refactor `InitTelemetry`**: Update `srcs/server/telemetry/telemetry.go` to evaluate `os.Getenv("OHC_MULTITENANT") != "true"` instead of checking for `OHC_STANDALONE`.
2.  **Refactor `DelegateMission`**: Update `srcs/server/orchestration/hub.go` to use `!envBoolDefault("OHC_MULTITENANT", false)` instead of `envBoolDefault("OHC_STANDALONE", false)` when checking if `isStandalone` is true.
3.  **Update Tests**: Refactor `telemetry_test.go`, `buffer_test.go`, and orchestration tests to mock/set `OHC_MULTITENANT` instead of `OHC_STANDALONE` to simulate different modes.

## Implementation Prompt
Hello Implementer agent! Please refactor the codebase to eliminate the `OHC_STANDALONE` assumption:
1. Search and replace all instances of `OHC_STANDALONE` in `srcs/server/telemetry/telemetry.go` and `srcs/server/orchestration/hub.go` with `OHC_MULTITENANT` logic.
