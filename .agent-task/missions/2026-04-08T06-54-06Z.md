# Problem Statement
The One Human Corp (OHC) platform needs a robust, distributed state machine to track the Shared Task List as part of the KAIROS Orchestration engine. Currently, there is a gap in decomposing complex feature requests into a shared, durable queue. We must design a system that works seamlessly in both Cloud-Native (PostgreSQL) and Standalone Desktop (SQLite) modes, preventing worker collisions when claiming tasks.

# Research Report
- Based on `docs/features/kairos/state_machine.md`, the Distributed State Machine Tracker ensures deterministic transitions (`PENDING` -> `ASSIGNED` -> `IN_PROGRESS` -> `REVIEW` -> `COMPLETED` | `FAILED`).
- For multi-tenant Cloud Mode, the architecture uses PostgreSQL. To ensure exclusive locking during task claiming without stalling other workers, `FOR UPDATE SKIP LOCKED` is the industry standard for queue-like tables in Postgres.
- For Standalone Mode, SQLite is used. Since SQLite lacks row-level locking, application-level transaction boundaries or mutexes must be used to ensure serialized transitions.
- A central `shared_tasks` table is required to track the decomposed features, their status, dependencies, and assigned agents.

**Database Schema (`shared_tasks`):**
```sql
CREATE TABLE IF NOT EXISTS shared_tasks (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL,
    parent_plan_id TEXT,
    title TEXT NOT NULL,
    description TEXT,
    status TEXT NOT NULL DEFAULT 'PENDING',
    assigned_agent_id TEXT,
    dependencies JSONB,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_shared_tasks_org_status ON shared_tasks(organization_id, status);
```

1. Create a migration file `srcs/server/db/migrations/014_shared_tasks.sql` with the `shared_tasks` table schema. Add it to `embedsrcs` in `srcs/server/db/BUILD.bazel`.
2. Implement the `tasks_db.go` repository in `srcs/server/orchestration/`.
3. Create a `ClaimTask` method.
   - Use conditional logic based on the provider:
   - `if !dbWrapper.Provider().IsSQLite() { ... }`: Execute `SELECT * FROM shared_tasks WHERE status = 'PENDING' FOR UPDATE SKIP LOCKED LIMIT 1`.

5. Write unit tests in `tasks_db_test.go` mocking both SQLite and Postgres flows.
