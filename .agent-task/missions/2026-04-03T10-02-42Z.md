# Manifest Excellence and Resource Orchestration

## Problem Statement
The OHC Hybrid Architecture requires peak efficiency for both Cloud clusters and Standalone Desktop environments. The K8s Vertical Pod Autoscaler (VPA) for the backend was configured with `updateMode: "Off"` and lacked dynamic boundary bindings, reducing the multi-tenant scaling efficiency. Simultaneously, the Standalone local docker-compose environment lacked resource reservations, risking host machine instability and sub-optimal local performance.

## Research Report
-   **Cloud Native HPA/VPA:** K8s VPAs function best when `updateMode` is set to 'Auto', dynamically adjusting resources. Linking `minAllowed` and `maxAllowed` constraints to Helm chart value requests and limits ensures the VPA does not scale out of bounds.
-   **Standalone Resource Orchestration:** Docker-Compose deployments need explicit boundaries. Explicitly providing `deploy.resources.reservations` prevents CPU starvation on the host machine and allows better container scheduling logic.

## Design Doc
-   **K8s Configuration (`deploy/helm/ohc/templates/backend-vpa.yaml`):**
    -   Set `updateMode: "Auto"`.
    -   Add `minAllowed` for CPU and Memory, mapped to `.Values.backend.resources.requests`.
    -   Add `maxAllowed` for CPU and Memory, mapped to `.Values.backend.resources.limits`.
    -   Add `cpu` to `controlledResources`.
-   **Standalone Configuration (`deploy/docker-compose.yml`):**
    -   Audit all services for missing resource limits/reservations.
    -   Add `reservations.cpus` and `reservations.memory` mapped safely under their respective `limits` values for all 11+ services (core, backend, redis, postgres, powersync, chatwoot, prometheus, grafana, plane).

## Implementation Prompt
Update VPA rules to auto-scaling and configure docker-compose resource limits and reservations.
