# Title: Integrate Multi-Tenant Key-Value Hybrid MCP Store

## Problem Statement
While OHC-HA operates across Cloud (PostgreSQL/Redis) and Standalone (SQLite) modes, agents lack a unified, fast key-value interface to store ephemeral configurations, settings, or transient states. When a standalone desktop agent moves to the cloud or needs to synchronize lightweight KV state (like "last processed block" or "user preferences"), they currently have to write full relational database schemas or abuse local files.

## Research Report
- **Market Context**: Modern AI workflows rely heavily on fast KV stores (like Redis or DynamoDB) to keep state across function calls. Local agents use LevelDB or JSON files.
- **OHC Requirement**: We need a "Hybrid KV Store MCP".
- **Tooling Discovery**: An adapter that exposes `kv_get`, `kv_set`, and `kv_list`. When `OHC_STANDALONE=true`, it backs into a dedicated SQLite table (`agent_kv_store`). In Cloud mode, it leverages Redis with strict multi-tenant key prefixing.
- **Security & Multi-Tenancy**: The cloud variant must prepend the agent's `organization_id` (from their `auth.Claims`) to all keys to enforce isolation.

## Design Doc
- **Module Path**: `srcs/server/tools/kvmcp`
- **Architecture**:
  - Exposes tools: `kv_get`, `kv_set`, `kv_delete`, `kv_list`.
  - Fallback logic: Detect `OHC_STANDALONE` or if Redis is available.
  - Multi-tenancy: Keys in Redis must be `tenant:{org_id}:kv:{key}`.
