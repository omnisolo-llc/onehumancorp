# Title: Bridge Observability Gaps in OHC Hybrid Architecture Telemetry

## Problem Statement
The OHC Hybrid Architecture (OHC-HA) operates across both Cloud-native Kubernetes and Standalone desktop modes. Recent audits have revealed a critical gap in telemetry monitoring. Specifically, while standalone metrics synchronization and API rate limiting are instrumented in the backend, we lack clear Grafana visualizations for them. This masks the operational health of the SyncDaemon and prevents proactive detection of external LLM API rate limits.

## Research Report
- **Market Context**: Competing AI operating systems either enforce cloud dependency or offer zero local observability. OHC aims to solve this by providing enterprise-grade metrics in local deployments via a sync buffer.
- **OHC Requirement**: We need to expose the newly developed sync_daemon_batch_size and api_rate_limit_exceeded_count metrics inside our primary Grafana dashboard.
- **Tooling Discovery**: The backend OpenTelemetry configuration (srcs/server/telemetry/telemetry.go) already emits sync_daemon_batch_size and api_rate_limit_exceeded_count. However, the provisioned dashboard at deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json completely omits them.
- **Bottlenecks**: Without this data prominently displayed, SRE agents and Human operators cannot proactively mitigate API throttling or debug synchronization failures between Standalone SQLite and Cloud metrics.

## Design Doc
1. **Grafana Dashboards Update**:
   - Locate the Grafana dashboard JSON file: deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json.
   - Add a new "SyncDaemon Batch Size" panel utilizing the expression rate(sync_daemon_batch_size_sum[5m]) / rate(sync_daemon_batch_size_count[5m]).
   - Add a new "API Rate Limits Exceeded" panel utilizing the expression sum(rate(api_rate_limit_exceeded_count[5m])).
2. **Dashboard Verification**:
   - Ensure all panels properly use the $datasource variables to stay environment agnostic.
