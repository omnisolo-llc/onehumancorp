# Title: Design Standalone Metric Buffer and Cloud Sync

## Problem Statement
Standalone Desktop Agents operate with limited observability because Prometheus cannot efficiently scrape local SQLite metrics in a decentralized manner. This creates a blind spot for Swarm Intelligence, violating the principle of Full-Spectrum Observability for our local-first operations.

## Research Report
The "Hybrid Observability Pattern" dictates that we must buffer agent execution metrics locally (in SQLite) during Standalone mode and periodically sync them to the Cloud (PostgreSQL/Prometheus) when an active connection is established. This requires a robust synchronization daemon that respects PII boundaries (`telemetry.RedactInterfacePII`).

## Design Doc
1. **Local SQLite Schema:** Create a schema for storing metric events (timestamp, metric name, value, labels).
2. **Buffer Interface:** Implement a `MetricBuffer` interface that the telemetry package can write to when `OHC_STANDALONE=true`.
3. **Sync Daemon:** A background worker that periodically wakes up, checks for an active Cloud connection, reads a batch of scrubbed metrics, and POSTs them to a new Cloud API endpoint.
4. **Cloud Receiver API:** Create a new endpoint `/api/telemetry/sync` on the Cloud backend to ingest these batched metrics and expose them via Prometheus.
