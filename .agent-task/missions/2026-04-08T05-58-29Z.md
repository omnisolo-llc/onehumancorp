# Title: Integrate Hybrid Secrets Management MCP Server

## Problem Statement
Agents operating within the OHC "Hybrid Agentic OS" need to securely access sensitive credentials (such as API keys and external tool credentials) across both Multi-tenant Cloud and Single-user Standalone environments. Currently, there is a risk of leaking secrets into plaintext context logs or local unencrypted storage because there is no unified, secure interface for credential management.

## Research Report
- **Market Context**: In standard Agentic deployments, secrets are often hardcoded into `.env` files locally or rely on rigid Vault implementations in the cloud. We need an agnostic abstraction that Agents can use directly via standard MCP tools.
- **OHC Requirement**: A "Hybrid Secrets Management MCP Server" is required.
  - **Cloud Mode**: Secrets must be strictly retrieved from tenant-scoped vaults (e.g., K8s Secrets, HashiCorp Vault) using the `auth.Claims` bound to the active context.
  - **Standalone Mode**: Secrets must be securely managed via an encrypted local storage mechanism (e.g., encrypted SQLite column using `OHC_SQLITE_KEY` or the local OS Keychain).

## Design Doc
- **Module Path**: `srcs/server/agents/mcp/secrets_mcp.go`
- **Architecture**:
  - Expose two standard tools to the agent: `get_secret` and `put_secret`.
  - Backed by an interface `mcp.SecretsProvider`.
  - **Security Bounds**: Cloud implementation injects `auth.Claims` to scope secret namespaces per tenant. Local implementation ensures encryption at rest.

  - Fallback logic should support the local encrypted SQLite DB when `OHC_STANDALONE=true`.
