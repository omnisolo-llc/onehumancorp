# Mission: Observability Mode Parity for Postgres Transaction Retries

## Problem Statement
Postgres transaction retries lack parity with SQLite in terms of telemetry recording within the retry loop in `srcs/server/orchestration/sip.go`. SQLite lock contentions are recorded during retries, but Postgres ones are only recorded when retries are exhausted.

## Research Report
Verified that `withSipRetry` in `srcs/server/orchestration/sip.go` records SQLite lock contentions (`telemetry.RecordSQLiteLockContention`) during the retry loop. However, for Postgres, it currently only records `telemetry.RecordPostgresRetryExhausted` after the loop fails completely. Parity requires recording `telemetry.RecordPostgresLockContention` during the retry loop as well.

## Design Doc
Update the retry loop in `withSipRetry` to detect Postgres-specific serialization failures (`could not serialize access`) and deadlocks (`deadlock detected`) and record them using `telemetry.RecordPostgresLockContention`.

## Implementation Prompt
Update `srcs/server/orchestration/sip.go` to include Postgres lock contention recording in `withSipRetry`. Update `srcs/server/telemetry/telemetry_test.go` and `srcs/server/telemetry/buffer_test.go` to include tests for these Postgres telemetry functions.
