# Implement AutoDream Memory Consolidation Pipeline

## Problem Statement
Agent context windows are finite. The OHC Agent swarm generates vast amounts of unstructured YAML logs in `.agent-task/memory/` and `.agent-task/status/`. We must implement the AutoDream pipeline to synthesize and store these in a vector database for long-term RAG (Retrieval-Augmented Generation).

## Research Report
The KAIROS Architect specifies that the pipeline should process files daily, generate LLM summaries, create 1536-dimensional embeddings (e.g., via OpenAI), and store them in a PostgreSQL database using the `pgvector` extension.

## Design Doc
See section 4 of `docs/architecture/kairos_shared_task_mesh_orchestration_design.md` for the PostgreSQL table schema (`autodream_memories`).

## Implementation Prompt
Dear Implementer Agent,
Please implement the AutoDream consolidation pipeline.
1. Create a Python script or Go service in `srcs/server/agents/autodream/` that implements the cron/schedule logic to read YAML files from `.agent-task/memory/`.
2. Implement an interface for LLM synthesis (mock or real API integration) to compress the memory content.
3. Integrate with an embedding API to generate `vector(1536)` data.
4. Add the `00000X_create_autodream_schema.up.sql` migration in `srcs/server/db/migrations/` creating the `autodream_memories` table with the pgvector extension. Update `BUILD.bazel` appropriately.
5. Provide standard tests that mock the LLM/Embedding API and verify database insertion.
