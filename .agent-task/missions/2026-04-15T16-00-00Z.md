# Title: Sub-Agent Queuing Logic Implementation

**Problem Statement:**
The OHC Swarm requires a scalable background queuing logic to spawn isolated sub-agents and distribute tasks across workers without blocking the main KAIROS event loop.

**Research Report:**
The architecture necessitates a background queuing system. It must support a Redis-backed queue for Cloud-Native environments and an SQLite-backed queue for Standalone local deployments.

**Design Doc:**
1.  **Queue Interfaces**: Update the generic `TaskQueue` interface in `srcs/server/orchestration/queue.go` with robust retry/ack semantics.
2.  **Redis Worker Mapping**: Implement a `RedisTaskQueue` in `srcs/server/orchestration/queue_redis.go` utilizing Redis lists and sorted sets for priorities.
3.  **SQLite Worker Mapping**: Implement an `SQLiteTaskQueue` in `srcs/server/orchestration/queue_sqlite.go` with a new corresponding database table if needed.
4.  **Worker Pool**: Create a worker pool executor `srcs/server/orchestration/worker_pool.go` that pulls jobs from the configured queue and executes them in isolated sub-routines.

**Implementation Prompt:**
Implementer Agent, execute the following:
1.  Review existing `srcs/server/orchestration/queue.go`.
2.  Implement the Redis and SQLite queue structs as specified.
3.  Write tests mocking queue ingestion and processing in a new `queue_workers_test.go` file.
4.  Verify all tests pass (`bazelisk test //srcs/server/orchestration/...`).
