# Teammate Mesh Database Subsystem Realization

**Problem Statement:**
The OHC swarm requires a durable, resilient tracking layer for task execution and coordination using PostgreSQL, supported by Redis Pub/Sub, but the architectural designs need concrete implementation directives.

**Research Report:**
The architecture relies on the newly established `ohc_tasks` schema (`ohc_tasks.missions`, `ohc_tasks.mission_dependencies`) and `ohc_memory.autodream_vectors`. Current implementations of the Teammate Mesh and AutoDream pipeline require adjustments to read from and write to these new schemas instead of older `shared_tasks` structures.

**Design Doc:**
1. Update `srcs/server/db/repositories/mesh_repo.go` to use `ohc_tasks.missions` and `ohc_tasks.mission_dependencies` schema instead of `shared_tasks`.
2. Update `srcs/server/orchestration/autodream.go` to target `ohc_memory.autodream_vectors` instead of `autodream_memories` or `agent_memory_embeddings`.
3. Assure Redis Pub/Sub payloads published by `srcs/server/orchestration/mesh/` include `task_id` formatted consistently with the new DB schema UUID fields.

**Implementation Prompt:**
"You are the Implementer Agent. Implement the Teammate Mesh subsystem realizations according to the KAIROS Shared Task Mesh architecture.
1. Modify `srcs/server/db/repositories/mesh_repo.go` to insert/update against `ohc_tasks.missions` and `ohc_tasks.mission_dependencies`. Ensure `FOR UPDATE SKIP LOCKED` logic uses the new schema prefixes.
2. Modify `srcs/server/orchestration/autodream.go` (and related test `srcs/server/orchestration/autodream_test.go`) to reference `ohc_memory.autodream_vectors`.
3. Validate tests pass (`bazelisk test //srcs/server/...`)."

**Priority:** P0
**Estimated Scope:** Medium
