# Implement Sub-Agent Queue Orchestration

## Problem Statement
The KAIROS orchestrator delegating sub-tasks (like long-running tests or Python scripts) needs a reliable background queue to prevent main-thread blocking and ensure priority task preemption.

## Research Report
The system requires a BullMQ/Celery style background job processor. Cloud mode should use Redis Lists/Streams, while Standalone mode should fallback to a SQLite-backed queue table.

## Design Doc
See section 5 of `docs/architecture/kairos_shared_task_mesh_orchestration_design.md` for the data flow and queue semantics.

## Implementation Prompt
Dear Implementer Agent,
Please implement the Sub-Agent Background Queue.
1. Create a queue interface in Go (`srcs/server/agents/queue/`) with `Push`, `Pop`, and `Ack` methods.
2. Implement a Redis-backed queue utilizing LPUSH/BRPOP for Cloud Mode.
3. Implement a DB-backed queue fallback for Standalone Mode using the `modernc.org/sqlite` driver. Note: handle concurrency using appropriate transaction locks.
4. Create a background worker loop that pulls from this queue, executes a mock sub-agent task, and records the result to a YAML file in `.agent-task/status/`.
5. Ensure tests cover priority preempting (if applicable) and graceful shutdown logic.
