**Title**: [backend] Implement advanced Bash execution sandboxing and security validations

**Problem Statement:**
Currently, OHC-HA may run shell commands with basic safeguards. However, market research (e.g., Claude Code v2.1.88) reveals that top-tier agent harnesses implement highly sophisticated, semantic Bash execution sandboxing. Without this, agents running terminal commands are exposed to severe security risks (e.g., Zsh expansions, process substitution, obfuscated flags) and lack precise filesystem/network isolation.

**Research Report:**
Deep dive into Claude Code's agent harness reveals:
- A dedicated `BashTool` that doesn't just run commands, but parses them.
- Uses `bashSecurity.ts` to block >20 dangerous patterns, including `zmodload`, process substitution `>()`, `$[]` legacy expansions, and obfuscated variables.
- Semantically understands commands (e.g., `isSearchOrReadBashCommand`) to alter behavior or UI representation.
- Wraps execution in `@anthropic-ai/sandbox-runtime`, restricting filesystem write paths and network host domains dynamically based on permission rules.

**Design Doc:**
1.  **Module:** `srcs/server/harness/bash_sandbox/`
2.  **Architecture:**
    - Introduce an AST-based (or robust regex) pre-execution validator in the harness.
    - Implement a `SandboxAdapter` that uses Linux namespaces or a similar isolated environment (like Docker or gVisor) if running in Cloud-Native Mode.
    - Define precise network (`allowedHosts`) and filesystem (`readRestriction`, `writeRestriction`) policies per agent task.
3.  **Metrics:** Add Prometheus metrics `ohc_bash_sandbox_violations_total` and `ohc_bash_execution_duration_seconds`.

**Implementation Prompt:**
"As an Implementer, create the `bash_sandbox` package in `srcs/server/harness/`. Implement a Go function `ValidateBashCommand(cmd string) error` that rejects Zsh expansions, process substitutions, and known dangerous tools (e.g., `zmodload`). Implement a `RunSandboxed(cmd string, policy SandboxPolicy) (Result, error)` function that executes the command with restricted filesystem paths. Ensure test coverage >90% and use `t.Setenv()` with `t.TempDir()` for filesystem isolation in tests. Instrument with OpenTelemetry for all executions."

**Priority:** P1
**Estimated Scope:** Large
