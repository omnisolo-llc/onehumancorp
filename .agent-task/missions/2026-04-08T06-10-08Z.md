# 🧠 Kairos: Architect the Shared Task List & Sub-Agent Queue

## Problem Statement
The OHC swarm requires a robust, durable, and distributed task management system to decompose high-level human goals into isolated, parallel workflows. Currently, agentic dependencies are not strictly tracked across pod restarts or network partitions. We need a definitive "Shared Task List" that operates via a DAG (Directed Acyclic Graph) state machine, ensuring that sub-agent workloads are properly enqueued, executed, retried, and consolidated back to the primary Orchestrator. This must function identically across Cloud (Postgres/Redis) and Standalone (SQLite) modes.

## Research Report
### Competitive & Architectural Analysis
- **Framework Gap:** Most LLM agent frameworks handle tasks entirely in-memory, which breaks down during multi-agent DAG execution if a single pod/node crashes.
- **KAIROS State Machine:** According to `docs/features/kairos/state_machine.md`, we must strictly enforce deterministic transitions (`PENDING` -> `ASSIGNED` -> `IN_PROGRESS` -> `COMPLETED`).
- **Sub-Agent Queue:** As outlined in `docs/features/kairos/sub_agent_queue.md`, the queuing mechanism must support BullMQ-style semantics, falling back to a `SQLITE_BUSY` mutex approach for standalone execution.
- **AutoDream Consolidation:** Once tasks complete, their context must be vectorized (pgvector) into `autodream_memories` to support long-term OHC-SIP shared intelligence.

### 1. Database Schema Definitions
We will extend the hybrid schema to support task DAG tracking and state machine audit logging.

**`swarm_tasks` (Postgres / SQLite Hybrid):**
```sql
CREATE TABLE IF NOT EXISTS swarm_tasks (
    id TEXT PRIMARY KEY,
    mission_id TEXT NOT NULL,
    parent_task_id TEXT,
    dependencies JSONB NOT NULL DEFAULT '[]', -- Execution DAG
    title TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'PENDING',
    assigned_agent_id TEXT,
    payload JSONB,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_swarm_tasks_mission ON swarm_tasks(mission_id);
```

**`state_machine_transitions`:**
Tracks all state transitions.
```sql
CREATE TABLE IF NOT EXISTS state_machine_transitions (
    id TEXT PRIMARY KEY,
    entity_id TEXT NOT NULL,
    entity_type TEXT NOT NULL,
    from_state TEXT NOT NULL,
    to_state TEXT NOT NULL,
    agent_id TEXT,
    reason TEXT,
    occurred_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_sm_entity ON state_machine_transitions(entity_id, entity_type);
```

### 2. Teammate Mesh APIs (Redis Pub/Sub)
All `status` changes in `swarm_tasks` must emit real-time events over the Teammate Mesh using the existing Pub/Sub infrastructure (`CentrifugeNode`).

### 3. Distributed Locking (Git-Lock & Sub-Agent Queue)
Queue ingestion and state transitions must be serialized.
- **Cloud Mode:** `srcs/server/orchestration/queue/postgres_queue.go` should leverage explicit `FOR UPDATE SKIP LOCKED`.
- **Standalone Mode:** Will utilize the SQLite Mutex approach natively available in the codebase.
