# Title: Shared Task List Database Schema Implementation

**Problem Statement:**
The OHC Swarm currently lacks a centralized, distributed database schema to manage task decomposition, track agent dependencies (DAGs), and maintain a robust state machine. This prevents KAIROS from safely coordinating complex multi-agent workflows without race conditions or duplication of effort.

**Research Report:**
Based on the `docs/KAIROS_ORCHESTRATOR_DESIGN.md` phase 1 requirements, the hybrid architecture necessitates a schema that supports both Cloud-Native (PostgreSQL) and Standalone (SQLite) modes. A `swarm_tasks` and `state_machine_transitions` table strategy must be implemented. Utilizing a distributed locking mechanism on these tables via row-level locks or separate Redis locks (as per Cloud mode) is crucial to maintain state integrity across parallel agent workflows.

**Design Doc:**
1.  **Architecture**: Implement schema migration files and Go ORM (e.g., GORM or raw SQL queries) structures.
2.  **Schema Definition**:
    *   `swarm_tasks`: `id` (UUID), `title` (VARCHAR), `description` (TEXT), `status` (VARCHAR - PENDING, IN_PROGRESS, DONE), `priority` (VARCHAR), `agent_id` (UUID, nullable), `created_at` (TIMESTAMP), `updated_at` (TIMESTAMP).
    *   `state_machine_transitions`: `id` (UUID), `task_id` (UUID, foreign key), `from_state` (VARCHAR), `to_state` (VARCHAR), `triggered_by` (VARCHAR), `transitioned_at` (TIMESTAMP).
    *   `task_dependencies`: `task_id` (UUID), `depends_on_task_id` (UUID).
3.  **Microservices Mapping**: Define the interface `TaskRepository` with methods `CreateTask`, `GetPendingTasks`, `ClaimTask(taskID, agentID)`, `CompleteTask(taskID)`, `GetTaskDependencies(taskID)`.

**Implementation Prompt:**
Implementer Agent, execute the following:
1.  Create database migration scripts (up and down) for `swarm_tasks`, `state_machine_transitions`, and `task_dependencies` in `srcs/server/db/migrations/`.
2.  Implement the Go models representing these tables in `srcs/server/db/models/tasks.go`.
3.  Implement the `TaskRepository` interface and its PostgreSQL/SQLite specific concrete implementations in `srcs/server/db/repositories/`. Ensure `ClaimTask` uses `FOR UPDATE SKIP LOCKED` in PostgreSQL for concurrency safety.
4.  Add unit tests in `srcs/server/db/repositories/tasks_test.go` using an in-memory SQLite provider (`db.NewTestProvider(t)`).
5.  Verify all tests pass (`bazelisk test //srcs/server/db/repositories:repositories_test`).
