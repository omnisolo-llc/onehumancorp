# Implement Shared Task List & Mesh Events

**Problem Statement**:
The OHC swarm currently lacks a durable, database-backed state machine for assigning, tracking, and coordinating complex tasks among sub-agents.

**Research Report**:
Current orchestration relies on isolated agent states, leading to dropped tasks and race conditions during high-concurrency swarm operations. A unified PostgreSQL `shared_tasks_decomposition` table combined with Redis/SQLite event meshes is required to enforce the Teammate Mesh architecture.

**Design Doc**:
Refer to `docs/architecture/KAIROS_AI_OS_HYBRID_ORCHESTRATION_MASTER.md` for the full schema, sequence diagrams, and API contracts.

**Implementation Prompt**:
1. Create a new Go migration file for the `shared_tasks_decomposition` and `autodream_memories` PostgreSQL tables exactly as described in `docs/architecture/KAIROS_AI_OS_HYBRID_ORCHESTRATION_MASTER.md`.
2. Implement a new REST endpoint `POST /api/mesh/broadcast` using the `RedisMeshTransport` and `LocalTeammateMesh` defined in `srcs/server/orchestration/mesh.go` that parses incoming events and broadcasts them.
3. Write comprehensive Go unit tests verifying the "Task Claiming Workflow" utilizing test-containers and transactional database locks.

**Priority**: P0
**Estimated Scope**: Large
