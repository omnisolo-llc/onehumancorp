**Title:** Missing Standalone BufferMetricFunc in Telemetry Extensions

**Problem Statement:**
Several metric extensions in the OHC backend telemetry module are missing the `BufferMetricFunc` instrumentation. This is critical for the "Standalone Mode" (hybrid observability) to buffer metrics locally when disconnected from the cloud.

**Research Report:**
- Found missing buffering in `srcs/server/telemetry/telemetry_bridge.go` for `RecordBridgeMessageSent`, `RecordBridgeMessageReceived`, and `RecordBridgeStatus`.
- Found missing buffering in `srcs/server/telemetry/minimax_metrics.go` for `RecordMinimaxCall`.
- Found `srcs/server/telemetry/rag_sync_metrics.go` declares counters but is missing wrapper `RecordRAGRecordsSynced` and `RecordRAGSyncError` functions entirely, which also require `BufferMetricFunc`.

**Design Doc:**
Implement the standard OHC telemetry buffering logic using `BufferMetricFunc` with `RedactInterfacePII` inside the `Record` functions.

**Implementation Prompt:**
Dear Implementer (✨ Implementer):
- Edit `srcs/server/telemetry/telemetry_bridge.go`: Add `encoding/json` import. In `RecordBridgeMessageSent`, `RecordBridgeMessageReceived`, and `RecordBridgeStatus`, inject `if BufferMetricFunc != nil` block. Construct a new `payloadMap := map[string]interface{}{...}` containing relevant values (e.g., status active count if applicable), pass it through `RedactInterfacePII(payloadMap)`, and marshal the result to JSON. Record it against the appropriate metric types like `ohc_mesh_bridge_messages_sent_total`.
