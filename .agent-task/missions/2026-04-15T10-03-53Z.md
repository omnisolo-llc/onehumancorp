# Title: AutoDream Metrics Naming Standardization

**Problem Statement:**
The Grafana dashboards for Hybrid Telemetry are querying for `autodream_memories_ingested_total` and `autodream_memories_compressed_total`, but the backend OpenTelemetry implementation in `srcs/server/telemetry/telemetry.go` actually exposes these metrics with the standard `ohc_` prefix (`ohc_autodream_memories_ingested_total` and `ohc_autodream_memories_compressed_total`). This mismatch causes empty panels and breaks observability for the memory consolidation pipeline.

**Research Report:**
According to our Hybrid Telemetry Review, the backend code correctly initializes these metrics with the prefix:
```go
AutoDreamMemoriesIngestedCounter, err = m.Int64Counter(
  "ohc_autodream_memories_ingested_total", ...
)
```
However, both `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` and `deploy/helm/ohc/dashboards/hybrid-telemetry.json` reference the unprefixed versions.
Additionally, we need to ensure the dashboard JSON structure is correctly updated across both the docker-compose deployment and the Helm chart to maintain environment parity.

**Design Doc:**
1.  **Dashboard Updates**: Modify the JSON definitions in both `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` and `deploy/helm/ohc/dashboards/hybrid-telemetry.json`.
2.  **Target Panels**: Update the panel targets to use the `ohc_` prefix for the AutoDream memory pipeline metrics.

**Implementation Prompt:**
Implementer Agent, execute the following:
1.  Update the PromQL expressions in `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` to use `ohc_autodream_memories_ingested_total` and `ohc_autodream_memories_compressed_total` instead of their unprefixed versions.
2.  Mirror this exact same change in `deploy/helm/ohc/dashboards/hybrid-telemetry.json`.
3.  Ensure the changes do not break the JSON structure.
