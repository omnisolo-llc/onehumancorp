# AutoDream Data Pipeline Architecture

**Problem Statement**:
Swarm intelligence is fragmented. We need to consolidate past executions, mission outputs, and architectural findings into a long-term Vector DB for autonomous memory recall.

**Research Report**:
We use PostgreSQL. Extending it with `pgvector` provides seamless embedding similarity search.

**Design Doc**:
- Create a background pipeline (`time.Ticker` with `select` loop) that scans completed missions and generates embeddings using the local or cloud LLM.
- Store embeddings in a `memory_embeddings` table. Field type must be `[]byte` in Go for the `vector_embedding` column.

**Implementation Prompt**:
Implement the `AutoDream` background daemon in `srcs/server/memory/autodream.go`. The daemon should process `.agent-task/memory/` and `.agent-task/missions/` items with `status: DONE` and upsert into `vector_embedding` fields. Ensure the daemon's active execution logic is explicitly wired into `srcs/server/main.go`. Use OpenTelemetry to emit `Int64Counter` metrics for processed memories.

**Priority**: P1
**Estimated Scope**: Large
