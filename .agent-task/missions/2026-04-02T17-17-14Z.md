# OHC: The Hybrid Agentic OS Identity - Architectural Evolution

## Problem Statement
The OHC (One Human Corp) platform is evolving its "Hybrid Agentic OS" capabilities to support a more complex autonomous swarm. Currently, agents lack a robust, centralized task orchestration layer capable of distributed state tracking across Multi-Tenant Cloud and Standalone Desktop modes. Additionally, long-term memory consolidation processes (AutoDream) need better handling to ensure the swarm can synthesize continuous insights without overwhelming system resources.

## Research Report
The existing `swarm_tasks` and `Teammate Mesh` implementations are partially available. Tasks utilize `IN_PROGRESS` and `PENDING` states with basic SQLite and Postgres support. The Teammate Mesh already uses Centrifuge for real-time pub/sub, broadcasting `mesh:tasks` messages.
AutoDream currently attempts vector search and consolidation using `pgvector` and an LLM client.
The missing pieces include a robust `UltraPlan` deep-deliberation state machine, advanced background queueing abstraction (to emulate BullMQ/Celery in Go), and a mature distributed locking strategy across modes. The `Shared Task List` must act as the primary interface for the human Orchestrator to decompose requests.

## Design Doc

### 1. Database Schema Additions
To support UltraPlan deliberation cycles and more robust sub-agent orchestration, we need to extend the `swarm_tasks` and related tables:
- **`swarm_ultra_plans`**: Tracks deep-deliberation multi-step plans.
  - `id UUID PRIMARY KEY`
  - `mission_id TEXT`
  - `status TEXT (DELIBERATING, EXECUTING, COMPLETED)`
  - `state_machine JSONB`
- **`swarm_tasks` updates**:
  - Add `parent_plan_id UUID` linking tasks to an UltraPlan.
  - Add `dependencies JSONB` for DAG-like state machine tracking.

### 2. Teammate Mesh Architecture (Phase 2)
The current `TeammateMesh` uses raw WebSockets with Redis, while `CentrifugeNode` provides the `mesh:tasks` broadcasting.
We will unify the Realtime Mesh on Centrifuge:
- **Channel `mesh:ultraplan:<plan_id>`**: For realtime state updates during deep deliberation.
- **State Machine Backend**: Implement a Redis-backed state machine (for Cloud Mode) and an in-memory/SQLite equivalent (for Standalone Mode) using `rueidis` for distributed locks during phase transitions.

### 3. Sub-Agent Background Queuing
Introduce an interface `TaskQueue` that wraps:
- **Cloud Mode**: Redis-based delayed queue using `rueidis` to simulate BullMQ functionality.
- **Standalone Mode**: SQLite-backed polling mechanism.

### 4. AutoDream Architecture (Phase 3)
Architect the data pipelines (e.g. pgvector, LLM embeddings) for OHC's long-term memory consolidation system.
Extend `AutoDreamWorker` with better pgvector schemas and continuous LLM embeddings generation pipeline:
- **`swarm_dream_epochs`**: Track the state of nightly/periodic consolidation runs.
- **Pipeline**: Utilize the existing `SearchTruth` and `InjectTruth` with a new `ConsolidateEpoch(ctx)` workflow that runs semantic clustering before invoking Minimax.
