# Title: Architect and Implement the Shared Task List (Teammate Mesh & AutoDream)

## Problem Statement
The OHC swarm currently lacks a centralized, distributed system for agents to securely coordinate, decompose, and track task execution across the hybrid architecture. Without a "Shared Task List" leveraging our Postgres backend and Redis Pub/Sub (Teammate Mesh), agents cannot effectively orchestrate complex, multi-step workflows.

## Research Report
- Analyzed existing KAIROS orchestration workflows and identified the lack of an execution backend.
- Competitive analysis highlights that Claude Code and Replit Agent struggle with deep multi-step delegation due to lack of a robust state machine.
- Utilizing pgvector for "AutoDream" consolidation ensures long-term multi-agent memory.

## Design Doc
See `docs/architecture/KAIROS_AI_OS_ARCHITECTURE.md` for full context.

**Database Schema (PostgreSQL):**
```sql
CREATE TABLE IF NOT EXISTS shared_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id VARCHAR NOT NULL,
    title VARCHAR NOT NULL,
    description TEXT,
    status VARCHAR NOT NULL DEFAULT 'PENDING',
    agent_id VARCHAR,
    priority VARCHAR NOT NULL DEFAULT 'P2',
    payload JSONB,
    parent_plan_id TEXT,
    dependencies JSONB NOT NULL DEFAULT '[]',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

**Architecture Components:**
1. Phase 1: Shared Task List API endpoints (Create, Update, List, Lock).
2. Phase 2: Teammate Mesh using Centrifuge node integration in `srcs/server/orchestration/centrifuge_hub.go`.
3. Phase 3: AutoDream pipeline for pgvector consolidation in `autodream_memories`.
4. Phase 4: Redis/SQLite background sub-agent queue worker in `srcs/server/orchestration/queue/queue.go`.
