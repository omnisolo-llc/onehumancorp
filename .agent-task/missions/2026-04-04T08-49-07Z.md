# Title: Add Observability Visualization for Task Queue and Synchronization Metrics

## Problem Statement
During a hybrid telemetry review, we identified an observability gap in the existing Grafana dashboards (`hybrid-telemetry.json` and `ohc-hybrid.json`). While the backend OpenTelemetry instrumentation successfully records critical execution data—such as `ohc_task_queue_length`, `ohc_task_processing_latency_seconds`, `sync_completed_count`, `sync_failed_count`, and `ohc.sync.escalations.count`—there are no corresponding panels in the Grafana dashboards to visualize these metrics. This prevents us from conducting bottleneck hunting and analyzing mode-specific throughput and error rates between Cloud-native and Standalone modes.

## Research Report
1. **Current Telemetry State**: `srcs/server/telemetry/telemetry.go` defines multiple metrics critical for evaluating task efficiency and sync stability:
   - `TaskQueueLengthGauge` (`ohc_task_queue_length`)
   - `TaskProcessingLatency` (`ohc_task_processing_latency_seconds`)
   - `SyncCompletedCount` (`sync_completed_count`)
   - `SyncFailedCount` (`sync_failed_count`)
   - `SyncEscalationsCount` (`ohc.sync.escalations.count`)
2. **Dashboard State**: `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` contains panels for HTTP latency, Token Burn Rate, and API Call Rates, but completely lacks task queue and local-to-cloud synchronization insights.
3. **Architectural Need**: Bottleneck hunting between Cloud and Standalone modes requires analyzing queue buildup and processing latencies. Sync escalations must also be monitored closely as they represent conflicts in multi-tenant/standalone resolution.

## Design Doc
1. **Modify `hybrid-telemetry.json`**:
   - Add a Time Series panel for `ohc_task_queue_length` to track queue buildup over time.
   - Add a Time Series panel for P95/P99 `ohc_task_processing_latency_seconds` (using `histogram_quantile(0.95, rate(ohc_task_processing_latency_seconds_bucket[5m]))`).
   - Add a Time Series or Bar Chart panel tracking rates of `sync_completed_count`, `sync_failed_count`, and `ohc.sync.escalations.count`.
2. **Ensure Aesthetic Mandate**: All new panels must align with the existing OHC Visual Excellence Mandate (Premium Glassmorphism styling if applicable to text/HTML panels, and standard dark/transparent Grafana styling for charts as seen in the rest of the dashboard).

## Implementation Prompt
Dear Implementer Agent,
Please update `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` to include three new panels:
1. **Task Queue Length**: A time series panel using the Prometheus query `ohc_task_queue_length`. Position this panel dynamically within the grid.
2. **Task Processing Latency**: A time series panel using `histogram_quantile(0.95, rate(ohc_task_processing_latency_seconds_bucket[5m]))`.
3. **Synchronization Health**: A time series panel visualizing `rate(sync_completed_count[5m])`, `rate(sync_failed_count[5m])`, and `rate(ohc.sync.escalations.count[5m])`.

Ensure the JSON schema remains perfectly valid Grafana configuration format and the panel IDs do not conflict with existing ones. Set the panels' `transparent` property to `true` to match the Glassmorphism aesthetic where appropriate. Verify the JSON is syntactically correct before submitting.
