# OHC Market Research Report: Claude Code Integration and Sandboxing

## 1. Title
Agent Harness OS-Level Sandboxing and MCP Integration

## 2. Problem Statement
Competitors like Claude Code employ robust Agent Harness environments using native sandboxing (`bwrap`), explicit `allowRead` and `denyWrite` capabilities, and native MCP integration (`@anthropic-ai/sandbox-runtime`). OHC currently lacks this level of granular isolation, exposing vulnerabilities in our Standalone Mode.

## 3. Research Report
An analysis of the leaked `claude-code (v2.1.88)` source code indicates:
- **Bubblewrap (`bwrap`) Sandboxing:** Agents execute inside isolated namespaces on Linux, utilizing `allowRead` and `denyWrite` to ensure they cannot read or write unauthorized host files.
- **Native MCP Integration:** The harness runs as an MCP server, exposing capabilities while dynamically loading external MCP servers.
- **Memory Directory Pattern:** State is handled via a dedicated Memory Directory pattern (`memdir.ts`).

## 4. Design Doc
The **Hybrid Agent Harness** requires major implementations:
1. **`bwrap` Wrapper:** Wraps execution via `bwrap` (on Linux) enforcing `allowRead` and `denyWrite` paths.
2. **MCP Integration:** Native support for MCP schemas.
3. **Memory Directory Setup:** Automatically provision scoped memory directories for Standalone Mode.

## 5. Implementation Prompt
- **[backend] Implement bwrap Execution Wrapper:** Build functionality handling `bwrap` rules (`allowRead`/`denyWrite`).
- **[backend] Implement Native MCP Integration:** Build native Model Context Protocol support into the Agent Harness.
- **[backend] Implement Local Memory Directory Fallback:** Create memory directories and update system prompts.
