# Title: Proactive Implementer Growth Improvements: Sovereign-to-Cloud Invite API

## Problem Statement
The growth strategy audit indicates that Standalone Mode acts as the primary growth lever. To facilitate the "Sovereign-to-Cloud Loop", we need an API endpoint that allows Standalone users to generate "Sovereign Invites" for their collaborators, sharing specific agentic outputs and bridging them to the Cloud.

## Research Report
Based on `docs/growth_strategy_audit.md`, increasing the Standalone to Cloud Team conversion rate (currently 18%) requires a Viral Invite Loop. This invite dynamically provisions a cloud context for a shared asset.

## Design Doc
1. Add a `SovereignInvite` struct to track these invitations.
2. Add a `handleSovereignInvites` HTTP handler to support GET (list) and POST (create) operations.
3. Register the route `/api/growth/sovereign-invites` in the server's router.

## Implementation Prompt
1. In `srcs/server/dashboard/handlers_growth.go`, define `SovereignInvite` struct with fields `ID` (string), `InviterID` (string), `AssetID` (string), `Status` (string), and `CreatedAt` (time.Time). Also add `s.sovereignInvites []SovereignInvite` to the Server struct if necessary.
2. Implement `func (s *Server) handleSovereignInvites(w http.ResponseWriter, r *http.Request)` supporting GET and POST. POST should accept `InviterID` and `AssetID`.
3. In `srcs/server/dashboard/server.go`, register `/api/growth/sovereign-invites` to `handleSovereignInvites`.
4. In `srcs/server/dashboard/handlers_growth_test.go`, write tests verifying the creation and retrieval of sovereign invites.
5. Ensure `bazelisk test //...` passes.
