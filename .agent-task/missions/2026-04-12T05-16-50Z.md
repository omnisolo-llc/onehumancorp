# Mission: AutoDream Memory Consolidation Pipeline (KAIROS Phase 3)

## Problem Statement
OHC-SIP mandates that temporary agent scratchpads (`.agent-task/memory/*.yml`) must be consolidated into long-term durable state to enable Swarm Intelligence. Currently, there is no pipeline to process these unstructured memories into semantic vectors.

## Research Report
The KAIROS Master Design (`docs/architecture/kairos/shared_task_list_design.md`) dictates the use of a background worker to embed these logs and store them into `autodream_memories` via `pgvector`. This grants the swarm semantic search capabilities over past operational logic.

## Design Doc
**Architecture Component:** `AutoDream Pipeline`
**Target Path:** `srcs/server/orchestration/autodream.go` & `srcs/server/db/migrations/000008_autodream_memories.up.sql`

**Database Schema:**
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE IF NOT EXISTS autodream_memories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    content TEXT NOT NULL,
    embedding vector(1536), -- Assuming standard LLM embedding size
    source_file VARCHAR NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

**Go Pipeline Logic:**
1. A background watcher reading `.agent-task/memory/*.yml`.
2. A processing loop that parses the YAML content.
3. An embedding step (stubbed for now or connecting to an LLM provider).
4. Insertion into the `autodream_memories` table.

## Implementation Prompt
1. Create the `000008_autodream_memories.up.sql` migration.
2. Define the corresponding struct `AutoDreamMemory` in `srcs/server/orchestration/models.go` (or similar).
3. Create `srcs/server/orchestration/autodream.go` with a `ConsolidateMemories` function that reads from the filesystem and inserts records into the database.
4. Add basic test coverage verifying that the pipeline correctly processes a mock YAML file and creates the expected database entry.
