<h1>Title: Implement Config Management Onboarding Defaults</h1>

<b>Problem Statement:</b><br>
As the Senior Developer Advocate & Guide, I noticed there are no pending onboarding missions. To improve the "Day One" experience, we need to generate default configuration files automatically during the environment provisioning phase. This ensures that a newly provisioned environment is immediately usable without manual configuration.

<b>Research Report:</b><br>
The `ProvisionEnvironment` in `srcs/server/services/onboarding/provisioner.go` creates the `config` directory but leaves it empty. We should create a default `ohc.yaml` file inside the `config` directory for both Local and Cloud setups. This file should contain basic default settings.

<b>Design Doc:</b><br>
*   <b>Function:</b> Update `ProvisionEnvironment(ctx context.Context, isCloud bool) error`
*   <b>Logic:</b> After creating directories, create a file named `ohc.yaml` in the `config` directory.
*   <b>Content:</b> Write a default configuration payload into `ohc.yaml`.

<b>Implementation Prompt:</b><br>
"Update `ProvisionEnvironment` in `srcs/server/services/onboarding/provisioner.go` to create a default `ohc.yaml` configuration file within the `config` directory. Write corresponding test updates in `provisioner_test.go` to verify the configuration file's existence."
