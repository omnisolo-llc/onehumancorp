# Mission: Implement KAIROS AI OS Orchestration Interactive APIs

**Title**: Implement KAIROS AI OS Orchestration Interactive APIs
**Priority**: P1
**Estimated Scope**: Medium

## Problem Statement
The OHC Interactive KAIROS API Playbook outlines interactive endpoints for the KAIROS AI OS Orchestration APIs, specifically focusing on the Teammate Mesh, Shared Task List, and AutoDream integration. The interactive endpoint `/api/mesh/v2/broadcast`, is currently missing from the dashboard API router (`srcs/server/dashboard/server.go`). This endpoint must be implemented to fulfill the API playbook requirements.

## Research Report
- Based on `docs/kairos/interactive_api_playbook.md`, we require the `/api/mesh/v2/broadcast` endpoint.
- `/api/mesh/v2/broadcast` (POST): Expects payload `{"channel": "swarm-events", "data": {"event": "status_update", "status": "IN_PROGRESS"}}`.
- These endpoints need to be added to `srcs/server/dashboard/server.go`.
- For `v2/broadcast`, the `Teammate Mesh` provides the broadcast functionality. We can use the existing `handleMeshBroadcast` as a reference for mTLS SPIFFE validation and how it interacts with the hub/mesh.

## Design Doc
1.  **API Router (`srcs/server/dashboard/server.go`)**:
    -   Add `mux.HandleFunc("/api/mesh/v2/broadcast", auth.RequireRole("system", server.handleMeshV2Broadcast))` alongside the other mesh endpoints.
2.  **API Handlers**:
    -   `handleMeshV2Broadcast` handles POST requests, parses JSON payload with `channel` and `data`. It must replicate the mTLS SPIFFE validation found in `handleMeshBroadcast`. It should then broadcast the data to the provided channel using the existing broadcast mechanism employed by `handleMeshBroadcast`, returning `200 OK`.
