# Title: Implement Shared Task List State Machine

## Problem Statement
The KAIROS orchestrator needs a robust way to distribute tasks to swarm agents without race conditions.

## Research Report
Based on the KAIROS Premium Design Document, the system must support both Cloud-Native (PostgreSQL) and Standalone (SQLite) modes. `FOR UPDATE SKIP LOCKED` is optimal for Postgres pod concurrency, while SQLite can fallback to application-level locks.

## Design Doc
See `docs/architecture/KAIROS_HYBRID_ORCHESTRATION_FINAL.md`. Key components:
- `shared_tasks` table with state (PENDING, IN_PROGRESS, COMPLETED, FAILED, BLOCKED).
- `shared_task_dependencies` for DAG tracking.
- `ClaimTask` API endpoint using `SELECT ... FOR UPDATE SKIP LOCKED`.

## Implementation Prompt
Implement the Shared Task List database schema in `srcs/server/db/migrations/` and the `ClaimTask` logic in the Go backend. Ensure the query uses `FOR UPDATE SKIP LOCKED` for PostgreSQL and standard updates for SQLite via the DB provider. Write tests to verify concurrent task claiming.
