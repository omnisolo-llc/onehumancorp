# Title: Integrate Hybrid Vector RAG MCP Server

## Problem Statement
The OHC Swarm Intelligence Protocol dictates that all agents share memory. In Cloud-Native mode, memory is embedded and persisted via PostgreSQL's `pgvector` in the `autodream_memories` table. In Standalone mode, memory degrades gracefully to local SQLite text search. Agents need a unified way to perform semantic search regardless of the active database backend.

## Research Report
- **Market Context**: Most RAG tools are hardcoded to a specific vector DB (Pinecone, pgvector) or use separate local tools. Replit Agent uses pure cloud.
- **OHC Requirement**: A "Hybrid Vector RAG MCP Proxy" that dynamically queries `pgvector` when `OHC_MULTITENANT` is active, and falls back to SQLite text/JSON search in `OHC_STANDALONE`.
- **Tooling Discovery**: A dedicated MCP adapter wrapping the internal database provider (`db.Provider`) to abstract vector queries.
- **Security & Multi-Tenancy**: The query must be strictly scoped to the tenant's `OrganizationID` in Cloud mode.

## Design Doc
- **Module Path**: `srcs/server/tools/vectorragmcp`
- **Architecture**: Expose a `semantic_search` tool that delegates to `dbWrapper.Provider().SearchMemories()`.
