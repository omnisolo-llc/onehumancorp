# Title: Implement Hybrid MCP RAG Protocol (Offline-to-Cloud State Sync)

**Problem Statement:**
Competitors like Claude Code, OpenClaw, and Replit Agent force users into a binary choice: trade privacy for cloud-scale execution, or trade scalability for local privacy. OHC needs to bridge this divide by synchronizing a local SQLite RAG state to the cloud Postgres orchestration engine via OHC-SIP, allowing private execution on sensitive datasets with cloud escalation for parallel computation.

**Research Report:**
A comprehensive audit of the global Agentic OS market reveals an over-reliance on pure cloud dependency or strictly siloed local states among competitors. OHC's Hybrid Architecture (OHC-HA) provides a unique advantage.

| Feature Area | Claude Code | OpenClaw | Replit Agent | **OHC Vision (OHC-HA)** |
| :--- | :--- | :--- | :--- | :--- |
| **Execution Mode** | CLI / Local-First | Pure Cloud Orchestration | Cloud IDE / Ephemeral | **True Hybrid** (K8s Cloud & Standalone Local) |
| **Data Sovereignty** | Local files (`CLAUDE.md`) | Provider-locked cloud | Replit Cloud Storage | **Postgres & SQLite SIPDB** Local/Cloud Sync |
| **Tool Execution** | Standard MCP | Custom Plugins | Platform-native | **Universal MCP Mesh** native to K8s/Bazel |
| **Resilience / Offline**| Requires API | Fails Offline | Fails Offline | **Graceful Degradation** (Local LLM/SQLite fallback) |

The most disruptive opportunity is the **Offline-to-Cloud State Sync for Swarm Memories**. This "Hybrid MCP RAG Protocol" enables highly sensitive datasets to be processed locally (Standalone Desktop mode) and seamlessly escalated to the multi-tenant K8s cloud for generalized tasks. Only required context payloads are synced into the cloud's `agent_missions` table.

**Architecture Overview:**
1.  **Local RAG Engine:** A local SQLite-backed mechanism for vector similarity search or full-text fallback.
2.  **Sync Daemon:** A background process within the Standalone Desktop that monitors local mission state.
3.  **Cloud Ingestion API:** A secured endpoint on the Cloud Server to receive sanitized context payloads and insert them into the `agent_missions` tracking table.
4.  **Mesh Broadcasting:** Task updates are published via the Teammate Mesh (`CentrifugeNode.PublishTaskBroadcast`).

**Implementation Prompt:**
As an Implementer agent, execute the following to realize the Hybrid MCP RAG Protocol:
1.  **Sync Daemon:** Create a Go background worker in `srcs/server/orchestration/sync_daemon.go` that monitors local SQLite tasks.
2.  **Cloud API:** Add a new endpoint `POST /api/orchestration/sync` in the API server to receive synced payloads.
3.  **Database Integration:** Ensure the endpoint injects data into the `agent_missions` Postgres table and publishes to the Teammate Mesh.
4.  **Tests:** Add comprehensive unit tests in `srcs/server/orchestration/sync_daemon_test.go` achieving >90% coverage.
5.  **Telemetry:** Expose OpenTelemetry metrics for sync latency and payload size.
