# Title: Implement KAIROS Shared Task List & Teammate Mesh

# Problem Statement:
The OHC Hybrid Agentic OS requires a deeply integrated Teammate Mesh and Shared Task List to orchestrate autonomous agents. Currently, there is a lack of formal implementation bridging the Cloud-Native Postgres state and the Realtime Redis Pub/Sub mesh.

# Research Report:
Market analysis shows that multi-agent systems fail without a centralized, lock-safe coordination layer. Competitors suffer from race conditions and stale memory. By implementing the KAIROS Orchestration design using `FOR UPDATE SKIP LOCKED` in Postgres and Redis Pub/Sub for realtime events, we achieve robust Swarm Intelligence.

# Design Doc:
The detailed design is located in `docs/architecture/kairos_ai_os_core_features.md`. It includes:
1.  **PostgreSQL schemas** for `ohc_tasks.mission_queue`, `ohc_memory.autodream_vectors`, and `ohc_tasks.sub_agent_queue`.
2.  **Sequence diagram** for task claiming using `FOR UPDATE SKIP LOCKED`.
3.  **API Contract** for the Teammate Mesh broadcast endpoint (`POST /api/mesh/broadcast`).

# Implementation Prompt:
You are an Implementer agent. Implement the Shared Task List and Teammate Mesh based verbatim on `docs/architecture/kairos_ai_os_core_features.md`.
1.  Create the database migrations (e.g. in `db/migrations/`) for:
    *   `ohc_tasks.mission_queue`
    *   `ohc_memory.autodream_vectors` (ensure `pgvector` extension is enabled)
    *   `ohc_tasks.sub_agent_queue`
    Ensure schemas exactly match the Design Doc.
2.  Implement the Redis Pub/Sub broadcasting service endpoint in Go (`POST /api/mesh/broadcast`). The handler should accept the exact JSON payload defined in the design doc and broadcast it to the appropriate Redis channel.
3.  Implement the task claiming mechanism in Go, executing the `SELECT ... FOR UPDATE SKIP LOCKED` query and returning the claimed mission.
4.  Write unit and integration tests covering the distributed lock claiming mechanism and the broadcast endpoint. All tests must pass.
