# Title: Implement Elastic Swarm Bursting

## Problem Statement
When local compute (e.g., M-series Apple Silicon) is saturated by an intensive agent task in Standalone Mode, agents cannot seamlessly hand off tasks to the OHC Headless Cloud API. There is no seamless degradation path, leaving agents constrained to their local execution environment.

## Research Report
A competitive audit of the "Hybrid Agentic OS" capabilities reveals that competitors (Claude Code, Replit Agent, OpenClaw) fail to provide a seamless degradation path between purely local and purely cloud execution. OHC's unique Hybrid Architecture can support "Elastic Swarm Bursting", allowing Standalone OHC clients to securely migrate the `agent_missions` payload over secure gRPC to the OHC Headless Cloud API when local resources are constrained. To support this secure Swarm Bursting, agents must seamlessly exchange short-lived JWTs via a zero-trust SPIFFE/SPIRE integration when moving from the local SQLite environment to the Cloud Postgres environment. Additionally, the Universal MCP Mesh must be extended to support local-to-cloud proxying via reverse tunnels.

## Design Doc
- **Database / Schema:** Extend the `SIPDB` to support a `status = 'BURSTING'` state in the `agent_missions` payload.
- **Authentication:** Integrate SPIFFE/SPIRE for zero-trust identity and exchange of short-lived JWTs between the local SQLite environment and Cloud Postgres.
- **MCP Proxy:** Extend the Universal MCP Mesh with reverse-tunnels to allow cloud agents to securely utilize MCP tools running on the user's Standalone Desktop.
- **Architecture Flow:** Evaluate local compute -> if insufficient -> initiate Swarm Bursting -> SPIFFE Auth -> OHC Headless Cloud API -> Execute via Cloud Postgres SIPDB -> return result via gRPC stream.

## Implementation Prompt

1. Update the `SIPDB` schemas and protobufs in `srcs/proto/` and `srcs/server/db/` to add `status = 'BURSTING'` to `agent_missions`.
