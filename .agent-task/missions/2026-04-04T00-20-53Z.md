# 🔬 Mission: Implement Shared Task List, Teammate Mesh APIs, and autoDream Pipelines

## Title
Architect and Implement Shared Task List, Teammate Mesh, and autoDream Data Pipelines for OHC Hybrid OS.

## Problem Statement
The One Human Corp (OHC) Swarm requires a robust underlying infrastructure to coordinate. Currently, there is a gap in distributed task tracking (Shared Task List), real-time inter-agent communication (Teammate Mesh), and long-term memory consolidation (autoDream). Without these, complex feature decomposition, autonomous execution, and memory persistence across the Hybrid Agentic OS cannot scale reliably.

## Research Report
- **Market Reality**: Competitors rely on rigid orchestrators (e.g., Temporal, Airflow). OHC requires a dynamic, decentralized Swarm Intelligence Protocol (OHC-SIP) capable of running in both Cloud-Native (K8s, Postgres, Redis) and Standalone (SQLite) modes.
- **Coordination Mechanisms**:
  - Distributed locks are essential for preventing race conditions in Teammate Mesh.
  - Pub/Sub patterns (Redis for Cloud, in-memory/SQLite events for Standalone) are best for the Mailbox/Mesh.
- **Memory Consolidation**: "autoDream" requires vector similarity search to synthesize findings over time. pgvector is standard for Postgres, but a fallback or simplified representation is needed for SQLite.

## Design Doc
1. **Shared Task List (Database Schema)**
   - `tasks` table:
     - `id` (UUID or integer, depending on mode)
     - `parent_id` (Self-referencing for sub-tasks)
     - `title`, `description`
     - `status` (PENDING, IN_PROGRESS, BLOCKED, DONE)
     - `assigned_agent_id`
     - `metadata` (JSONB/TEXT for context, inputs, outputs)
     - `created_at`, `updated_at`
   - In Cloud Mode: Use PostgreSQL schemas with tenant-aware `org_id` filtering.
   - In Standalone Mode: Use SQLite with `json_extract()` compatibility for `metadata`.

2. **Teammate Mesh APIs**
   - **Protocol**: Real-time communication layer over Redis Pub/Sub (Cloud) or WebSocket/local channels (Standalone).
   - **Endpoints**:
     - `POST /api/mesh/broadcast`: Broadcast an event to all agents in a specific swarm category.
     - `POST /api/mesh/direct`: Send a direct message/payload to a specific agent's mailbox.
     - `GET /api/mesh/mailbox`: Poll or connect via WS to receive messages.
   - **State Machine**: Track dependency states via a robust locking mechanism (Redis Redlock for Cloud, SQLite file locks for Standalone).

3. **autoDream Data Pipelines**
   - **Architecture**: A periodic background worker that processes DONE tasks and synthesizes them into long-term vector embeddings.
   - **Storage**:
     - Cloud: PostgreSQL + `pgvector` for embedding storage.
     - Sync: Use `telemetry.RedactPII` for any data synchronized from Standalone to Cloud.
   - **Interface**: Expose `orchestration.MinimaxClient` methods for generating embeddings from the synthesized markdown summaries.
