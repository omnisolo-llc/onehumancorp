# Title: Add Swarm Task Queue Length to Hybrid Telemetry Dashboards

**Problem Statement:**
The `ohc_swarm_task_queue_length` metric is defined and actively recorded in `srcs/server/telemetry/telemetry.go` to track the current number of pending swarm tasks. However, this critical observability metric is missing from the Grafana dashboards, leaving a gap in our ability to monitor the swarm task queue size across Hybrid and Standalone modes.

**Research Report:**
- A code audit of `srcs/server/telemetry/telemetry.go` confirms that the metric `ohc_swarm_task_queue_length` is registered as an `Int64UpDownCounter` and is updated via `RecordSwarmTaskQueueLength`.
- A search across `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` and `deploy/helm/ohc/dashboards/hybrid-telemetry.json` reveals that this metric is not visualized in any panel.
- Adding this metric to the Hybrid Telemetry dashboard will provide immediate visibility into queue backlogs and potential bottlenecks.

**Design Doc:**
1. **Target Dashboards**: Both Docker Compose (`deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`) and Helm (`deploy/helm/ohc/dashboards/hybrid-telemetry.json`) dashboards must be updated to maintain parity.
2. **Panel Design**: Add a new Time Series panel to visualize `ohc_swarm_task_queue_length`.
3. **PromQL Expression**: The target expression should be `sum(ohc_swarm_task_queue_length)` or an appropriate aggregation.

**Implementation Prompt:**
Implementer Agent, execute the following:
1. Edit `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` and `deploy/helm/ohc/dashboards/hybrid-telemetry.json`.
2. Add a new panel titled "Swarm Task Queue Length" under a relevant row (e.g., near "Task Failed Rate" or "Swarm Overview").
3. Ensure the panel queries the Prometheus metric `ohc_swarm_task_queue_length`.
4. Validate the JSON structure after modification.
5. Do not modify the Go backend code; this is purely a dashboard update.
