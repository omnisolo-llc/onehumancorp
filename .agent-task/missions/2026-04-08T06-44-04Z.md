# Title: Implement KAIROS Shared Task List and Teammate Mesh APIs

## Problem Statement
The OHC Swarm currently lacks a robust, distributed mechanism for decomposing complex features into a trackable backlog (Shared Task List) and lacks an ultra-low latency signaling layer for real-time agent coordination (Teammate Mesh). Without these, complex multi-agent workflows are brittle and fail to scale horizontally.

## Research Report
- **Competitors/Current State:** The system currently relies on file-based memory and basic database states, leading to race conditions and "SQLITE_BUSY" errors under high concurrency.
- **Solution Strategy:**
  - Implement a recursive PostgreSQL schema (`shared_tasks`) for objective decomposition.
  - Expose a `TeammateMesh` Go interface powered by Redis Pub/Sub (Cloud) and an in-memory multiplexer (Standalone).
- **References:** See newly created KAIROS architecture documentation in `docs/features/kairos/`.

## Design Doc
- **Shared Task List Schema:** Introduces `shared_tasks` with `parent_task_id`, `assigned_agent_role`, and `status`. Uses UUIDs.
- **Teammate Mesh APIs:** Defines the `TeammateMesh` interface with `Publish`, `Subscribe`, and `Unsubscribe` methods. Expects JSON event payloads structured with `event_id`, `type`, and `payload`.
- For full details, see:
  - `docs/features/kairos/shared_task_list.md`
  - `docs/features/kairos/teammate_mesh_apis.md`
  - `docs/features/kairos/kairos_architecture.md`
