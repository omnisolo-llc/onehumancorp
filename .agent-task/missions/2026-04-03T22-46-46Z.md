# Shared Task List and Teammate Mesh Coordination

## Problem Statement
The KAIROS Orchestrator needs to implement the Shared Task List, Teammate Mesh APIs, and AutoDream Vector Pipelines to enable swarm intelligence and asynchronous orchestration within the OHC platform. Complex architectural changes like these must be broken down and delegated across the agent team for parallel execution.

## Research Report
The existing architecture supports `Hub` coordination (`srcs/server/orchestration/hub.go`) and persistent meeting rooms. However, to execute the "Execution Playbook" (Master Loop: Think → Act → Observe → Decide) defined in the KAIROS Orchestrator spec, we require discrete database designs and sequence diagrams to formally delegate the task execution logic to the Sub-Agents via the Teammate Mesh. The Teammate Mesh requires realtime APIs (e.g., via Redis Pub/Sub or gRPC) to track State Machine transitions. The AutoDream vector pipeline is needed for long-term memory consolidation of these actions.

## Design Doc
### Architecture
1. **Shared Task List (Database Schema)**
   - Introduce `orchestration_tasks` table to track task delegation, status (PENDING, IN_PROGRESS, DONE, BLOCKED), owner, and priority.
   - Introduce `teammate_mesh_logs` for auditability of realtime Pub/Sub messages.
   - Target schemas must support both PostgreSQL (Cloud) and SQLite (Standalone).
2. **Teammate Mesh API**
   - Extend `Hub` interface to include `PublishTeammateMesh(channel string, payload []byte)`.
   - Implement `RedisTeammateMesh` utilizing `go-redis` for multi-tenant cloud deployments.
   - Implement `LocalTeammateMesh` utilizing Go channels for standalone deployments.
3. **AutoDream Data Pipeline**
   - Define the `AutoDream` consolidation worker that polls `teammate_mesh_logs`.
   - Utilize Minimax Embeddings API to generate vectors.
   - Persist findings into a `pgvector` compatible table `swarm_memory_embeddings` (with a local JSON/blob fallback for SQLite).
4. **Sequence Diagram**
   - KAIROS -> Database: Create Shared Tasks.
   - Database -> KAIROS: Return Task IDs.
   - KAIROS -> Teammate Mesh: Publish Task Assignment to Sub-Agents.
   - Sub-Agents -> Teammate Mesh: Acknowledge execution state.
   - AutoDream Worker -> Database: Poll completed tasks, generate vectors, save context.
