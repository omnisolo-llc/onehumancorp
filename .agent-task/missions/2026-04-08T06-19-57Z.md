# Problem Statement
The OHC platform lacks a central "KAIROS" orchestrator for the Swarm. We need to define the structural and aesthetic vision for the OHC "Hybrid Agentic OS", including decomposing complex feature requests into a shared task list for the agent team, architecting the Teammate Mesh APIs for realtime communication, and AutoDream pipelines for long-term memory.

# Research Report
- Based on `README.md` and context, OHC operates in a "Hybrid Architecture" (`OHC-HA`). Database persistence relies on PostgreSQL for Cloud-Native mode and SQLite for Standalone Desktop mode.
- The Swarm is powered by the KAIROS Orchestration engine which maintains stability via three core pillars: Distributed State Machine Tracker, Sub-Agent Queue, and AutoDream Pipeline.
- The "Shared Task List" feature requires a durable database schema (`shared_tasks`) and queuing logic to track agent tasks and decompose features.
- Teammate Mesh requires realtime APIs (e.g., Redis Pub/Sub channels) for agent coordination.
- AutoDream memory consolidation requires data pipelines (pgvector, LLM embeddings) with graceful degradation to SQLite in standalone mode.

# Design Doc
- **Phase 1 (UltraPlan/Decomposition)**: Backend database designs for the "Shared Task List" feature.
  - Create table `shared_tasks` with fields: `id`, `organization_id`, `parent_plan_id`, `title`, `description`, `status` (default 'PENDING'), `assigned_agent_id`, `dependencies` (JSONB), `created_at`, `updated_at`.
  - Use `FOR UPDATE SKIP LOCKED` in Postgres and application-level mutexes for SQLite when claiming tasks.
- **Phase 2 (Orchestration)**: Realtime Teammate Mesh APIs.
  - Agents communicate via production Redis Pub/Sub channels. Use distributed Redis locks for Git-Lock coordination before modifying files.
  - Implement scalable background queuing logic (e.g., BullMQ, Celery or Postgres SKIP LOCKED queues) to spawn isolated sub-agents.
  - Track agent states using a Distributed State Machine.
- **Phase 3 (autoDream)**: AutoDream Data Pipelines for OHC's long-term memory consolidation.
  - Create table `autodream_memories` with fields: `id`, `organization_id`, `agent_id`, `content`, `embedding` (vector(1536) in Postgres, text/JSON blob in SQLite), `source_type`, `created_at`.
  - Asynchronously consolidate ephemeral session contexts, embed via `srcs/server/agents/local/llm.go`, and upsert to `autodream_memories`.
- **Phase 4 (Finalize)**: Submit a premium Design Doc detailing OHC's implementation.
