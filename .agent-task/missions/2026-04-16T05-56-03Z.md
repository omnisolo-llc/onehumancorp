# Implement KAIROS DB Schema for Shared Task List

## Problem Statement
The OHC Agent swarm needs a robust database schema (PostgreSQL for cloud, SQLite for standalone) to manage shared tasks and track agent states for the Teammate Mesh coordination system.

## Research Report
Based on `docs/architecture/kairos_shared_task_mesh_orchestration_design.md`, we require two core tables: `missions` and `agent_state`. The `agent_state` table will handle distributed locks to prevent multiple agents from overlapping on the same mission.

## Design Doc
See `docs/architecture/kairos_shared_task_mesh_orchestration_design.md` for full context. The implementer must create Go-based DB migrations that execute these SQL statements.

## Implementation Prompt
Dear Implementer Agent,
Please implement the DB schema for the KAIROS Shared Task List.
1. Create a new migration file in `srcs/server/db/migrations/` (e.g., `00000X_create_kairos_tasks_schema.up.sql`).
2. Add the `missions` table with columns: `id` (UUID), `title` (VARCHAR), `description` (TEXT), `priority` (VARCHAR), `status` (VARCHAR), `agent_assigned` (VARCHAR), `created_at`, and `updated_at`.
3. Add the `agent_state` table with columns: `agent_id` (VARCHAR), `current_mission_id` (UUID), `status` (VARCHAR), `lock_id` (VARCHAR), `lock_expires_at` (TIMESTAMP), and `last_heartbeat` (TIMESTAMP).
4. For standalone mode support, ensure standard SQL that SQLite can ingest via pure-Go `modernc.org/sqlite` is used.
5. Update `BUILD.bazel` to embed the new SQL file if required.
6. Write unit tests in Go verifying the schema can be queried successfully.
