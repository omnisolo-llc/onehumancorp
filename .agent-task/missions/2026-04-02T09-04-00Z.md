# Title: Implement the "Shared Task List" and Teammate Mesh Coordination System

## Problem Statement
OHC agents currently lack a centralized, highly-available, and distributed state machine for coordinating complex decomposed tasks. To act as a true swarm under the OHC Hybrid Architecture, agents need a robust shared task queue that supports task dependencies, state tracking (Pending, In-Progress, Blocked, Done), and real-time state synchronization across both multi-tenant cloud and local standalone nodes.

## Research Report
To implement the KAIROS Orchestrator's vision, we require a system that handles deep-deliberation cycles and complex architectural changes.
- **Competitor Analysis**: Tools like Temporal or BullMQ offer robust distributed queues, but introducing massive heavy external dependencies violates OHC's Standalone Desktop Mode constraint (low resource consumption, graceful degradation without Redis).
- **Hybrid Approach**: We must use our existing consistency boundaries. A PostgreSQL (Cloud) / SQLite (Standalone) backed `agent_tasks` table will act as the durable state machine.
- **Teammate Mesh**: To ensure real-time collaboration without polling, we will utilize Redis Pub/Sub channels in Cloud mode, gracefully degrading to a local in-memory event bus (e.g., Go channels) in Standalone mode.
- **Coordination & Locking**: To prevent "split-brain" agent execution, task checkout must be gated by distributed locks (Redis in Cloud, DB-level locks in Standalone).

## Design Doc
**1. Database Schema (`agent_tasks`)**
Must be implemented in both PostgreSQL and SQLite (via `db.Provider`).
- `id` (UUID / String)
- `mission_id` (String - links to parent mission)
- `parent_task_id` (String - for sub-tasks)
- `title` (String)
- `description` (Text)
- `status` (Enum/String: PENDING, IN_PROGRESS, BLOCKED, COMPLETED, FAILED)
- `assigned_agent_id` (String - nullable)
- `dependencies` (JSON - list of task IDs that must be completed first)
- `created_at` (Timestamp)
- `updated_at` (Timestamp)

**2. Teammate Mesh API Architecture**
- **Transport**: Build upon the existing orchestration hub (`srcs/server/orchestration/hub.go`). Expand the realtime capabilities to include a `/api/swarm/tasks/stream` WebSocket/gRPC endpoint.
- **Pub/Sub Channels**:
    - `swarm:tasks:updates` - Broadcasts state changes.
    - `swarm:coordination:locks` - Broadcasts lock acquisitions.

**3. State Machine & Sub-Agent Orchestration**
- **KAIROS Decomposer**: A background worker (using standard Go goroutines + locking) that reads newly created `missions` and decomposes them into `agent_tasks`.
- **Checkout Logic**:
  ```go
  // Pseudocode for task checkout
  func CheckoutTask(agentID string) (*Task, error) {
      // 1. Check Redis Lock / SQLite DB lock
      // 2. Find PENDING task where all dependencies are COMPLETED
      // 3. Update status to IN_PROGRESS, assign to agentID
      // 4. Publish to Teammate Mesh
  }
  ```
