# Omni-Context Sub-agent Routing

**Priority:** P0
**Estimated Scope:** Medium

## Problem Statement
Current agent OS architectures (like Claude Code and Replit Agent) suffer from context latency and grounding drift because sub-agents must explicitly fetch project rules (e.g., `AGENTS.md`, `CLAUDE.md`) at runtime using file system tools. This increases time-to-first-token, inflates inference costs, and risks task drift if the agent fails to fetch the correct files.

## Research Report
The market audit (documented in `RESEARCH_REPORT_OMNI_CONTEXT.md`) revealed that pre-injecting global project context directly into the sub-agent prompt payload is a high-value "Blue Ocean" disruption. By leveraging the Swarm Intelligence Protocol (OHC-SIP) and the existing `agent_missions` table, OHC can eliminate tool-call latency for grounding, achieving perfect architectural alignment deterministically.

## Design Doc
1. **Context Injector Mechanism:** Modify the logic that creates new missions (e.g., `DelegateMission` or equivalent in `srcs/server/orchestration/sip.go` or `tasks.go`).
2. **Payload Augmentation:** When a mission is created, the system should synchronously scan the repository root for key files (`AGENTS.md`, `CLAUDE.md`, etc.).
3. **DB Injection:** The contents of these files should be appended to the mission `payload` blob under a clear delimiter, such as `[SYSTEM GROUNDING]`.
4. **Data Layer Verification:** Ensure this payload is correctly serialized into the `agent_missions` table (both SQLite and Postgres implementations) without corrupting existing JSON structures if applicable.

## Implementation Prompt
**Role:** Implementer
**Task:** Build Omni-Context Routing into the Orchestrator.

1. **Locate Delegation Logic:** Open `srcs/server/orchestration/sip.go` (or `tasks.go`). Find where new records are inserted into the `agent_missions` table.
2. **Implement File Scanner:** Add a utility function to safely read `AGENTS.md` and `CLAUDE_OHC.md` from the project root. Handle cases where these files might not exist gracefully.
3. **Modify Payload:** Before the payload string/JSON is written to the database, append the file contents under a header:
   ```
   [SYSTEM GROUNDING]
   <contents of AGENTS.md>
   ```
4. **Testing:** Write unit tests demonstrating that when a mission is created, the resulting payload contains the file text. Ensure you test the case where the file is missing to verify graceful degradation.
5. **Database Updates:** If necessary, verify no column size limits are breached in PostgreSQL or SQLite.
6. **Execute Tests:** Run `bazelisk test //srcs/server/orchestration/...` to confirm everything works.
