# Title: Realtime Teammate Mesh APIs - KAIROS Orchestration

## Problem Statement
The OHC Hybrid Agentic OS requires agents to collaborate seamlessly across boundaries. Currently, the Teammate Mesh lacks a robust API for the KAIROS Orchestrator to notify agents about statemachine transitions (e.g., Task ASSIGNED, Task COMPLETED). We need to architect the Realtime Teammate Mesh APIs (Phase 2) so other feature agents can implement them in production, supporting both Redis Pub/Sub for the Cloud-Native Mode and lightweight alternatives for the Standalone Mode.

## Research Report
- Current `mesh.go` handles basic routing but lacks dedicated API endpoints for state machine transition broadcasts.
- The `hub.go` could potentially be reused or extended for this purpose.
- Standalone mode relies on SQLite, requiring long-polling or simplified event channels instead of Redis.

## Design Doc
1. **API Contracts**:
    - Define a new interface `TransitionBroadcaster` with methods like `BroadcastTaskTransition(ctx, taskID, oldStatus, newStatus)`.
    - Create HTTP/gRPC endpoints or simple in-memory Go channels based on deployment mode (`OHC_MULTITENANT`).
2. **Architecture Diagram**:
    ```mermaid
    sequenceDiagram
        participant TaskOrchestrator
        participant StateMachine
        participant TeammateMesh
        participant WorkerAgent

        TaskOrchestrator->>StateMachine: ClaimTask(task-1)
        StateMachine-->>TaskOrchestrator: Status: ASSIGNED
        TaskOrchestrator->>TeammateMesh: BroadcastTaskTransition(task-1, PENDING, ASSIGNED)
        TeammateMesh-->>WorkerAgent: Notify(task-1, ASSIGNED)
    ```
