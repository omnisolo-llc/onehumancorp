# Title: Implement KAIROS Orchestration Core APIs (Shared Task List, Teammate Mesh, AutoDream)

## Problem Statement
The OHC Swarm requires a robust KAIROS Orchestrator to decompose high-level human directives into actionable DAGs, orchestrate them via a sub-millisecond realtime mesh, and consolidate learnings into long-term vector memory. Currently, the design exists but implementation of the core Go interfaces and PostgreSQL migrations is incomplete.

## Research Report
Based on a comprehensive review of `KAIROS_ORCHESTRATOR_DESIGN.md` and OHC Core Values:
- The `Shared Task List` must use `swarm_tasks` and `state_machine_transitions`.
- `Teammate Mesh` requires `MeshTransport` interface in `srcs/server/orchestration/hub.go`.
- `AutoDream` requires vector embeddings in `consolidated_memory` using pgvector.
- The system must degrade gracefully to SQLite and `MemoryMeshTransport`.

## Design Doc
See `docs/KAIROS_PREMIUM_DESIGN.md` for the complete aesthetic and architectural blueprint.
- Phase 1: `swarm_tasks` implementation with `FOR UPDATE SKIP LOCKED`.
- Phase 2: `RedisMeshTransport` mapped to `mesh:tasks` and `mesh:coordination`.
- Phase 3: `AutoDreamPipeline` reading from `.agent-task/memory/` and writing to `consolidated_memory`.

## Implementation Prompt
1. Create `srcs/server/db/migrations/033_kairos_core.sql` to define `swarm_tasks`, `state_machine_transitions`, and `consolidated_memory` tables with pgvector schema as outlined in `docs/KAIROS_ORCHESTRATOR_DESIGN.md`.
2. Implement `MeshTransport` interface in `srcs/server/orchestration/hub.go` with methods `Publish(channel, msg)`, `Subscribe(channel)`. Create `RedisMeshTransport` and `MemoryMeshTransport` structs.
3. Implement `AutoDreamPipeline` in `srcs/server/agents/autodream.go` to process `.agent-task/memory/` files using `srcs/server/agents/local/llm.go` for embeddings.
4. Ensure 100% test coverage using Bazelisk (`~/go/bin/bazelisk test //srcs/server/orchestration/...`).
5. All new functions must support graceful degradation using `pool.IsSQLite()`.
