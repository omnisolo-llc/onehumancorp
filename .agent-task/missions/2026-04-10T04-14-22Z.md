# Title: Shared Task List - Update Teammate Mesh APIs for Task Hierarchy

## Problem Statement
The OHC KAIROS Orchestrator requires a robust task decomposition mechanism to support complex multi-agent workflows. The database schema already supports plan hierarchies via the `parent_plan_id` column added in migration `025_kairos_dag_deps.sql`. However, the real-time Teammate Mesh APIs (specifically the `TaskManager`) fail to properly utilize this schema. The `CreateTaskWithPlan` function signature lacks the `parent_plan_id` argument, and the internal SQL queries attempt to return `parent_plan_id` without ever inserting it. We need to update the Go APIs to expose this hierarchy data to the Teammate Mesh.

## Research Report
The existing `shared_tasks` table is modified in `srcs/server/db/migrations/025_kairos_dag_deps.sql` to include `parent_plan_id`. The Go codebase in `srcs/server/orchestration/tasks.go` contains a `TaskManager` struct with methods like `CreateTaskWithPlan`. However, `CreateTaskWithPlan` currently has the signature `func (tm *TaskManager) CreateTaskWithPlan(ctx context.Context, organizationID string, dependencies []string, title, description, priority string) (*SharedTask, error)`, omitting the actual `parentPlanID` argument required to properly nest tasks in the hierarchy. Furthermore, the `INSERT INTO shared_tasks` SQL strings try to insert `parent_plan_id` by calling `COALESCE(parent_plan_id, '')` in the `RETURNING` clause, but it's not present in the `VALUES` clause or function arguments.

## Design Doc
1.  **API Update**: Update the `CreateTaskWithPlan` function signature in `srcs/server/orchestration/tasks.go` to accept `parentPlanID string`.
2.  **SQL Query Update**: Update the `INSERT` statements in `CreateTaskWithPlan` to include `parent_plan_id` in the `INSERT` and `VALUES` clauses, mapping the new `parentPlanID` argument to the corresponding parameterized value (`$3` or appropriate index) for both PostgreSQL and SQLite branches.
3.  **Test Coverage**: Update `srcs/server/orchestration/tasks_test.go` to cover `CreateTaskWithPlan` functionality, specifically verifying that the `parentPlanID` is correctly stored and retrieved.
