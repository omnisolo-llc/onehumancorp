**Title**: Implement Deliberation State Machine and Teammate Mesh Integration

**Problem Statement**:
While the shared task list provides basic state transitions, OHC requires a robust deliberation state machine to manage deep-deliberation cycles for complex architectural changes. These deliberation cycles must be tracked via distributed locks and broadcast their progress over the Teammate Mesh.

**Research Report**:
- Current state management in orchestration lacks integration with the `Teammate Mesh` for real-time progress broadcasting.
- Task status updates update the DB but do not emit `TASK_DECOMPOSED` or `DELIBERATION_STEP` events.
- We need the system to push mesh events reliably upon state transitions to achieve the "Shared Task List updated and coordination messages sent" operational requirement.

**Design Doc**:
1. Locate orchestration state machine update logic.
2. Inject the `MeshClient` (Teammate Mesh).
3. After successfully updating the database, construct a `MeshEvent` payload containing the status delta.
4. Broadcast this event asynchronously (using a goroutine) to the `orchestration.tasks` channel.

**Implementation Prompt**:
- Locate the state update logic for tasks (e.g. `srcs/server/orchestration/task_orchestrator.go`).
- Add the mesh client to the struct handling the updates.
- Add a fire-and-forget goroutine `go func() { ... }()` that constructs a JSON payload conforming to the Teammate Mesh API contract (action: `DELIBERATION_STEP`, status: `newStatus`).
- Send this payload via the `MeshClient.Broadcast` method.
- Add tests to mock the `MeshClient` and verify that `Broadcast` is called during a state transition.
- Ensure all tests pass by running `bazelisk test //srcs/server/orchestration/...`.

**Priority**: P0
**Estimated Scope**: Medium
