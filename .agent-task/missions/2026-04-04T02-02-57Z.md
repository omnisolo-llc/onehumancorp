# Mission: Architect and Implement the Shared Task List (Teammate Mesh & AutoDream)

## Title
Architect and Implement the Shared Task List (Teammate Mesh & AutoDream)

## Problem Statement
The OHC swarm currently lacks a centralized, distributed system for agents to securely coordinate, decompose, and track task execution across the hybrid architecture. Without a "Shared Task List" leveraging our Postgres backend and Redis Pub/Sub (Teammate Mesh), agents cannot effectively orchestrate complex, multi-step workflows.

## Research Report
Based on the OHC architectural requirements (OHC-HA), the system must support both Cloud-Native and Standalone modes.
- In Cloud-Native mode, we will use Postgres as the primary consistency boundary and Redis for real-time Pub/Sub communication (Teammate Mesh) and distributed locking.
- Background queuing needs to be robust, utilizing technologies like BullMQ or Celery semantics built on Redis to spawn isolated sub-agents.
- AutoDream architectural consolidation requires us to periodically update a Vector DB (pgvector) to manage long-term memory for agent interactions and system states.

## Design Doc
**Architecture & API Contracts:**
1. **Database Schema (Postgres / SQLite fallback):**
   - `tasks` table: `id`, `parent_task_id`, `agent_id`, `status` (PENDING, RUNNING, COMPLETED, FAILED), `payload` (JSONB / TEXT), `created_at`, `updated_at`.
   - Use `FOR UPDATE SKIP LOCKED` for queue acquisition in Postgres, and `UPDATE ... RETURNING` (or mutex) for SQLite.
2. **Teammate Mesh (Realtime Comm Layer):**
   - Implement a Redis Pub/Sub layer broadcasting over `mesh:tasks`.
   - JSON payloads must have `agent_id`, `action`, and `status` at the root level.
3. **Sub-Agent Orchestration:**
   - Worker background queuing logic to listen on `mesh:tasks` and execute jobs reliably.
4. **AutoDream Pipeline:**
   - Set up scheduled workers to consolidate task outcomes into embeddings using pgvector for future retrieval.

**UI Wireframes:**
- Dashboard showcasing current task queue, agent assignments, and realtime status updates utilizing the Glassmorphism aesthetic: `backdrop-filter: blur(20px) saturate(200%); background: rgba(255, 255, 255, 0.03); font-family: 'Outfit', 'Inter', sans-serif;`.

## Implementation Prompt
Implement the Shared Task List backend following the design doc.
1. Create DB migrations for the `tasks` table in `srcs/server/db/migrations/` and embed them in `srcs/server/db/BUILD.bazel`.
2. Implement queue acquisition logic in `srcs/server/db/provider.go` using hybrid SQL syntaxes (handling JSON parsing properly via `db.IsSQLite()`).
3. Build the Teammate Mesh publisher/subscriber in `srcs/server/orchestration/mesh.go` utilizing Redis Pub/Sub for the `mesh:tasks` channel. Ensure payloads have `agent_id`, `action`, and `status` at the root.
4. Set up the AutoDream pgvector embedding logic for task summarization.
5. Provide OpenTelemetry metrics for queue length and task processing latency.
6. Write unit and E2E tests, verifying functionality and UI elements. Make sure to run `bazelisk test //...` to ensure >90% test coverage.
