# Mission: Implement KAIROS Hybrid Agentic OS Orchestration State Machine

## Problem Statement
The OHC AI OS lacks a robust distributed state machine capable of decomposing high-level architectural missions into granular tasks. Without this, swarm agents suffer from race conditions when attempting to concurrently claim work, limiting our horizontal scaling potential. The architecture must gracefully degrade for local Standalone (SQLite) execution while maintaining transactional integrity in Cloud Native (PostgreSQL) deployments.

## Research Report
Competitive analysis reveals that leading orchestration engines (e.g., Temporal, Cadence, BullMQ) rely strictly on robust row-level locking or optimistic concurrency. In the OHC Hybrid Infrastructure, we will rely on distributed Redis locks and strict `locked_until` timestamps on the Database rows. Our design dictates avoiding any polling, instead adopting an event-driven architecture using the Teammate Mesh APIs for sub-agent coordination.

## Design Doc
Reference Document: `docs/architecture/KAIROS_AI_OS_FINAL_BLUEPRINT.md`

### Key Implementations Required:
1. **Database Migrations:** Create the `shared_tasks_v2` tables for both PostgreSQL and SQLite.
2. **Data Layer Methods:** Implement the atomic `ClaimTask(agentId string) (Task, error)` mechanism utilizing `UPDATE ... RETURNING ...` for PG and application-level retry/lock mechanisms for SQLite.
3. **Queue Ingestion:** Build the logic that parses a High-Level Mission into the JSON dependencies payload.
4. **Mesh Notifications:** Hook task transitions into the `Teammate Mesh` broadcast API.
