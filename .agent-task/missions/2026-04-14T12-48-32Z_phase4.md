# Research Report
Sub-agents need a reliable polling mechanism to claim jobs and report results. The system needs an interface that wraps job pushing and popping, allowing us to swap out Redis (Cloud) for an in-memory/SQLite implementation (Standalone).

# Implementation Prompt
You are a Principal Software Engineer implementing Phase 4 of the KAIROS Hybrid OS Orchestration.
1. Define a `JobQueue` interface in `srcs/server/orchestration/queue/queue.go` containing `Push(ctx context.Context, topic string, payload []byte) error` and `Pop(ctx context.Context, topic string) ([]byte, error)`.
2. Implement a `RedisJobQueue` utilizing `rueidis` to leverage Redis lists (`LPUSH`/`BRPOP`).
3. Implement an `InMemJobQueue` utilizing a buffered Go channel or `sync.Map` of channels.
