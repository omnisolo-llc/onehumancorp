# Implement Telemetry for Shared Task Orchestration

**Problem Statement**:
The OHC swarm relies on the `shared_tasks_decomposition` database logic in `srcs/server/orchestration/shared_tasks.go` to safely claim, create, and transition tasks. However, this critical domain currently completely lacks OpenTelemetry and Prometheus observability coverage, creating a blind spot in the Swarm Vitality Dashboard regarding database lock contention and claiming throughput.

**Research Report**:
A codebase audit reveals that while the `kairos/metrics.go` defines `TransitionsTotal`, `TransitionDuration`, and `TaskQueueDepth`, the core database workflows in `shared_tasks.go` (`ClaimTask`, `CreateTask`, `TransitionTask`) are completely silent. This prevents identifying mode-specific bottlenecks (Cloud-native Postgres vs Standalone SQLite) and violates the Full-Spectrum Observability core value.

**Design Doc**:
We must introduce OpenTelemetry (OTel) metrics directly to `srcs/server/orchestration/shared_tasks.go`.
- Metric 1: `shared_tasks_claimed_total` (Counter) - Tracks successful and failed `ClaimTask` operations, labeled by mode.
- Metric 2: `shared_tasks_db_duration_seconds` (Histogram) - Tracks execution time of `ClaimTask`, `CreateTask`, and `TransitionTask`.
The metrics should utilize `go.opentelemetry.io/otel/metric` and be initialized globally within the orchestration package.

**Implementation Prompt**:
1. In `srcs/server/orchestration/shared_tasks.go`, import `go.opentelemetry.io/otel` and `go.opentelemetry.io/otel/metric`.
2. Define global variables `tasksClaimedTotal metric.Int64Counter` and `tasksDbDuration metric.Float64Histogram` and initialize them using `otel.Meter("orchestration")`.
3. Wrap the database execution logic inside `ClaimTask`, `CreateTask`, and `TransitionTask` with timing defer statements that record to `tasksDbDuration`.
4. In `ClaimTask`, increment `tasksClaimedTotal` with an attribute `status="success"` when a task is successfully claimed, and `status="failed"` on error.
5. Ensure these edits strictly match the OHC project's OHC-SIP Stylistic Intent Profile, retaining existing behavior while simply adding observability.
