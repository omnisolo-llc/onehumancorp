# Title: KAIROS Teammate Mesh APIs

## Problem Statement
Agents lack a realtime communication layer to coordinate and pass distributed state machine updates securely.

## Research Report
- The Teammate Mesh requires low latency for sub-agent coordination.
- Redis Pub/Sub satisfies Cloud-Native, but Standalone needs an in-memory event bus or SSE for UI updates.

## Design Doc
**Mesh Architecture Overview:**
- Cloud Mode: Uses `rueidis` for reliable Pub/Sub, bridging separate Go servers.
- Standalone Mode: Uses local Go channels to implement a `MeshHub` interface.
- Core Event Type: `MeshEvent { topic: string, payload: json }`

## Implementation Prompt
Implementer, please build the Teammate Mesh API in `srcs/server/orchestration/mesh.go`:
1. Define a `MeshHub` interface with `Publish(topic, payload)` and `Subscribe(topic)`.
2. Implement `RedisMeshHub` for Cloud-Native mode.
3. Implement `LocalMeshHub` (using channels/sync.Cond) for Standalone Mode.
4. Ensure robust tests simulating high concurrency without data races.
