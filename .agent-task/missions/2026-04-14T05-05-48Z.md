# Mission: Implement KAIROS Orchestration Backend

**Title**: Implement KAIROS Orchestration Backend (Shared Task List, Teammate Mesh, AutoDream, Sub-Agent Queue)

## Problem Statement
The OHC swarm requires a unified backend architecture to support its hybrid multi-agent operating system. Currently, task delegation, background queuing, real-time communication, and long-term memory consolidation lack a robust, centralized, and visually-compliant orchestration layer that degrades gracefully from Cloud (PostgreSQL/Redis) to Standalone (SQLite/In-Memory).

## Research Report
The KAIROS Orchestration layer must handle four core pillars:
1. **Shared Task List**: Distributed state machine utilizing `FOR UPDATE SKIP LOCKED` (Postgres) and Mutexes (SQLite).
2. **Teammate Mesh**: Real-time Pub/Sub transport via Redis (Cloud) and sharded in-memory (Standalone), enforcing OHC-SIP compliance (`agent_id`, `action`, `status`).
3. **AutoDream Pipeline**: Background vector consolidation of YAML logs into `pgvector` (`autodream_memories`).
4. **Sub-Agent Queue**: Background polling of `sub_agent_jobs` table to spawn isolated execution workers.
