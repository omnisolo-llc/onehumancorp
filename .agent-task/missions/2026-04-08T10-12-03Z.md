# Observability Gap Bridge: Token Burn Rate Forecasting and SQLite Throttling Visualization

**Problem Statement**:
While the backend has had recent adaptations for token burn rate forecasting and SQLite concurrency throttling, there remains an observability gap. Specifically, there is no dedicated metric tracking **Token Burn Rate Forecasting**, and the Grafana dashboard (`deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`) lacks visualization for both token burn rate forecasting and standalone mode SQLite concurrency throttling metrics. This hinders proactive monitoring and self-correction in the OHC Hybrid Architecture.

**Research Report**:
A review of `OBSERVABILITY_AUDIT_REPORT.md` highlights that despite basic token usage logging, per-tenant predictive extrapolation for budget alerts is missing. Additionally, the standalone desktop mode suffers from database lock contention which necessitates concurrency throttling, but the impact and activation of this throttling are not adequately visualized. Bridging these gaps in observability is critical for the "AutoDream" architectural consolidation and self-correction of the Swarm.

**Design Doc**:
1.  **Backend Metrics Implementation**:
    *   Introduce a new Prometheus metric (e.g., `ohc_token_burn_rate_forecast`) in the Go backend to track the calculated token burn rate forecast.
    *   Ensure this metric is correctly updated by the background worker in the Orchestration Hub.
    *   Expose a metric for SQLite concurrency throttling activity (e.g., `ohc_sqlite_throttling_active` or a counter for throttled requests) in Standalone mode.
2.  **Grafana Dashboard Updates (`deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json`)**:
    *   Add a new panel to visualize the `ohc_token_burn_rate_forecast` metric.
    *   Add a new panel to visualize the SQLite concurrency throttling metrics, providing insight into when and how often throttling occurs in Standalone mode.

**Implementation Prompt**:
1.  **Backend Metrics**: Implement the Prometheus metric `ohc_token_burn_rate_forecast` in the Orchestration Hub's background worker. Expose a metric tracking SQLite concurrency throttling events in `DelegateMission` (or the relevant throttling component) when in Standalone mode. Update the relevant Go source files (e.g., `srcs/server/orchestration/service.go`, `srcs/server/orchestration/hub.go`, and metrics definitions).
2.  **Dashboard Visualization**: Modify `deploy/docker/grafana/provisioning/dashboards/hybrid-telemetry.json` to include panels for both the new `ohc_token_burn_rate_forecast` metric and the SQLite concurrency throttling metric. Ensure the panels are correctly configured and placed within the "Hybrid Telemetry Review" dashboard.
3.  **Verification**: Write tests to ensure the new metrics are correctly registered and updated. Verify the dashboard JSON is structurally valid.
