# Problem Statement
The OHC Swarm lacks a centralized, distributed state machine to decompose and track high-level feature requests across agents. Without a durable database schema that scales in Cloud-Native mode (PostgreSQL) and degrades gracefully in Standalone Mode (SQLite), tasks cannot be coordinated effectively without collisions.

# Research Report
- **Cloud-Native Mode:** Requires PostgreSQL row-level locks using `FOR UPDATE SKIP LOCKED` to prevent horizontal pod worker collisions during task claiming.
- **Standalone Mode:** Requires application-level semaphores and SQLite transaction isolation.
- **Teammate Mesh Integration:** Tasks must track state to emit events to the Mesh Hub upon status changes.
- **Schema Status:** The `shared_tasks` table and `task_dependencies` already exist in the database migrations. We must use the existing schema and implement the lock-free polling logic.

# Design Doc
**Architecture:** Use the existing `shared_tasks` and `task_dependencies` schema. Focus on the data access layer to ensure robust locking and dependency resolution.

**Sequence Diagram (Task Claiming):**
~~~mermaid
sequenceDiagram
    participant Agent as Worker Agent
    participant DB as Postgres (shared_tasks)

    Agent->>DB: BEGIN
    Agent->>DB: SELECT id FROM shared_tasks WHERE status = 'PENDING' FOR UPDATE SKIP LOCKED LIMIT 1
    alt Task Found
        DB-->>Agent: Returns Task 123
        Agent->>DB: UPDATE shared_tasks SET status = 'ASSIGNED', assigned_agent_id = 'worker-1' WHERE id = 123
        Agent->>DB: COMMIT
    else No Task Found
        DB-->>Agent: Returns 0 rows
        Agent->>DB: ROLLBACK
    end
~~~
