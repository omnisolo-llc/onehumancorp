# Title: KAIROS Hybrid Agentic OS Core Orchestration Implementation

## Problem Statement
The OHC Hybrid Agentic OS requires the foundational implementation of the KAIROS Orchestration engine, specifically the unified Shared Task List, Teammate Mesh APIs, and AutoDream memory pipelines to enable horizontal scaling and standalone graceful degradation.

## Research Report
Based on `docs/architecture/kairos_hybrid_agentic_os_master_blueprint.md`, we need a robust integration of task decomposition, realtime teammate communication (Redis Pub/Sub or In-Memory), and `pgvector`-backed AutoDream consolidation triggered on task completion.

## Design Doc
See `docs/architecture/kairos_hybrid_agentic_os_master_blueprint.md` for full schema, sequence diagrams, and API contracts.

1.  **Shared Task List**: Create `shared_tasks_master` and `task_dependencies_master` tables with graceful `FOR UPDATE SKIP LOCKED` / SQLite transaction locking.
2.  **Teammate Mesh**: Implement `POST /api/mesh/broadcast` and `GET /api/mesh/stream` endpoints.
3.  **AutoDream Pipeline**: Hook into the task completion lifecycle to vectorize payloads into `autodream_memories_master`.

## Implementation Prompt
Implement the KAIROS Master Blueprint:
1.  **DB Migrations**: Create SQL migrations for `shared_tasks_master` and `autodream_memories_master` in `srcs/server/db/migrations/` and update `srcs/server/db/BUILD.bazel`.
2.  **Shared Task List Engine**: Implement the polling and locking logic (Postgres vs SQLite) in `srcs/server/orchestration/tasks.go` and `srcs/server/orchestration/tasks_db.go`.
3.  **Teammate Mesh APIs**: Add the routing logic in `srcs/server/api/mesh/mesh.go` integrating with Redis Pub/Sub if available.
4.  **AutoDream Integration**: Ensure task completion events synchronously or asynchronously invoke the vectorization pipeline in `srcs/server/orchestration/autodream.go`. Ensure zero secrets are hardcoded; use SPIFFE/SPIRE context.
