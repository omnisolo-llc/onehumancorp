# Architecting the OHC Shared Task List

## Problem Statement
The OHC Hybrid Agentic OS requires a robust, distributed "Shared Task List" to allow multiple AI agents to collaborate seamlessly. Currently, there is no centralized, durable database schema or microservice architecture designed to handle complex feature requests decomposed by the central KAIROS orchestrator. Without this, agents cannot coordinate effectively, leading to deadlocks and fragmented execution.

## Research Report
- **Goal:** Design the data layer and architectural components for a Shared Task List.
- **Context:** The system operates in both Cloud-Native (PostgreSQL) and Standalone (SQLite) modes. The solution must support both, falling back gracefully in Standalone mode.
- **Key Components Required:**
    1.  **Task Entity:** A table to store tasks, status, assigned agent, and priority.
    2.  **State Machine:** Distributed state tracking using DB transactions (and potentially Redis locks in Cloud mode) to prevent race conditions when multiple agents try to claim the same task.
    3.  **Teammate Mesh:** A communication mechanism (e.g., Redis Pub/Sub in Cloud, or simple polling/event bus in Standalone) to notify agents of new tasks.

## Design Doc
### Architecture & Schema
We need a new table `ohc_tasks` in the central database to represent the shared task list.

**Table `ohc_tasks` (PostgreSQL / SQLite compatible):**
- `id` (UUID or TEXT, Primary Key)
- `title` (TEXT, Not Null)
- `description` (TEXT)
- `status` (TEXT, e.g., 'PENDING', 'IN_PROGRESS', 'DONE', 'FAILED')
- `assigned_agent_id` (TEXT, Nullable)
- `priority` (INTEGER, Default 0)
- `created_at` (TIMESTAMP)
- `updated_at` (TIMESTAMP)

### State Machine Tracking
To prevent deadlocks and ensure absolute autonomy, task claiming must use an atomic operation:
- `UPDATE ohc_tasks SET status = 'IN_PROGRESS', assigned_agent_id = ?, updated_at = NOW() WHERE id = ? AND status = 'PENDING'`
This ensures only one agent successfully claims a task, acting as a distributed lock backed by the database.

### Sub-Agent Orchestration & Teammate Mesh
- **Cloud Mode:** When a task is created or its status changes, a notification is published to a Redis Pub/Sub channel (`ohc:tasks:events`). Agents subscribe to this channel.
- **Standalone Mode:** Agents use long-polling or a local in-memory event bus to detect task changes.
