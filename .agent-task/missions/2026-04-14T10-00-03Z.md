# Title: KAIROS: Phase 3 - autoDream Data Pipelines

**Problem Statement:**
Agent intermediate state and architectural findings are ephemeral, limiting the swarm's long-term intelligence. There is no automated memory consolidation system to ensure findings persist across execution sessions.

**Research Report:**
The Swarm Intelligence Protocol dictates that contextual memory must be retained. "autoDream" solves this by vectorizing task logs. A `pgvector` pipeline effectively embeds these findings, enabling robust RAG (Retrieval-Augmented Generation) based semantic search.

**Design Doc:**
**autoDream Architecture:**
1. A background worker periodically sweeps the `.agent-task/memory/` folder and `shared_tasks` completions.
2. Content is chunked and embedded via an LLM.
3. Resulting vectors are upserted into the `consolidated_memory` Postgres table using `pgvector`.

**Database Schema:**
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE IF NOT EXISTS consolidated_memory (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id UUID REFERENCES shared_tasks(id),
    content TEXT NOT NULL,
    embedding vector(1536),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

**Implementation Prompt:**
Implement the autoDream Vector DB consolidation pipeline.
1. Add the `consolidated_memory` table migration.
2. Develop the `AutoDreamSyncEngine` daemon to periodically extract, embed, and store execution findings.
3. Include graceful degradation logic to conditionally bypass pgvector syntax if `dbWrapper.IsSQLite()` is true.
