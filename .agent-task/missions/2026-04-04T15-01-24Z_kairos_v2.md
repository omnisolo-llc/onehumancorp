# Title
Implement KAIROS Orchestration V2: Shared Task List, Teammate Mesh, and AutoDream

# Problem Statement
The OHC Swarm needs a high-performance distributed task orchestration and memory consolidation system. We must build robust 'Shared Task List' capabilities using `FOR UPDATE SKIP LOCKED` (with SQLite fallbacks), 'Teammate Mesh APIs' for realtime Redis Pub/Sub coordination, and an 'AutoDream Vector Data Pipeline' for converting ephemeral agent memory into durable pgvector embeddings.

# Research Report
Based on OHC Hybrid Architecture (OHC-HA) principles and our latest technical audit:
1. **Shared Task List**: In PostgreSQL, we require zero TOCTOU race conditions. Explicit DB transactions must be used (`tx.Begin()`) to ensure the row lock is maintained while processing the `QueryRow` / `Query` with `FOR UPDATE SKIP LOCKED`. SQLite cannot process `UPDATE ... RETURNING` with a `LIMIT` cleanly, so a select-then-update wrapped in `tx.Begin()` is required.
2. **Teammate Mesh**: Realtime coordination needs a dedicated Pub/Sub layer. Cloud mode utilizes Redis channels (`mesh:tasks`, `mesh:coordination`) connecting down to Centrifuge, while Standalone mode gracefully degrades to in-memory Go channels.
3. **AutoDream Pipeline**: Background queues (AutoDreamWorker) must ingest from `agent_session_data` (older than 24h), process the context using an LLM, and insert the high-dimensional vectors into `autodream_memories` and `agent_memories` using exact Nearest Neighbor algorithms (`ORDER BY embedding <-> $1`).
