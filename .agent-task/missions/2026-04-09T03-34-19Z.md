# 🎯 KAIROS Orchestration: Shared Task List, Teammate Mesh, and AutoDream

**Priority:** P0 (critical)
**Estimated Scope:** Large

## 1. Problem Statement
The OHC swarm currently lacks a centralized, distributed system for agents to securely coordinate, decompose, and track task execution across the hybrid architecture. Without a "Shared Task List" leveraging our Postgres backend and Redis Pub/Sub (Teammate Mesh), agents cannot effectively orchestrate complex, multi-step workflows. AutoDream memory consolidation is required for long-term agent learning.

## 2. Research Report
Analyzed competitive agentic architectures and internal Hybrid constraints. Most agent frameworks lack robust hybrid state tracking that degrades gracefully to SQLite.
*   **State Machine**: We require a robust state machine utilizing PostgreSQL `SKIP LOCKED` for cloud concurrency, and SQLite fallback for local standalone mode.
*   **Coordination**: A Redis Pub/Sub layer (Teammate Mesh) is required for real-time state broadcasts.
*   **Memory**: Long-term consolidation needs pgvector pipelines (AutoDream) to store and retrieve agentic context securely.

## 3. Design Doc
*   **Shared Task List Database Schema**: Introduce `agent_tasks` table supporting parent-child DAG dependencies, status (`PENDING`, `IN_PROGRESS`, `DONE`, `FAILED`), and assigned agent mapping.
*   **Teammate Mesh Architecture**: Implement real-time broadcast handlers over Redis/Centrifugo targeting channels to emit task state transitions.
*   **AutoDream Pipeline**: Architect background cron job to query completed tasks, generate embeddings via LLM, and store them in `autodream_memories` with graceful degradation to local SQLite representations.
*   **Aesthetics Constraint**: All orchestration UI widgets must implement the Premium Glassmorphism visual tokens.
