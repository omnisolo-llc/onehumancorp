# Title: OHC KAIROS Orchestration & Shared Task List Backbone

## Problem Statement
The One Human Corp (OHC) Swarm lacks a robust, scalable backend for its "Hybrid Agentic OS". To achieve multi-agent orchestration, we need to finalize the Shared Task List logic, define distributed state machine transitions, provide low-latency Realtime Teammate Mesh APIs, and orchestrate sub-agents via a durable background queue. We must also support the autoDream Vector Data pipeline to ingest agent session data. This architecture must degrade gracefully from Cloud-Native (pgvector/Redis) to Standalone Desktop (SQLite).

## Research Report
- Based on `docs/features/kairos/autodream_pipeline.md`, `docs/features/kairos/state_machine.md`, and `docs/features/kairos/sub_agent_queue.md`:
- We need the **Shared Task List** backed by a distributed state machine (PENDING -> ASSIGNED -> EXECUTING -> REVIEW -> SUCCESS).
- We need **Teammate Mesh Architecture** via Redis Pub/Sub (Cloud) or in-memory channels (Standalone) using `CentrifugeNode`.
- We need a **Sub-Agent Orchestration Queue** for routing sub-tasks with retry logic.
- We need the **autoDream Data Pipeline** to take `.agent-task/memory/*.yml` and ingest into `autodream_memories` table (pgvector 1536 dim / SQLite JSON blob).
- All visual components (agent task dashboards) must maintain OHC premium feel: `backdrop-filter: blur(20px) saturate(200%); background: rgba(255, 255, 255, 0.03); font-family: 'Outfit', 'Inter', sans-serif`.

## Design Doc
### Architecture
The KAIROS Orchestrator acts as the central brain.
1. **Task Decomposition:** The Shared Task List decomposes goals into a DAG. `task_dependencies` table tracks relationships.
2. **Distributed Locks:** Redis `rueidis` `SET NX EX` (Cloud) / SQLite database lock (Standalone).
3. **State Machine Tracker:** Table `state_machine_transitions` audits agent actions and emits Teammate Mesh events.
4. **Sub-Agent Queue:** Table `sub_agent_jobs` or Redis ZSETs power `TaskQueue`.
5. **autoDream Pipeline:** Polling Go worker chunks episodic memory and calls the LLM embedding client.

### Schema Blueprint (PostgreSQL/SQLite compatible)
```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS shared_tasks (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL,
    title TEXT NOT NULL,
    status TEXT NOT NULL,
    agent_id TEXT
);

CREATE TABLE IF NOT EXISTS task_dependencies (
    task_id TEXT NOT NULL,
    depends_on_task_id TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS state_machine_transitions (
    id TEXT PRIMARY KEY,
    entity_id TEXT NOT NULL,
    entity_type TEXT NOT NULL,
    from_state TEXT NOT NULL,
    to_state TEXT NOT NULL,
    agent_id TEXT,
    reason TEXT,
    occurred_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS autodream_memories (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL,
    agent_id TEXT,
    content TEXT NOT NULL,
    embedding vector(1536),
    source_type TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
```
