# Title: Implement Standalone Metric Buffer and Cloud Sync

## Problem Statement
When operating in Standalone Desktop mode (`OHC_STANDALONE=true`), OHC currently lacks robust local telemetry buffering and cloud synchronization. This observability gap prevents full visualization of local agent execution metrics (e.g., token usage, latency) in the central Grafana dashboards, conflicting with the Full-Spectrum Observability mandate.

## Research Report
Competitive analysis of Claude Code and OpenClaw shows they either ignore local telemetry or enforce fully observable but non-private cloud execution. OHC's Hybrid Observability approach requires capturing local metrics securely in SQLite, applying PII scrubbing, and syncing them efficiently to the cloud without sacrificing data sovereignty. We need to complete the implementation of local metrics buffering and sync.

## Design Doc
1. **Local Metric Buffer**: A buffer table `telemetry_buffer` exists in `srcs/server/db/migrations/026_telemetry_buffer.sql`. Ensure it's correctly managed and utilized in the Standalone (SQLite) DB provider.
2. **PII Scrubbing**: Ensure all metric payloads are routed through `telemetry.RedactPII` (or `telemetry.NewPIIRedactingHandler` for loggers) before insertion into the buffer.
3. **Sync Daemon**: `StartSyncDaemon` exists in `srcs/server/telemetry/sync_worker.go`. Ensure it is correctly invoked during Standalone mode startup to push to the Cloud API endpoint.
4. **Cloud API**: Add an endpoint on the Cloud API to receive batched metrics and push them to Prometheus, completing the sync flow.

## Implementation Prompt
Implementer Agent, execute the following:
1. Ensure `telemetry_buffer` SQLite schema is properly defined and loaded for `OHC_STANDALONE=true`.
2. Implement the `SyncBufferedMetrics` function (if missing or incomplete) on the `orchestration.SIPDB` interface for the Standalone SQLite provider.
3. Ensure `telemetry.RedactPII` is called on all metric payloads before they are written to `telemetry_buffer`.
4. Add a `/api/v1/telemetry/sync` endpoint in the Cloud API handlers to receive these batches and register them with Prometheus.
5. Wire up `telemetry.StartSyncDaemon` in the Standalone node entrypoint (`main.go` or equivalent startup logic) to run every 5 minutes.
6. Write unit tests for the PII redaction integration, SQLite buffering, and the sync daemon. Ensure test coverage is >90%.
