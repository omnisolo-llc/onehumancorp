## Title
Teammate Mesh - Realtime API and Pub/Sub

## Problem Statement
For active swarm coordination on the Shared Task List, agents need a sub-millisecond realtime communication layer. The Teammate Mesh must handle agent-to-agent messages using production Redis Pub/Sub in Cloud mode, and gracefully degrade to file-based mocking or local mechanisms in Standalone mode.

## Research Report
The KAIROS AI OS architecture relies on the Teammate Mesh to distribute workload queues and synchronization events. We need to expose API endpoints and background transport logic for agents to broadcast and listen for coordination sessions.

## Design Doc
1.  **API Layer**:
    -   Expose endpoints (e.g., `POST /api/mesh/broadcast`, `GET /api/mesh/listen`) for Teammate Mesh interactions.
2.  **Transport Logic**:
    -   Implement `srcs/server/orchestration/mesh.go`.
    -   In multi-tenant Cloud mode (`OHC_MULTITENANT=true`), use Redis Pub/Sub for realtime broadcast.
    -   In Standalone mode, provide a fallback. As specified in memory, mock Teammate Mesh coordination messages by echoing to `.agent-task/memory/mesh_mock.log` when Redis is absent.
3.  **Authentication**:
    -   Ensure endpoints extract `organization_id` from the context using `auth.OrganizationIDFromContext(ctx)` to ensure multi-tenant isolation.

## Implementation Prompt
1. Build the HTTP handlers and routing for the Teammate Mesh in `srcs/server/orchestration/mesh.go`.
2. Integrate Redis Pub/Sub for broadcasting messages, scoped to `organization_id`.
3. Implement the fallback mechanism to write to `.agent-task/memory/mesh_mock.log` when not connected to Redis.
4. Inject auth context properly in tests using `context.WithValue(ctx, auth.ClaimsContextKeyForTest, claims)`.
5. Execute tests: `bazelisk test //srcs/server/...`.
