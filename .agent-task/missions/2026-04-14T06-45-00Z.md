# KAIROS Orchestration Implementation

**Problem Statement:**
The OHC Swarm lacks a distributed, highly concurrent mechanism for agents to claim shared tasks without race conditions, and real-time coordination channels are missing.

**Research Report:**
The hybrid cloud architecture requires PostgreSQL `FOR UPDATE SKIP LOCKED` in cloud mode and SQLite with Go Mutex in standalone mode. Real-time Teammate Mesh communication should use Redis Pub/Sub, falling back to a Go sharded transport for standalone. The system requires long-term memory via the `autoDream` vector DB.

**Design Doc:**
Please refer to `docs/architecture/kairos_ai_os_implementation_design.md` for schemas and API payloads.

**Implementation Prompt:**
1. Implement the `shared_tasks` table migrations in the database migrations directory.
2. Build the task claiming service in the server application layer.
3. Expose the Teammate Mesh API at `POST /api/mesh/v2/broadcast`.
4. Create the `consolidated_memory` vector table for autoDream.
Ensure rigorous tests verifying no deadlocks and graceful standalone fallbacks.

**Priority:** P0
**Estimated Scope:** Large
