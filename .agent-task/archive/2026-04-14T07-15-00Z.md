# Mission: Enforce OHC-SIP compliance in Teammate Mesh unified gateway requests

## Title
Enforce OHC-SIP compliance in Teammate Mesh unified gateway requests

## Problem Statement
Teammate Mesh unified gateway requests (e.g., `POST /api/mesh/broadcast`) must enforce OHC-SIP compliance by verifying that `agent_id`, `action`, and `status` exist at the root of the JSON payload. Currently, this compliance is checked manually inside the handler instead of systematically before reaching it.

## Research Report
The mesh unified gateway request handler `handleMeshBroadcast` in `srcs/server/dashboard/server.go` expects a JSON payload containing `channel`, `agent_id`, `action`, and `status`. It currently decodes the payload into a struct, but we need a systematic way to enforce this via middleware.

## Design Doc
Created a `ValidationMiddleware` inside `srcs/server/api/mesh/middleware.go` to intercept POST requests, decode the JSON payload, and verify that `agent_id`, `action`, and `status` are present in the JSON body. If they are missing, it returns `http.StatusBadRequest`.

The middleware is then wrapped around `server.handleMeshBroadcast` inside `srcs/server/dashboard/server.go`. Tests for the middleware have also been added to `srcs/server/api/mesh/middleware_test.go`.

## Implementation Prompt
Implement `ValidationMiddleware` in `srcs/server/api/mesh/` to ensure `POST /api/mesh/broadcast` contains `agent_id`, `action`, and `status`.
