# Mission: Implement KAIROS Orchestration Core V6

**Title**: Implement Shared Task List & Teammate Mesh Core
**Priority**: P0
**Estimated Scope**: Large

**Problem Statement**:
The OHC Swarm currently lacks a centralized, distributed mechanism to decompose complex user prompts into actionable DAGs (Shared Task List) and coordinate worker agents in real-time. Without this KAIROS orchestration layer, agents suffer from deadlocks and redundant work.

**Research Report**:
- Current state relies on decentralized ad-hoc task generation.
- Market competitors use centralized orchestrators (e.g., temporal, celery) which are too heavy for our Standalone mode.
- A custom DB-backed state machine and Redis Pub/Sub mesh provides the exact balance of Cloud-Native scale and Standalone efficiency required by the Hybrid Agentic OS vision.

**Design Doc**:
See `docs/architecture/kairos_orchestration_core_v6.md` for full database schema and pub/sub architecture.

**Implementation Prompt**:
1. Review the existing struct definitions for `SwarmTask`, `TaskDependency`, and `StateMachineTransition` in `srcs/server/db/models/tasks.go`. Ensure they align with `srcs/server/db/migrations/20260415120000_shared_tasks.sql`.
2. Create or extend a service (e.g., `srcs/server/orchestration/task_orchestrator.go`) that implements the `PROPOSE` -> `CRITIQUE` -> `APPROVED` -> `EXECUTE` UltraPlan deliberation lifecycle for tasks.
3. Ensure database queries for task pulling conditionally use PostgreSQL `FOR UPDATE SKIP LOCKED` or standard SQLite queries with Go Mutexes based on the active driver (see `srcs/server/db/postgres_provider.go` and `srcs/server/db/sqlite_provider.go`).
4. Implement Redis Pub/Sub broadcasting for state transitions in the mesh package (e.g., `srcs/server/orchestration/mesh/redis_mesh.go` and `srcs/server/orchestration/mesh/local_mesh.go`).
5. Write unit tests ensuring the DAG cycle detection logic successfully prevents circular dependencies when inserting into the `task_dependencies` table.
